# 本国水手与军队上限只读接口

N02 的 `sailors` 返回本国当前水手储备，`force_limits` 返回陆军与海军上限。两者支持主动查询和后台周期报告，来源限定已核对的 EU4 1.37.4 二进制及 FRA 观察方。读取采用有界 ReadProcessMemory，不调用游戏函数。

```json
{
  "request_id": "military-resources-query-unique-id",
  "queries": [{
    "topic": "N02",
    "object": {"type": "country", "country": "FRA"},
    "fields": ["sailors", "force_limits"],
    "parameters": {}
  }]
}
```

将此参数传给 `information_query`。只查询水手、上限及现存单位时，可省略 `reference_recipient`；若同时索取 `manpower`，仍须提供其他国家标签作为原有人力读取路径的参考方。

| 字段 | 返回值含义 | 完整性 |
| --- | --- | --- |
| sailors | `value` 与 `raw` 为千分位储备整数，`unit=sailors`、`scale=1000`；`display_value` 为原生界面整数 | available；单独查询时可 complete=true |
| force_limits | `value.land` 与 `value.naval` 分别给出上限团数及舰船数；子项 `value` 是数量，`raw=value*1000`、`scale=1000` | partial，complete=false |

例如水手 `raw=2597984` 表示2597.984，`display_value=2597`。显示值按原生 float32 转换与截零取得，不能在所有数值范围内简单替换为整数除1000。最大水手量不在本字段含义内，其内存来源仍待核对。

上限从原生 getter 使用的基础值及比例modifier缓存计算，保留signed32输入、截零顺序与最小1的规则。当前合格样本为陆军56团、海军25艘；现存单位48团与12艘由[现存军队接口](本国现存军队只读接口.md)返回，两组数量含义不同。遇到非空动态processor时，不调用回调，也不假定缓存值已包含回调效果，上限返回 unknown，水手仍可保持 known。

读取前后核对进程创建时间、会话、EXE身份、原生代码片段、完整国家引用和游戏日期，比较两遍原始输入。公开结果只保留字段数值、单位和来源摘要，不包含地址、modifier编号或私有读取轨迹。两遍一致并非原子快照；海军GUI独立样本及其他processor分支尚未完成，因此上限仍为 partial。

周期报告复用相同查询：先通过 `information_manage_report` 创建带 `name`、`detail` 和上述 `queries` 的报告，再用 `information_manage_subscription` 创建 `kind=periodic` 的订阅，设置 `schedule={"basis":"real","every":30,"unit":"seconds","missed":"coalesce"}`。后台调度与主动查询共用读取实现；报告已交付不表示LLM已阅读。
