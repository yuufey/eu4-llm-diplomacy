## 从当前待办查询提议

285批增加来源元数据`source.proposal_lookup`。当当前原生条目与同会话已准入提议唯一匹配时，`links`返回`entry_id`和A04使用的公开`proposal_id`。查询多个C03字段时，按组合来源定位`source.sources`中`fields`包含`pending_matters`的来源，再读取其`source.proposal_lookup`。完整结果和简报均保留该关联。

```json
{"status":"known","links":[{"entry_id":"pending-entry-a9a9c07e96bb98dbd355d7f0e2fa1ff2","proposal_id":"b1d5309317ec647953495ed84ab2b427"}],"response_authority":false}
```

将取得的`proposal_id`传入A04的`parameters.proposal_id`即可查询同项提议。关联按行动类型、国家完整引用及原生待办身份匹配。缺少或歧义匹配时不产生对应链接，关联读取失败返回`unknown`，原有当前清单继续返回。空队列及全部未识别队列返回已知空链接，不扫描提议日志。日志读取复用现有有界游标，未追到本次起始边界时关联保持未知。

关联属于查询辅助元数据，当前清单的变化比较继续使用原待办事实。`response_authority=false`表示该关联不提供执行权限，实际回应仍沿既有提议检查与权限合同。285批用当前BOU→FRA联姻完成单项与组合报告、A04查询及持久重开，复用284批的fresh_pending证据，本批没有重复调用该原生检查。[285批收据](../../../work/runtime/information-pending-proposal-links-20261108-285-001/summary.json)

## 当前队列中的期限

284批为已识别的`native_inbound_pending.value.entries`增加`deadline`。它复用已读取的行动头创建日期，按已核对的B23规则提供期限阈值，字段形状与`A04.deadline`一致。`pending_created_game_date`是待办创建日期，`value`为该日期加72个原始时刻单位，即3个游戏日。原生清理条件为`current_game_date > deadline.value`，实际结束日期仍由对应事件提供。

默认配置为`native-pending-memory-1374-r3.json`，保留r2原件。新配置在原有队列守卫之外核对113字节过期规则代码，每条目继续复用原双遍读取的64字节行动头。旧条目缺少期限仍可验证。未知行动不附加期限，非法、溢出或未来创建日期只使期限未知，已识别事项和队列计数继续返回。清单顺序沿原生链表，期限不会改变条目顺序。

下面查询取得当前会话待处理事项。

```json
{"topic":"C03","object":{"type":"session"},"fields":["pending_matters"],"parameters":{}}
```

C03分别提供操作方指示、日志待对账事项和原生待处理队列。strategic_goals和diplomatic_constraints来自显式声明，game_fact=false。pending_matters中的journal_requests来自配置日志，native_inbound_pending在受支持的实时会话中提供FRA收件国原生队列摘要，两部分各自标记状态与范围。

```json
{"queries":[{"topic":"C03","object":{"type":"session","session_id":"45688-1dd6b3ed674d8d0"},"fields":["strategic_goals","diplomatic_constraints","pending_matters"],"parameters":{}}]}
```

输入字段须在启动时提供--decision-context PATH。文件格式如下；替换binding为对应会话身份。空列表表示该文件没有声明条目，不表示国家没有目标或游戏限制。

```json
{"schema":"EU4-DECISION-CONTEXT/1","binding":{"session_id":"45688-1dd6b3ed674d8d0","observer":"FRA","game_sha256":"b23fa0e1f698d31b01cdd1c3817a675805d8c6286cb66f9c231e6e2a42544d77"},"strategic_goals":[],"diplomatic_constraints":[]}
```

每条声明为{id,text}，同字段ID不得重复，按文件顺序返回；每字段最多64条，text非空且最多2048字符，整文件最多64KiB。两个声明字段可分别缺失，缺失返回unknown；未配置文件来源时unsupported。错误schema、未知键、重复JSON键、身份不符或非法条目不会替换成空声明。文件与上下文在读取期间变化会撤回结果。输入只读取，不执行；配置这些条目不会增加任何外交动作权限。

声明value含source_kind=operator_input、binding、declarations和game_fact=false，分别使用declared_objectives/declared_constraints、scale1、period=declared。文件SHA/字节数/路径在provenance，避免无关文件格式变化成为字段事实变化。文件可以更新；change通过采样比较选定字段，并非无损编辑事件。

pending_matters.value含scope、journal_requests、pagination、native_inbound_pending及action_authorization。只读取已绑定experiment/session内actor等于观察国、且尚未终态的请求。每项保留request_id、action_id、actor/recipient/phase、status、submitted、updated_at、has_submission_claim、claimed_at及review_kind。constructed也可能已占用唯一submission channel；submitted/executing/unknown必须对账，waiting_response仅为日志状态，本地received/queued/consumed不代表游戏正在等待回应。查询不授权提交、重派或因超时重试。

日志摘要读取已绑定的这一份配置日志。payload做有界SHA核对后只导出白名单字段，专用结果、回执和令牌正文留在原日志。journal_requests=[]只说明当前日志分页没有匹配请求。

## 当前原生收件队列

默认生产工厂为pending_matters启用原生队列采集，适用EU4 1.37.4、固定B23构建及FRA观察方，物理玩家须为其它国家。直接构造JournalPendingMattersSource时，native_pending默认false，供原有日志使用方继承原行为。未就绪或不支持的上下文保留unknown或unavailable。

native_inbound_pending.status为known时，value提供下列摘要。

| 字段 | 含义 |
| --- | --- |
| scope | 固定为recipient_owned_native_pending_action_list，限定这条收件国原生链表 |
| native_queue_count | 链表条目总数，单位为native_pending_list_entries |
| recognized_entry_count、unresolved_entry_count | 已识别与未识别条目数，两者之和等于总数 |
| entries | 已识别项提供entry_id、action_id、actor、recipient、phase及可知的deadline，未识别项提供entry_id与reason |
| list_traversal_complete | 整条计数链表已遍历并核对双向链接、尾部和条目数 |
| identity_scope | native_list_entry_observation，编号限定在该会话的原生条目观察 |
| payload_details_complete | 当前为false，条款及行动载荷详情另查 |
| response_contexts_available | 当前为false，回应入口需要原有提议观察与权限合同 |

已识别类型覆盖联盟、王室联姻、支持独立、请求军事通行权、附庸化、三类人情交换及和平提议。条目须满足已有原生形状约束，并通过当前国家表的完整引用核对。未知类型或形状保留未识别条目，读取失败、超出256条上限或链表损坏使该部分返回unknown。

entry_id格式为pending-entry加32位摘要，用于比较队列观察。回应操作继续使用既有接口取得的proposal_id和相应上下文。原生条目数量0的结论只适用于这条链表，其它待办通道、参战召唤和完整生命周期仍有独立缺项。

采集复用既有国家定位、进程身份和只读内存预算，读取上限1MiB，连续两次读取相同才接纳。进程创建身份、EXE SHA、代码字节、观察方与查询日期均须符合当前会话，句柄关闭后才返回可用值。两次外部读取仍保留atomic_snapshot=false。来源凭据位于provenance，字段只保留公开摘要。原生部分失败时，已验证的日志分页继续返回。

分页参数只作用于journal_requests。单独查询pending_matters时，parameters可给limit（1–128，默认64）及接口返回的next_after_request_id。返回has_more/next_after_request_id，游标按当前scope定位。原生部分每次读取完整的有界队列。输入字段使用空parameters，混合查询带分页会被拒绝。全部字段complete=false/partial=true，报告与周期共用查询路径。

仅选择pending_matters的change订阅，在日志和原生队列均取得可用结果后建立采样基线。队列或所选日志分页变化时交付，采集凭据和采样日期变化本身不触发通知。原生读取失败时保留旧基线，恢复后比较并交付一次，取消后停止该订阅的采集。声明字段沿原采样比较合同。
