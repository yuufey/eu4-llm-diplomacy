`N03` 当前公开五个本国军事质量字段：`military_technology`、`army_tradition`、
`morale`、`professionalism` 和 `discipline`。五个字段都只接受 EU4 1.37.4 的 `FRA` country 对象，查询
参数必须是空对象 `{}`，支持主动 `query` 和 `periodic` 读取。科技、传统、士气和职业度的
字段能力为 `coverage="available"`、`complete=true`；纪律为
`coverage="partial"`、`complete=false`。这里的 `complete` 只描述该字段的有界原生
读取合同，不表示 N03 的其他字段或未覆盖的计算路径已经实现。

| 字段 | 原始值含义 | `unit` | `scale` | `period` | `basis` |
| --- | --- | --- | --- | --- | --- |
| `military_technology` | 有符号 int32 科技等级缓存 | `technology_level` | `1` | `current` | `native_country_technology_level_cache` |
| `army_tradition` | 有符号 int32 军事传统缓存 | `army_tradition` | `1000` | `current` | `native_country_army_tradition_cache` |
| `morale` | 陆军和海军各自的有符号 int32 当前士气缓存 | `morale` | `1000` | `current` | `native_country_morale_caches` |
| `professionalism` | 有符号 int64 陆军职业度当前缓存 | `ratio` | `32768` | `current` | `native_country_army_professionalism_cache` |
| `discipline` | 按原生纪律基值和已识别修正处理器计算的有符号 int32 结果 | `ratio` | `1000` | `current` | `native_country_discipline_calculation` |

`value` 和 `raw` 都是原始整数；科技、传统和纪律的 `raw_hex` 是四字节小端编码，职业度
的 `raw_hex` 是八字节小端编码。军事传统的显示值按 `raw / 1000` 解释；例如 `21052`
是 `21.052` 点，编码为 `3c520000`。科技等级 `4` 的编码为 `04000000`。

士气的 `value` 和 `raw` 是两个缓存的对象：`army=3123`、`navy=2142`，对应
`raw_hex` 的 `330c0000` 和 `5e080000`。它们表示当前复制的原生缓存，不能据此声称
已经复原游戏的最大值公式。纪律的 `1000` 按 `scale=1000` 表示 `1.000`，也就是
100%；`e8030000` 是该结果的原始四字节编码。职业度 `655` 按 `raw / 32768`
解释，约为 `0.019989`（约 2%）；它不是 `655%`，也不按 `1000` 缩放，
`8f02000000000000` 保留八字节原始值。

## 报告和周期订阅

可以先用 `information_manage_report` 保存一份查询配置：

```json
{
  "request_id": "military-quality-report-create-001",
  "operation": "create",
  "config": {
    "name": "FRA military quality",
    "queries": [{
      "topic": "N03",
      "object": {"type": "country", "country": "FRA"},
      "fields": ["military_technology", "army_tradition", "morale", "professionalism", "discipline"],
      "parameters": {}
    }],
    "detail": "full"
  }
}
```

服务返回 `report_id` 后，可以用它复用配置，而不必再次提交 `queries`：

```json
{
  "request_id": "military-quality-report-query-001",
  "report_id": "report-replace-with-returned-id"
}
```

N03 的周期订阅使用同一报告。下面的 `report_id` 和 `session_id` 是占位值；实际
调用时应分别替换成创建报告的返回值和 `information_discover` 返回的当前会话绑定：

```json
{
  "request_id": "military-quality-subscription-create-001",
  "operation": "create",
  "config": {
    "name": "FRA military quality every 2 seconds",
    "kind": "periodic",
    "report_id": "report-replace-with-returned-id",
    "enabled": true,
    "binding": {
      "session_id": "session-replace-with-current-session",
      "observer": "FRA",
      "game_version": "1.37.4"
    },
    "schedule": {
      "basis": "real",
      "every": 2,
      "unit": "seconds",
      "missed": "coalesce"
    }
  }
}
```

`information_tick` 到期后重复执行只读读取，不推进游戏日期，不调用游戏业务动作。父
读取器对每次采样执行两遍有界读取并比较上下文和字段；这不是游戏主线程上的原子快照。
如果会话、日期、代码守卫或字段读取不一致，本次结果保留 `unknown` 或
`unavailable`，不会继续消费旧值。当前字段支持 `query` 和 `periodic`，没有声明
`event` 或 `change`。

## 来源和单位边界

科技等级按原生名称 `mil_tech` 查找实际类别索引，再读取国家科技数组对应的等级。
读取器不假定军事类别永远位于固定槽位，也不把君主点当成科技等级。
见[科技来源合同](../../../work/runtime/information-military-quality-20261027-001/military-technology-source-002.json)
及[科技读取配置](../../../bridge/information/profiles/military-quality-memory-1374.json)。

军事传统的 country getter 在 [tradition-source-002.json](../../../work/runtime/information-military-quality-20261027-001/tradition-source-002.json)
中直接复制 `country+0xe40` 的 32 位缓存。UI formatter 的 selector `0x56` 和显式
`0x3e8` 小数余数路径见
[tradition-source-004.json](../../../work/runtime/information-military-quality-20261027-001/tradition-source-004.json)，
它说明 `scale=1000` 的显示单位。小型 serializer 的
[tradition-source-005.json](../../../work/runtime/information-military-quality-20261027-001/tradition-source-005.json)
确认四字节输入在该 writer 中保持原始宽度，没有再执行一次 1000 换算。

profile 位于
[military-tradition-memory-1374.json](../../../bridge/information/profiles/military-tradition-memory-1374.json)。
读取器在读取 country 缓存前检查固定版本、来源文件哈希和 RVA-relative 代码守卫；静态
vtable RVA 只作为来源证明，不把 ASLR 后的绝对指针当作运行时守卫。

士气读取 `country+0x9874` 和 `country+0x987c` 的有符号 int32 缓存，分别作为陆军和
海军士气返回，scale 为1000。它读取的是当前缓存，不复原最大值或完整修正公式。独立
参考中的值为 `army=3123`、`navy=2142`，对应 `330c0000` 和 `5e080000`；参考文件见
[expected-military-effective-002.json](../../../work/runtime/information-military-effective-20261027-001/expected-military-effective-002.json)。

职业度读取 `country+0x50` 的内联有符号 int64 缓存，不把这八个字节当作指针。当前
合同使用 `unit=ratio`、`scale=32768`，因此 `655 / 32768` 约为 `0.019989`；它不是
`655%`，也不按 `1000` 缩放。类型 8 的静态 formatter 路径和 `raw / 32768` 的单位
证据见[职业度来源合同](../../../work/runtime/information-military-professionalism-20261027-001/professionalism-scale-source-001.json)，
profile 见[职业度读取配置](../../../bridge/information/profiles/military-professionalism-memory-1374.json)。
独立原始参考见[职业度参考](../../../work/runtime/information-military-professionalism-20261027-001/expected-military-professionalism-001.json)。
该合同保证当前存储值、符号和比例尺度，不承诺缓存刷新时机、增减原因或主线程原子性。

纪律读取使用修正对象的内嵌布局：`country+0x28d0` 是 modifier object 本身，不是需要
再次解引用的指针；对象内部的值容器和 `0x77` 原始项由 v2 profile 校验。结果按
scale=1000 返回，`1000` 表示 `1.000`（100%）。当前合同保留原始输入、代码守卫和
线程路径状态；它不把非零线程贡献路径伪装成已闭合。见[纪律来源合同 v2](../../../work/runtime/information-military-effective-20261027-001/source-contract-002.json)
及[纪律读取配置 v2](../../../bridge/information/profiles/military-effective-memory-1374-v2.json)。
