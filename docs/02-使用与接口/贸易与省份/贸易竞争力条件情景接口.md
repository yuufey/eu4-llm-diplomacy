# 贸易竞争力条件情景

第206批增加[省份来源变化情景](../../04-实现研究/贸易与省份/省份来源与国家贸易力量情景.md)：可从明确给定的省份来源变化推导国家力量变化，再使用本文收入模型；总力量变化仍须明确提供。下文原有手工国家变化形式继续适用。

`T06.expected_trade` 使用同一次原生采集的节点收入、本国竞争力、总竞争力和收取资格，估算显式竞争力变化在固定贸易环境下的收入影响。`T06.assumptions` 返回本次计算使用的基线、校准系数、系统假设和调用者给定的变化。

来源支持 EU4 1.37.4、逻辑法国观察国及指定贸易节点。查询、报告和周期订阅共用同一实现；默认实时服务会注册这两个字段。绑定现有观察器的实时服务还提供 `T06.costs`，把显式行动的当前成本预览关联到情景编号。

```json
{
  "topic": "T06",
  "object": {"type": "trade_node", "node_id": "champagne"},
  "fields": ["expected_trade", "assumptions"],
  "parameters": {
    "scenarios": [
      {"id": "unchanged", "country_power_delta_raw": 0, "total_power_delta_raw": 0},
      {"id": "own-add-one", "country_power_delta_raw": 1000, "total_power_delta_raw": 1000}
    ]
  }
}
```

每个查询需要 1 至 8 个情景。`id` 为唯一的非空 ASCII 标识符，最多 128 字符；可选 `description` 为非空白说明，最多 512 字符。两个变化量均为 signed i32 原始整数，单位为竞争力、比例尺为 1000，因此 1000 表示 1 点竞争力。本国竞争力与总竞争力的变化分别声明，不自动假定取得省份或改变外交关系会产生哪些变化。完整参数最多 64 KiB。

令当前收入为 `I`，本国竞争力为 `P`，总竞争力为 `T`，情景给定的变化为 `dP`、`dT`，模型使用：

```text
I_new = I × ((P + dP) / (T + dT)) / (P / T)
k = I × T / P
```

`k` 是从这份收入与竞争力缓存校准出的有效收入系数。节点价值、流入流出和贸易效率的独立数值仍为 `unknown`，模型明确把它们视为保持不变；`k` 不充当这些字段的原生读数。收取策略也保持当前状态，竞争对手的变化只通过显式 `dT` 表达。竞争力比值在这里是数学模型的代理量，实际界面份额和完整引擎公式仍未核对。

计算要求当前节点可收取、收入非负、`P>0`、`T>0` 且 `P<=T`。当前不收取、基线缺失或无法校准时，预期收入保持未知。某个情景使新竞争力超出有效范围时，只将该情景标为未知，保留其它有效情景。经过验证的零收入与缺失值分开表达；显式将本国竞争力降为零时，模型可以得出零收入。

金额保留 `exact_raw.numerator`、`exact_raw.denominator` 的十进制整数字符串，表示比例尺 1000 下的精确有理数；`decimal` 以金币表示，保留 6 位小数并采用 half-even 舍入。精确分数是计算依据。金额周期继承输入收入的周期，目前原生投影为 `month`。

收入与假设字段均为 `partial`、`complete=false`、`game_fact=false`，并保留 `actual_future_income=unknown` 或对应假设边界。当前缓存的新鲜度、取得领土后的竞争力变化、贸易网络反应、改派商人和完整战争代价仍待分析。第196批已提供下述候选省份分页，但国家与省份对象的完整方案估算仍未交付。下述成本字段只覆盖明确行动的当前规则预览。

采集复用既有 `NativeTradePowerSource` 严格路径：每次创建局部采集包装，一次请求 `include_trade_income=True` 和 `include_trade_power=True`。只有原有身份、EXE、创建时间、双遍、清理状态和两类记录相互绑定的校验通过后，才从同份报告投影收入与收取资格。不会再发一次 T05 读取来拼接输入，不跨请求缓存，也不修改共享来源实例。双遍一致不表示主线程原子快照。

本批恢复后的法国实际采集显示，香槟节点是可收取节点，收入 raw4589、本国竞争力 raw199320、总竞争力 raw721085。下表是明确假设下的数学结果，单位为金币／月：

| 情景 | 本国竞争力变化 | 总竞争力变化 | 条件收入 |
| --- | ---: | ---: | ---: |
| 保持不变 | 0 | 0 | 4.589000 |
| 本国增加 1 点，总量也增加 1 点 | +1 | +1 | 4.605636 |
| 仅总量增加 1 点 | 0 | +1 | 4.582645 |

同份采集中的波尔多不满足收取前提，接口返回未知。香槟正例先使用已保存联合报告严格回放并逐项核对精确分数，随后通过真实 MCP 主动查询、报告与两种周期订阅验证。恢复使用既有保存场景，当前实读日期为 1456.7.26，物理玩家 POR、逻辑观察国 FRA；历史 1456.8.30 不作为新会话日期。

## 情景关联的当前行动成本

第195批新增 `costs`。选择该字段时，每个情景须提供 `actions` 数组，逐项声明 `id`、`action_id`、`recipient` 和 `parameters`。例如，在前述查询中添加 `costs`，并给每个情景添加：

```json
"actions": [{
  "id": "declaration-preview",
  "action_id": "declare_war",
  "recipient": "BUR",
  "parameters": {
    "casus_belli": "no_casus_belli",
    "war_goal": {"province_id": -1, "beneficiary": "FRA"},
    "call_allies": []
  }
}]
```

支持 `declare_war` 的完整明确选择，以及 `cede_province` 的当前战争、方向和条款选择；参数沿用[任务候选成本接口](../任务/任务链候选成本接口.md)中的行动合同。每个情景至少一个行动，整个查询最多16个行动；行动编号在各情景内唯一、最长64字符。情景编号仍可用128字符，查询仍最多8个情景、64 KiB。行动国固定为逻辑观察国法国。未选择 `costs` 时，原先不含行动的收入查询继续可用，来源不会调用行动检查器。

`costs.value.schema` 为 `information.trade_scenario_costs.v1`，`association=caller_scenario_id`，`scenarios` 按输入顺序保留编号和行动。宣战预览保留经核对的稳定度损失、厌战原始值、单位、比例尺和承担国的推导依据；领土议和复用 P02／P05 的预览字段与未知项。各行动保留 `phase=initiate`、`submitted=false`；查询不会执行行动。

这些行动都独立按当前局势检查，不模拟前一行动之后的局势。`total_cost` 明确为未知，不把不同单位相加。未来战损、战争时长、贸易和外交机会成本、完整战争或扩张方案代价仍未求出。调用者给定的竞争力变化也未证明由这些行动产生，`power_deltas_caused_by_actions=unknown`。结果保持 `partial=true`、`complete=false`、`game_fact=false`。

同一次查询仍读取一份联合贸易基线。完全相同的行动选择在本次读取内共享一次检查，包括失败结果；下一次读取重新检查。某行动失败只撤回该行动的成本，不把成本填成零；观察国、会话、世界、版本、EXE或日期在组合读取前后变化，则撤回本次所有字段。基线和行动检查不是原子事务。仅有成本选择时也读取一次基线，返回来源中的 `baseline_reads=1` 如实记录这一行为。

## 节点候选省份及当前贸易中心

开启 `--static-game-data` 的实时服务提供 `T06.targets`。它从有效静态节点定义的 `members` 生成有序候选，再分页复用已有 G02 的 `owner`、`controller`、`center_of_trade`。这些当前属性沿用逻辑法国的发现正位校验和原生双遍校验；不会切换物理玩家。可单独查询：

```json
{
  "topic": "T06",
  "object": {"type": "trade_node", "node_id": "champagne"},
  "fields": ["targets"],
  "parameters": {"target_page": {"offset": 0, "limit": 4}}
}
```

只选择 `targets` 时不要求 `scenarios`，也不读取贸易收入基线。与收入、假设或成本混合查询时，继续提供原有 `scenarios`；这些字段共用一次基线，目标读取失败独立表达。`target_page` 可省略，默认 offset=0、limit=4；offset 最大4096，limit 为1至16。候选总数最多4096，整个输出最多4 MiB；超限返回明确未知，不静默截断。

`value.schema=information.trade_targets.v1`，含 `candidate_count`、本页 `rows`、`next_offset` 和静态 `topology`。按照 `next_offset` 继续查询即可遍历清单；超出末页的空页不表示世界上没有目标。每行保留静态节点成员来源，以及 `current_annotations` 中的原 G02 字段、会话、日期和采集证明。省份在同页去重读取，不跨请求缓存。一个省份未知或读取失败时保留该行的未知注释；不会把未发现、空引用或缺失值填成无贸易中心。

候选表示“磁盘节点定义中的成员”，不是已证明的引擎加载成员、可征服目标或战略推荐。原始 `routes.path/control` 只保留为配置拓扑；不据此认定港口、河口、陆地或可扩张领土。当前贸易中心的存在、级别和类型可以显示，但关键程度、扩张资格、贸易外交目标及实际竞争力／收入增益仍为未知。整体为 `partial`、`game_fact=false`、`complete=false`，当前属性各自保留原 G02 的状态含义。

读取前后核对版本、配置与定义哈希、文件／模组和目录清单；这些静态输入在省份注释期间变化会撤回目标字段。会话、观察国、世界、版本、EXE或日期在组合读取前后变化，则撤回整次读取。静态文件与当前属性不构成引擎原子快照。

196批实机香槟定义有33个候选成员。首两行省份182为ORL所有并控制、无贸易中心；省份183为FRA所有并控制，贸易中心级别2、类型inland。这些是当次 G02 原结果的逐项投影，不据此认定应当扩张。MCP主动查询、报告、2秒／5秒周期语义一致，另验证下一页与 targets-only 零基线读取；所有订阅和服务已关闭。每次采集摘要独立检查，语义比较仅排除这个随读取变化的摘要，其余来源信息保留。

最初实机步骤在任何候选／省份／基线采集前因帧健康失效停止，随后脚本确认游戏窗口最小化；恢复同一窗口后心跳恢复，再继续原未开始的核对。日期仍1456.7.26且暂停，无保存、推进、重启、重新安装或外交执行。日志在 `work/runtime/information-trade-targets-20261105-196-001/`。完整测试集仍未重验，完整贸易扩张、战报及其余目标继续按原计划开发。
