# 贸易收入只读接口

第四十八批实机结果：FRA在莱茵兰转移、香槟收集，其余78节点无商人标志；80节点与独立参考一致。三字段共同查询、报告和三条两秒周期交付通过，订阅已取消，服务退出码0。见[本批验收报告](../../../work/runtime/information-trade-merchant-task-20261027-001/live-acceptance-001/report.json)。

`T05` 当前公开 `income`、`collection` 和 `merchant_task`。这些字段都只读取 EU4
1.37.4 FRA 的原生贸易节点缓存；`income` 给出收入数值，`collection` 给出节点的原生
聚合资格结果，`merchant_task` 给出当前有活动标志的节点及其任务枚举。

国家对象的 `income` 返回 FRA 的贸易节点收入总额，国家对象的 `collection` 返回按
原生节点顺序排列的 `node_id` 列表；国家对象的 `merchant_task` 返回同一顺序中非
`none` 的任务对象列表。贸易节点对象返回该节点的 `income` 贡献、`collection` 布尔值
和/或 `merchant_task` 枚举。三个字段在同一次 T05 读取中共享父 capture 和上下文校验。

## 查询

`information_query` 可以直接提交查询集合。国家总额示例：

```json
{
  "request_id": "trade-income-country-001",
  "queries": [{
    "topic": "T05",
    "object": {"type": "country", "country": "FRA"},
    "fields": ["income"],
    "parameters": {}
  }]
}
```

贸易节点贡献示例。`node_id` 使用定义中的稳定 ASCII 键：

```json
{
  "request_id": "trade-income-node-001",
  "queries": [{
    "topic": "T05",
    "object": {"type": "trade_node", "node_id": "champagne"},
    "fields": ["income"],
    "parameters": {}
  }]
}
```

同一次读取也可以请求两个字段；`parameters` 仍必须为空：

```json
{
  "request_id": "trade-income-collection-001",
  "queries": [{
    "topic": "T05",
    "object": {"type": "country", "country": "FRA"},
    "fields": ["income", "collection"],
    "parameters": {}
  }]
}
```

请求国家的活动商人任务：

```json
{
  "request_id": "trade-merchant-task-country-001",
  "queries": [{
    "topic": "T05",
    "object": {"type": "country", "country": "FRA"},
    "fields": ["merchant_task"],
    "parameters": {}
  }]
}
```

请求单个节点的任务枚举：

```json
{
  "request_id": "trade-merchant-task-node-001",
  "queries": [{
    "topic": "T05",
    "object": {"type": "trade_node", "node_id": "champagne"},
    "fields": ["merchant_task"],
    "parameters": {}
  }]
}
```

`income`、`collection` 和 `merchant_task` 也可以放在同一查询中；适配器只执行一次
父 capture：

```json
{
  "request_id": "trade-income-collection-task-001",
  "queries": [{
    "topic": "T05",
    "object": {"type": "country", "country": "FRA"},
    "fields": ["income", "collection", "merchant_task"],
    "parameters": {}
  }]
}
```

当前只接受 FRA 的国家选择；贸易节点键必须是非空、有限长度的 ASCII 标识符。参数
对象必须为空。查询不存在的节点返回字段级
`{"status":"unknown","reason":"NODE_NOT_FOUND"}`，不会把不存在解释成零。

## 数值和结果形状

收入字段保留原生有符号整数，不在接口层换成浮点数：

| 属性 | 含义 |
| --- | --- |
| `value`、`raw` | 本次对象的原始收入整数；两者当前相同 |
| `raw_hex` | `raw` 的四字节小端表示 |
| `unit` | `ducats` |
| `scale` | `1000`，因此可读金额为 `raw / 1000` ducats |
| `period` | `month` |
| `basis` | `native_trade_node_country_income_cache` |
| `complete` | `false`，表示当前有界合同仍不完整 |

`collection` 是同一份父 capture 中的原生聚合资格投影，不是收入数值。其结果使用
`unit="state"`、`scale=1` 和 `period="current"`：

```json
{
  "status": "known",
  "value": ["champagne"],
  "unit": "state",
  "scale": 1,
  "period": "current",
  "basis": "native_trade_node_collection_predicate",
  "value_origin": "derived_from_copied_native_flags",
  "complete": false
}
```

这是国家对象的形状；贸易节点对象的 `value` 是布尔值，例如 `champagne` 为
`true`、`rheinland` 为 `false`，其余键相同。`champagne` 节点的实际字段形状为：

```json
{
  "status": "known",
  "value": true,
  "unit": "state",
  "scale": 1,
  "period": "current",
  "basis": "native_trade_node_collection_predicate",
  "value_origin": "derived_from_copied_native_flags",
  "complete": false
}
```

上面的 `champagne` 列表和节点布尔值
来自归档的独立原始参考，见[collection source 002](../../../work/runtime/information-trade-merchant-state-20261027-001/merchant-state-source-002.json)和[collection参考](../../../work/runtime/information-trade-merchant-state-20261027-001/expected-trade-collection-001.json)；它不是把收入数值或零值重新解释成资格。

### `merchant_task` 字段

国家对象的 `merchant_task` 使用 `state` 作为单位，`scale=1`，`period=current`。它只
返回活动任务行，并保留原生节点顺序。当前 FRA 的参考结果为：

```json
{
  "status": "known",
  "value": [
    {"node_id": "rheinland", "task": "transfer"},
    {"node_id": "champagne", "task": "collect"}
  ],
  "unit": "state",
  "scale": 1,
  "period": "current",
  "basis": "native_trade_node_merchant_presence_and_collection_predicate",
  "value_origin": "derived_from_copied_native_flags",
  "complete": false
}
```

贸易节点对象的 `value` 是三个枚举值之一：`none`、`collect` 或 `transfer`。例如，
`champagne` 返回 `collect`，`rheinland` 返回 `transfer`；如果节点的 `has_trader`
标志为零，则返回 `none`。节点结果保留相同的 `unit`、`scale`、`period`、`basis`、
`value_origin` 和 `complete` 字段。

上面的任务列表来自[48批独立原始参考](../../../work/runtime/information-trade-merchant-task-20261027-001/expected-trade-merchant-task-001.json)，用于固定字段形状、原生顺序和参考计算结果；它不替代新的实机验收或完整测试统计。

收入字段的国家结果 `value` 是 `trade_income.total_raw`。节点结果的 `value` 是匹配节点的
`income_raw`，并同时保留 `cache_income_raw`、`eligible` 以及可用的原生标志。节点
贡献可以为负数或零。

三个数值概念必须分开理解：

* `cache_income_raw` 是从原生节点条目复制出的缓存值；
* `eligible` 是原生资格谓词的结果；
* `income_raw` 是公开的节点贡献：资格通过时等于缓存值，不通过时按原生投影为零。

所以“资格不通过且贡献为零”与“资格通过但缓存本来就是零”都可以是已知结果；两者
不会互相伪装。缓存缺失、会话守卫失败或节点不存在也不会用零填充。

当前独立原始采样中，FRA 国家合计为 `3813`，即每月 `3.813` 金币。
`champagne` 贡献全部 `3813`；`rheinland` 的缓存值为0、`eligible=false`，贡献也为0。
其余节点贡献均为0。`collection=false` 只表示通过身份、上下文和条目守卫后的原生
聚合资格谓词为假，不能单独据此判断商人任务、转移方向或 steering 方向，也不能把
`false` 当成 `none`。`merchant_task` 另外读取 `entry+0xae` 的 `has_trader` 标志：
`AE=0` 时即使 `collection` 为真也返回 `none`；`AE` 非零且资格为真时返回 `collect`，
资格为假时返回 `transfer`。因此，一个节点可以具备收集资格但没有活动商人任务。
公开收入贡献按同一资格谓词计算，原始收入缓存仍单独保留。

这项投影不覆盖完整的 `transit`/`idle` 商人生命周期，也不把任务枚举解释成转移方向。
独立的 `transfer` 字段和 `steering_direction` 仍未接入公开接口。

`has_trader` 的键绑定来自[修正后的序列化来源报告](../../../work/runtime/information-trade-merchant-task-20261027-001/merchant-serialization-source-002.json)。该报告撤回了旧报告中“没有写回 entry 或调用 parser，因此不能是 serializer”的负面推理：序列化器可以读取 entry 后写外部输出。这个静态键名证据只说明 `AE` 的 `has_trader` 绑定，不证明缓存刷新时机或完整的界面任务语义；旧记录仍保留在[序列化来源001](../../../work/runtime/information-trade-merchant-task-20261027-001/merchant-serialization-source-001.json)。

## 节点键和显示名称

节点选择使用内部定义的 ASCII 键，例如 `champagne`。调用时请使用这个键；
中文显示名称可以通过已有的 `T01.name` 接口另行读取。

## 报告和周期读取

同一份查询可以通过现有 `information_manage_report` 保存为报告。例如报告配置只需
把上面的 `queries` 放入：

```json
{
  "request_id": "trade-income-report-create-001",
  "operation": "create",
  "config": {
    "name": "FRA trade income",
    "queries": [{
      "topic": "T05",
      "object": {"type": "trade_node", "node_id": "champagne"},
      "fields": ["income"],
      "parameters": {}
    }],
    "detail": "raw"
  }
}
```

用返回的 `report_id` 调用 `information_query` 时传 `report_id`，即可复用完整报告
配置，不必重复提交查询集合。T05 当前声明 `query` 和 `periodic`，因此可以用现有
`information_manage_subscription` 为该报告创建定期订阅：订阅类型设为 `periodic`，
并提供已验证会话绑定和例如 `{"basis":"real","every":2,"unit":"seconds","missed":"coalesce"}`
的 schedule。调度器随后沿用同一报告和同一来源；`information_tick` 只运行到期读取，
不会推进游戏日期，也不会执行业务动作。T05 不声明 `event` 或 `change`，不能用这两
种触发器订阅。

周期读取仍是重复读取已有原生缓存。适配器不主动刷新或重算该缓存，所以目录和每次
结果保持 `coverage="partial"`、`complete=false`；已知字段可以同时带有这个完整性
边界。会话、日期、文件守卫或缓存记录不通过时，字段保留具体的 `unknown` 或
`unavailable` 原因，不沿用旧值。

## 未覆盖字段和边界

当前 T05 适配器公开 `income`、`collection` 和 `merchant_task`。独立的 `transfer`
字段和 `steering_direction` 仍为 `unsupported`，不会从收入缓存、节点名称或零值推断。
`merchant_task` 中的 `transfer` 只是任务枚举，不等于独立的 `transfer` 字段；完整的
`transit`/`idle` 生命周期仍未覆盖。未知节点使用 `NODE_NOT_FOUND`，与不支持字段分开
处理；缺失节点也不会投影为 `collection=false`。

本接口只做只读观察：不保存或载入游戏、不重启进程、不换 DLL、不推进日期、不执行外交
或其他业务动作。当前结果也不声称等于界面完整预算；动态预算预测、收集方向、独立的
转移字段和 steering 方向需要后续独立来源。`merchant_task` 目前只提供上述原生标志与
收集资格的组合投影，不代表完整的商人生命周期。
