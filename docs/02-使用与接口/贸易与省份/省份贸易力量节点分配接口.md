# 省份贸易力量的节点分配

第205批在 `T06.targets` 的 `rows[].current_trade_power.node_allocation` 中加入已加载节点身份、当前省份的直接分配量，以及 FRA 的省份来源合计核对。它复用[当前力量及重算](当前省份贸易力量重算接口.md)，不把当前贸易力量直接当作征服收益。

候选页仍来自有效磁盘节点定义；新注释单独读取游戏中已加载的节点和成员列表。LLM 可以比较候选页的节点编号与注释的 `node_id`。两者不一致时，不能将磁盘候选归属当作当前游戏事实。

## 结果含义

已知注释给出以下信息，比例尺均为1000，金额单位为 `trade_power`：

| 属性 | 含义 |
| --- | --- |
| `node_id`、`center_province_id` | 已加载节点编号及其规范中心省份；被查询省份不必是中心 |
| `province_id`、`recipient_country` | 当前省份与原生累加选择的控制国 |
| `contribution_raw` | 按当前缓存和所有者存在条件重建的该省份直接来源量 |
| `observer_country`、`observer_contribution_raw` | 观察国固定为非玩家FRA；控制国不是FRA时，对FRA的直接贡献为0 |
| `observer_node_province_power_cache_raw` | 当前节点FRA条目的 `TP_PROVINCE_POWER` 缓存 |
| `observed_observer_province_power_sum_raw` | 在本次正位发现且身份可判定的成员中，FRA直接省份力量的有符号32位合计 |
| `observer_sum_complete` | 本次是否能判定完整已加载成员集合中的相关贡献；不是整项贸易收益已经完成 |
| `matches_observer_cache` | 完整合计是否等于上述缓存；成员不可判定时为 `null`，不补为真或假 |
| `member_count`、`observed_member_count` | 已加载成员总数与本次可观察、贡献可判定的成员数 |
| `owner_present` | 原生所有者引用的高字节是否非零；不额外宣称这是完整的所有者有效性检查 |

`complete=false`、`cache_refresh_timing_verified=false`、`atomic_game_snapshot=false` 和 `acquisition_delta_evaluated=false` 保留。合计与缓存不同可以返回已知的两个数值和 `matches_observer_cache=false`；这个差异需要继续调查刷新条件，不能通过改写缓存或推进日期消除。

## 原生依据与可知范围

仅支持EU4 1.37.4 B23，EXE SHA-256为 `b23fa0e1f698d31b01cdd1c3817a675805d8c6286cb66f9c231e6e2a42544d77`。新的有界普通反汇编确认：节点更新函数从运行时节点 `+0xa8` 定义的 `+0x68/+0x70` 遍历省份指针，读取省份 `+0x470` 控制国编号；所有者引用高字节 `+0x46f` 非零时，将省份 `+0x890` 数值加到控制国条目 `+0x28`。该位置与既有节点来源明细的 `TP_PROVINCE_POWER` 一致，不能与最终国家 `country_power` 混为一项。

调度片段先逐节点执行清理，再逐节点执行累加；条目清理明确将 `+0x28` 置零。静态顺序不证明当前缓存刚刚刷新，也没有覆盖所有可能的更新入口。函数、地址范围、字节及证据类别见[本批原生合同](../../../work/runtime/information-province-node-allocation-20261106-205-001/native-node-allocation-contract-001.json)，没有把普通反汇编记作成功REA分析或实际执行。

节点身份复用既有 `trade_value_memory.find_node` 的管理器定义、键和中心反向引用检查。被查询省份另须出现在该定义的实际成员向量中，且规范记录、ID和运行时节点指针一致；不会将任意成员错误地要求为节点中心。

只读取FRA的节点国家行，并检查节点国家条目数量及FRA编号界限。其它成员先检查FRA发现位，未发现时不读取其控制者、所有者或力量。未发现或引用代次不可判定的成员使合计不完整。所选省份的FRA非玩家角色、国家准入、发现和规范身份在扩展前后复核；扩展与原采集合计仍为512 KiB，不新增完整国家扫描，不调用游戏函数。

## 验证与剩余范围

第205批实机仍为会话 `37508-1dd6d9d6c2ae4b3`、1456.7.26、暂停。巴黎183确属香槟节点，中心为186，直接贡献17.520给FRA；该节点33个成员全部可判定，FRA合计64.672与原生来源缓存相符。里斯本227确属塞维利亚节点，中心为1293，当前控制国为POR，对FRA的直接贡献为0；53个成员中51个可判定，另2个未发现，因此合计完整性为假，比较结果为 `null`。没有为补全合计而读取那两个省份的归属或力量。

塞维利亚中心1293是已发现、没有普通控制国引用的成员；按原生所有者引用高字节为零的条件，可明确排除其贡献。初版读取器将它保留为不明，现已修正为已知零；两个真正未发现成员仍保留缺项。活动profile为 `province-node-allocation-memory-1374-v3.json`，哈希及修正证据由批次汇总记录。初版新增守卫缺少范围结束字段的格式错误与v2修正前源码、采集均保留。

实机采集、独立原始字节复核、严格回放负例及查询／报告／订阅结果以[批次汇总](../../../work/runtime/information-province-node-allocation-20261106-205-001/summary.json)为准。合成测试分别覆盖非中心成员、缺失或重复成员、引用变化、未发现成员、零贡献、合计回绕和缓存不匹配；这些测试不冒称游戏中发生了同样的事件。

本项导出当前的直接省份来源，尚未重建换属后的全部省份修正、最终国家竞争力和未来贸易收入。`expected_benefit` 继续未知。完整74主题397字段、阶段二至四及B01–B04继续按原计划推进，定向测试不能替代最新全范围失败基线。
