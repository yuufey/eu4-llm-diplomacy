# 已发现省份快照接口

`C02.discovered_provinces` 可以读取指定历史存档中，明确记为观察国已发现的省份 ID。它与已有核心、宣称接口共用 `SavedProvinceInterestsSnapshotV2`，由已固定版本的 Jomini / eu4save 在服务启动时解析一次。查询和手动报告使用内存中的同一份结果，不会保存、载入或操作游戏。

本文的历史来源是 `SavedProvinceDiscoverySource`，只登记这个字段。第128批已另行提供 [实时正索引发现列表及周期订阅](实时已发现省份接口.md)，两种来源分开选择。`C02.discovered_countries`、`C02.related_countries` 及完整界面可知范围仍未实现。

## 启用与查询

沿用已有 `--province-interest-save` 参数，不新增另一套解析器或状态来源：

```powershell
python tools/serve_information.py --province-interest-save "C:\Users\wangyufei\Documents\Paradox Interactive\Europa Universalis IV\save games\llm_diplomacy_interest_quote_20261101_001.eu4" --observer FRA --database work/runtime/information-discovered-provinces-20261103-119-001/example.sqlite3
```

该命令默认提供 MCP stdio。历史存档来源与 `--operator-session`、其他历史状态来源互斥，不能把存档数据混入当前游戏会话。已有 `--province-interest-parser-manifest` 可以显式指定受信的解析器 manifest。

一次性工具请求为：

```json
{
  "request_id": "saved-discovery-example",
  "queries": [{
    "topic": "C02",
    "object": {"type": "session"},
    "fields": ["discovered_provinces"],
    "parameters": {}
  }]
}
```

将这段参数传给 `information_query`。同一个查询也可以加入手动报告配置。`session` 对象只接受 `{"type":"session"}`；存档没有实时游戏会话编号。也可以使用 `{"type":"country","country":"FRA"}`，其中 FRA 必须与启动时指定的观察国一致。其他国家选择器返回 `not_applicable/OBSERVER_DISCOVERY_VIEW_ONLY`，不会读取该国的探索视角。观察国等于存档 `saved_player` 时返回 `not_applicable/NON_PLAYER_OBSERVER_REQUIRED`。

## 结果含义

| 情况或字段 | 含义 |
| --- | --- |
| `status=known`、`value=[...]` | 列出序列化 `discovered_by` 明确包含观察国的省份 ID，按数字排序 |
| `status=known`、`value=[]` | 所有已解析省份行都有明确的发现列表，而且没有一行包含观察国 |
| 没有正向成员，但存在缺失或 null 的发现列表 | 返回 `unknown/SNAPSHOT_DISCOVERY_NOT_ESTABLISHED`，不提供空集合 |
| 有正向成员，也有缺失发现列表 | 保留明确的成员，并说明遗漏记录数量 |
| `snapshot_membership_complete` | 是否每一条已解析省份行都有明确的发现列表；只描述这份存档的省份记录 |
| `omitted_unknown_discovery_records` | 发现列表缺失或 null 的省份行数量 |
| `period=saved_snapshot` | 数据属于结果中注明的保存日期 |
| `complete=false` | 整个目标仍缺实时状态及完整可知范围验证；存档行完整不等于目标完整 |

来源记录保留存档路径、大小、SHA-256、玩家标签和解析器身份。游戏 `session_id`、`world_id`、暂停状态仍为空，不伪造实时绑定。每次读取核对输入和解析器来源，前后不一致时撤回该字段并返回 `unavailable`。结果只包含观察国的省份 ID 和完整性说明，不包含核心、宣称或其他国家的发现列表。

目前目录只声明 `query`。历史上下文没有订阅要求的非空游戏会话编号，周期订阅会明确拒绝；该接口没有逐场事件或发现变化通知。

## 验证范围

第119批使用的参考来自已归档的同一份解析输出，独立遍历 4,941 条省份记录，得到 FRA 1,067 个、POR 1,074 个已发现省份。缺失或 null 的发现列表为 0；明确的空列表为 1,227 条。存档 SHA-256 为 `99345c60eac07a26ac43a3c8c1800afaa53995386cef648a32b706729bd6c8b8`，日期为 `1456.4.12`，`saved_player=POR`。参考只适用于这个保存文件，不说明当前游戏的发现状态。

独立参考位于 `work/runtime/information-discovered-provinces-20261103-119-001/saved-reference-001/`。本批接口测试、实际 MCP 结果与进程收尾证据在同批目录记录。

实际 MCP 的 session 与 FRA 查询都返回上述 1,067 个 ID，POR 选择器返回不适用；手动报告的字段和对象与查询一致。证据分别保存在 `mcp-001/direct.json` 和 `mcp-002/report-run.json`，由 `mcp-retained-audit-001.json` 对同一存档、解析器和生产源码的结果进行离线核对。

两个验收脚本原件都保留为失败状态：第一份在成功查询后，把服务补充的单位和比例元数据误判为错误；第二份完成报告后，周期探测遗漏 MCP 必填的 name/enabled，先被参数校验拒绝。因此本批没有取得“有效 MCP 周期请求因历史绑定而拒绝”的实测证据，不把这两份脚本称为全程通过。服务层的定向测试验证了空会话绑定会返回 `invalid_binding`。未为修正检查器重发成功查询，也没有第三次启动服务。

新接口与旧 G01 V1/V2 共 53 项定向测试通过，私有实时 leaf 的 9 项测试另行通过；它们不构成一次完整 bridge 回归。两个实际服务器均正常退出，读取线程及受监控的子进程均已结束。

实时研究新增的 `province_discovery_memory.py` 仍是私有 leaf。现有证据没有闭合全部省份候选域、ID 0 语义及发现位图容量；它未接入公开工厂，本批也未进行实时采集。这些缺项不能由存档结果替代。
