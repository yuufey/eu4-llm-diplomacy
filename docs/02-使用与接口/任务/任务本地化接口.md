# 任务本地化接口

M01 的 `name` 和 `description` 读取实际加载的任务对象，再按任务 ID 查询原生本地化缓存。当前已验收的运行边界是 1.37.4、FRA 观察方、只读 live 会话；字段可以逐项已知，也可以在保留动态模板的同时返回部分结果。

## 请求

任务必须属于当前国家任务容器中实际加载的子任务。国家对象只接受本国观察方，当前为 `FRA`；不能用国家标签推断另一国的任务，也不能用静态文件列表替代 live 的任务成员关系。

```json
{
  "topic": "M01",
  "object": {"type": "country", "country": "FRA"},
  "fields": ["task_id", "name", "description"],
  "parameters": {"task_id": "fra_liberate_norm"}
}
```

`task_id` 省略时，接口为捕获到的加载任务批量生成名称和说明；指定时，任务仍须先通过实际加载列表核对。原生名称键和说明键分别是 `<task_id>_title` 与 `<task_id>_desc`。这一键名规则来自原生读取证据，不能把脚本 ID 当成用户可见名称。

## 读取合同

`NativeMissionReader.localized_text` 使用当前会话明确记录的原生文本编码，通过只读缓存读取；`normalize_localization` 在发布前核对以下条件：

内部调用形状是 `localized_text(country, context, keys)`；每个有界批次先由 `normalize_localization(report, context, keys, codec)` 绑定到同一会话，再返回 `{"status":"known", "entries":..., "language":..., "provenance":...}`。这里的读取器顶层 `known` 表示捕获结构和身份完整，不表示每个键都是字面文本。

- 会话为 ready/live，观察方、会话 ID、EXE 身份和请求国家相符；
- 语言报告为 `l_*`，当前运行验收为 `l_english`；编码来自会话的 `native_text_codec`，当前为 `eu4_escape`，不从字节内容猜编码；
- 请求键是唯一 ASCII 键，每个不超过160个字符；每批最多128个键，整个调用最多8192个键；
- 原生捕获为只读、双遍结果一致，静态合同、文件代码和运行时代码守卫均通过，句柄已关闭；采集前后游戏日相同；
- 每个批次独立核对捕获报告中的身份、游戏日、守卫和清理状态，并核对该批次语言；跨批次要求语言一致。全部批次完成后，再通过一次 `base_source.context()` 整体复核会话状态、模式、会话 ID、EXE、观察方和游戏日；任一身份变化都会拒绝本次本地化结果。

值最多读取8192字节；单次 `ReadProcessMemory` 不超过65536字节，总量不超过512 KiB。本批实际原生缓存读取量为150661字节；生产读取探针 SHA-256 为 `018a38caac355e57d5eecc7b9d98aa12ffea3647ea7b488464bbcc68c31a2fd0`，本地化 profile SHA-256 为 `8052f51329598bb3baea137dd7694baba53ace7ecef970773a06cfafe0aef6cb`。读取器不调用游戏函数，不执行任务效果，也不进行动态模板替换。

## 返回结构

字段值保留任务来源和本地化来源。例如已验收的 `fra_liberate_norm` 结果包含：

```json
{
  "task_id": {
    "status": "known",
    "membership_source": "captured_loaded_task_objects",
    "value": [{
      "root_id": "french_missions_1",
      "task_id": "fra_liberate_norm",
      "branch_visibility": "unknown"
    }]
  },
  "name": {
    "status": "known",
    "complete": true,
    "value": {
      "language": "l_english",
      "resolved_count": 1,
      "unresolved_count": 0,
      "resolution_complete": true,
      "dynamic_substitution_evaluated": false,
      "entries": [{
        "status": "known",
        "text": "解放诺曼底",
        "task_id": "fra_liberate_norm",
        "localization_key": "fra_liberate_norm_title",
        "codec": "eu4_escape"
      }]
    }
  },
  "description": {
    "status": "known",
    "complete": true,
    "value": {
      "entries": [{
        "status": "known",
        "text": "诺曼底公国在法理上是法兰西王国的封邑，理应重归我等统治之下。",
        "task_id": "fra_liberate_norm",
        "localization_key": "fra_liberate_norm_desc"
      }]
    }
  }
}
```

每个文本条目还保留 `root_id`、原始字节的 `raw_template_hex`、`codec` 和来源报告中的批次信息。`text` 出现在 `status=known` 的字面文本条目或通过合同 002 限定派生的条目中；后者另有 `custom_text_derivation`，并标记 `dynamic_substitution_evaluated=false`。未通过派生守卫的动态文本保留 `template` 和 `unresolved_tokens`，不伪造最终显示值。

## 状态和部分结果

接口沿用信息服务的字段状态。要区分字段状态与字段内部的条目状态：

读取器返回的顶层 `status="known"` 只说明本次请求的键集合、身份和守卫都已完整核对；`entries` 中仍可有 `status="unknown"` 的动态或缺失条目。任务适配器再根据每个字段的已解析条目数设置 `complete`，信息服务据此生成结果层的 `partial`。

| 状态 | 含义 |
| --- | --- |
| `known` | 字面文本已按显式编码解码，或已满足合同 002 的有限派生规则；条目有 `text`，派生条目还带 `custom_text_derivation`。字段的 `complete` 仍可能为 `false`，表示同一字段中还有未解析条目。 |
| `unknown` | 键不存在、动态替换未解析，或条目只保留了未知原因；动态模板可保留 `template`，不提供 `text`。 |
| `unavailable` | 会话、身份、守卫、清理或读取失败，无法把本次捕获绑定到当前上下文。 |
| `partial` | 服务结果层的状态：至少有一个字段已知，但一个或多个字段或条目未完整解析。任务项会有 `complete=false`；周期结果的顶层状态随之为 `partial`。 |

因此，含 `task_id` 和一个字面名称、但说明含仍未支持的 `[Root.GetAdjective]` 的结果，可以让 `name.status=known` 且 `name.complete=true`，让 `description.status=known` 且 `description.complete=false`，同时把该动态条目标为 `unknown`；调用者应检查条目状态和 `complete`，不能只看字段外层的 `known`。当前三次两秒现实周期都保持相同的逐项内容，并按这个语义交付。

## 第七批有限动态派生（合同 002）

第七批在读取原生本地化缓存之后增加了一个受限的派生步骤。它不是通用动态本地化求值器，也不调用游戏函数或选择器；它只把已经捕获、已经通过结构守卫的单项自定义方法结果与本地化缓存中的字面值拼接起来。规则合同见[动态本地化合同 002](../../../work/runtime/information-dynamic-text-20261024-001/dynamic-localization-contract-002.json)，该文件 SHA-256 为 `ea13b783902b9a5410aa808ae7956e03732fe57376383cd0d4ea094ac9f1a5f7`。

可派生的方法只有 `GetSelectableMissionTitle` 和 `GetSelectableMissionDescription`。原条目必须是 `status=unknown`、原因是 `DYNAMIC_LOCALIZATION_UNRESOLVED`，模板中恰好出现一次对应的 `[Root.<方法>]` 标记；标记前后的字面内容逐字符保留，包括前导 ASCII 空格和 `§` 格式控制。模板或前后缀中若再出现其他 `[]`、`$` 标记，两个受支持标记同时出现，标记重复、括号不平衡或模板超出 8192 个字符，都继续返回 `unknown`；模板和选中缓存拼接后的 UTF-8 字节数还必须不超过 32768。

自定义方法只有在运行时捕获证明它是唯一一个候选、谓词数为零、修正向量为空、权重是小于 `2^31` 的正整数、内建名称缺失且 Root promotion 为枚举 `3` 时才可使用。查询 Root 明确绑定到 FRA 观察方；这不等于已证明游戏界面自己的 Root，`ui_root_scope_verified=false`。缓存条目必须是已知字面值、具有显式 codec 且与模板条目的 codec 一致，不含 NUL 或未解析标记。成功条目保留原始 `template`、`raw_template_hex` 和 `codec`，并写入 `custom_text_derivation`、`literal_prefix`、`literal_suffix` 以及 `dynamic_substitution_evaluated=false`；没有调用原生函数，不能据此声称完成了 UI 求值。其他国家、省份或一般动态占位符仍保持未知。

第七批 `live-acceptance-003` 已按独立逐字段期望通过：61 个任务、122 个键中有 14 个派生、116 个已知、6 个未解析；名称字段为 `status=known`、60 个已知和 1 个未知，说明字段为 `status=known`、56 个已知和 5 个未知，两个字段容器都保持 `complete=false`，顶层结果为 `partial`。主动逐项、单项读取和三次两秒周期均交付，POR 玩家槽189、FRA 观察方、暂停日期与 raw 游戏日保持不变。详见[003报告](../../../work/runtime/information-dynamic-text-20261024-001/live-acceptance-003/report.json)和[003手工结果](../../../work/runtime/information-dynamic-text-20261024-001/live-acceptance-003/manual-result.json)；此次使用的自定义方法捕获 SHA-256 为 `b0608f11ba54c174dcb742bfeddbcfd77ddbc671802d27be834d786cd28c1e8f`，原生缓存 SHA-256 为 `985d1b5b8bb839d6295f91e7b19f8ad369ca278a651164d4ed8f27b5b06ca3c1`。002 中自动分项期望曾写错而报告失败，生产结果与 002 相同；该历史失败不覆盖 003 的通过报告。

## 来源、编码和未证明事项

第七批静态、运行与条件派生的总索引见[research-index-002](../../../work/runtime/information-dynamic-text-20261024-001/research-index-002.json)；旧 `research-index.json` 保留为未接入状态的历史索引。

第六批实际运行捕获覆盖18个任务根、61个任务和122个本地化键：102个字面值已知，20个动态或未解析值保持未知。`native-runtime-001` 的双遍捕获一致且句柄关闭；其原始缓存指纹、会话身份和守卫结果见机器报告。静态索引以显式 `l_english` 与 `eu4_escape_cp1252` 读取，随后与保留的原生 `eu4_escape` 缓存逐键交叉核对，122个键的字节和解码文本均一致。该交叉核对只说明当前样本，不证明一般的引擎合并优先级或所有语言配置。

原生查找的语义是 `native_FNV1_hash_only`：接口没有扫描完整本地化表，也没有证明不存在哈希碰撞，因此 `literal_key_collision_excluded=false`。除合同 002 明确允许的两个单项 Root 标记外，其他动态 token 不求值；任务分支可见性、完整 trigger、世界代际、主线程原子快照以及动态替换后的最终界面均未证明。任务成员读取与本地化读取跨批次也不构成一个游戏主线程原子快照。

证据分为原生、普通静态和运行验收三层，不能互相替代。原生与周期验收见[原生运行报告](../../../work/runtime/information-localization-20261024-001/native-runtime-001/report.json)和[本地化 live 验收报告](../../../work/runtime/information-localization-20261024-001/live-acceptance-001/report.json)；静态缓存逐键核对见[交叉核对报告](../../../work/runtime/information-localization-20261024-001/static-cache-crosscheck.json)，动态来源范围见[动态本地化调查](../../../work/runtime/information-localization-20261024-001/dynamic-localization-source-review.json)，文件来源清单见[静态来源报告](../../../work/runtime/information-loaded-tasks-20261024-001/localization-source-review.json)。REA 标签 `16faf60`、`16faa10`、`6f7cc0` 与普通分析 `14b33a0` 分别保留各自证据类型，不把静态命中提升为运行时求值。
