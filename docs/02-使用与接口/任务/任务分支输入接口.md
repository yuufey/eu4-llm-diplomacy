# 任务分支的实时输入

启用现有 `--mission-game-data` 后，实时 M02 `unlock_conditions` 会按需读取四个法国国家旗标、地图模式和 Domination 条件的原生输入，并放在 `captured_inputs` 中。这个入口与主动查询、周期报告共用；查询其他任务字段时不额外读取分支输入。当前只支持绑定的 FRA 观察方和固定 1.37.4 EXE。

`country_flags` 每个值都有 `status/value`，`map_setup` 给出原始枚举及名称。`dlc_loaded` 只在已证明的原生短路路径上给出 `{"Domination": true}`，并标明 `scope=Domination_condition_only`、`complete_inventory=false`；其他组合保持未知。外层 `evaluated=false` 继续保留；输入已取得不代表引擎分支可见性已求值。日期或身份不一致时，`captured_inputs` 不可用；单项读取失败保留对应缺项，同一请求中的任务规则和完成记录仍保留。

实际 MCP 结果见 [prerequisite-acceptance-003/report.json](../../../work/runtime/information-branches-20261024-001/prerequisite-acceptance-003/report.json)：Domination 条件为真，地图模式为 `normal/raw0`，以下四个旗标均为 `false`：

- `fra_shed_the_blood_of_the_saxon_man_flag`
- `fra_fufujoni_flag`
- `fra_chose_to_piss_off_pope_flag`
- `fra_papal_lap_dop_flag`

其他国家旗标名称不输出。当前来源检查完整的有界旗标 ID/名称序列后才判断目标是否存在；不能把读失败当作旗标未设置。

## 原生合同与限制

EXE SHA-256 为 `b23fa0e1f698d31b01cdd1c3817a675805d8c6286cb66f9c231e6e2a42544d77`，静态基址 `0x140000000`。以下代码地址为 RVA，读取时加实际模块基址。

| 输入 | 普通静态证据 | 运行时检查 |
| --- | --- | --- |
| 国家旗标 | 国家 `+0x270` 嵌入对象，`+0x280/+0x288` 为 begin/end；元素为 int16 ID；名字表指针位于 RVA `0x2357d60`，String32 项步长 `0x20` | 对象虚表 RVA `0x1c57520`，`+8/+0x10` 分别指向 `0xd2f280/0x737ce0`；检查跨度、符号、指针和完整名称解析 |
| 地图模式 | 叶函数 RVA `0xd15590` 从 `[module+0x233fe58] -> +0x2150 -> +0x34 DWORD` 读取模式；枚举 0/1/2/3 对应 normal/historical/random/custom | 固定文件与内存指令字节，拒绝未知枚举与坏指针 |
| Domination 条件 | REA `0xcc5a10` 确认名称映射至位 `0x80000`，`0xcc5fb0` 调用普通静态 helper `0xcfc70`；全局字节 `0x233ff6c` 非零且覆盖字节 `0x233feb6` 为零时直接返回真 | 核对指定谓词、分支与 helper 字节；两字节参加双遍比较，不读取 TLS，不从其他组合推导假 |

生产配置为 `bridge/information/profiles/mission-branch-memory-1374.json`，包含机器计算的来源 SHA 与代码字节，读取不依赖本机研究报告存在。普通静态报告为本批 `country-flag-contract.json`、`map-setup-trigger-contract.json` 及 DLC helper 字节；Domination 的两份 REA Evidence 与普通 helper 的关系集中在 `domination-short-circuit-contract.json`。各类证据与独立 RPM 观察分别记录，详见[引擎路径](../../04-实现研究/任务/任务分支引擎路径.md)。

读取器核对安装会话、EXE、进程创建时间和模块路径，以 `QUERY_INFORMATION|VM_READ` 打开句柄。单次总 RPM 上限 512 KiB，前后两遍比较日期、国家身份、指针、旗标 ID/名称、模式及 DLC 两字节；句柄关闭失败也会撤回顶层输入结论。最终独立观察 [branch-inputs-runtime-003.json](../../../work/runtime/information-branches-20261024-001/branch-inputs-runtime-003.json) 使用 10,620 字节，双遍一致、字节为 `01/00`，句柄关闭成功。第一次 DLC 读取的地址对齐失败保留在 `branch-inputs-runtime-002.json`，没有改写为成功。

名字表长度尚未独立证明，来源保留 `table_length_known=false`；ID 和每次读取仍有上限。分支输入与任务槽位是同进程、同日期的顺序快照，不是主线程原子快照，世界代际仍未证明。保存来源不把 `dlc_enabled`、保存旗标或配置提升为实时输入。
