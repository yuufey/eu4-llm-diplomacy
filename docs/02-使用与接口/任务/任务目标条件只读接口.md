# M03 任务目标条件只读接口

M03 的 `provinces`、`regions`、`countries`、`ownership`、`control`、`cores` 和 `subjects` 字段，按法国（FRA）任务来源中选定任务的 `trigger` 树，列出静态规则引用。v1 只识别固定 CWT 规则声明的直接字面形式；v2 在保留这些引用的同时，增加经地图索引核实的作用域块名和少量有明确 CWT `scope[...]` 声明的符号条件。两版都只读取脚本结构，不求值游戏条件，也不表示当前任务分支已显示、条件已满足或目标集合已经完整。

## 查询范围

查询对象必须是来源中的国家。实时任务来源先使用 FRA 当前捕获的任务槽根；如果读取器还取得已加载子任务成员，投影只处理这些根与任务 ID 的交集。`parameters.root_id` 和 `parameters.task_id` 可以进一步缩小范围。没有已加载任务成员证据时，来源会标明它使用所选根的当前定义，不能据此断言该任务当时已加载。历史存档同样只使用它实际提供的根与定义证据。

```json
{
  "request_id": "m03-fra-liberate-norm-example-001",
  "queries": [{
    "topic": "M03",
    "object": {"type": "country", "country": "FRA"},
    "fields": ["provinces", "regions", "countries", "ownership", "control", "cores", "subjects"],
    "parameters": {"root_id": "french_missions_1", "task_id": "fra_liberate_norm"}
  }]
}
```

`--mission-game-data` 启用任务定义读取，并默认使用配置好的 CWTools CLI。运维者可用 `--mission-parser-manifest` 指定受信 parser manifest；该参数必须与 `--mission-game-data` 一起使用。当前 manifest 位于 [`tools/dotnet/cwtools-script/adapter-manifest.json`](../../../tools/dotnet/cwtools-script/adapter-manifest.json)。例如：

```powershell
python tools/serve_information.py `
  --operator-session work/runtime/<installation>/installation.json `
  --observer FRA --mission-game-data `
  --mission-parser-manifest tools/dotnet/cwtools-script/adapter-manifest.json
```

`MissionDefinitionIndex` 仍负责按当前安装版本和已启用模组选择有效文件、确定覆盖顺序；CWTools CLI 负责这些文件的脚本结构解析，不求值游戏条件。若省略 manifest 参数，服务使用默认 CLI 配置。

CLI 调用 CWTools 0.6.0-alpha 的脚本解析器，并保留重复节点、运算符、裸值和源位置。CWTools 将某些 `command { ... }` 写法返回为相邻的裸名称与裸代码块；`CwtoolsScriptParser` 会按相邻关系把它们归一为一个 AST 块，并在节点上记录这一归一化。Windows-1252 输入的 C1 字节槽会保留为结构文本中的对应码点，不会被替换或丢弃；这只保证语法结构读取，不把这些字节解释成玩家可见文本。

## v1：可分类的直接字面规则子集

v1 投影器只接受下列固定 CWTools 规则中直接标量 `=` 形式。这是已实现字面规则的子集，不是对所有任务条件的解析。投影器依据 CWT 声明类型区分省份 ID、国家标签、叛军类型、区域名和地区名；不会把 `area` 或 `region` 展开成省份列表。

| 字面条件形式 | 可分类字段 | 引用类型 |
| --- | --- | --- |
| `owns`、`controls`、`subject_owns`；`owns_core_province`；`is_core`、`is_territorial_core` 的省份 ID 形式；`area` 的省份 ID 形式 | `provinces`；按规则还会归入 `ownership`、`control`、`subjects` 或 `cores` | `province_id` |
| `owned_by`；`is_core`、`is_territorial_core` 的国家标签形式；`tag`、`is_subject_of`、`owned_by_subject_of`；`controlled_by` 的国家标签形式；`country_or_*_holds` | `countries`；按规则还会归入 `ownership`、`control`、`cores` 或 `subjects` | `country_tag` |
| `controlled_by` 的叛军类型形式 | `control` | `rebel_type` |
| `area` 的命名区域形式；`region` | `regions` | 分别为 `area`、`region` |

具体字段归类会随命令语义保留。例如，`owns_core_province = 42` 同时列在省份、所有权和核心规则中；`is_core = FRA` 是国家标签形式，不会被转换为省份列表。返回记录带命令、原始字面值、字段归类、引用类型、AST 路径、任务 ID、来源文件 SHA-256 与行号；`trigger_contexts` 保存相应完整条件树，记录通过上下文 ID 和路径引用它。`NOT`、`OR`、`AND` 等祖先也会保留，但投影器不会判断这些条件是否必需。

在 v1 中，`ROOT`、`FROM` 等动态符号不会被解析成国家或省份。非标量、非直接 `=` 形式、无法按固定类型分类的值及超出预算的输入会作为 gap 记录；同一字段可同时包含已分类引用与未解决 gap。

## v2：地图作用域头与动态符号

v2 在同一组任务 AST 上增加两类记录。输出记录的公共 `kind` 保持为 `literal_reference`、`scope_head_reference` 或 `symbolic_condition_reference`：后两类分别记录地图定义中的静态作用域名称，以及 CWT 明确声明为作用域参数的动态符号。

作用域块名只有在批量地图索引以该原文名称返回 `known`，并且该块位于可识别的 trigger、逻辑、条件或已知作用域路径中时，才会作为 `scope_head_reference`。数字块名不会仅凭数字外形变成省份，国家标签也不会仅凭大写外形变成国家。处于数量、权重或其它不透明参数结构中的候选只记 gap。

记录保留原始 `literal_value`。`static_scope.kind` 使用稳定的规范名称，`index_kind` 保留索引原始类别；`value` 与 `members` 来自已验证的静态定义。例如，省份作用域的 `members` 是对应省份 ID，命名区域或地区的 `members` 是配置中的省份 ID 列表，国家标签没有省份成员列表时 `members` 为 `null`。这些成员说明地图配置如何定义名称，不表示任务中的实际目标、控制权或国家当前存活状态。

只有固定 `triggers.cwt` 中存在相应 `scope[...]` 重载、且命令能对应到 M03 关系字段时，v2 才会输出 `symbolic_condition_reference`。这类记录使用 `symbolic_value` 保存 `ROOT`、`FROM` 等原文，并将 `target_resolution` 保持为 `unknown`；不会把 `ROOT` 推成 FRA，也不会给它补入国家或省份 ID。作用域索引的总体 `complete=false` 不会抹掉逐项已知的地图定义；相反，某个具体名称查找未知时，v1 已识别的字面引用仍保留，但该引用的地图解析会标为 `unknown`。

## 状态与边界

公共字段为 `known` 只表示至少取得了一条可分类记录；记录可以是 v1 字面引用，也可以是 v2 作用域头或动态符号。即使为 `known`，`complete=false`、`evaluated=false`、`scope_targets_resolved=false` 和 `full_target_set_resolved=false` 仍成立；`known` 不代表完整目标清单。没有任何可分类记录时字段为 `unknown`，不会返回假定的空目标集合。来源缺失或固定 CWT 规则 pin 不匹配时，字段不可用；地图索引不可用时，已识别的 v1 字面引用仍可报告，但不会附加地图成员。

这组字段读取 `trigger` 中的条件，不从 `provinces_to_highlight`、任务奖励或 `effect` 推导目标。脚本条件的存在也不证明分支已加载、已显示或已满足。即便某条引用出现在 `NOT` 或 `OR` 子树中，接口仍只报告它在 AST 中的位置，不判断它对目标是否必要。

投影器消费的 `triggers.cwt` 固定为仓库 vendored CWTools EU4 配置 commit `a85622d368bbb7afca938ed70fdd5eda44aec769`，文件大小 222281 字节，SHA-256 `3aa0f3382ea56ca759e4d3ac0dacd79627699b486bd4ac0f6d716e377f7b2f84`。v2 还单独固定 `scope_links.cwt`（55779 字节，SHA-256 `edf81dcb3b77ae270d2dcc77c44cbbe28715e8bb16e1ff8a91ffe9d92bfdc06a`）；这些文件 pin 和实际 alias 行会随结果记录。它们只支撑已选规则的分类，不是完整 CWT schema 校验，也不验证引擎运行时语义。实现见 [`mission_target_rules.py`](../../../bridge/information/mission_target_rules.py)、[`mission_target_rules_v2.py`](../../../bridge/information/mission_target_rules_v2.py)、[`mission_scope_index.py`](../../../bridge/information/mission_scope_index.py)，source 适配见 [`missions.py`](../../../bridge/information/missions.py)，脚本解析见 [`cwtools_script.py`](../../../bridge/information/cwtools_script.py)。

## 第107批实际验证

CWTools 已解析当前安装及启用模组覆盖后的全部 228 个有效任务文件，共 6360384 字节、1422 个根、4813 个任务。与旧索引逐项比较，根集合与顺序、各根任务 ID 顺序、前置任务规则的结构和值均一致；新增行列和原始拼写元数据不参与这项语义比较。15 个解析批次中首批复用已保存的实际 CLI 输出，其余 14 批实际运行。原始位置比较器误报及其它失败原件均保留。

实际 live MCP 使用 R76、非玩家 FRA、物理 POR，日期保持 raw 56556984。当前捕获的 61 个已加载任务均能对应有效静态定义。`regions` 返回 12 条引用，`countries`、`ownership`、`subjects` 各返回 14 条引用；同一条件可归入多个字段，数量不能相加作为目标总数。`provinces`、`cores` 未取得所支持的字面形式，`control` 尚有动态作用域引用，三项保持 unknown。这些 unknown 不表示任务没有对应要求。

同一服务的七字段手动报告与直接查询一致；2 秒区域引用、5 秒国家引用各送达一次，随后两订阅取消，服务 exit0、reader 停止。durable outbox 的 delivered 不表示 LLM 已阅读。前后会话、日期及六项选定输入 pin 一致；选定 MCP 进程聚合 PeakPagefile 为 570667008 字节，0.5 秒采样、1e9 字节停止线，未触限。MCP 启动时的短命 .NET 子进程没有逐个监控；独立全索引验证分别监控了实际子进程，不把独立峰值外推到 MCP。

初次 live 查询因投影器不接受新加入的合法 C1 编码列表而全部 unknown，原结果保留。修复只允许 `c1_byte_slots_preserved` 中最多五个唯一合法槽，不接受任意嵌套元数据；四项回归及新的实际 MCP 已验证修复。最初 Python CP1252 解码和 partial 投影状态的合同问题也分别修复并保留失败记录。

本批目标规则投影 10 项、source/adapter 19 项、partial 回归 1 项、编码回归 2 项及编码消费者回归 4 项通过。另 116 项受影响旧测试的断言均通过，但第一批执行中发生了 M03 helper 的源码同步修改，不能称这 116 项全程使用同一冻结源码。没有重跑完整 bridge；最后完整回归仍有 141 个既有失败/错误。

完整目标集合、数字省份及命名作用域头、动态作用域解析、当前条件是否满足和分支是否显示继续未完成。所有证据及限制见 [本批汇总](../../../work/runtime/information-cwtools-parser-20261102-001/summary.json)；实际接口记录位于同目录 `mcp-002/`。本批没有游戏状态修改、业务派发、日期推进、保存/重载、重启、注入或 Computer Use。
