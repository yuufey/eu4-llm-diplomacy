# 任务最外层条件变化订阅

该来源通过C04交付已观察到的任务条件真假变化，支持最外层AND条件及直接area中的ROOT省份持有条件。当前实机与修复证据见[任务通知验收记录](../../../logs/2026-11-13诺曼底任务通知与查询整合修复.md)。

## 来源与协议

最外层area内的`country_or_non_sovereign_subject_holds = ROOT`直接子条件使用schema2，完整视图增加`child_index`、`child_count`和`province_id`。公开payload提供`condition_name`与`comparison_country=ROOT`，便于按省份判断任务进展。ROOT指向逻辑FRA，物理客户端国家独立。

完整视图保留父条件的`condition_index`，省份编号区分同一条件在不同省份的结果。该省份来源的scope为`FRA_direct_root_area_ROOT_province_holding_returns`，父任务国家、名称、日期与结构校验成功后才提交。首次观察建立基线，未实际执行的省份保持未知，事件整体为partial。

condition wire2使用组合scope及显式省份能力，wire1继续支持最外层条件来源。以下配置适用于提供`native_mission_condition_observation`能力的会话。

## 事件范围

`mission_condition_changed`报告FRA任务最外层AND列表中，某个已实际求值的条件由满足变为不满足，或由不满足变为满足。整个任务仍可能不可完成，LLM可据此重新读取所选任务的M02条件进度。

来源核对任务、国家、原生列表、子条件及实际方法，并使用任务构造的FRA国家上下文。每任务最多128项条件，最多跟踪4096项任务，触达限制会产生原生断档信息。直接area内的ROOT省份持有条件沿上文v57增量，其他嵌套上下文按具体任务需求处理。

首次观察只建立基线。短路后未执行的条件保持未知，后续变化的前值日期沿用该条件上次实际观察日期。`condition_index`对应原生列表的零起始位置。列表结构变化或日期回退时重建基线并报告断档。

## 配置示例

先保存报告配置，再将返回的报告编号交给事件订阅。

```json
{
  "request_id": "root-condition-report",
  "operation": "create",
  "config": {
    "name": "任务条件变化",
    "detail": "full",
    "queries": [{
      "topic": "C04",
      "object": {"type": "session"},
      "fields": ["event_id", "event_type", "event_date", "event_objects", "event_payload", "complete"],
      "parameters": {"event_type": "mission_condition_changed"}
    }]
  }
}
```

```json
{
  "request_id": "root-condition-subscription",
  "operation": "create",
  "config": {
    "name": "任务条件变化",
    "kind": "event",
    "enabled": true,
    "report_id": "返回的报告编号",
    "event": {"types": ["mission_condition_changed"]}
  }
}
```

## 结果与日期

默认`event_payload`提供任务编号、前后真假及已识别的省份、条件名称。完整视图保留条件位置、最外层条件数、本次实际观察数、原始返回值、节点及方法信息。前后真假按原生返回值的低8位解释。

事件日期是本次原生求值的观察日期，`previous_observed_date_raw`是该条件前一次实际观察日期，两次观察之间的具体修改时刻仍未知。事件、来源和整体结果均为`complete=false`，六个C04字段可以全部为`known`。完整读取和冷重开保留同一份事件快照。

同批原生宏观通知按记录的游戏日期合并，同日期保留既有来源顺序。外交提议的原始提议先于终态交付。跨来源的同日调用先后尚无统一原生序号。
