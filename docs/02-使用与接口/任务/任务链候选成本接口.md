# 任务链候选成本接口

第190批已改进后台周期读取期间的状态与取消响应，见[信息采集与调度并发](../../03-开发与验收/信息采集与调度并发.md)。下列成本数据和四字段耗时保留第189批的实测时点。

第189批为实时 `M05.costs` 接入显式候选行动的成本预览，覆盖为 `partial`。LLM 选定当前已加载的任务后，可以提交几个候选方案，比较其中各行动在当前局势下的已知成本。任务条件、奖励声明、国库余额和兵力门槛都不会被当作实际花费。

## 输入与查询

服务启用 `--mission-game-data`，并绑定实时外交检查器。对象仍为逻辑观察国 FRA；物理玩家可为 POR。保存快照模式没有实时成本检查器，保留原任务字段。

```json
{
  "queries": [{
    "topic": "M05",
    "object": {"type": "country", "country": "FRA"},
    "fields": ["linked_targets", "basis", "reward_timing", "costs"],
    "parameters": {
      "root_id": "french_missions_1",
      "task_id": "fra_burg_succession",
      "candidate_plans": [{
        "id": "burgundy-no-cb-preview",
        "actions": [{
          "id": "declaration",
          "action_id": "declare_war",
          "recipient": "BUR",
          "parameters": {
            "casus_belli": "no_casus_belli",
            "war_goal": {"province_id": -1, "beneficiary": "FRA"},
            "call_allies": []
          }
        }]
      }]
    }
  }]
}
```

这是一组明确参数的预览示例，不表示推荐该行动。行动的 actor 来自 M05 对象，phase 固定为 `initiate`；适配器只调用 `inspect_diplomatic_action`，不持有执行接口。

`root_id`、`task_id` 仍必填。最多8个方案、全请求累计16个行动，方案输入最多64 KiB。方案 ID 不得重复，同一方案内的行动 ID 也不得重复。缺少候选方案时，原三个字段仍可查询，`costs` 返回 `MISSION_CANDIDATE_PLANS_REQUIRED`。

## 可复用的成本与边界

`declare_war` 必须给出非空的具体选择。参数复用原 `ObserverSession` 规范化器，包含宣战理由、战争目标、受益国及参战选择；空对象对应旧默认预览，不能用于候选成本。返回结果必须核对 action、双方国家、phase、当前日期、`submitted=false`，以及原检查器给出的选择已匹配标志和实际参数。单凭调用者输入的回显不能证明原生选择成功。

当前可识别的宣战成本是 `stability_loss` 和 `war_exhaustion`。每项保留整数 `amount_raw`、`scale=1000`、资源单位、精确三位小数和原生规则来源。`cost_country` 标为 `derived`，表示按宣战行动的 actor 上下文解释承担国；它不是从成本项目中复制出的国家字段。未解释的原始组合量不会被赋予资源或单位。

`cede_province` 使用原和约规范化器，必须提供精确 `peace_context`，包括当前战争 ID、`demand`/`offer` 方向和包含领土条款的完整 terms。返回必须匹配同一战争、方向、条款顺序、省份和受益国，再复用已有 P02/P05 投影。原投影未知的项目继续未知；本批没有重新运行 P05 实机正例，也不据此宣称完整未来扩张成本已完成。

字段按方案、行动分别返回。稳定度、厌战、战争分、行政点等不同单位不相加。每个方案的 `total_cost` 仍为未知，`combined_future_state_evaluated=false`：多个行动都是在当前局势下独立预览，没有把前一个行动的结果应用到后一个行动。战争持续费用、战损、未来议和和贸易或外交机会成本仍有明确缺项。

任务关联标为 `caller_selected_task`。当前任务的已加载身份经过核验，但候选行动是否满足任务目标、能否连带完成任务以及完整可行性仍未求值。原 `basis` 中的 `COSTS_NOT_EVALUATED` 描述任务链图投影本身；新增 `costs` 另行提供候选行动预览，不改变这层图分析的含义。

## 采集与订阅

`MissionAnalysisSource` 统一 M05 的参数和字段路由，复用原任务链、奖励期限投影及 CWTools 解析器。一次请求读取一份任务状态，组件共用冻结输入；定义、session、world、观察国或日期变化时撤回整次组合结果。任务快照与行动检查器不构成原子快照，返回中保留这一限制。

同一次请求中，完全相同的行动选择只检查一次，各方案仍保留自己的 ID；失败结果也不会在本次请求内重试。跨请求不缓存结果。第180批已有的单次原生任务采集范围继续保留，本批不宣称把两次原生采集优化成一次。

当前声明 `query`、`periodic`，报告使用相同读取路径。M05 尚无 partial 变化比较接口；本批撤回旧奖励期限来源继承的 `change` 声明，创建变化订阅会在读取前被拒绝。周期到期点可合并；配置2秒或5秒不表示每隔该时长一定交付一次。

## 实测

当前 EU4 1.37.4、逻辑 FRA NPC、物理 POR，会话 `6472-1dd6caf31db41bd`、日期原始值56560344（1456.8.30）。上述显式无宣战理由方案的预览返回稳定度损失7、厌战增加7，两项原始值均为7000。结果是当前所选行动的规则预览，不能当作已发生支出或完整战役成本。

正式采集只读一份任务状态、调用一次已有检查器。实际 MCP 四字段查询约10.33秒、报告约10.30秒，2秒/5秒周期结果相同；短订阅取消后长订阅仍活动，最后全部取消、服务和读取线程结束。第189批重叠采集时状态查询与取消曾等待约20秒；第190批已拆分配置锁，原数据读取耗时与事件路径仍需分别处理。

150项相关回归及后补的1项能力测试通过；完整测试集仍为 `whole_suite_passed=false`。能力修正仅改目录声明，原读取与投影方法的 AST 保持，原成功采集和交付没有重跑。游戏保持暂停；检查器调用了既有只读原生查询，没有提交外交动作、推进、保存重启、注入、采集启停或 computer use。原始结果、成本检查收据及失败记录见 `work/runtime/information-mission-costs-20261105-189-001/`。
