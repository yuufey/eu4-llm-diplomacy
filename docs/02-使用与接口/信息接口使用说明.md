本页保留服务启动、工具调用、报告与订阅管理的操作说明。当前字段、对象、版本及触发能力以实际能力发现结果为准，交付状态见[核心缺项与调整方案](../01-需求与计划/剩余核心缺项与调整方案.md)。

示例命令从项目根目录运行，示例会话值按当前连接替换。历史批次内容见[整理前原文](../05-历史记录/2026-11-07整理前/信息接口使用说明.md)。

按宏观战略用途组合已有字段，可直接使用[宏观报告配置与操作方法](宏观战略报告.md)。

`detail="brief"`的呈现范围和完整记录读取入口见[简报与完整结果](信息简报与完整结果.md)。

### 连接信息服务

在不绑定游戏观察会话时，服务仍可用于发现接口和管理离线配置。此时能力目录会明确标记来源尚未就绪，不会用样例数据填充查询结果。

```powershell
python tools/serve_information.py --database work/runtime/information-service/information.sqlite3
```

需要使用已经核对过的观察会话时，同时提供安装记录和外交日志数据库：

```powershell
python tools/serve_information.py `
  --database work/runtime/information-service/information.sqlite3 `
  --operator-session work/runtime/<installation>/installation.json `
  --observer FRA `
  --journal work/runtime/information-service/diplomacy.sqlite3 `
  --tick-seconds 2
```

如果只需要读取已经保存的历史记录，可以显式指定记录清单或归档文件：

```powershell
python tools/serve_information.py `
  --database work/runtime/information-service/information.sqlite3 `
  --recorded-manifest work/runtime/<recorded>/manifest.json
```

`--recorded-manifest` 与 `--operator-session` 互斥。没有提供这两个参数时，实时来源保持未就绪，仍可发现目录、管理配置，并使用另外启用的静态规则来源；服务不会把历史记录当成当前游戏状态。

### 本国行政、外交和军事点数

N06 `monarch_points` 使用固定 1.37.4、FRA 范围内的纯内存读取器，不需要参考国家：

```json
{
  "queries": [{
    "topic": "N06",
    "object": {"type": "country", "country": "FRA"},
    "fields": ["monarch_points"],
    "parameters": {}
  }]
}
```

本批样本返回 `{"administrative":471,"diplomatic":389,"military":152}`，单位 `monarch_points`，尺度 1。可用同一查询创建周期订阅；`change` 仍是采样比较。同一次查询也可请求 `prestige`，此时必须加 `reference_recipient`，两种来源各自保留审计。读取失败不会用历史保存回填。来源、守卫与边界见[国家点数原生来源](../04-实现研究/国家与国内/国家点数原生来源.md)。

### 本国威望与成对宗属关系

实时来源增加 N06 `prestige` 和 R02 的 `overlord`、`subject`、`subject_type`，当前核验范围为1.37.4、FRA观察方。它们复用现有只读附庸检查，查询不会提出附庸或取消关系。请求威望需要显式参考国家；威望始终属于FRA，不属于参考国家。R02只回答指定国家对，完整属国列表仍待开发。

```json
{
  "queries": [
    {
      "topic": "N06",
      "object": {"type": "country", "country": "FRA"},
      "fields": ["prestige"],
      "parameters": {"reference_recipient": "PAP"}
    },
    {
      "topic": "R02",
      "object": {"type": "country_pair", "actor": "FRA", "recipient": "ORL"},
      "fields": ["overlord", "subject", "subject_type"],
      "parameters": {}
    }
  ]
}
```

当前样本的威望为 `value=-11643, scale=1000, unit="prestige"`，即−11.643；负数和零值都是已知余额。奥尔良样本返回宗主FRA、属国ORL、类型 `appanage`。PAP样本的三个关系字段为 `not_applicable`，只说明选定的FRA/PAP国家对没有宗属关联；不能据此判断FRA没有其他属国。

两类字段支持主动查询、周期导出和采样变化检测，共用相同读取路径。只请求已实现字段时，已确认的无关联结果可以完整交付；混入R02 `permissions`等未实现字段时，已知端点保留，报告为partial。日期、会话或身份变化会拒绝该次值，读取不构成跨查询原子快照，也未证明世界代际。合同见[国家资源](国家与国内/国家资源信息接口.md)和[宗属关系](机制与宗教/宗属关系信息接口.md)。

### 任务信息来源

任务信息接口的主题、字段、对象和边界见[任务信息接口](任务/任务信息接口.md)。`--mission-game-data` 启用任务定义、任务槽位和[实际子任务对象](任务/任务实际子任务接口.md)的读取（当前接口中的 M01、M02、M04），包括[字面前置完成核对](任务/任务前置状态接口.md)和按需读取的[分支输入](任务/任务分支输入接口.md)；它不会使任务分支可见性变为已知，也不会求值完整任务 trigger 或执行、应用奖励。

实时任务读取必须同时提供已核对的 `--operator-session` 和可信宿主指定的 `--observer FRA`：

```powershell
python tools/serve_information.py `
  --operator-session work/runtime/<installation>/installation.json `
  --observer FRA --mission-game-data `
  --database work/runtime/information-service/information.sqlite3 `
  --journal work/runtime/information-service/diplomacy.sqlite3 `
  --tick-seconds 2
```

当前已核验的原生实时任务读取边界是 FRA 观察方。`--observer` 是宿主提供的观察方和控制范围约束，不能用它切换到未核验的国家；实时会话的版本、安装身份和会话身份仍须由来源上下文核对。

#### M01 名称和说明

M01 可以在实际加载任务 ID 的基础上请求名称和说明：

```json
{
  "topic": "M01",
  "object": {"type": "country", "country": "FRA"},
  "fields": ["task_id", "name", "description"],
  "parameters": {"task_id": "fra_liberate_norm"}
}
```

实时源使用原生键 `<task_id>_title` 和 `<task_id>_desc`，运行会话明确记录语言和编码；当前验收为 `l_english` 与 `eu4_escape`。选定 `fra_liberate_norm` 时，`name` 的字面文本为“解放诺曼底”，`description` 的字面文本为“诺曼底公国在法理上是法兰西王国的封邑，理应重归我等统治之下。”；条目还保留 `localization_key`、`root_id`、`task_id` 和原始缓存来源。完整字段合同见[任务本地化接口](任务/任务本地化接口.md)。

名称和说明是实时字段。`--mission-save` 仍标为 `recorded`，不会从静态文件或存档猜出当前界面文本；如果没有可绑定的实时本地化会话，字段返回 `unavailable` 或 `unknown`，已读出的任务 ID不会被伪造的文字替换。

原生模板中的两个方法 `GetSelectableMissionTitle` 和 `GetSelectableMissionDescription`，在捕获到唯一无条件正权重选项、内建同名项缺失及相应守卫通过时，可以派生为已知文本。模板须恰好含一个支持的 Root 标记，前后字面内容原样保留；混入其他动态标记继续未知。结果以 `custom_text_derivation` 说明派生依据；Root 只代表显式查询的 FRA 观察方，界面 Root 尚未证明。

未解析条目保留 `status="unknown"`、`template` 和 token，不提供 `text`；其所在字段仍可是 `status="known"`，但 `complete=false`，服务顶层据此返回 `partial`。当前61个任务的122项文字中，14项通过有限派生，合计116项已知、6项未知；名称为60项已知，说明为56项已知。三次两秒周期均按此语义交付，完整 trigger、分支可见性和一般动态求值仍未完成。

如果要从明确指定的历史存档读取任务信息，使用 `--mission-save`：

```powershell
python tools/serve_information.py --mission-game-data `
  --mission-save 'C:/path/to/test.eu4' --observer FRA `
  --database work/runtime/information-service/information.sqlite3
```

`--mission-save` 必须与 `--mission-game-data`、`--observer` 一起使用，并与 `--operator-session`、`--recorded-manifest` 互斥；`--mission-game-data` 也不能和 `--recorded-manifest` 组合，因为外交记录清单不提供任务槽位状态。存档来源按 `recorded` 处理，只支持主动查询，不提供实时的 `periodic`、`change` 或事件订阅；它没有可靠的实时 `session_id`、`world_id` 或单调游戏日，服务不会用文件修改时间或当前心跳伪造这些身份和日期。

`--observer` 由可信宿主指定决策国家，并与安装中的控制范围核对；它与游戏玩家身份分开保存。历史归档的观察方来自归档本身，不能用该选项改写。国家资源适配器已接入 N01 国库、N02 人力和 N05 可用外交官，其他字段仍保留缺项，详见[国家资源信息接口](国家与国内/国家资源信息接口.md)。

提供运行中的 `--operator-session` 并启用 `--static-game-data` 后，T01 可读取节点的当前显示名称，并支持周期订阅。`english_channel` 的名称为“英吉利海峡”；请求键就是节点 ID。查询时可把 `name` 与 `upstream`、`downstream`、`routes` 放入同一字段列表。没有实时会话时，名称保持明确未知，节点图仍可查询。动态模板尚未求值；具体示例和来源说明见[静态贸易与节点名称接口](贸易与省份/静态贸易信息接口.md)。

读取安装目录及当前启用模组的静态贸易定义时，增加 `--static-game-data`。路径缺省来自本机 `local.env`；宿主也可以用 `--static-game-root` 和 `--static-user-data` 指定。静态规则与运行会话分别校验，因此没有游戏进程时仍可查询 T01 的节点图、G04 的省份所属节点，以及 T02 的静态出口部分。它们不会提供本局实时贸易价值、港口状态或国家的贸易权转移关系。

```powershell
python tools/serve_information.py --static-game-data `
  --database work/runtime/information-service/information.sqlite3
```

同一请求可以同时包含静态和实时查询。实时来源尚未就绪时，静态条目保留成功结果，实时条目标记 `unavailable`，整份结果为部分成功；结果顶层的游戏会话仍为未就绪。静态来源的文件、版本和模组范围可在条目的 `source` 中检查，不能由静态条目成功推断游戏已经载入。

默认传输是 MCP stdio。服务从标准输入读取一行一个 JSON-RPC 消息，并把响应写到标准输出；日志写到标准错误。`--tick-seconds` 大于零且客户端完成 `notifications/initialized` 后，服务才在后台周期性调用一次 `tick()`；这个循环不推进游戏时间。关闭输入流后，服务会等待正在执行的 tick 完成，再关闭数据库。

需要在脚本中逐行调用工具时，可以使用诊断用 JSONL 入口：

```powershell
'{"tool":"information_discover","arguments":{}}' |
  python tools/serve_information.py --jsonl --database work/runtime/information-service/information.sqlite3
```

JSONL 每行都必须是 `tool` 和 `arguments` 两个字段。未知字段、未知工具和不符合 schema 的参数会返回错误对象；当前行的错误不会结束服务。

## MCP 连接顺序

stdio 使用 UTF-8 的换行分隔 JSON-RPC。客户端先发送 `initialize`，其中包括 `protocolVersion`、`capabilities` 和 `clientInfo`；服务支持 `2025-03-26` 和 `2024-11-05`。如果客户端请求了未知版本，服务会在成功响应中选择一个已支持的版本；客户端检查响应后，若不能使用该版本，应断开连接并按自身支持的版本重新连接。初始化成功后，客户端发送 `notifications/initialized`，再调用 `tools/list` 和 `tools/call`。

服务提供以下 MCP 工具：

| 工具 | 用途 |
| --- | --- |
| `information_discover` | 列出实际可用的主题、字段、对象范围、来源和触发能力 |
| `information_query` | 主动读取一次信息，或者引用报告配置读取一组信息 |
| `information_get_result` | 按结果编号读取结果和交付状态 |
| `information_manage_report` | 创建、读取、列出、修改和删除报告配置 |
| `information_manage_subscription` | 创建、读取、列出、修改、暂停、恢复和取消订阅 |
| `information_configure` | 读取、修改或清除全局配置覆盖值 |
| `information_status` | 查看服务、来源、调度、订阅和最近结果的状态 |
| `information_list_results` | 列出最近生成的结果 |
| `information_tick` | 手动运行一次到期调度和事件匹配循环 |

工具的完整 `inputSchema` 由 `tools/list` 返回。工具名称使用 `information_` 前缀，配置对象拒绝未声明的字段。工具发生业务错误时，响应仍是合法 MCP 响应，并把错误放在 `content` 中且设置 `isError=true`；协议错误（例如未知方法）使用 JSON-RPC error 对象。这样单次失败不会杀死服务进程。

## 主动查询

`information_query` 至少需要一个稳定的 `request_id`，并可选地提供查询数组或 `report_id`。每个查询包含 `topic` 和 `object`；也可以用 `fields` 指定字段、用 `parameters` 提供该主题允许的筛选参数。省略这两个可选项时，服务按主题目录展开字段并使用空参数对象。

```json
{
  "request_id": "decision-20261024-001",
  "queries": [
    {
      "topic": "C01",
      "object": {"type": "session"},
      "fields": ["game_date", "observer", "session_id"],
      "parameters": {}
    }
  ]
}
```

服务返回的结果必须保留本次请求、游戏会话、版本、观察方、对象、游戏日期、采集时间、来源和完整性。未知、不可见、不适用、暂时不可用、过期以及数值为零分别表达；来源只取得部分字段时，结果保留已取得内容并列出缺项。

## 报告配置

报告配置把多个查询和一个详细程度保存成可复用的集合：

```json
{
  "request_id": "report-create-001",
  "operation": "create",
  "config": {
    "name": "短周期局势简报",
    "queries": [
      {
        "topic": "C01",
        "object": {"type": "session"},
        "fields": ["game_date", "observer", "session_id"],
        "parameters": {}
      }
    ],
    "detail": "brief"
  }
}
```

`detail` 可取 `raw`、`brief` 或 `full`。`create` 和 `update` 都必须提交完整的 `name`、`queries` 和 `detail`；`update` 会先整体校验，再一次性替换原配置，不接受只提交部分字段。成功后服务返回稳定的 `report_id` 和递增的配置版本。修改时应发送 `expected_version`；版本不匹配时更新失败，原配置继续有效。删除正在被订阅引用的报告时，服务应返回明确错误，不会留下半生效订阅。

## 订阅配置

订阅引用报告，并声明触发方式。下面的绑定值对应一个已核对的 1.37.4 记录；实时会话必须用 `information_discover` 返回的当前身份替换它们。

```json
{
  "request_id": "subscription-create-001",
  "operation": "create",
  "config": {
    "name": "每周局势报告",
    "kind": "periodic",
    "report_id": "report-...",
    "enabled": true,
    "binding": {
      "session_id": "3228-1dd6006ee2dc2bc",
      "observer": "FRA",
      "game_version": "1.37.4"
    },
    "schedule": {
      "basis": "game",
      "every": 7,
      "unit": "days",
      "missed": "coalesce"
    }
  }
}
```

事件订阅不提供 `schedule`，而是在 `event` 中声明来源能够交付的事件类型及可选的双方筛选：

```json
{
  "request_id": "subscription-event-001",
  "operation": "create",
  "config": {
    "name": "入站外交事件",
    "kind": "event",
    "report_id": "report-...",
    "enabled": true,
    "binding": {
      "session_id": "3228-1dd6006ee2dc2bc",
      "observer": "FRA",
      "game_version": "1.37.4"
    },
    "event": {
      "types": ["diplomatic_proposal"],
      "actors": ["SAV"],
      "recipients": ["FRA"]
    }
  }
}
```

`periodic` 使用完整的 `schedule`；`change` 也使用完整的 `schedule`，其中采集方式由能力目录声明。`event` 使用完整的 `event.types`，并可按 `actors` 和 `recipients` 过滤国家标签。`binding` 缺省时使用当前来源上下文；恢复配置时服务重新核对游戏版本、观察方和会话，不能把旧会话的事件游标或对象地址带入新会话。`update` 必须提交完整的订阅配置，先整体校验后替换，不接受只更新 `name` 或其他单个字段；`pause`、`resume` 和 `cancel` 使用 `expected_version` 做并发保护。

订阅管理的 `pause`、`resume` 和 `cancel` 只改变所指定的订阅。暂停或取消一个订阅不会停止其他订阅共用的信息来源。创建订阅、到期调度、采集、结果生成和 outbox 交付是不同状态；读取 `information_status` 或 `information_list_results` 时应分别查看这些阶段。

## 全局配置与调度

`information_configure` 的 `get` 读取当前有效配置；`update` 和 `clear` 都需要当前 `expected_version`，并在事务中整体校验后生效。可覆盖项包括 `enabled` 和 `max_results_per_tick`，默认结果预算为 100。`information_tick` 只执行一次到期调度和事件匹配，不推进游戏时间；事件向多个订阅的分发作为一个整体处理，单个事件可能超过本次结果预算，未处理积压会留在数据库中。

如果来源没有提供 `world_id`，服务不能仅凭相同游戏日判断重启后仍是同一世界。重启时这类订阅会进入 `world_revalidation_required`，清除旧事件游标并等待显式恢复或完整更新；暂停期间游戏日保持不变，现实时间流逝不会额外产生游戏日周期结果。

## 参考与边界

本实现采用官方 MCP 的 JSON-RPC stdio 约定：消息以 UTF-8 换行分隔，标准输出只承载协议消息；初始化必须先协商协议版本和能力，随后由客户端发送 `notifications/initialized`。工具列表与调用格式遵循 `tools/list`、`tools/call` 和 `inputSchema` 定义。

- [MCP 2025-03-26 生命周期规范](https://modelcontextprotocol.io/specification/2025-03-26/basic/lifecycle)
- [MCP 2025-03-26 传输规范](https://modelcontextprotocol.io/specification/2025-03-26/basic/transports)
- [MCP 2025-03-26 工具规范](https://modelcontextprotocol.io/specification/2025-03-26/server/tools)

MCP 工具暴露的是信息服务能力，不是外交执行权限。现有 `DiplomacyTools` 作为来源时，信息适配器只调用已接入的查询和事件读取路径；它不会调用 `submit`、外交动作执行器或任何会推进游戏日期的接口。
