# 双向好感计划结束日期接口

第188批将 `R04.end_date` 接入默认 live 服务，覆盖为 `partial`。接口从逻辑 FRA 参与的双向具名好感修正记录中，读取固定期限模式保存的计划结束日期。它显示的是记录中的计划值，不表示游戏已经判定修正到期、比较了当前日期或移除了记录。

## 查询

请求一个包含逻辑观察国 FRA 的国家对，并选择 `end_date`：

```json
{
  "queries": [{
    "topic": "R04",
    "object": {"type": "country_pair", "actor": "FRA", "recipient": "ENG"},
    "fields": ["end_date"],
    "parameters": {}
  }]
}
```

国家对两端必须不同，且其中一端必须是 FRA。物理玩家仍可为 POR；采集器核验的是逻辑观察国 FRA，不要求把法国切换为玩家。接口支持即时查询和现实时间周期订阅；报告使用同一读取器。它可与 `opinion`、`opinion_modifiers`、`decay` 在同一聚合请求中选择。订阅不推进游戏日期。

## 结果含义

字段单位为 `game_date`，`scale` 为1，`period` 为 `current_stored_schedule`，`complete` 为 `false`。方向按请求顺序返回：`holder` 是持有该修正记录的国家，`target` 是被评价国家。每个方向保留原记录顺序和重复修正键。

当记录使用已识别的固定期限模式时，结果包含计划日期及其原始日期整数。日期文本采用现有 `engine_dates` 转换的 EU4 固定365日历。`schedule_state` 为 `stored_unverified`，`actual_removal_evaluated` 为 `false`。本批实采的两条计划日期为：

| 持有国 → 被评价国 | 修正键 | 原始计划日期 | 转换后的计划日期 |
| --- | --- | ---: | --- |
| ENG → FRA | `eng_supported_rebels_during_war_of_the_roses` | 56972136 | 1503.9.2 |
| ENG → FRA | `declared_war_on_neighbor` | 56639448 | 1465.9.10 |

当记录使用已识别的非固定期限模式时，记录返回 `status: "not_applicable"` 和原因 `RECORD_USES_NON_FIXED_DURATION_MODE`。接口不公开该模式下未使用的日期字段；这个状态也不表示修正永久有效。不能用配置中声明的 `years`、`months` 或 `yearly_decay` 替代本接口的原生记录日期。

若记录类型或模式超出已验证范围，日期投影返回 `unknown`。例如未识别的模式返回 `OPINION_END_DATE_MODE_UNSUPPORTED`；日期超出日历允许范围时返回 `OPINION_END_DATE_CALENDAR_RANGE`。一条记录未知不会撤回同一方向其他可用记录。

字段结果的核心结构如下。未列出的方向或记录元数据仍按接口原样返回：

```json
{
  "unit": "game_date",
  "scale": 1,
  "period": "current_stored_schedule",
  "complete": false,
  "partial": true,
  "basis": "native_opinion_modifier_stored_duration_schedule",
  "value_origin": "copied_record_date_and_constructor_duration_mode",
  "value": [
    {
      "holder": "ENG",
      "target": "FRA",
      "status": "known",
      "records": [
        {
          "status": "known",
          "modifier_id": "declared_war_on_neighbor",
          "scheduled_end_date_raw": 56639448,
          "scheduled_end_date": "1465.9.10",
          "calendar": "eu4_fixed_365_day",
          "raw_unit": "eu4_hour_tick",
```

本批实采的 FRA→ENG 与 ENG→FRA 共8条记录中，2条返回计划日期，另6条因使用非固定期限模式而返回 `not_applicable`。FRA→ENG 的两条记录均属后者；ENG→FRA 的玫瑰战争修正和 `declared_war_on_neighbor` 返回计划日期。

## 证据与实现边界

目标为 EU4 1.37.4，EXE SHA-256 为 `b23fa0e1f698d31b01cdd1c3817a675805d8c6286cb66f9c231e6e2a42544d77`。下列地址都是静态 image base `0x140000000` 下的 RVA；运行时 VA 应使用实际模块基址加 RVA，不能把二者混写。

REA Evidence 支持固定期限日期的创建和写入路径：

- 复用已接受的 RVA `0x384070` 路径，读取当前游戏日期并取得定义 `+0x54` 中保存的月数。
- `ev_3eb88f4cccf633951bf5801de0593b35be38e3a32eb253337e2f0f0348b8ba79` 覆盖 RVA `[0x14c7f30, 0x14c801d)`，共237字节，显示日期包装器执行 `AddMonths`。
- `ev_e85c421180a7ad30a45f685bb463cec072d303ee06475fa8252e718fb20590b0` 覆盖 RVA `[0x383f20, 0x384069)`，共329字节，连接日期与记录构造。
- `ev_892d901656d88093e9fff4746d786eb00a8e3d08274b28dc22404be666c1c6ad` 覆盖 RVA `[0x28c520, 0x28c7c8)`，共680字节，写入记录的 `+0x18` 日期和 `+0x26` 模式。

日期读取使用独立 profile `opinion-end-dates-memory-1374-v1`，SHA-256 为 `211b76e0d32f656c6c2bf5030c88a34fb981ebdb41c881df9f8b9d4829fc334a`。四个完整方法范围合计1379字节，profile 检查的实际重定位目标与读取守卫没有重叠。首个 `.pdata` 小段只有56字节或20字节，不能代替 `0x28c520` 或 `0x14c7f30` 的完整方法范围。

`mode +0x26 = 0` 表示这条记录保存固定期限计划；接口将记录 `+0x18` 转成日期文本。`mode +0x26 = 1` 进入非固定期限模式，接口只返回 `not_applicable`，不推断记录是否永久有效。上述静态路径说明计划日期如何产生并写入记录；实际游戏是否在某处比较当前日期、何时删除记录，仍无已接受证据。普通反汇编候选扫描也没有闭合删除消费者，不能当作 REA 结果或完整调用链。

接口复用既有具名修正记录容器、国家对准入与身份核验、双遍读取一致性和严格原始读取记录回放；日期功能只增加独立投影，不另造内存布局或脚本解析器。完整日期 UI 可见性及引擎缓存新鲜度仍未验证。

## 实采与验证

本批实读的游戏日期原始值为 `56560344`，对应 `1456.8.30`。旧 saved snapshot 中的 `1456.4.12` 不属于这次实时采集。正式 end-date capture 的严格回放通过，篡改输入会被拒绝；MCP 正向查询约0.625秒、反向查询约0.563秒、四字段混合查询约2.812秒、报告约0.938秒。2秒与5秒周期结果一致；取消短周期后长周期仍运行，最后所有订阅已取消，服务退出码为0、读取线程结束、交付期间源码指纹未变。

188批最终12个相关文件中的176项针对性测试全部通过。整体测试集仍记录为 `whole_suite_passed=false`；完整132项集合继承的126个历史失败 ID没有在本批重验。覆盖矩阵为61 available、255 partial、81 planned；本批仅将 `R04.end_date` 从 planned 增为 partial，完整74主题、397字段及阶段二/三/四与B01–B04仍在开发范围内。

采集只读游戏内存，没有调用游戏函数、提交外交动作、写入世界状态、推进日期、保存或重载、重启游戏、注入代码或使用 computer use。完整证据见 `work/runtime/information-opinion-expiry-20261105-188-001/summary.json`。
