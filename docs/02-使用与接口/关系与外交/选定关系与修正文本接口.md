# 选定关系与修正文本接口

本文说明 1.37.4 中当前可以调用的两组部分只读字段：选定国家对的关系状态（R01），以及本国直接修正实例的名称和说明文本（N07）。两者都限定为经过身份校验的 FRA 观察方；对象范围和字段完整性由目录返回值决定。本文不把关系检查结果扩展成全球关系网，也不把修正定义效果扩展成最终国家属性。

当前固定对象是游戏版本 `1.37.4`、观察国 `FRA`。生产读取仍会在读取前后核对游戏会话、日期、进程和代码守卫。批 53 的实机验收、完整回归和覆盖统计由发布流程另行填入；本文不预先声称它们已通过。

## R01：选定国家对

对象使用两个不同的三字母国家标签：`actor` 必须是 `FRA`，`recipient` 是要检查的另一个国家。适配器不会枚举全世界，也不会把一次 action 的可行性、待接受状态或合法性当成当前关系。当前支持五种关系族：

`vassalization`、`guarantee`、`support_independence`、`military_access` 和 `rival`。

`parameters.relation_types` 可省略（默认五种），也可以传 1 至 5 个不重复的枚举值。读取的是每个族自己的 `relationship_state.<family>_active`；`true` 映射为 `status: "active"`，`false` 映射为 `status: "inactive"`。`relation_type` 和 `status` 的行顺序与请求中的 `relation_types` 相同。

只有 vassalization 的互斥 `actor_is_overlord` / `actor_is_subject` 证明了角色方向时，`grantor` 和 `recipient` 才会返回国家标签。保证、支持独立和军事通行的当前实现只证明选定端点，不把 action 名称猜成 grantor/recipient；rival 的这两个字段为 `not_applicable`。过期日期没有已证来源，仍未实现。

示例查询：

```json
{
  "request_id": "relation-state-query-001",
  "queries": [
    {
      "topic": "R01",
      "object": {"type": "country_pair", "actor": "FRA", "recipient": "ORL"},
      "fields": ["relation_type", "status", "grantor", "recipient"],
      "parameters": {
        "relation_types": ["vassalization", "guarantee", "support_independence", "military_access", "rival"]
      }
    }
  ]
}
```

每个请求字段的顶层 `status` 可以是 `known`，但字段的 `value` 仍是带逐行状态的集合；这是因为某个关系族可能已知、另一个关系族可能因原生状态不完整而 `unknown`。例如归档的 `FRA → ORL` vassalization active 样本，公开字段形状如下：

```json
{
  "status": {
    "status": "known",
    "value": [
      {"relation_type": "vassalization", "status": "known", "value": "active"}
    ]
  },
  "grantor": {
    "status": "known",
    "value": [
      {"relation_type": "vassalization", "status": "known", "value": "FRA"}
    ]
  },
  "recipient": {
    "status": "known",
    "value": [
      {"relation_type": "vassalization", "status": "known", "value": "ORL"}
    ]
  }
}
```

`R01` 的目录字段仍为 `coverage: "partial"`、`complete: false`。来源是选定端点上的原生外交检查；查询之间是有稳定身份检查的连续观察，不宣称一个不可分割的世界快照。

## N07：本国直接修正的名称和说明

查询对象为 `{"type":"country","country":"FRA"}`，当前 `N07` 可请求 `modifier_id`、`target`、`effects`、`name`、`description`。本页重点是最后两个文本字段；其他三个字段仍按 N07 目录返回。

名称使用修正记录中的原生 key，说明使用 `desc_<modifier key>`。以下四项归档参考已得到已知中文字面值：

| 文本用途 | 原生查找 key | 已知字面值 | 当前语言约定 |
| --- | --- | --- | --- |
| 名称 | `papal_sanction_for_church_taxes` | 教宗特许加税 | `l_english` |
| 说明 | `desc_papal_sanction_for_church_taxes` | 教廷特许我们对我国信众收税一段时间，大大增加了我国税收。 | `l_english` |
| 名称 | `shady_people` | 暗处的人 | `l_english` |
| 说明 | `desc_shady_people` | 有些躲在暗处的人能服务您的国家。 | `l_english` |

实现会先验证当前 `country_modifiers` 子记录，再对去重后的名称和说明 key 做一次共享 native localization 读取。没有磁盘资源回退。当前修正列表和文本缓存不是一个原子快照；如果读取前后上下文变化，所有选定文本都会撤回。

文本字段的返回行保留 `modifier_id`、`key`、`raw_key_hex`、`language`、`codec`、`encoding`、`source` 和 `reader_provenance`。能够解码为字面文本时附带 `value`；缺失 key 或读取异常时返回 `status: "unknown"` 及原因，并保留原始模板字段。四项参考 raw 使用 `codec: "eu4_escape"`；raw 中的 `0x10` 是编码转义标记，不表示未替换动态模板。`unit` 为 `localized_text`，`scale` 为 `1`，`period` 为 `current`。当前 N07 的适配器结果固定保留 `complete: false`、`partial: true`；即使某个字段的行全部为 `known`，也不把它升级为完整 UI 绑定。

示例查询：

```json
{
  "request_id": "country-modifier-text-query-001",
  "queries": [
    {
      "topic": "N07",
      "object": {"type": "country", "country": "FRA"},
      "fields": ["modifier_id", "name", "description"],
      "parameters": {}
    }
  ]
}
```

这四项的 raw bytes、编码和会话绑定在 [`native-cache.json`](../../../work/runtime/information-country-records-localization-20261027-001/literal-reference-001/native-cache.json)，期望文字在 [`expected-literals.json`](../../../work/runtime/information-country-records-localization-20261027-001/literal-reference-001/expected-literals.json)。这些是归档的只读参考，不替代当前会话的身份和代码守卫。

## 报告和周期读取

两组查询都声明 `query` 和 `periodic`，不执行游戏业务动作。

### `information_query`

主动查询直接提交 `queries`：

```json
{
  "request_id": "selected-relation-text-query-001",
  "queries": [
    {
      "topic": "R01",
      "object": {"type": "country_pair", "actor": "FRA", "recipient": "ORL"},
      "fields": ["relation_type", "status", "grantor", "recipient"],
      "parameters": {}
    },
    {
      "topic": "N07",
      "object": {"type": "country", "country": "FRA"},
      "fields": ["name", "description"],
      "parameters": {}
    }
  ]
}
```

### `information_manage_report`

上面的 `queries` 也可以通过 `information_manage_report` 保存为报告。示例中的 `operation` 和 `detail` 是完整报告配置：

```json
{
  "request_id": "selected-relation-text-report-create-001",
  "operation": "create",
  "config": {
    "name": "FRA selected relation and modifier text",
    "queries": [
      {
        "topic": "R01",
        "object": {"type": "country_pair", "actor": "FRA", "recipient": "ORL"},
        "fields": ["relation_type", "status", "grantor", "recipient"],
        "parameters": {}
      },
      {
        "topic": "N07",
        "object": {"type": "country", "country": "FRA"},
        "fields": ["name", "description"],
        "parameters": {}
      }
    ],
    "detail": "raw"
  }
}
```

创建成功后，将返回的 `report_id` 放进 `information_manage_subscription` 的周期配置。绑定值必须替换为当前 `information_discover` 返回的实时会话：

```json
{
  "request_id": "selected-relation-text-subscription-001",
  "operation": "create",
  "config": {
    "name": "FRA relation and modifier text every 2 seconds",
    "kind": "periodic",
    "report_id": "report-replace-with-created-id",
    "enabled": true,
    "binding": {
      "session_id": "session-from-information-discover",
      "observer": "FRA",
      "game_version": "1.37.4"
    },
    "schedule": {
      "basis": "real",
      "every": 2,
      "unit": "seconds",
      "missed": "coalesce"
    }
  }
}
```

周期读取重复读取已验证的只读来源，不刷新或重算修正、关系或本地化缓存。上下文、版本、日期、缓存记录或文本解码守卫失败时，结果应保留具体 `unknown` / `unavailable` 原因，不沿用上一周期值。`R01` 的 `change` 能力以目录为准，仍只适用于选定国家对的采样比较，不是事件流。
