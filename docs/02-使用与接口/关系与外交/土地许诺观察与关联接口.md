# 土地许诺观察与关联接口

R07.land_commitments与W04.land_commitment保留当前受益国、土地标记和本方战争领袖，并从共同事件账本附加已经观察到的许诺发送方。适用范围为逻辑观察国FRA参与的战争与B23版EU4 1.37.4。

## 发送方与当前议和

beneficiary为当前具有土地许诺标记的参战国。war_leader为其当前阵营领袖，原生土地分配计算以该国参与议和判断。领袖变化后，该值随当前阵营更新。

observed_promisor为同会话、同公共war_id和受益国对应的最近一次已采集许诺发送方。它记录原生命令发起国。采集开始前成立的许诺、历史账本缺少对应事件及公共战争编号未知时，该值为null。当前标记的可读性与发送方历史的覆盖情况分别保存在字段complete和land_promise_association中。

已观察发送方用于回答该国曾在这场战争中向谁许诺土地。当前分配判断仍可直接使用beneficiary、side和war_leader。历史观察覆盖至事件发生时，参战国随后退出和再次加入的全部生命周期仍有覆盖限制。

## 成立事件

C04登记land_promise_established事件。原生采集在实际命令返回时检查以下条件。

- 宣战使用实际payload中的promise_land_to及call_allies名单。执行前后仅新增一场对应战争，战争登记的本次构造身份与宣战双方匹配，所选受益国已实际同侧参战并具有土地标记。
- 召盟使用实际CallAction的actor、recipient与反向存储的promise_land标志。执行后受益国新增参战，发送国在执行前后均属于该战争，双方实际同侧，受益国的当前土地标记为真。同次加入多场战争时分别记录各自的公共war_id。
- FRA是该战争的实际参战国，国家完整引用通过现有国家表精确核对，公共war_id通过现有战争登记取得。

仅发出邀请且仍待回应、被拒绝或尚未新增参战时，观察器等待实际成立的来源。已确认事件的日期为原生命令返回时的游戏日期。

公开payload包含以下字段。

```json
{
  "promisor": "ENG",
  "beneficiary": "SAV",
  "war_id": "war_0123456789abcdef_00000001",
  "action_id": "call_to_arms",
  "scope": "FRA_member_in_observed_promise_war"
}
```

action_id为declare_war或call_to_arms。事件对象包含战争、发送国、受益国以及按promisor→beneficiary定向的国家对。订阅actors筛选发送国，recipients筛选受益国。

```json
{
  "queries": [
    {
      "topic": "C04",
      "object": {"type": "session"},
      "fields": ["event_id", "event_date", "event_payload"],
      "parameters": {"event_type": "land_promise_established"}
    }
  ]
}
```

## 当前标记关联

正常工厂将NativeCommitmentsSource.land_promise_history_reader设置为InformationService.observed_events。读器先取得并核对当前土地标记，再从同一账本读取相关事件。W04通过原有R07组合方法取得相同结果。

历史关联要求事件会话、观察国、B23身份、事件编号、对象列表、来源范围和原生sequence有效。按公共war_id与beneficiary精确匹配，再以事件游戏日期及原生sequence选取最近一次记录。已知日期大于当前游戏日期、历史内容冲突或读取失败时，observed_promisor保留null，当前已确认标记仍可使用。

每次关联最多读取1000条相关事件。完整视图的land_promise_association包含事件编号与日期、批次摘要、complete及gaps。原生丢失、历史页达到上限和发送方尚未观察分别保留对应缺项。空的当前标记列表直接返回，无需读取发送方历史。

## 安装合同

能力要求v64顶层ACK中的native_land_promise_observation=true、native_land_promise_wire=1和native_land_promise_scope=FRA_member_in_observed_promise_war。v64继承完整v63及三条到期能力。

新增原生模块复用既有通用执行入口和宣战直接入口的前后观察，以及战争构造与退休登记。安装时核对固定B23的相关指令字节和CallAction执行槽。两个入口嵌套时，同日期、同战争、同发送国和受益国在队列中合并为一条事件。队列溢出、读取失配和日志故障通过共同事件完整性机制报告。
