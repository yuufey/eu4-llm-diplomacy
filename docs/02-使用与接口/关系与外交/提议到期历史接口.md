# 提议到期历史接口

H02.proposal_expiry提供本服务已采集并保存的外交提议实际到期记录。每条包含提议编号、行动、发起国、接收国、事件编号和实际发生日。到期判定复用已有原生待回应提议清理来源与A04快照。

## 主动查询

```json
{
  "queries": [{
    "topic": "H02",
    "object": {"type": "session"},
    "fields": ["proposal_expiry"],
    "parameters": {"limit": 50}
  }]
}
```

session读取当前账本范围中的记录。country可筛选FRA或相关发起国，country_pair按提议实际actor、recipient筛选。当前原生入站提议的接收国为FRA。

默认输出采用可读日期。以下示例取自已保留的真实BOU至FRA联姻提议到期记录。

```json
{
  "proposal_expiry": [{
    "proposal_id": "427d91d20dff425ad84358f500638d21",
    "action_id": "offer_royal_marriage",
    "actor": "BOU",
    "recipient": "FRA",
    "event_id": "inbound-expired:8bfb832d536843347555e51975ea48f0",
    "event_date": "1445.2.13"
  }]
}
```

历史按入库顺序最近优先。limit默认50，范围1到1000。有后页时，默认响应提供next_cursor.proposal_expiry，将其传入下一次查询的parameters.cursor。末页省略next_cursor。完整视图保留采集缺口和日期来源。

## 到期订阅

先以包含上述查询的配置创建报告，再以其report_id创建事件订阅。事件筛选配置如下。

```json
{
  "name": "外交提议到期",
  "kind": "event",
  "report_id": "填入实际报告编号",
  "enabled": true,
  "event": {
    "types": ["diplomatic_proposal"],
    "proposal_statuses": ["expired"]
  }
}
```

proposal_statuses只筛选diplomatic_proposal的业务状态，可在同一订阅中继续选择修正变化等其它事件类型。提议初次出现、通用失活与到期使用各自的业务状态。H02.proposal_expiry只记录expired，通用失活继续由A04提供。

## 通用失活通知

按提议编号移除、有效性重检及整队清空待回应队列时，已确认完成析构的提议通过共同来源交付`diplomatic_proposal`，状态为`inactive`。订阅使用`proposal_statuses=["inactive"]`，仍按原有国家和提议编号关联到A04。记录保留实际发生日期，消费者将该提议的`currently_pending`更新为`false`。

整队清空时，每条提议按自己的公开编号单独交付。明确到期记录优先于同一对象后续的通用清理。通用失活的业务原因沿现有来源范围解释，发送方撤回需要独立的业务来源。

原生日志对这些必要的终态记录持续保留。辅助诊断达到额度后仍交付到期及上述失活记录，既有64 MiB诊断限额继续生效。

事件与历史查询复用同一持久账本、去重和快照投影。历史查询读取已登记记录，采集由原有共享事件来源完成。显式request_id或case查询继续沿既有H02请求日志入口。

修正变化见[修正生命周期历史接口](../国家与国内/修正生命周期历史接口.md)。
