创建报告时，将下面的查询放入 `config.queries`，`detail` 设为 `full`。取得报告编号后，创建 `kind="event"` 的订阅，将 `report_id` 设为该编号，`event.types` 设为 `["relation_changed"]`。完整管理参数沿用[信息接口使用说明](../信息接口使用说明.md)。

```json
{
  "topic": "C04",
  "object": {"type": "session"},
  "fields": ["event_id", "event_type", "event_date", "event_objects", "event_payload", "complete"],
  "parameters": {"event_type": "relation_changed"}
}
```

先通过 `information_discover` 检查 C04 的 `native_relation_change.capture_available`。事件只包含涉及 FRA 的国家对，物理玩家国家另行记录。订阅可用 `event.actors` 和 `event.recipients` 筛选事件双方，角色含义随上述采集路径确定。

`event_payload.relation_kind` 的取值为 `alliance`、`royal_marriage`、`military_access`、`guarantee`、`support_independence` 和 `subject`。`before.active`、`after.active` 保存原生读取的前后关系状态。`command_state`、`command_mode` 保留命令的原生状态值，不能单凭这两个值判断成功。业务事件以实际前后状态为依据，拒绝或无效果的调用不会产生关系变化通知。

命令路径的 `actor`、`recipient` 表示命令双方。保障关系附带 `guarantee`，其中 `actor_grants`、`recipient_grants` 分别表示命令发起国给予目标国、目标国给予发起国的保障。即使反向保障已经存在，正向保障的新增或移除也会产生通知。支持独立附带 `support_roles`，其中 `actor_is_subject`、`recipient_is_subject` 保存双方当时的属国身份。宗属关系附带 `subject`，明确 `actor_is_overlord`、`actor_is_subject` 及原生类型标识 `type`。同一宗属关联的类型或方向发生变化也会产生通知。各关系不适用的附加对象为 null。

v51 的采集复用原命令调用位置，读取范围限于该命令的国家对。相同关系、相同国家对的同步嵌套调用由最外层记录返回后的净变化，命令内部发生后又恢复的中间状态尚未完整采集。v54 候选另覆盖上述联盟记录入口。其它关系直接改写、绕过已知入口的调用，以及驻港权和贸易联盟的即时写入仍需来源。日期、身份、队列或运输异常保留 gap。

通知保存返回时的日期和前后状态。完整结果读取及持久重开使用保存的快照，游戏继续推进后仍可读取。当前关系另由 R01 查询。原生候选与公共交付的验证范围见[第325批记录](../../../work/runtime/information-relation-source-20261109-325-001/summary.json)。

## 查询对象和字段

`country_pair` 的 `actor` 必须是 `FRA`，`recipient` 必须是另一个国家标签。`parameters.relation_types` 可以省略，表示该对象支持的七类；也可以提交 1 至 7 个不重复枚举值。`country` 的 `country` 必须是 `FRA`，省略参数时读取联盟和王室联姻；该对象只接受这两类。

四个已接入的关系状态字段为 `relation_type`、`status`、`grantor` 和 `recipient`。行顺序跟随请求的关系类型，国家视图按原生国家表顺序保留活动伙伴，`partner` 标明伙伴国家。`status` 的行值是 `active` 或 `inactive`；读取不完整时保留 `unknown` 和原因。联盟与联姻为对称关系，`grantor`、`recipient` 返回 `not_applicable`；附庸角色沿用已验证来源。`expires_at` 仍为计划字段。

## `information_query`

选定国家对的查询可以这样提交：

```json
{
  "request_id": "r01-pair-001",
  "queries": [
    {
      "topic": "R01",
      "object": {"type": "country_pair", "actor": "FRA", "recipient": "ORL"},
      "fields": ["relation_type", "status", "grantor", "recipient"],
      "parameters": {
        "relation_types": [
          "vassalization", "guarantee", "support_independence",
          "military_access", "rival", "alliance", "royal_marriage"
        ]
      }
    }
  ]
}
```

FRA 关系网的查询使用 `country` 对象：

```json
{
  "request_id": "r01-network-001",
  "queries": [
    {
      "topic": "R01",
      "object": {"type": "country", "country": "FRA"},
      "fields": ["relation_type", "status", "grantor", "recipient"],
      "parameters": {"relation_types": ["alliance", "royal_marriage"]}
    }
  ]
}
```

对于公开字段，顶层字段结果仍使用 `{status, value}`。例如一个已知的选定关系行会写成：

```json
{
  "status": {
    "status": "known",
    "value": [
      {"relation_type": "alliance", "status": "known", "value": "active"}
    ],
    "complete": false,
    "partial": true
  }
}
```

国家视图中的 `value` 是按原生顺序排列的伙伴行；没有已知活动伙伴时，返回空集合仍需结合顶层来源状态和缺口判断。上下文、版本、日期、进程或代码守卫变化时，读取器撤回本次值，不沿用上一轮结果。

## `information_manage_report`

报告保存完整查询配置：

```json
{
  "request_id": "r01-report-create-001",
  "operation": "create",
  "config": {
    "name": "FRA relation network",
    "queries": [
      {
        "topic": "R01",
        "object": {"type": "country", "country": "FRA"},
        "fields": ["relation_type", "status", "grantor", "recipient"],
        "parameters": {"relation_types": ["alliance", "royal_marriage"]}
      }
    ],
    "detail": "raw"
  }
}
```

创建后，使用返回的 `report_id` 创建周期订阅。订阅绑定必须来自当前 `information_discover` 的会话，不得复用旧进程的对象地址。

## `information_manage_subscription`

```json
{
  "request_id": "r01-subscription-create-001",
  "operation": "create",
  "config": {
    "name": "FRA relation network every 2 seconds",
    "kind": "periodic",
    "report_id": "report-replace-with-created-id",
    "enabled": true,
    "binding": {
      "session_id": "session-from-information-discover",
      "observer": "FRA",
      "game_version": "1.37.4"
    },
    "schedule": {
      "basis": "real",
      "every": 2,
      "unit": "seconds",
      "missed": "coalesce"
    }
  }
}
```

周期读取重复读取已验证的只读来源，不刷新关系缓存，也不执行外交动作。`change` 仍是连续采样比较，不等同于事件流；读取之间也不宣称一个不可分割的世界快照。

## 已知边界和来源

当前网络合同覆盖联盟和王室联姻的 FRA 活动伙伴枚举，以及七类关系的选定国家对读取。`fleet_basing`（驻港权）、`trade_league`（贸易联盟）和关系过期日期仍缺少可用的当前原生来源；它们不能由 action 名称、legality 或 pending 状态代替。批54目前使用普通有界来源 `relation-current-source-002.json` 和已接受的 REA 合同 `relation-current-contract-003.json`；已有 raw/reference/replay 收据由归档 helper 按选定文件动态核对，任何实机伙伴和统计都应以后续通过的 live/replay 收据为准。
