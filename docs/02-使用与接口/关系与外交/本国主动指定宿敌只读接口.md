# 本国主动宿敌只读接口

## 字段范围

R03 rivals 返回本国当前主动指定的宿敌标签列表，按标签升序排列。这是本国发出的单向声明，不表示其他国家对本国的指定。

查询只读取国家宿敌链和目标国家身份，不调用游戏业务函数。历史宿敌、AI候选优先级和其他国家对本国的指定不在此列表中。

## 可用范围

- 国家：FRA。
- 游戏版本：1.37.4。
- 方向：outgoing_declared_by_country。
- 有效采样返回known、国家标签数组、unit为country_tags、scale为1、period为current、complete为true。
- 采集或身份校验失败时返回未知或不可用，不发布已读到的部分名单。
- 实机观察：[]。
- 空链已通过实机验收；非空链目前只有夹具验证，未通过实机验收。

## 主动查询

向 `information_query` 传入以下参数；每次新请求使用新的 `request_id`。

```json
{
  "request_id": "r03-rivals-example-001",
  "queries": [{
    "topic": "R03",
    "object": {"type": "country", "country": "FRA"},
    "fields": ["rivals"],
    "parameters": {}
  }]
}
```

结果在 `items[0].fields.rivals`。本轮返回 `status: "known"`、`value: []`、`complete: true`，表示已完整读取法国的出站宿敌列表，列表为空；读取失败不会用空数组代替。

## 周期订阅

将同一 `queries` 保存为报告，再通过 `information_manage_subscription` 创建 `kind: "periodic"` 的订阅，并提供该报告的 `report_id`。本轮已验证的调度为：

```json
{"basis": "real", "every": 2, "unit": "seconds", "missed": "coalesce"}
```

服务在后台采样，无需调用 `information_tick` 或推进游戏日期。结束后取消订阅。结果中的 `delivery.status: "delivered"` 表示交付记录已写入；`llm_read: "unknown"` 不表示模型已经阅读。

## 完整性边界

- 按声明数量读取并要求末节点为空；循环、重复成员、数量不符或身份不一致时拒绝投影。
- 两遍读取必须在同一会话、日期取得一致的名单和国家身份；这不构成原子快照。
- 当前仅支持固定版本中的FRA。非空名单已通过合成测试，尚未通过新读取器的实机验收。
- R03其余字段继续保留为planned。

实机原件见[第70批记录](../../../work/runtime/information-diplomacy-state-20261028-001/live-acceptance-001/report.json)。

## 宿敌变化事件订阅

v48将三种宿敌命令正常返回后的实际成员变化接入C04，事件类型为 `rival_changed`。逻辑观察国为FRA，覆盖FRA发起命令、成为命令目标，或在替换时作为旧宿敌的情况。安装回执必须明确提供对应能力、wire1、精确范围及继承能力，当前可发现的类型以 `information_discover.event_types` 为准。离线公共接口已验证，实际游戏回调正例仍缺少，运行现场见HANDOFF顶部。

将以下配置传给 `information_manage_report` 创建报告。

```json
{
  "request_id": "rival-changes-report-001",
  "operation": "create",
  "config": {
    "name": "与本国相关的宿敌变化",
    "detail": "full",
    "queries": [{
      "topic": "C04",
      "object": {"type": "session"},
      "fields": ["event_id", "event_type", "event_date", "event_objects", "event_payload", "complete"],
      "parameters": {"event_type": "rival_changed"}
    }]
  }
}
```

把返回的报告编号填入下列 `report_id`，传给 `information_manage_subscription`。

```json
{
  "request_id": "rival-changes-subscription-001",
  "operation": "create",
  "config": {
    "name": "与本国相关的宿敌变化",
    "kind": "event",
    "report_id": "填写报告编号",
    "enabled": true,
    "event": {"types": ["rival_changed"]}
  }
}
```

调度器运行时自动处理事件，也可调用 `information_tick` 驱动一轮。交付的完整结果可通过 `information_get_result` 按 `result_id` 读取。

`event_payload` 保存以下内容。

| 内容 | 含义 |
| --- | --- |
| `actor`、`recipient` | 命令发起国和命令目标国，订阅的 `actors`、`recipients` 分别按这两项筛选 |
| `old_rival` | 替换命令中的旧宿敌，其它操作为null；这一国家不并入 `recipients` 筛选 |
| `operation` | 经过的命令入口，取值为 `set`、`replace` 或 `remove` |
| `before`、`after` | 该命令发起国的宿敌数量、目标及旧宿敌的成员状态，以及仍为成员时的原始起始日期 |
| `scope` | 三种国家宿敌命令入口及FRA相关范围 |

命令正常返回后，只有成员状态确实变化才生成事件。替换若只新增新目标，或只移除旧目标，事件保留实际前后状态，不能仅凭 `operation=replace` 判断两步都成功。日期采用执行前后确认一致的原生日期，报告重放使用已经保存的快照。来源按宿敌事件自己的原生序号保持顺序，与其它来源分别保留游标。

不可读、身份不符、丢弃、序号冲突或运输失败会保留缺口。当前来源尚未证明覆盖绕过这三种命令入口的直接关系改写，C04目录的 `direct_country_writes_covered` 为false。R03当前主动名单查询仍按前述合同使用。
