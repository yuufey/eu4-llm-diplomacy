# 双向好感修正快照接口

`R04.opinion_modifiers` 提供历史存档中，观察国参与的国家对的两向修正记录。服务复用固定版本的 Jomini / eu4save 解析语法，由 `SavedOpinionSnapshot` 校验输入，`SavedOpinionSource` 将记录接入查询与手动报告。它不会执行改善关系、推进日期或操作游戏。

这里导出的是 `countries.<国家>.active_relations.<对方>.opinion` 保存项。`holder` 表示存放这条关系记录的国家，`target` 表示子项的国家标签。存档顺序和重复的修正项都会保留；这些记录不构成完整的界面修正列表，也不直接给出最终好感。

## 启用与调用

沿用统一 MCP stdio 服务，显式选择新的历史来源：

```powershell
python tools/serve_information.py --opinion-save "C:\Users\wangyufei\Documents\Paradox Interactive\Europa Universalis IV\save games\llm_diplomacy_interest_quote_20261101_001.eu4" --observer FRA --database work/runtime/information-opinion-reuse-20261103-120-001/example.sqlite3
```

需要时可用 `--opinion-parser-manifest` 指定受信的解析器 manifest。历史来源与实时安装、其他历史来源、任务或神罗规则模式及战报状态来源互斥。默认实时模式不会创建这个保存快照。

将以下参数传给 `information_query`，或将其中的查询加入手动报告：

```json
{
  "request_id": "saved-opinion-example",
  "queries": [{
    "topic": "R04",
    "object": {"type": "country_pair", "actor": "FRA", "recipient": "ENG"},
    "fields": ["opinion_modifiers"],
    "parameters": {}
  }]
}
```

对象必须包含两个不同的国家标签，至少一方是启动时指定的观察国。返回的第一个方向是 actor 所存的 recipient 关系记录，第二个方向相反。交换 actor 与 recipient 会交换结果方向的顺序。Source 拒绝无关国家对，也拒绝把存档 `saved_player` 指定为观察国；统一服务的作用域检查也会拦截无关国家对。

## 字段与缺项

| 字段 | 表达的内容 |
| --- | --- |
| `modifier_id` | 存档中的修正标识，不补造显示名称 |
| `recorded_date` | 原始 `date` 保存值；不推断它是施加日、到期日或下一次更新日 |
| `current_opinion_decimal` | 该修正项的保存数值，使用十进制字符串保留精度；不作为最终好感 |
| `expiry_date_flag` | 原始 `expiry_date=yes/no` 对应的布尔值，不是一个日期 |
| `holder`、`target` | 保存记录所属国家与关系子项国家，保持两向独立 |

数值、日期和布尔标志未保存时保留 null，不补成 0 或 false。缺少 active_relations、对方关系或 opinion 保存项时，该方向返回 unknown。至少一个方向有记录时保留该方向及另一方向的缺项；两个方向都未知时不提供 value。没有记录不能据此证明不存在任何好感修正，也不能转换成已知空集合。

`period=saved_snapshot`、`complete=false`。来源包含存档 SHA-256、保存日期、玩家标签及解析器身份；实时会话、世界和暂停状态保持为空。服务启动时解析一次，此后的查询和报告共享快照，并重新核对输入及解析器来源是否变化。读取前后不一致时撤回结果。

当前仅声明 query，不提供逐场变化事件或绑定游戏会话的周期导出。`R04.opinion`、`R04.end_date`、`R04.decay` 仍未实现。解析器也不把 cached_sum、trust_value、attitude 等其它保存项混入输出。

当前解析投影为 `serialized_opinion_entries_only`，会流式扫描关系行，只保留含非空 opinion 保存项的关系。父级 active_relations 缺失保持 null；存在但没有保留项时输出空容器。后者不表示不存在关系或好感修正，查询该方向仍返回 unknown。解析器分别限制原始扫描量、保留关系数、修正数和输出大小，不先积累全部无修正的关系行再过滤。

## 验证与保留的问题

实际 MCP 的正向、反向查询均与这8条原始记录逐项一致；手动报告与查询的字段和对象一致。有效的周期创建请求返回 JSON-RPC `-32602`，原因是历史绑定缺少 session_id；只读检查服务数据库确认没有创建订阅。结果位于同批 `mcp-002/direct.json`、`mcp-003/report-run.json` 和 `mcp-retained-audit-001.json`。

9项 Rust 夹具测试通过，包括扫描69,632条原始关系行而只保留1条修正关系，以及超出保留量或每国扫描量时拒绝输出。当前 Python 意见接口的36项定向测试通过；此前108项新旧保存接口回归属于过滤调整前的源码快照，保留其原始范围，不合称一次当前全量测试。测试原件保存在 `work/runtime/information-opinion-snapshot-20261103-120-001/`，其余原件在 `information-opinion-reuse-20261103-120-001/`，未移动覆盖。

三个 MCP 验收 helper 原收据均保留为失败：第一版解析器原始关系行超过上限，服务未开始数据查询；第二份取得正确查询结果后误比较参考文件的取证元数据；第三份取得正确报告及绑定拒绝后，未识别标准数字错误码。现有响应通过离线合同审计，成功查询未重新派发，也没有第四次启动服务。第一版 CLI 及 manifest 已归档，修订版使用独立二进制文件。

验收时应先保存合同要求的响应，再分别核对数据、来源和错误；参考文件附带的偏移、哈希不属于公共返回值。标准 MCP 错误需要同时检查错误码与原因，不能只接受内部服务的文本错误码。检查器失败后优先复核原件，避免重新采集已经成功的内容。
