# 信息简报与完整结果

报告配置的`detail`控制对LLM呈现的结果。`brief`已接入主动查询、结果列表、手动调度返回以及外部输出适配器。数据库保存完整采集结果，结果编号在简报与完整记录之间保持一致。

## 详细程度

| 配置 | 呈现 |
| --- | --- |
| `brief` | 保留业务字段、完整字段值、状态、单位、尺度、时间、未知原因和字段限制，提供来源摘要及完整结果入口 |
| `raw`、`full` | 完整结果，包含来源及字段的取证元数据 |

当前简报省略`source.provenance`和字段顶层的`provenance`，来源组合中的同类元数据也作相同处理。`value`内部的规则、条件、完整战报、原文及其它业务内容原样保留。字段的`reason`、`gaps`、`unknown_conditions`、`complete`和`partial`等状态继续提供。

事件订阅的新结果同时保存`event_batch.complete`和`event_batch.gaps`，简报和完整结果均可读取。它们记录该次来源批次的覆盖状态及缺口。单条事件的`event.complete`、字段投影的`items[].complete`分别描述对应内容。356批的两条修正到期事件及字段完整，复合批次含战报范围缺口，因此结果外层为`partial`。357批起这些批次缺口随结果持久保存，后续来源状态变化不会改写旧结果。此前未记录该元数据的结果继续保留原样。

简报的`presentation.omitted_metadata`说明省略范围。需要核对完整来源、采集字节或取证条件时，按入口读取完整结果。

## 读取完整记录

简报返回以下入口，其中`result_id`为本次结果编号。

```json
{
  "presentation": {
    "view": "brief",
    "omitted_metadata": ["source.provenance", "fields.*.provenance"],
    "full_result": {
      "tool": "information_get_result",
      "arguments": {"result_id": "result-..."}
    }
  }
}
```

将该入口的参数交给`information_get_result`，可直接取得完整存储记录。读取已有结果使用其原观察日期和会话，原记录的身份、时间及完整性随结果提供。服务重开后，沿用相同数据库与owner继续按编号查询。

`information_query`引用brief报告、`information_list_results`及`information_tick`中的brief结果都按上述规则呈现。自动周期和事件交付也使用相同呈现函数，完整记录及交付状态保存在原数据库中。
