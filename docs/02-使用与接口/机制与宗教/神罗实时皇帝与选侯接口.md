# 神罗实时皇帝与选侯接口

第118批另加独立的[当前改革记录来源](神罗当前改革记录接口.md)，与本页皇帝、选侯来源共享 S01 路由。新来源的 GUI/profile 校验失败只影响改革字段；本页 v1 模块和 profile 保持独立。

`S01` 的实时来源读取当前神罗皇帝与选帝侯名单，逻辑观察方为非玩家法国（FRA）。玩家所在国家由采集器独立核对，不要求把客户端切换为法国。历史存档查询继续使用[神罗机制快照接口](神罗机制快照接口.md)。

## 查询与订阅

实时服务沿用现有启动方式；绑定经过核验的 observer 安装目录后，工厂自动接入 `NativeEmpireSource`：

```powershell
python tools/serve_information.py --operator-session <installation.json路径> --observer FRA
```

通过 `information_query` 提交：

```json
{
  "request_id": "hre-current-001",
  "queries": [{
    "topic": "S01",
    "object": {"type": "session", "session_id": "从information_discover取得当前session_id"},
    "fields": ["emperor", "electors"],
    "parameters": {}
  }]
}
```

`country` 选择器也可使用，例如 `{"type":"country","country":"FRA"}`。两种选择器均读取同一份全局神罗记录；国家选择器不表示该国属于帝国，也不据此判断该国是否为皇帝或选侯。`session_id` 可在一次性查询中省略；订阅应使用目录及工具要求的完整会话绑定。

两个字段的单位均为 `country_tag`，比例为 1，时间为 `current`。皇帝为单个标签，选侯为按标签排序且不重复的列表。有效空选侯容器返回已知空列表；结构读取失败返回未知状态。两字段均为 `partial`，结果的 `complete` 为 `false`。

同一查询可以保存为报告，再由 `information_manage_subscription` 创建多个 `periodic` 订阅。频率使用现有调度合同；采集不会推进游戏日期。这里只支持主动查询和周期读取，不声称捕获每次皇帝或选侯变化事件。

## 数据来源与边界

生产代码由 `empire_memory.py`、`empire_capture.py`、`empire_live.py` 与独立 `empire-memory-1374-v1.json` profile 组成，复用现有只读进程句柄、身份检查和严格 trace 重放。支持的 EXE 为 1.37.4，SHA-256：

```text
b23fa0e1f698d31b01cdd1c3817a675805d8c6286cb66f9c231e6e2a42544d77
```

布局证据来自该版本的序列化函数、构造函数和已保存的有界界面代码。world 全局槽 RVA 为 `0x233fe58`，HRE 位于 `world+0x15d0`；采集时另外核验 world/HRE 虚表和运行代码片段。皇帝与每个选侯的完整国家引用均须与当前国家表对应，不能只从引用的前三个字符取得标签。

选侯容器使用 head/count 和 next 链。采集限制节点数量、拒绝环、重复引用和长度不符；节点 `+8` 的不透明内容不读取。采集前后检查游戏身份与上下文，并比较两遍结果。双遍一致不能保证原子快照，因此公开来源明确保留 `atomic_snapshot=false`。

窄范围公开依据是全局神罗记录的静态界面数据流：保存的完整函数 `[0x115ca80,0x115ee21)` 将皇帝引用复制到窗口成员，并沿神罗选侯链构造 `hre_electors` 列表内容。已核对的两个 `global+0x241c` 分支不阻断这些全局读取或列表填充。皇帝成员的外部消费者、部分条件的含义、任意观察方的完整可知范围和当前实际绘制尚未证明；结果不声明这些能力。原始依据与区分见[实时来源研究](../../04-实现研究/机制与宗教/神罗实时来源研究.md)及[界面数据流审计](../../../work/runtime/information-live-empire-20261102-001/ui-binding-audit-001/report.json)。

`empire_status`、`intervention`、`religious_leagues` 尚无本实时来源的公开实现。它们在实时查询中保持 `unsupported`；可从历史快照取得的内容不会填入当前结果。`reforms` 已由第118批独立来源提供，见上方接口。影响力的原始整数和相邻六个标志仅保留于先前私有研究，本生产采集器不读取它们。

## 验证记录

生产模块定向测试 18 项、Source/服务最终版本 23 项、工厂注册与历史来源隔离测试 12 项通过。首轮测试失败、相应源码版本和后续修正分别保存，未覆盖旧结果。

R76 下的一次[生产采集](../../../work/runtime/information-live-empire-20261102-001/production-capture-001/capture-receipt.json)通过严格保存 trace 重放：5620 次读取、45528 字节，句柄关闭，前后上下文及来源 pin 一致；两遍均核对 FRA 非玩家角色和物理 POR。当前皇帝为 HAB，选侯为 BOH、BRA、KOL、MAI、PAL、SAX、TRI。此生产读取没有采集先前私有探针中的影响力或六个机制标志。

[独立原始字节审计](../../../work/runtime/information-live-empire-20261102-001/production-raw-audit-001/report.json)的 15 项检查通过：分别核对底层读取与国家表行，并将全部读取地址区间与选侯节点 `+8`、影响力及六标志的区间比较，确认这些区间没有被本生产采集读取。该审计只解析已保存原件，没有调用生产 validator/projector 或重新读取游戏。

[实际 MCP 验收](../../../work/runtime/information-live-empire-20261102-001/mcp-001/receipt.json)通过：session 六字段查询、FRA/HAB 的两字段查询、手动报告，以及两个分别为 2 秒和 5 秒的周期，已支持字段一致；其余四字段仍为 unsupported。短周期取消后长周期仍保持运行，最后两个订阅均取消。服务器退出码为 0、读取线程结束，最终 discovery、上下文及来源 pin 核对完成。结果轮询按订阅状态取得稳定编号后再读取对应结果，不批量重复拉取历史内容。MCP 监控聚合 PeakPagefile 为 96407552 字节，未触及 1e9 字节停止线。MCP 结果保存各次内部验证报告的摘要哈希，没有逐份归档其私有 raw trace；它们不计作上述独立审计过的生产 capture。

上述采集与 MCP 都没有控制 UI、调用游戏函数、写游戏内存、推进日期、保存、重载或重新注入。当前完整回归的结果与剩余目标以[交接记录](../../../HANDOFF.md)顶部及本批 `summary.json` 为准；定向测试不证明全部信息目录已经完成。
