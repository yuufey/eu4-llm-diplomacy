# 战报攻守角色

248批补齐B01双方的战斗攻守角色。该信息用于区分一次进攻或防守的结果，并结合战损和胜负判断战局与后续外交选择。

## 读取

通过现有B01查询、报告或`battle_observation`事件订阅读取`sides`。事件编号沿用已交付的实际`event_id`。

```json
{
  "topic": "B01",
  "object": {"type": "battle"},
  "fields": ["sides", "winner"],
  "parameters": {"event_id": "替换为实际事件编号"}
}
```

`sides.value`中的每项保留原有结果侧索引、战斗侧索引、代表国和参与国，`role`返回`known/attacker`或`known/defender`。原始战斗侧0为进攻方，侧1为防守方。结果对象可能将两侧换序，因此根据完整国家引用建立唯一对应后再赋予角色。

无法唯一匹配时，`role`返回`unknown/RESULT_SIDE_MAPPING_UNRESOLVED`，B04的`gaps`也记录同一缺项。有效角色字段的目录声明包含`combat_side_roles`与`result_side_order_can_reverse`，公开投影版本为30。

B04中的`details.value.display.side_identity.value.attack_defend_roles`同步提供角色与原始战斗侧的对应。观察国是否参与、OUR/ENEMY模板标签、结果侧顺序及战斗攻守角色分别解释。战争攻守阵营需要其自身的战争数据。

## 固定版本依据

范围为EU4 1.37.4，EXE SHA-256为`b23fa0e1f698d31b01cdd1c3817a675805d8c6286cb66f9c231e6e2a42544d77`。

普通PE字节和有界反汇编显示，陆战和海战的虚表在`+0x10`共同引用写出函数RVA`0x22a450`。两者的`+0x60`分别读取返回1、2的类型函数，与既有采集器的种类校验相符。写出函数将对象`+0x20`子对象写入键`0x28f9`，`+0x28`写入`0x28fa`，固定编译键名分别为`attacker`、`defender`。函数范围为RVA`[0x22a450,0x22a618)`，preferred-image VA从`0x14022a450`开始。

原始字节、虚表、类型函数、编译键及摘要保存在[角色合同](../../../work/runtime/information-battle-roles-20261107-248-001/native-role-contract.json)。本次新增依据属于普通PE和反汇编静态证据，已有REA结果侧复制依据单列在合同中。

## 已取得的结果

既有真实陆战序号3中，法国FRA为防守方，HSA为进攻方。真实海战序号8中，PSA为防守方，KEL为进攻方。两个结果对象的顺序都是先防守方、后进攻方。查询、报告、事件订阅及数据库重开保存了相同角色字段。

本批181个唯一相关测试节点取得通过结果，包含结果侧换序、引用不匹配及重复匹配的反例。适用范围继承现有采集和观察方准入，测试采用历史实采及明确标记的映射变体。

当前游戏会话的新战斗尚未实采。完整原文、完整显示及其它原计划缺项继续按各自记录处理。
