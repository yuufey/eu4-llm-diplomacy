# 战争分数只读接口

W02 使用既有原生 `native_live_war_score_query` 返回真实战争分数。当前支持1.37.4、选定战争的 whole_war 模式、actor 视角。安装确认中缺少该能力时，字段返回不可用。

先用 W01 取得当前战争编号，方法见[战争发现与议和信息接口](战争发现与议和信息接口.md)。随后调用 `information_query`，例如：

```json
{
  "request_id": "war-score-query-unique",
  "queries": [{
    "topic": "W02",
    "object": {
      "type": "war",
      "war_id": "替换为W01返回的当前编号",
      "actor": "FRA",
      "recipient": "BUR"
    },
    "fields": ["war_score", "cumulative_goal_score"],
    "parameters": {}
  }]
}
```

actor、recipient 和明确的战争编号都必须提供。编号也可放在 `parameters.war_id` 或 `parameters.peace_context.war_id`；多个位置同时提供时必须一致。`peace_context.direction` 支持 demand/offer，`terms` 必须为空数组。W02 兼容 `action_id=white_peace`、`phase=initiate`，其来源会临时构造并释放一个空白议和预览，以取得已绑定的战争分数；返回记录的 `submitted=false`。读取不会推进日期。

| 字段 | 值与单位 |
| --- | --- |
| `war_score` | 分数对象，包含实际 mode、perspective、total、max_score、overview_goal_cap、goal、tooltip 及完整性 |
| `war_score.total` | 带符号总分；raw/scale=实际分数，scale=1，unit=`war_score_point` |
| `cumulative_goal_score` | 累计战争目标分的 metric 对象；scale=1000，同样以战争分数点为单位 |
| `war_score.max_score` | 原生总分上限，scale=1 |
| `war_score.overview_goal_cap` | 战争目标概览上限，scale=1000 |

方向由 actor 视角决定，保留原始符号。例如累计 raw=-5600、scale=1000 表示 actor 视角的-5.6点；不会因为议和方向改成 offer 就在信息层自行反转符号。战争分数与议和方案的 aggregate score、条款费用分别表示。

真实零值返回 `known` 且 raw/value 均为0。`goal.present=false`、`goal.inapplicable=true` 且来源已确认存在性时，累计目标分返回 `not_applicable/WAR_GOAL_NOT_CONFIGURED`。目标存在但读取失败、能力缺失或事件未验证时，返回对应未知或不可用状态。

同一 W02 查询只进行一次选定读取，多个字段共享该次结果。查询前后核对会话和日期，并核对返回的国家对、战争编号、模式和视角。读取中改变上下文会撤回字段，不自动重发。

当前 `war_score_sources`、`war_goal_controller`、`duration` 仍返回 `WAR_SCORE_FIELD_UNIMPLEMENTED`；每日战争目标分也缺少可靠来源。`war_score.complete` 仅描述这个分数对象已经实现的组成部分，不能表示全部战争状态、参与者或可见范围已经完整。

报告和周期订阅使用同一组查询。第66批验证与回归收据位于 `work/runtime/information-war-score-20261027-001/`；当前运行身份仍以 HANDOFF 顶部为准。
