# 战报战争编号接口

本接口读取观察国在当前游戏会话中可见的外交战报结果，并返回外交信息模型中的 `war_id` 字段。当前原生来源证明该编号与外交共享 registry 在 observer session 内一致；跨会话稳定性、对象 generation 和 cross-save 绑定仍未证实。

## 当前能力

当前批次的实机收据状态为 `passed`，服务器退出码为 `0`；生产比较收据为 `passed`。当前外交 `war_id` 结果以实机收据中的 session-scoped 记录为准。主动查询、报告和事件结果都复用相同的只读会话绑定；实机收据记录了 1 条事件结果。

本次观察器绑定 session `17112-1dd65cdbff135b5`、当前 game date `56559408`、观察国 `FRA`；事件自身的 raw date 为 `56558784`，二者是不同语义。样本的外交 `war_id` 为 `war_412ee732430b7c99_00000003`；FRA 是参战方之一，完整参战国为 `SAV, FOI, FRA, GNV, FLA`，双方结果代表为 `SAV, FLA`。新的 session、进程或 EXE 绑定需要重新查询当前状态；这不会改写事件自身的历史日期。公开接口读取已采集的战报，不提交外交动作。

## 查询示例

```json
{
  "request_id": "b01-war-identity-example-001",
  "queries": [{
    "topic": "B01",
    "object": {"type": "battle"},
    "parameters": {"event_id": "battle-observation:3ef3259111cfc004:01dd65cdbff135b5:9"},
    "fields": ["battle_type", "commanders", "end_date", "event_id", "location", "name", "sides", "war_id", "winner"]
  }]
}
```

返回结果中的外交 `war_id` 只在本次 observer session 内有效。它不是新造的 native integer，也不能据此推出跨 session 或 cross-save 的稳定身份。`status: "known"` 表示本次读取通过了身份、代码守卫和当前上下文检查；如果战争引用、双方关系行或结果对象无法绑定，接口返回 `unknown` 或 `partial`，不会用历史存档或相邻战争记录补齐缺失字段。

战争两侧保留原生顺序。双方国家 fullref 用于核对当前国家表中的槽位；fullref 不等同于稳定标签，也不能单独推出战争结束日期、胜者或结果文本。

## 覆盖与边界

本批覆盖矩阵仍为 74 个主题、397 个字段。配置矩阵当前按本批 live/catalog 结果计算为 available/partial/planned = `60`/`156`/`181`；live discovery 为 `54`/`143`/`200`。B01、B02、B03、B04 均保持 `partial` 且 `complete: false`；本次样本只证明 B01 的 `war_id`，B02–B04 的完整战报结果仍未实现。目录中仍为 `planned` 或 `unsupported` 的额外字段保持原状态，不因事件原始字节而升级。

外交 `war_id` 当前仍是 session-scoped；稳定公共编号、对象 generation/cross-save 绑定、跨会话去重、完整战争历史、战争名称的本地化绑定和 B01–B04 完整结果尚未闭合。
