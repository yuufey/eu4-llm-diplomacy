# 地图导出接口使用说明

要让服务定期把当前观察国的地图保存到指定文件夹，调用 `manage_political_map_export`。以下示例立即发布第一批，此后每六个**游戏月**更新一次。观察国沿用当前 MCP 会话绑定的国家。

```json
{"operation":"configure","directory":"campaign"}
```

## 定期更新

| 操作 | 调用参数示例 | 结果 |
|---|---|---|
| 配置 | `{"operation":"configure","directory":"campaign","interval_months":3}` | 发布首批或更新配置。重复提交已经发布的相同配置会复用现有结果。|
| 查看 | `{"operation":"status"}` | 查看是否启用、目标目录、上次成功日期、下次到期日和最近错误。|
| 立即更新 | `{"operation":"refresh"}` | 按已保存的设置重新发布三张图和省份数据。已停用的计划仍保持停用。|
| 停止 | `{"operation":"disable"}` | 停止自动发布，已有文件继续可读。|

首次配置时指定 `directory`。相对路径从服务允许的导出根目录算起，可传 `"."` 使用根目录。服务启动者也可用 `--map-export-directory` 指定自动导出的目录，或用 `--map-export-root` 指定调用者可选的根目录。

`interval_months` 范围为 1–120，初始默认 6。若首批日期是 1495.2.3，下次到期日为 1495.8.3。目标月份缺少对应日期时取月底。服务运行期间自动检查；游戏暂停不会重复发布。错过多个周期时一次采集当前局势，再从成功采集日计算下一期。用同一数据库、调用身份、观察会话和导出根目录重新启动服务，可恢复计划。

可在 `configure` 时指定一个中心：`center_country` 为国家标签，`province` 为已发现省份 ID，`xy` 为原始地图左上角起算的像素坐标。省略中心时取观察国领土的中间位置。`size` 可选 `compact`（768 × 512，默认）或 `detailed`（1152 × 768）。三个尺度共用中心和尺寸。

## 读取导出结果

成功响应中的 `result.latest_path` 指向导出目录的 `latest.json`。先读这份清单，再相对该目录打开下列路径。同批文件共用 `snapshot_id` 和游戏日期。

| 清单字段 | 内容 |
|---|---|
| `images.overview`、`images.region`、`images.local` | 总览、区域、局部三张 PNG |
| `snapshot` | JSON 数据。`owners` 按省份 ID 给出已发现省份的所有国，值为 `null` 表示所有国未知。所有国和控制国均已知且两者不同时，`controllers` 记录该省的控制国。缺少控制国条目时，占领状态可能未知。 |

服务保留最近两批。需要长期留档时复制对应批次。每张 PNG 都内嵌点选数据，可用 `python tools/political_map.py inspect <图片路径> <x> <y>` 查询，包括服务关闭之后。

## 在 MCP 中看图和点选

直接调用 `render_political_map` 即可看图。例如 `{"province":1876,"scale":"local"}` 返回局部 PNG 和 `view_id`；`scale` 也可选 `overview`、`region`。中心和尺寸与定期导出用法相同。首次看图、收到新战略简报后首次看图，或显式传 `"refresh":true` 时会采集新快照。

调用 `inspect_political_map`，将返回的编号填入 `{"view_id":"…","x":384,"y":256}`。坐标以输出图左上角为原点。服务可点选最近八张交互地图，返回省份、所有国或边界候选。定期导出独立采集，既不会占用交互图编号，也不会改变本轮正在查看的局势。

已确认的占领省份沿用所有国底色，再叠加控制国颜色的粗斜纹。点选该省可同时读取 `owner` 和 `controller`。需要刷新占领情况时，选择完整刷新。

## 只刷新战区的军事图层

调用 `render_political_map` 时用 `layers` 选择图层。`armies` 表示军队，`forts` 表示堡垒，省略或传空数组时只显示政治地图。总览图会隐藏堡垒。堡垒层只显示当前归属参战双方成员的堡垒。观察国只参加一场当前战争时可省略 `war_id`。同时参加多场时，在 `W01` 查询对应战争的编号并传入 `war_id`。选不到战争时，堡垒层返回原因。首次查看战区时可请求完整刷新：

```json
{"province":1876,"scale":"local","refresh_scope":"full","layers":["armies","forts"]}
```

有底图后，战时可只更新同一战区的军事图层。将上一张图的 `view_id` 放进 `previous_view_id`。画面相同时，响应只返回文字，`view.unchanged_from` 指向可复用的图片。`view.date` 是政治底图日期，`view.military.<图层>.date` 是该图层的采集日期。

```json
{"province":1876,"scale":"local","refresh_scope":"military","layers":["armies","forts"],"previous_view_id":"…"}
```

服务只在调用方显式选择 `military` 时采用军事刷新。底图缺失、会话失效或需要查新发现省份时，调用方选择 `full` 重新取得底图。图层返回 `partial` 或 `unavailable` 时，按响应中的 `reason` 和 `fields` 判断哪些数据可用。空记录仅在相应来源给出完整结果时表示没有对象。兵力标牌中的 O、A、E、X 分别表示本国、同阵营、敌军、其他。区域或局部图的标牌若用短线连接，线的端点指向所属省份。点选省份可读取本张图中该省的采集记录。

军队层显示本国陆军和所选战争的同阵营陆军，并尝试显示与本国陆军同处已知陆地省份的参战敌军。区域和局部图在同一省份分别标出友方和敌方兵力，点选省份可以查看各国兵力。军队层为 `partial` 时，图上空白处的敌情仍按未知处理。堡垒标牌显示等级、地图配置中明确列出的地形防御修正和实时围城天数。例如 `F2 +2 S42d` 表示二级堡垒、地形防御修正 +2、围城已持续 42 天。距下一阶段的天数与围城百分比目前未知。

定期导出也可在 `configure` 时传 `layers`，随后在 `snapshot.json` 的 `military` 中读取图层状态和数据。交互刷新和定期归档分别采集。
