# 供游玩模型使用的政治地图

模型在决定下一步查询前，需要看清本国周边各国的位置。第一次交付采用离线存档和省份位图，先验证从区域总览放大到边境、再识别所选领土的完整过程。

面向 MCP 调用方的参数、自动导出目录和定期更新说明见[地图导出接口使用说明](地图导出接口使用说明.md)。

## 规划中的战时地图刷新

模型在调用地图时选择完整刷新或只刷新军事图层。首次完整刷新建立底图。战时连续查看同一战区时，可显式选择只刷新地图取景窗口内启用的军事图层。缺少底图或会话变化时，模型需要重新请求完整刷新。取景窗口决定画哪一片区域，观察国的军事视野决定其中哪些部队可以显示。阵营按所查看战争的参战方划分，本国部队单独标记。无法确定阵营的可见部队按所属国标记。军队与堡垒可独立隐藏。军队用简图标和兵力数字表示，区域和局部图按省份、阵营显示，总览允许把邻近的同阵营部队合并标数。堡垒默认在区域和局部图显示。标牌保留等级和地形防御修正，例如 `F3 +2`。围城字段取自实时游戏，显示时区分阶段进度与下一阶段的投降概率。

- **采集。** 复用省份几何和地形。所有军事动态字段都从正在运行的游戏读取。对请求范围重新确认当前可见的部队集合、位置、实际人数和阵营，以及围城的开始、进度与结束。截图和存档仅用于核对。游戏实时来源缺少证据时，字段标为未知。须能发现新进入视野的对象。敌军移出取景窗口或观察国失去对它的军事视野时，从本次结果移除。只有能证明期间没有相关变化时，才可跳过读取，同一游戏日期内也适用。若游戏只提供完整集合枚举，则先枚举可见对象，再决定哪些省份要重画。
- **绘图与传输。** 复用同一取景窗口的底图。军事记录变化后，从当前记录重新绘制该取景窗口的军事标记，部队起点和已经解除的围城不会留下旧标记。未变化的战区允许调用方凭上次视图编号确认“无变化”，免传同一张 PNG。首次请求或缺少对应视图时返回完整图片。后续可通过实测比较整层重绘和仅重绘变化位置的耗时，再决定是否增加局部排版缓存。
- **一致性。** 观察国变化、重载存档或无法确认增量是否连续时，请求方先重新建立基线。模型需要最新省份归属或发现范围时选择完整刷新。底图和军事图层分别返回各自的观测日期。交互查看只出所请求的尺度，定期归档仍在同一游戏日期完成采集并生成三张图。
- **性能验证。** 分别测量无变化、部队跨省或进出视野、围城数值变动三类场景的采集时间、重绘时间和返回字节数。用同一时点的完整刷新核对可见部队、兵力和围城数值，尤其检查旧位置及已解除的围城标记是否清除。

## 第一阶段：只读存档原型

1. 从指定游戏地图的有效配置读取省份位图和颜色定义，将像素映射为省份 ID。区分陆地、水域和未知区域。
2. 从同一份存档读取日期、省份主权和观察国的发现记录。用不同颜色绘制已发现国家；未发现区域统一遮盖，点选时也应用同一限制。
3. 按省份或坐标选择中心，提供总览、区域、局部三档范围，以及紧凑、详细两档尺寸。输出 PNG，并让查询使用与画面一致的坐标系。
4. 使用同一真实存档导出欧洲总览与莱茵河局部图。检查图像尺寸、海陆、国家可辨性和小邦边界，从局部图选点并与存档所有国核对。记录实际耗时和输入范围。

## 实时地图与决策回合

统一 MCP 服务绑定运行中游戏的 installation.json 和逻辑控制国后，`render_political_map` 会返回 PNG、游戏日期、快照编号、视图编号和分项耗时。首次调用读取全图的发现状态和已发现省份的所有国。自管决策调度器取得新战略简报时会标记地图需要更新，并在简报中给出工具名。模型在本轮首次看图时采集，随后平移、放大共用这份快照。其他客户端可传 `refresh: true` 立即重采。两遍读取之间的日期、世界状态或省份结果出现差异时，工具返回错误，可在局势稳定后重试。

例如，调用 `render_political_map({"province":1876,"scale":"local"})` 放大法兰克福；随后把返回的 `view_id` 传给 `inspect_political_map({"view_id":"…","x":384,"y":256})`。同一服务保留最近八次绘图的视图编号。即使新地图的边界发生变化，旧图的点选仍依据旧快照。客户端只能选择视野中心，观察国由服务绑定。

命令行可直接指定当前安装记录，独立重复采集并输出每次的秒数。下面的 `$installation` 指向正在运行的 EU4 测试会话的 installation.json。采集器使用本项目已验证的 B23 读取布局，观察国从会话配置取得，按该国的发现记录绘制。

```powershell
python tools/political_map.py render --installation "$installation" --observer TUR --province 1876 --scale local --samples 5 --out work/runtime/rhine-live.png
```

未来增加神罗省界或多尺度矢量边界时，可沿用现有的观察国、快照与视图编号。

## 离线入口

在项目根目录运行以下 PowerShell 命令。Python 环境需要 NumPy 和 Pillow（10.1 以上）。将 `$save` 设为本机 EU4 文本存档的路径，游戏安装与用户数据目录沿用项目的 `local.env` 配置。请选用与存档相符的游戏和模组配置。

```powershell
python tools/political_map.py render --save "$save" --observer TUR --province 1876 --scale local --size compact --out work/runtime/rhine.png
python tools/political_map.py inspect work/runtime/rhine.png 384 256
```

`--province` 将指定的已发现省份置于视野中心，也可用 `--xy X Y` 指定原始地图像素，以左上角为原点。三档视野 `overview`、`region`、`local` 默认横跨 1350、650、160 个原图像素；靠近地图边缘时窗口向内平移。紧凑图为 768 × 512，详细图为 1152 × 768。切换尺寸保留地理范围。

图内使用国家标签；暗灰表示未发现或缺少可见性记录，浅蓝表示已发现水域。PNG 内嵌当时的可见省份索引。点选使用输出图片的像素坐标，左上角为 (0, 0)。缩小后一个输出像素覆盖多个省份时返回候选项，可用省份 ID 为中心重新放大。同一 PNG 即可在游戏关闭后回查，转码或去除元数据会使点选失效。

省份中心会在图上以小三角标出。`--country TUR` 会选择该国已发现领土上靠近中间的位置，省略中心参数时使用观察国。颜色取自有效游戏配置的国家定义，找不到定义的标签使用稳定的替代色。局部图显示省界，点选返回的 `definition_name` 是静态地图定义名。底色表示省份所有国。已发现省份的控制国与所有国不同时，用控制国颜色绘制粗斜纹。

首次读取会在 `work/runtime/political-map-cache` 缓存已发现省份的所有国和已确认的占领控制国。后续调用以存档 SHA-256 和观察国查找缓存，同一存档切换视野可以复用。ZIP 存档需要包含文本格式的 gamestate，日期和物理玩家可来自 meta。运行环境使用 Python 3.11 或以上版本。
