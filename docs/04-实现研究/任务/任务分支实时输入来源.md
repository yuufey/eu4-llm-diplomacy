# 任务分支实时输入来源

后续实现已接入国家旗标、地图模式和 Domination 原生条件的有限结论，见[任务分支输入接口](../../02-使用与接口/任务/任务分支输入接口.md)及本批 `branch-inputs-runtime-003.json`。Domination 只在全局字节非零、覆盖字节为零的已证明短路路径上给出真；其他组合的 TLS 路径和完整 DLC 清单仍未提供。下文为接线前对已有代码的调查，保留其当时的 `missing` 状态，不覆盖后续原生布局、REA 证据与实采结果。

本文只做现有来源的机械定位，回答 1.37.4 的任务根 `potential` 求值所需的两个实时输入是否已有可复用来源：`has_dlc = "Domination"` 的实际加载状态，以及 `map_setup` 模式。机器可读清单见 [`existing-input-sources.json`](../../../work/runtime/information-branches-20261024-001/existing-input-sources.json)。

结论是：当前仓库没有能证明这两个值的 1.37.4 实时 API 或偏移。静态 `dlc_load.json`、存档头的 `dlc_enabled`、任务 slot、暂停状态和 `world_id` 都不能替代它们。

## 检查边界

目标版本和可复用的任务 profile 是 1.37.4，EXE SHA-256 为 `b23fa0e1f698d31b01cdd1c3817a675805d8c6286cb66f9c231e6e2a42544d77`。本次只检查 `bridge/information`、相关 `bridge` 文件、`work/native` 文本和 `reverse_engineering` 文本索引，并对选定的小文件做有界读取；没有启动游戏、读取进程、调用 RPM、调用 REA、读取 43MB 存档或扫描大型 runtime 反汇编。

之前的分支输入清单已经证明 18 个 FRA 根的静态条件包含 `has_dlc` 和 `map_setup`，但实时输入仍为 unknown；本次只定位来源，不实现求值器。

## DLC 实际加载状态

当前状态为 `missing`。可见的 `dlc_load.json` 只被静态来源用于寻找启用模组描述文件；测试 fixture 也只在进程启动前验证配置文件存在和内容固定。`SavedMissionSnapshot` 的 `dlc_enabled` 是历史存档字段，不能回答当前游戏进程加载了什么。

要安全支持这个输入，需要一个与 1.37.4 EXE SHA 和当前 session/world 绑定的来源，证明引擎 `has_dlc` 判断所读取的 DLC manager/加载集合。需要保存读取范围、RVA/VA 区分、原始字节或结构校验，以及同一时点的稳定性证据。没有这些证据时，`has_dlc = "Domination"` 必须保持 `unknown`。

## `map_setup` 模式

当前状态为 `missing`。`map_setup = map_setup_random` 只在任务静态规则中出现；现有实时 C01、任务 profile 和任务 RPM reader 都没有该字段或偏移。不能从任务 slot、存档头、国家、日期、暂停状态、`world_id` 或静态地图文件推断地图 setup。

下一步需要定位 1.37.4 世界初始化/地图 setup 状态的版本绑定存储或引擎 evaluator，并以同一 session/world 的只读观察证明它。仅有静态规则或推测出的字段布局时，`map_setup` 仍为 `unknown`。

## 可复用边界与下一步

当前可以复用既有任务 reader 提供的 session/date/任务 slot 读取，以及 `ObserverSession.health()` 提供的身份绑定；不能在这些结果上附加猜测的 DLC 或地图字段。根求值继续使用 `true`、`false`、`unknown` 三值规则，缺少任一实时原子输入就不宣称当前分支可见。

下一步由潜在条件引擎路径的负责人取得版本绑定的 evaluator/DLC 证据；地图 setup 采用同样的证据标准。确认来源后，再单独增加实时输入适配器和一致性检查；本轮不修改生产代码，也不把配置或存档元数据提升为实时事实。
