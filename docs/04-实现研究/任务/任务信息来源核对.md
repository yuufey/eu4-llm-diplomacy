# 1.37.4 任务信息来源核对

2026-10-24 后续复核：完整的 `SavedMissionSnapshot` 流式解析确认下表第五槽还含有 `fra_missions_5_continuation`，总计 18 个根，与当前纯 RPM 读取一致。初次机器摘要漏列了这个末尾值；原始 `information-stage2-20261024-001/mission-source-review.json` 保留历史错误，不作为最新完整清单。修正依据见 `information-missions-20261024-001/live-acceptance-001/saved-snapshot.json` 的原始块及 SHA，存档文件未变化。完成字段缺失与实时已确认空列表仍分别表达。

后续接口已落地，当前状态见[任务接口](../../02-使用与接口/任务/任务信息接口.md)与[原生读取合同](任务原生读取合同.md)，最终实时证据为 [live-acceptance-003/report.json](../../../work/runtime/information-missions-20261024-001/live-acceptance-003/report.json)。下文“本次核对”和 `planned` 描述最初第二批离线研究，保留其历史范围，不覆盖后续交付。

最初核对只读取本地游戏文件、启用模组清单和 R70 测试存档，没有启动游戏、调用原生查询或修改存档。目标是区分 M01–M04 中可以从静态任务脚本取得的候选信息，以及只有在当前存档或游戏会话中才能确认的实际信息。

## 结论

R70 存档是 43,165,756 字节的纯文本 `EU4txt` 文件。存档头记录的日期为 `1455.11.13`，玩家为 `POR`，保存版本为 `1.37.4.0`。在 `countries.FRA` 块中，程序读到了一个 `country_missions` 块，其中有五个 `mission_slot` 记录。每个记录保存了该槽位当时的任务树根标识及其候选分支；这些值可以作为这个存档时点的已保存任务树快照。

同一个 FRA 块没有 `completed_missions`、`active_missions`、`mission_progress` 或 `mission_tree` 字段。`completed_missions` 并不是扫描器漏读的字段：同一存档的 SWE 块有该字段并列出了三个已完成任务。因此，对 FRA 只能确认保存的任务槽位，不能从这个存档确认已完成任务、当前可完成状态或条件进度。字段缺失也不能单独证明 FRA 没有完成任务，因为还需要确认游戏对空集合采用省略还是写空块。

当前有效的法国静态候选来自启用的 `Chinese Language Supplementary Mod for 1.37/missions/DOM_French_Missions.txt`。它覆盖游戏安装目录中同名的 `DOM_French_Missions.txt`；两个文件的 SHA-256 不同，但结构化比较得到相同的 27 个法国任务树根和相同的根内任务标识。启用的主中文模组与 `llm_bridge` 没有 `missions` 目录。静态候选不能只依据 `tag = FRA` 加入结果：必须先解析版本、DLC 和启用模组的文件覆盖关系，再按 `potential_on_load`、`potential` 及当前状态判断。

因此，本轮对 M01–M04 的可靠边界如下：

| 主题 | 本轮可以确认 | 仍然未知或只能部分确认 |
| --- | --- | --- |
| M01 实际加载的任务树 | R70 的 FRA `country_missions` 保存了五个槽位及根标识；有效静态文件可以列出 27 个法国任务树根和其任务标识 | 名称和说明尚未从本地化文件读取；存档之后是否发生任务树交换、当前会话是否与该存档一致，尚未确认 |
| M02 前置与状态 | 静态脚本中的 `required_missions`、`potential`、`trigger` 可以有界解析 | FRA 没有完成列表或进度字段；当前可完成状态和条件进度需要当前国家、外交和省份状态，不能由静态脚本单独给出 |
| M03 目标条件 | 静态脚本中的 `provinces_to_highlight`、省份/区域/国家条件可以保留为规则表达式 | 规则表达式不是当前拥有、控制、核心或属国状态；需要同一时点的状态快照并进行作用域求值 |
| M04 奖励与后续解锁 | 静态脚本中的 `effect`、条件分支和 `swap_non_generic_missions` 可以列为候选规则 | 不能据此声称奖励已经执行、修正已经生效或某一分支已经被选择；这些事实需要存档字段或会话读取证据 |

## 来源和版本范围

版本文件 `launcher-settings.json` 的 `rawVersion` 为 `v1.37.4.0`。R70 存档的 `savegame_version` 为 `first=1, second=37, third=4, forth=0`，并且 `dlc_enabled` 包含 `Domination`、`Emperor`、`Leviathan` 等 DLC。用户数据中的 `dlc_load.json` 明确列出三个启用模组：

```text
mod/Chinese Language Mod for 1.37.mod
mod/Chinese Language Supplementary Mod for 1.37.mod
mod/llm_bridge.mod
```

启用补充中文模组的 `missions` 目录有 59 个文件，总计 3,068,059 字节；在其中搜索法国任务根和 `fra_` 标识时，只有 `DOM_French_Missions.txt` 命中。游戏目录的 228 个任务文件中，法国相关候选还包括 `EMP_French_Missions.txt` 和 `French_Missions.txt`：

- `EMP_French_Missions.txt` 的每个法国根都带有 `potential_on_load`，要求 `has_dlc = "Emperor"` 且 `NOT = { has_dlc = "Domination" }`。R70 同时启用了这两个 DLC，所以这组 Emperor 任务不是该存档的有效候选。
- `French_Missions.txt` 的 `french_missions_north` 和 `french_missions_colonial` 要求 `NOT = { has_dlc = "Emperor" }` 且 `NOT = { has_dlc = "Domination" }`，同样不适用于 R70。
- 启用补充模组的 `DOM_French_Missions.txt` 没有 `potential_on_load`。它的主要根条件包含 `tag = FRA`、非随机地图和 `has_dlc = "Domination"`；带国家 flag 的根还会增加分支条件。

这里的“有效来源”指按照当前 `dlc_load.json` 和同路径模组覆盖关系选择用于静态解析的文件。它仍然只描述脚本候选，不能替代游戏在载入和运行期间对条件的求值。

## R70 中 FRA 的保存任务槽位

流式扫描的 `countries.FRA` 行范围为 782376–786747。`country_missions` 从 786734 行开始，五个 `mission_slot` 的原始内容如下：

| 槽位 | 存档记录的根标识 |
| --- | --- |
| 1 | `french_missions_1`、`french_missions_1_blank_hre`、`french_missions_1_Continuation_a` |
| 2 | `french_missions_2`、`french_missions_2_blank_hre`、`french_missions_2_Continuation_b` |
| 3 | `french_missions_3`、`french_missions_3_blank_hre`、`french_missions_3_continuation_after_hre_missions`、`french_missions_3_normal_continued` |
| 4 | `french_missions_4_normal`、`french_missions_4_branching`、`french_missions_4_normal_continuation`、`french_missions_4_normal_contiuation` |
| 5 | `french_missions_5_normal`、`french_missions_5_branching`、`french_missions_5_continuation_normal_1`、`fra_missions_5_continuation` |

这些根标识均可在有效模组版本的 `DOM_French_Missions.txt` 中找到。这个一一对应关系是把保存字段视为任务树快照的依据；实现 M01 时应保留槽位顺序、重复 `mission_slot` 记录和根标识，而不能重新根据 FRA 标签推算一套树。

同一存档的 SWE 块在 `completed_missions` 中保存了 `swe_gain_support_from_estates`、`swe_military_advisor` 和 `swe_swedish_allies`。这说明完成列表在有内容时会进入存档，但 FRA 块本身没有该字段。完成 ID 只能回答已完成的任务，不能代替 `country_missions` 对当前加载树的记录。

## 静态候选与实际树的判定规则

静态适配器应先建立带版本和来源指纹的文件栈。对于当前安装，至少要记录游戏目录中的基础文件、`dlc_load.json`、启用模组目录成员清单以及同路径覆盖文件的 SHA-256。基础文件和启用模组出现新增、删除或覆盖关系变化时，应使旧的候选图失效，不能静默回退到 basegame。

对每一个任务树根，建议把字段分成三个层次：

1. `static_candidate`：文件中定义的根标识、槽位、任务标识、`required_missions`、`potential_on_load`、`potential`、`trigger`、`effect` 和 `provinces_to_highlight`。这些字段只说明规则文本和候选结构。
2. `saved_loaded_tree`：如果目标国家的存档块包含 `country_missions.mission_slot`，直接记录存档中的槽位和根标识，并附上存档日期、版本和存档哈希。这个结果表示“存档记录的任务树”，不应改名为当前游戏会话的实时树。
3. `evaluated_state`：只有拿到同一时点的国家、DLC、国家 flag、已完成任务、省份、外交关系和其他脚本依赖后，才能求值 `potential`、`trigger` 和分支效果。缺少其中任一类输入时，相关字段应为 `partial` 或 `unknown`。

`potential_on_load` 适合标记载入时是否允许根进入候选集合，`potential` 仍然需要当前国家状态。两者都不能把 `country_missions` 之外的静态根自动写成“当前已加载”。`swap_non_generic_missions = yes` 位于 `fra_ducal_lands_avignon` 的效果中；它表明任务完成后的运行时效果可以替换非通用任务。实现不能把初始静态树当作跨时间不变的树，也不能从某个 `swap` 文本出现推断该效果已经发生。

本次没有在 FRA 块中找到 `fra_chose_to_piss_off_pope_flag`、`fra_papal_lap_dop_flag`、`fra_shed_the_blood_of_the_saxon_man_flag` 或 `fra_fufujoni_flag`。这只能说明这些字面量没有出现在本次捕获的 FRA 块中，不能替代引擎对任务分支的求值，也不能据此证明所有历史分支选择都没有发生。

## 现有研究索引与下一步缺口

现有目录仍把 M01–M04 标为 `planned`，`docs/01-需求与计划/LLM导出信息目录.md` 只登记了静态键线索，并明确指出本国实际任务树及进度需要结合生效脚本和当前国家状态。`docs/信息导出与订阅开发计划.md` 的阶段二完成标准也要求区分静态定义与当前生效分支，并能对应实际任务界面。本轮没有把研究结果登记为已交付能力。

可以先实现的窄范围是：在版本和模组来源完整时，有界解析法国任务根及其静态规则；对 R70 这类存档读取目标国家的 `country_missions`，输出 `saved_loaded_tree`；对缺失的完成状态、当前可完成状态、条件进度、本地化名称和说明返回明确的 `unknown` 或 `partial`。要把 M01 声明为当前实际加载树，仍需要一份与会话绑定的实时读取证据，或一份已证明语义的存档字段契约。M02–M04 还需要状态求值器以及任务完成/奖励的实际字段来源。
