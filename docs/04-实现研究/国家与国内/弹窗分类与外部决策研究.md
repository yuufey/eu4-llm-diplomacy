# EU4 弹窗分类与外部决策研究

研究日期：2026-10-24。

本研究回答四个问题：如何为不同弹窗找到上层类别，如何区分通知与待处理选择，如何由外部程序选择事件选项，以及如何阻止原生 AI 抢先作出受控国的决定。信息提取需求另见 [LLM 导出信息目录](../../01-需求与计划/LLM导出信息目录.md)。

目前已确认消息配置中的主题分类与具体消息 key，并通过静态 REA 查询定位了脚本事件的窗口、选项命令、AI 自动选择分支和实例登记路径。外交请求已有可复用的桥接分类、待处理记录和授权执行结构；收到盟友参战召唤后的回应仍需单独研究。尚未证明所有弹窗共用一个原生 C++ 基类，也尚未把新的事件选项路径接入外部接口。

### 业务对象比窗口外观更适合决定处理权限

| 业务类别 | 主要判别依据 | 处理原则 |
| --- | --- | --- |
| 普通结果通知 | 消息 key、主题类别、双方、日期及观察方 | 导出既成事实，按重要性触发 LLM 重新评估 |
| 外交待处理请求 | 动作家族、请求编号、完整双方、请求状态和原生队列成员关系 | 交给 LLM 接受或拒绝，受控国原生 AI 不抢先回应 |
| 脚本事件选择 | 事件定义、事件实例编号、国家或省份作用域、选项及其条件 | 普通事件由原生 AI 处理；需要接管的具体事件另行分类和授权 |
| 战役结果 | 陆海战类型、所属战争、双方、战果与损失 | 自动逐场导出，无需作出选项决定 |
| 确认或系统提示 | 具体提示用途和回调 | 与国家业务决定分开，不将通用确认按钮视为外交接口 |

建议未来为统一消息输出保留“业务类别、具体子类型、涉及国家、接收方、是否需要回应、决策归属及期限”。这是桥接层的归一化设计，不表示已经恢复了游戏中覆盖全部弹窗的统一基类。

宿敌变化属于需要及时获知的事实。本国是否更换宿敌、改善关系或调整联盟由 LLM 决定；外国将本国列为宿敌本身没有本国的接受或拒绝选项。

## 脚本事件的原生路径

### 窗口与选项命令

本机 `interface/eventwindow.gui` 定义了 `EventWindow`、`Title`、`Description`、`event_option_listbox`、`event_option_entry` 和选项按钮。文件 SHA-256 为 `82defb3b1b429787d37b51cfb1992ad7afe705aa2ee390d2cba1a25bfb5fad54`。

静态调用关系为：

```text
事件窗口构造 0x10B9920
  → 窗口内容与选项按钮建立 0x10BA070
  → 选项按钮回调 0x10BC0F0
  → 选项提交 0x10BC1A0
  → 选择命令构造 0x6F2690
  → 游戏命令队列
  → 选择命令执行 0x6F2730
```

窗口建立函数遍历原始选项并检查显示条件；被过滤的选项仍占原始索引。按钮回调从标识中取得选项序号，不能把“界面上第几个按钮”直接当作命令中的原始选项序号。

执行函数的诊断文本明确包含 `CSelectEventOptionCommand`。其构造函数设置虚表 RVA `0x1CAB740`；以下字段由构造和执行路径交叉核对。

| 相对命令对象的偏移 | 静态观察 |
| --- | --- |
| `+0x44` | 写入内部标识 `0x2998`；不据此宣称存在同名公开脚本 effect |
| `+0x50` | 事件定义对象指针；执行时重新解析并写回 |
| `+0x58` | 从事件对象取得的定义引用，用于执行时解析 |
| `+0x60` | 原始选项序号，执行时按选项数组范围检查并取对应对象 |
| `+0x68` | 从调用方复制的事件作用域上下文 |
| `+0x138` | 事件实例编号，执行结束路径将其交给实例移除函数 |

执行路径不只是关闭窗口：它解析事件定义和选项，调用选项相关处理、效果及 `after` 路径，最后以实例编号清理登记。直接关闭窗口、重新触发同名事件或只复制一部分效果，都不能视为完成对已有事件的正常回应。

该路径为开发外部选项接口提供了候选入口，尚未验收可调用 ABI、游戏线程约束、跨帧对象寿命及过期实例行为。执行入口中看到的序号检查也不能替代对当前选项条件和权限的完整校验。

### 实例登记与 AI 自动选择

事件触发函数 `0x6F4F70` 的已观察顺序如下：

```text
执行 immediate
  → 对有选项的事件登记实例并取得编号
  → 按控制条件分流
     → 人工展示或其他处理
     → AI 选择选项 0x6F01B0
        → 构造选择命令 0x6F2690
        → 提交命令
```

实例登记函数 `0x756F30` 生成正数编号并检查现有编号冲突。其记录位于当前游戏对象的 `+0x1E98` 容器，记录宽度 `0x28`；可观察到事件对象、复制的作用域、日期相关字段和实例编号。具体登记与移除机制不等于已经证明可任意延长事件寿命，超时、保存和重载语义仍未完成研究。

AI 分支在选择函数返回 `-1` 时把它改成 `0`，然后继续构造选择命令。因此不能通过让 AI 选择器返回 `-1` 来表示“等待 LLM”。该调用方会继续尝试选择第一个原始选项。

由这条顺序可得两个实现约束：第一，AI 可能在窗口出现前已经选定选项，窗口钩子不能覆盖全部选择；第二，`immediate` 在选择前已经发生，接管某个事件时应保留正常触发及实例登记，不能简单跳过整个触发函数，也不能回应时重新执行一次触发。

### 公开脚本资料能证明什么

CWTools 的 [事件规则](https://github.com/cwtools/cwtools-eu4-config/blob/a85622d368bbb7afca938ed70fdd5eda44aec769/events/events.cwt) 和 ParadoxCode 的 [events.json](https://github.com/danxiaogu520/ParadoxCode/blob/75b601a51d80e1c1c88b0b730603f28b2a67325d/rules/eu4/events.json) 记录了国家及省份事件、`immediate`、带条件和效果的 `option`、`ai_chance` 与 `after`。这些规则可辅助导出事件内容、选项条件和 AI 权重，但不能单独提供当前待处理实例的外部回应接口。`hidden` 控制事件展示，不能解释为关闭 AI 选择。

公开第三方命令资料将控制台命令写为 `event [event id] [country tag] [option id]`；[EU4UniversalConsole](https://github.com/Taikelenn/EU4UniversalConsole/blob/b8a0bd3a55a483b5ab7193ce16307c6767db979c/README.md) 也提到事件选项选择，但其转发代码没有建立“回应已有待处理实例”的完整语义。因此不能用这些资料替代本机事件实例与原生命令研究。

`country_event_with_option_insight` 也不能当作外部选项选择器。[Atlas Novum 的实际定义](https://github.com/Amazonys/Atlas-Novum/blob/1c8f08d6d3e3db2785519f9828ac5d65d4dba2c3/AN_Core/common/scripted_effects/02_scripted_effects_mission_rewards.txt) 将普通事件触发与选项效果提示组合起来，作用是帮助展示选项效果。

## 外交待处理请求与权限控制

### 可以复用的桥接结构

当前源码中的 `ActionFamily`、`Phase`、`State` 是桥接权限账本的枚举；`LifecycleActionShape` 是从不同原生动作提取的字段快照。它们有助于统一接口，但不是本轮恢复出的原生统一 C++ 基类。

`InboundPendingView/Record` 同样是桥接记录，保存请求编号与 generation、双方、日期、外交官、状态与变体、家族，以及原生队列节点和动作地址。已观察到队列成员关系，只表示请求仍待处理，不表示已经接受、执行或持久化。

### 参战召唤与宿敌的边界

宣战接口已有 `call_allies`、土地承诺和共同参战方等出站参数，但“发起战争时召集盟友”与“收到盟友召唤后接受或拒绝”是不同链路。当前通用入站形状检查明确排除了 `declare_war`；本轮没有在该目录中找到盟友参战召唤的独立入站对象、回应与 AI 挂起接线。需继续定位召唤的产生、等待、回应、过期和执行路径，不能把已有出站参战功能登记为入站覆盖。

本国设置、替换、移除宿敌已有独立 country-command 权限入口，见 [rival-authority.inc](../../../work/native/rival-authority.inc) 166–205、383–418 行。受控国的主动动作要求绑定；其他国家继续执行原生路径。宿敌通知没有类似联盟的接受或拒绝对象，应及时导出事实，由 LLM 判断后续动作，不应阻止外国设置自己的宿敌。

### 通知历史不能代替待处理队列或持续订阅

既有 [1.37.5 消息研究](../原生外交/native-pair-replies-1375.md) 在另一 EXE 上确认了消息 key、双方与日期字段，以及受消息设置过滤、限制为最近 200 条的历史记录。这说明通过历史快照补读消息存在遗漏条件；没有找到通知不能据此判断对方尚未回应，空队列也不等于拒绝。

该结论支持优先研究消息产生或派发时的导出入口，但本轮没有实现新的消息持续订阅，也没有把 1.37.5 历史对象偏移移用到 1.37.4。

## 外部决策与拦截的实现方向

本节是基于上述证据提出的设计，尚未实现或运行验收。

1. **先确定决策归属。** 普通事件默认原生 AI；外交提议及需要接管的特定脚本事件交给 LLM；宿敌变化、宣战通知和战报及时导出。业务内容影响归属，不只依据窗口标题、主题类别或是否显示按钮。
2. **在自动选择前保留实际对象。** 外交请求复用其待处理身份；事件保存事件实例编号、定义引用及完整作用域。保留事件正常触发的 `immediate`，仅挂起被接管实例的自动选择，不能只拦截窗口。
3. **外部选择绑定一个明确实例。** LLM 提交选择时，对照当前会话、受控国、请求或事件实例、原始选项及条件重新校验。选项已失效、请求被撤回或状态已改变时，返回实际状态，不重新触发事件。
4. **在最终执行处复核一次性授权。** 仅允许对应实例与完整参数的选择执行；保留原生选项效果、`after`、响应结算和清理流程。授权不能被复制成对另一事件或请求的许可。
5. **分别处理期限和结果。** 等待 LLM 时不能由 AI 偷选；但挂起并不自动暂停游戏内期限。需要继续确认过期、默认选择和清理机制，并记录实际执行结果，不能把命令入队当作已生效。

不建议通过全局 AI 开关实现外交或事件接管。事件触发路径使用的 AI 判定可能被其他系统复用，关闭国家整体 AI 既不能证明对象会进入可回应队列，也可能改变用户希望保留的原生行为。应围绕受控国、具体家族和实例限定拦截范围。
