# 逐场战报胜负字段

第二十九批已接入海战四类初始船数，见[海战初始数量](逐场战报海战初始数量.md)。下文保留第二十八批当时状态。

当前FRA会话已通过公开报告和事件订阅收到巴黎战役的胜负：FRA、FOI、AUV一侧获胜，观察国FRA为victory。B01新增winner字段，保持partial；同一服务配置现为48 available、111 partial、238 planned，仍为74主题397字段。见[实际报告](../../../work/runtime/information-battle-outcome-20261026-001/live-result-001.json)和[交付摘要](../../../work/runtime/information-battle-outcome-20261026-001/live-acceptance-001.json)。

查询B01时，在fields中加入winner即可，报告配置与事件订阅沿用现有入口。winner的participants列出整条获胜参战侧，representative只是该侧的结果代表国。combat_side_index与result_side_index分别指原始侧和重排后的结果侧；observer_outcome取victory或defeat。它们不表示进攻方或防守方。

胜负方向来自固定1.37.4的原生战斗结束处理。正常结束、兵力比例溃灭以及最后单位移除路径，将获胜原始侧编号写入summary+4C。结果对象以flag108记录结果侧方向，双方重排时同步翻转。消费端要求完整国家引用形成唯一双射，并要求这两种方向一致；不能确定时只将winner标为unknown，保留其他可读字段。新REA范围、原始证据和推断条件见[方向合同](../../../work/runtime/information-battle-outcome-20261026-001/outcome-contract-001.json)。

本批复用已捕获的14条真实记录，9条陆战和5条海战的两种方向表示均一致。当前FRA公开工具实际交付的是其中既有巴黎记录，下一tick为0条；这次消费验证没有重放战斗。旧报告保持原内容，新结果标记projection_version=3，已有订阅游标不回退。

胜负仍未与实际结果窗口逐项对照，runtime_popup_verified=false。完整窗口文本、海战兵种损失与剩余、歼灭或撤退分类、俘获和奖励、稳定战争/战斗编号及其他已知战场的可见性继续开发；不能由伤亡或剩余数量代替这些字段。

本批沿用现有游戏进程、DLL和成熟保存/启动工具，没有保存、重启、推进日期或外交派发。消费端验证读取既有接收库；未启停原生采集。完整开发目标与阶段二、三、四保持不变。

相关测试分组通过46项，包括真实陆战胜利、海战败方、结果重排、不一致方向保留unknown及既有摄取/组合来源。见[战斗专项](../../../work/runtime/information-battle-outcome-20261026-001/regression-battle-001.xml)、[海战分支](../../../work/runtime/information-battle-outcome-20261026-001/regression-naval-outcome-001.xml)和[组合验证](../../../work/runtime/information-battle-outcome-20261026-001/regression-integration-002.xml)。最近全套的既有失败/错误保持原记录，本批未重跑全套。
