## 第187批已证明的年度变化路径

目标固定为 EU4 1.37.4，EXE SHA-256 为 `b23fa0e1f698d31b01cdd1c3817a675805d8c6286cb66f9c231e6e2a42544d77`。静态 image base 为 `0x140000000`，运行时 VA 必须用实际 module base 加 RVA。

REA Evidence `ev_2929804b5caa01012a1d35d652cf8406eeeda7489645945315de2f706947eac2` 对应 RVA `[0x948cd0, 0x949498)`，共1,992字节。它生成具名好感修正提示，并向调用者提供的累计量加入年度变化：

- 当前值取记录 `+0x20`，以1000为比例转换。
- 记录 `+0x25` 非零时，函数直接返回，不向这一年度变化累计量添加贡献。这个字节具有实际用途，不能当成填充字节。
- 基础年度变化量取已加载 definition 的 `+0x58`。这与磁盘配置解析得到的声明属于不同来源。
- 当前原始值为负时，基础量还要结合国家属性、一个虚调用结果及国家对计算入口 `0xb4ded0` 的结果；因子下限为零。
- 正常分支将上述乘积除以1000；结果小于1时返回，否则根据当前值的整数转换结果向累计量加减，并附上 `YEARLY` 文本。

这是静态计算路径证据，没有调用该游戏函数，也没有观察实际提示绘制或年度结算。特别是绝对值不足1点的记录涉及整数截断，不能自行按实数符号改写算法。记录 `+0x25` 非零也只证明此提示函数不计年度贡献，不能直接宣称整个游戏永不改变该记录。

普通 PE/Capstone 分析另确认 `[0x3d62dd, 0x3d6399)` 内存在遍历当前修正、检查当前值、调用上述提示函数的路径。这部分是普通反汇编，不能标作 REA Evidence。第185批已有的私有 typed 记录包含 `+0x25`；原8条记录此字节均为0，直接复用这些原始结果，没有重采。
