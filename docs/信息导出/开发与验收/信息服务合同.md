# 信息查询、调度与订阅合同

## 同主题字段来自不同适配器

组合层允许不同适配器实现同一主题中的不同字段；重复拥有同一字段仍会被拒绝。每个字段保留自己的对象类型、版本和触发能力，订阅按实际请求字段校验。例如 T02.home_node 接受 FRA 国家对象并支持周期读取；静态 upstream/routes 接受节点对象并仅支持主动查询。主题列出的触发方式是各来源的合集，调用者还应查看字段的 triggers。

一个查询可以读取多个来源的字段。组合层只向各来源发送其负责的字段，并分别保留来源、失败原因及静态/实时范围；实时来源不可用或会话变化时，仍保留有效的静态结果。默认字段跨越不同对象视角时，当前视角不适用的字段单独返回 not_applicable，不阻断其他字段。只请求不受支持的对象视角时仍会明确拒绝。各适配器对同一查询的参数 schema 和对象规范化结果必须一致，否则整体拒绝配置。主来源继续独立轮询事件，读取适配器不会增加事件消费者。

本合同对应[开发计划](../计划/信息导出与订阅开发计划.md)的通用框架。信息主题和字段由来源适配器声明；能创建订阅，不表示来源已经取得数据，也不表示外部模型已经阅读结果。目录中尚未实现的项目继续记录缺口。

## 查询与结果

`InformationService` 接收一个只读来源、SQLite 数据库路径、可选输出适配器和可信的所有者标识。所有者由宿主配置，不接受工具请求覆盖。不同所有者的报告、订阅、请求编号和结果分别保存。这个标识提供服务内的分区，宿主仍负责鉴别调用方。

查询包含 `topic`、`object`、可选 `fields` 和 `parameters`。能力发现返回主题的字段、对象类型、参数 schema、版本和触发能力。服务先校验整份查询，再交给适配器；来源还可以检查对象身份和可见范围。一次调用最多包含 64 项查询。

结果记录请求编号、结果编号、会话、观察方、游戏版本、游戏日期、采集时间、具体对象、来源和完整性。每个字段分别标记：

| 状态 | 含义 |
| --- | --- |
| `known` | 取得了本字段；`value` 可以是零、`false` 或空集合 |
| `unknown` | 尚不知道该值，或来源没有返回本字段 |
| `invisible` | 当前观察方无权知道该值 |
| `not_applicable` | 本对象或条件不适用 |
| `unavailable` | 当前来源或读取失败 |
| `stale` | 数据已经过期，或采集期间上下文发生变化 |
| `unsupported` | 此来源未实现该字段 |

只有 `known` 字段携带可消费的 `value`。结果保留成功读出的字段和缺项，不把部分读取标为完整读取。宏观只读采样允许游戏日期正常前进，各项保留采集范围。采集前后会话、观察方、版本或世界身份改变，以及日期倒退时，本次动态字段失效。适配器负责更细的时间、版本及可见性检查。

本国N01–N04在主动查询或周期刷新中返回unknown/unavailable时，可附带`last_known`。其中`field`保留最近已知字段及其单位和尺度，`context`和`observation_window`保留原采集日期，`result_id`提供原结果读取入口。本次字段状态、失败原因和完整性继续描述本次读取，历史数值单独提供给战略判断。历史匹配限定owner、会话、观察方、版本、世界、可执行文件与DLL指纹、报告编号/版本及完整查询。没有世界身份时仅复用本次服务实例取得的数据，重开后仍可按原结果编号读取已有记录。历史值没有按天数作废的期限，日期倒退后清除该身份的历史复用范围。N05/N06、外国、行动预览、变化检测和事件投影沿各自原合同。

多个主题逐项核对来源范围。一项失败不会抹掉其他主题已经取得的内容。`context_scope=static_rules` 的条目读取已核对的配置定义，可以在没有运行会话时取得结果；它的来源需要保留定义版本、文件及模组配置哈希，并自行检查输入变化。游戏会话改变不使这些静态定义自动过期，但不得据此补出本局的状态。初始来源未就绪的字段保留 `unavailable`，不能改写成“曾取得但已过期”的 `stale`。

组合来源由一个主来源负责游戏会话和事件流，各读取适配器负责独立主题。组合目录保留尚未实现的字段；窄适配器没有实现的字段返回 `unsupported`，不会因省略字段选择而静默消失。同一事件流由主来源统一采集，读取适配器不会各自重复消费。

## 配置与订阅

报告保存查询集合、名称和详细程度标识。`raw`、`brief`、`full` 当前用于说明请求的呈现级别，结果保留原字段；框架不会假定已经调用另一个模型生成正文。

报告及订阅的创建返回稳定编号和版本 1。后续修改必须提供当前 `expected_version`，并提交完整的新配置。服务在 SQLite 写事务中校验后整体替换。失败时旧配置不变。报告修改会重新检查所有引用它的有效订阅；仍被引用的报告不能删除。报告内容更新后，变化检测重新建立基线。

每个写请求使用稳定的 `request_id`。同一所有者重复提交相同编号和内容，返回原来的结果；复用编号提交不同内容则返回冲突。读取、列出操作不写配置。取消是终态；如需再次订阅，应创建新编号。

订阅有三种类型：

| 类型 | 触发与采集 |
| --- | --- |
| `periodic` | 到期后使用报告查询一次；多个任务可分别设置周期 |
| `change` | 到期后使用同一报告采样，与上次完整采样比较；首次只建立基线 |
| `event` | 来源交出已采集的事件后，按事件类型及可选双方过滤，再读取报告并附上原始事件 |

暂停停止该订阅产生新结果，其他订阅继续运行。恢复或修改订阅重新计算到期点，并清除变化检测基线。已经生成的结果继续保留，取消不会撤回已经交付的内容。

## 时钟与恢复

首批周期支持现实时间秒和游戏日。游戏日由来源提供，框架不会推动游戏。暂停期间游戏日不变，因此不会因现实时间流逝额外产生游戏周期结果。已经跨过到期点后暂停，仍可以导出已到期的内容。

创建或恢复任务时，以当前对应时钟加一个周期作为首次到期点。`coalesce` 将跨过的多个到期点合并为一次读取，并记录 `due_count`；它不会把当前状态冒充过去每个日期的历史状态。`skip` 在跨过多个到期点时跳过本次生成，同时记录跳过原因。下次到期点保持原周期相位。

配置和调度状态在正常重启后恢复。每次读取和调度都重新核对来源状态；订阅默认固定在创建时的会话、观察方、版本及来源已提供的世界身份和 EXE 校验值。会话不匹配时停止生成，由调用方提交新配置重新指定适用范围。日期倒退会清除基线和事件游标，并记录时间断点。若实时来源没有世界代际，框架不能仅凭日期识别同一天读档；服务重启后，这类已有订阅进入 `world_revalidation_required`，清除旧事件游标并等待显式恢复或更新。宿主需要提供可靠的世界代际，才能在重启后自动延续这类订阅。运行中同日期读档仍需要原生来源另行通知，不能声称框架已识别所有读档。

## 事件与交付

事件来源返回稳定事件编号、类型、会话、观察方、游戏日期、顺序、原始内容、完整性和游标。服务按会话及世界范围去重；相同编号内容冲突会记录断档。不同订阅可分别取得同一事件；共享来源不会因取消其中一个订阅而停止其他订阅。

来源必须说明自己提供的是原生通知、桥接请求记录还是状态变化检测。状态采样不能证明采样间隙发生的每次变化。事件积压保存在数据库中，按批次生成结果；一个事件向多个订阅分发是一个整体，因此单个事件的分发数可以超过每次循环的结果预算。未处理内容留待后续循环，不丢弃原始载荷。

默认输出适配器把结果写入同一数据库的持久 outbox。此时 `delivery.status=delivered` 表示结果已交给 outbox，`llm_read=unknown`。模型可通过读取结果工具消费内容。

外部输出在结果持久化后调用。调用前先保存 `delivering`；明确取得成功收据后才保存 `delivered`。失败记录 `failed` 及原因；交付中崩溃会留下收据未知的 `delivering`，重启和重复请求不会自动重发。外部输出适配器应按结果编号去重。自动重试和长期保留策略留在适配器层另行确定。

## 适配器边界

来源实现 `context()`、`catalog()`、`read(query, context)`、`poll_events(context, cursor)`，并声明 `event_types`。可选 `validate_query(query)` 进一步检查对象。输出实现 `deliver(result)`，明确返回 `status=delivered` 的收据。

主动查询、周期导出、变化检测和事件后的报告读取都使用同一个来源方法。信息服务不会调用外交执行、接受或拒绝、日期推进和游戏脚本接口。已有原生查询仍使用原来的版本、合法性和对象校验；新框架不会扩大其能力。
