# 省份贸易力量的计算与写入路径

第204批已在可验证条件下实现[当前数值重算](../../02-使用与接口/贸易与省份/当前省份贸易力量重算接口.md)。复核同时明确：下文历史所称“节点相关”的 `0xb0b190` 路径操作省份 `+0x8a8` 的未命名所有者关联容器，不能据此认定它是贸易节点；已有节点锚点位于省份 `+0xe8`。国家节点的逐省分配仍未闭合。

第200批已公开当前省份贸易力量，但当前值还不足以推算取得省份后的收益。第201批沿省份界面的原生路径，确认了计算器和两个缓存写入点，并发现计算会读取控制国的修正。后续应根据新的控制国和省份条件重新求值，再研究国家节点的汇总规则；不能直接把当前省份值加到法国的节点竞争力上。

本页是普通有界反汇编的静态结论，没有新增成功的 REA 证据，也没有调用游戏函数、观察缓存刷新或验证真实征服效果。现有公开字段、profile 和覆盖数量保持不变。[当前接口及实机证据](省份贸易力量读取依据.md)继续适用。

## 版本和地址

目标仅为 EU4 1.37.4 B23，EXE SHA-256：`b23fa0e1f698d31b01cdd1c3817a675805d8c6286cb66f9c231e6e2a42544d77`。本页函数地址和代码位置均为 RVA，静态 VA 为 RVA 加 `0x140000000`；省份或其他对象的 `+偏移` 不是 RVA。未将这些地址应用到1.37.5。

原始字节、函数范围、哈希、核对位置和未决条件保存在 [计算路径合同](../../../work/runtime/information-trade-allocation-20261106-201-001/native-calculator-contract-001.json)。只反汇编明确函数或不超过4096字节的片段，没有整文件反汇编。

## 界面和缓存使用同一个省份数值

实际 `provinceview.gui` 的 `tradepower_value` 控件为调查入口。以该字面值的 RVA `0x1d7aa00` 定向寻找 RIP 相对引用后，在 `[0x1371d10, 0x1372773)` 的更新函数中发现：

1. 从当前省份对象读取 `+0x890` 的32位值；
2. 更新界面对象的 `+0x161c` 缓存；
3. 找到 `tradepower_value`，以1000比例尺格式化后设置文本。

这证明原生界面更新代码使用同一省份缓存，增强了第200批字段的静态依据。它没有证明实际界面已渲染当前读数，也不改变现有 `actual_UI_observed=false` 或缓存新鲜度限制。

在另一个界面处理函数中，名称比较函数 `0xcfeb0` 对相同字符串返回真，`tradepower_value` 分支进入 `0x137e912`，再调用 `0xa21510`。后者在 `[0xa21510, 0xa2155a)` 中调用同一计算器并返回省份 `+0xf8` 的描述对象，最终用于 `PROV_TRADEPOWER_DESCR`。描述对象与数值输出是不同参数，不能将描述读取入口假定为没有副作用的原生查询。

早期的普通文件名 `ordinary-tradepower-element-factory-001.json` 保留未改；其实际角色已核实为上述更新函数，不能按文件名把它解释为构造器或工厂。

## 已确认的计算器与写入点

计算器 `0xa20b10` 的完整 `.pdata` 范围为 `[0xa20b10, 0xa214b2)`，2466字节。它接收省份、数值输出指针、可选描述对象，以及若干数字输入指针。

短包装函数 `[0xa214c0, 0xa2150b)` 为75字节：它将额外数字输入初始化为零，调用计算器，然后在 `0xa214ff` 将数值输出写入原省份 `+0x890`。这是从完整指令边界确认的缓存写入证据。

函数 `[0xb0b190, 0xb0b2dc)` 也有一条写入路径：先在匹配的节点国家条目中切换 `+0x40` 字节，再遍历该节点的省份编号，用规范省份数组和 `0x2e10` 步长取得记录，调用相同计算器，在 `0xb0b2bb` 写入省份 `+0x890`。该字节对应的业务动作名称尚未确认，不能凭相邻文字或类似功能猜定，也不能执行它来验证信息导出。

已找到写入函数，不等于已经核对所有写入来源或刷新频率。静态发现不授予重放旧动作、调用写入函数或开展新业务实验的权限；现有 no-repeat 和新实验审计规则继续适用。

## 计算取决于哪些当前对象

计算器直接使用下列对象。表中的偏移和索引是二进制观察；尚未完成语义映射的项目保留原编号。

| 输入 | 已确认的读取路径 | 当前限制 |
| --- | --- | --- |
| 控制国 | 省份 `+0x470` 完整引用，再访问国家表 | 这是既有G02定义的controller位置；不能按owner替换 |
| 所有者 | 省份 `+0x468` 完整引用，参与节点条目查找 | 对分配和附加条件的完整影响未闭合 |
| 省份数值修正 | 省份 `+0x998`，索引 `0xf`、`0x10` | 修正名称及所有动态调整尚未完整映射 |
| 控制国相关修正 | 国家 `+0x28c0` → `0x93d5c0` → 结果 `+8`，索引 `0x11` | 辅助函数还包含类型检查和诊断，不能只当裸指针读取 |
| 进一步修正 | 省份 `+0x2438` → `0x8e6a10`，索引 `0x10` | 尚不能给出完整业务名称或最终数字来源 |

计算还检查省份 `+0xe8` 指针、其虚函数槽 `+0x40`，以及控制国关联对象的一个标志。不满足相应条件时有输出零的分支。代码条件已经定位，但这些条件的业务名称尚未完整确认，不能据此宣布某类省份必定没有贸易力量。

非描述路径含两次有符号整数乘法和除以1000，并有非负夹限。32位加法及低32位的有符号判断也参与结果。未来重建计算时必须保留这些截断和溢出语义，不能直接替换成无限精度比例公式。现有 T06 条件收入模型是另一种显式假设模型；本项不会把原生计算器与该模型混为一谈。

## 布尔修正读取器不能替代数值读取器

第199批的省份修正读取器回答某个修正是否存在。这里需要的是引擎最终参与计算的数字，两者不同。

数值辅助函数 `0x8e6a10` 的范围为 `[0x8e6a10, 0x8e6aae)`。它支持稠密或稀疏的索引／数值记录：标志在 `+0x10`、数据指针在 `+0x58`、稀疏数量在 `+0x64`，记录步长8字节。然而，它随后还可能通过全局索引表调用虚拟调整方法。只复制数组中的数字不一定等于函数的最终返回值。

因此，本批没有把“修正存在”换算为修正金额，也没有把稠密或稀疏数组注册为新的已知公开字段。下一步必须闭合这些调整方法及其读取条件，或在无法解析时明确返回未知。

限定检查现有9个修正相关模块后，找到可复用的底层实现 [modifier_storage.read_raw_modifier](../../../bridge/information/modifier_storage.py)。它遍历国家修正的稠密或稀疏原始存储，当前绑定的是国家对象，并不执行处理器。后续可以复用容器遍历和边界检查，但必须另核省份对象的规范绑定及虚拟调整，不能直接把国家读取接口用于省份。检查范围及未找到的部分见 [复用审查](../../../work/runtime/information-trade-allocation-20261106-201-001/reuse-numeric-modifier-001.json)。
