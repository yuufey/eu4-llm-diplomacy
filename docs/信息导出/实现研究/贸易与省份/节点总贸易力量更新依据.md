## 总量循环实际做什么

`0xb51ff0` 将入口 `rcx` 保存到 `r15`，调度器调用处传入的是节点记录。核心循环读取全局管理器的 `+0x1d08` 指针列表和 `+0x1d14` 数量。每个列表成员的 `+0x20` fullref高位提取有符号16位slot，用 `slot*0xc0 + node.entry_table` 定位国家节点条目。

循环包含资格与状态分支，但对应的条件累计写入 `node+0xd0/+0xd4` 等其它字段。总量累加所在的共同尾部使用同一套国家力量表达式：

```text
q = i32(trunc_toward_zero(i64(multiplier44) * i64(base4c) / 1000))
p = max_signed(0, q)
c = min_signed(cap48, p)
country_power = i32(c + i32(add54 - subtract50))
node_total = i32(node_total + country_power)
```

`+0xc8` 的累加保留32位回绕。国家条目 `+0x28` 的省份来源还会另行加到 `node+0xcc`，不能用它代替总力量。上述零夹限、限额和加减规则与既有 `trade_power_memory._country_power` 一致。

因此，在这次求和阶段，若同一列表中的法国恰好出现一次，列表及其他国家贡献保持不变，并把当前总量当作该阶段的基线，则法国贡献变化会使总量按相同变化更新，并保留32位回绕。它是有前提的阶段关系，不能扩展为所有游戏状态下的完整网络预测。
