## 结论

`province + 0x5d8` 是一个位图子对象；其 `+0x8`（省份对象绝对偏移 `+0x5e0`）是 `uint32_t*` 存储指针。`FUN_1400c62e0`（REA，RVA `0xc62e0`）读取 `words[slot >> 5]` 并取 `slot & 31`；`FUN_140a2ebf0`（REA，RVA `0xa2ebf0`）用相同索引设置或清除该位。省份解析函数 `FUN_1409d8e30` 在 RVA `0x9d9d7e` 以 `param + 0x5d8, slot, 1` 调用 setter；既有 `FUN_140a0acf0` 还带有 `province.cpp` 的 `Invalid tag trying to undiscover province` 字符串并清除同一位。因此，把这条路径称为省份 discovery bitmap 有足够的原生来源证据，而不是只凭运行时字段猜测。

普通静态解码进一步闭合了子对象布局：

| 省份对象偏移 | 位图子对象偏移 | 解释（逆向命名） |
| ---: | ---: | --- |
| `+0x5e0` | `+0x08` | `uint32_t*` words 指针 |
| `+0x5e8` | `+0x10` | 分配容量，单位为 `uint32_t` word |
| `+0x5ec` | `+0x14` | 当前逻辑长度，单位为 `uint32_t` word |
| `+0x5f0` | `+0x18` | inline 存储/小对象哨兵地址 |

`FUN_1400cfa50` 读取 `+0x14`，按 `4 * size` 分配并把 size 传给 `FUN_1400cf9f0`；后者复制旧的 `+0x14` 个 32 位 word、经 vtable `+0x10` 释放旧存储，然后写回 `+0x10 = 新元素数`、`+0x08 = 新指针`。`FUN_140305240` 的有界析构解码还以 `0x218` 释放该类型，和 `+0x18` 起始的 `0x200` 字节（128 个 word）相符。故当前运行时样本的 `+0x5e8=128`、`+0x5ec=44` 可解释为 **128-word capacity、44-word logical length**；前者是 4096 bits，后者是 1408 bits 的 word 范围上限。这个单位结论来自普通静态证据与运行时原始值的合并，不是 bitmap-header REA 自己声称的单位。

这与省份记录数量是两个维度：运行时 manager header 的 `pointer_difference_count=4942` 是省份记录数，不是每个省份 discovery bitmap 的 bit 数。静态 guard 只证明正索引在记录数组内：`1 <= id < count` 后才计算 `records_base + id * 0x2e10`；循环函数从 `0` 开始、每次增加 `0x2e10`，按 count 次访问记录。它没有证明 bitmap 的 slot 已做边界检查。
