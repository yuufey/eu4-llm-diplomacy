# 贸易候选页的河口注释

第199批已在启用 `--static-game-data` 的 live 服务中接通 `T06.targets` 的 `classification.estuary`。它把法国可发现省份的当前原生修正，与有效磁盘配置中的 `has_river_estuary_trigger` 规则组合。查询、报告和周期订阅使用同一条读取路径。

结果仍是部分信息：`game_fact=false`、`complete=false`、`engine_loaded_rule_verified=false`。当前修正的成员判定来自游戏进程，河口规则来自磁盘文件；尚未证明引擎已加载的脚本定义与磁盘完全相同。结果保留完整 `rule_binding`，不能省略这项条件后把它当作完整的引擎河口触发器结果。

## 查询方式

下例读取塞维利亚节点的一个候选成员。候选顺序来自当前有效的静态节点定义，索引不是固定省份选择接口；配置变化后，应按返回的省份 ID 理解该页。

```json
{
  "queries": [
    {
      "topic": "T06",
      "object": {"type": "trade_node", "node_id": "sevilla"},
      "fields": ["targets"],
      "parameters": {"target_page": {"offset": 18, "limit": 1}}
    }
  ]
}
```

本次配置中，这一项为省份227里斯本。河口注释的关键内容为：

```json
{
  "status": "known",
  "value": true,
  "matched_modifier_keys": ["tagus_estuary_modifier"],
  "unknown_modifier_keys": [],
  "basis": "native_province_modifiers_under_effective_disk_estuary_rule",
  "engine_loaded_rule_verified": false,
  "game_fact": false,
  "partial": true,
  "complete": false
}
```

实际输出还包含 `source`、日期和完整静态规则绑定。来源保留省份、法国观察国、会话及原始采集摘要。同页省份去重读取，不跨请求缓存。`estuary_reads` 记录该页实际请求了多少个不同省份；只选 `targets` 时仍不读取贸易收入基线。

## 已知、未知与失败

规则只接受能够完整解释为字面省份修正 OR 的有效定义，并沿用现有模组栈、同路径覆盖和 `replace_path` 规则。重复定义、额外条件、无效键、文件或配置漂移都会撤回已知规则。

原生读器依次查找两类定义，按引擎类型分支比较当前省份中的定义指针，保留同名遮蔽关系。任一键已知为真时，OR 返回真，同时保留其他未知键；只有所有键均已知为假时才返回假；其余情况返回未知。读取失败、定义缺失或不支持的类型方法都不填成 `false`。

父级采集负责法国非玩家角色、国家视图准入、省份发现、规范 ID、进程创建身份、模块、日期、代码守卫、两遍稳定性与严格回放。规则绑定前后身份也必须保持一致。贸易候选页再核对规则与节点图使用的配置文件和有序模组层；两个静态索引的汇总散列口径不同，因此比较实际输入身份，不直接比较汇总散列。

单省份河口失败只影响该项分类。归属、控制者、贸易中心、港口及有效贸易估算继续各自保留来源。节点图或整个 live 上下文变化则按既有守卫撤回结果。各来源分别采集，不能当作原子快照。
