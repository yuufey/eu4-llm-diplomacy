# 当前省份贸易力量的读取依据

本项读取一个省份当前的贸易力量缓存，为贸易候选省份提供实际数值。它与国家在节点中的“来自省份”合计不同，也不能直接作为取得该省份后法国增加的贸易力量。国家分配、所有权变化后的修正重算及节点收入变化仍需另行验证。

## 使用公开接口

以已安装的 live 会话启动信息服务并启用 `--static-game-data`。沿用 `T06.targets`，不增加独立的 G02 字段或另一套订阅入口：

```json
{"topic":"T06","object":{"type":"trade_node","node_id":"champagne"},"fields":["targets"],"parameters":{"target_page":{"offset":1,"limit":1}}}
```

结果中的 `fields.targets.value.rows[].current_trade_power` 给出当前值。例如省份183为 `value={"raw":17520,"scale":1000,"unit":"trade_power"}`，同时给出省份 ID、采集日期、来源和 capture 摘要。`power_reads` 记录本页实际请求的去重省份数；同一页共享同省份结果，不跨请求缓存。读取失败保留未知，不填零，也不影响同一行有效的归属、港口或河口注释。

查询、报告和周期订阅共用该来源。第200批真实 MCP 的两省查询、报告及2秒／5秒周期订阅均与原始参考相符；短订阅取消后长订阅仍 active，最终全部取消，服务和读取线程结束。2秒／5秒是调度配置，不代表采集延迟：本次主动查询约7.70秒、报告约8.36秒，不能据此泛称性能改善。见 [交付核对](../../../work/runtime/information-territorial-trade-power-20261106-200-001/mcp-001/delivery-audit-001.json)。

`acquisition_delta_evaluated=false` 和 `cache_refresh_timing_verified=false` 明确保留两项缺口。候选页的 `classification.expected_benefit` 仍为未知；不会将当前缓存自动填入条件收入模型的竞争力变化参数。公开能力仍属于既有 T06.targets 的部分实现。

## 适用版本与证据

仅适用于 EU4 1.37.4 B23，EXE SHA-256 为 `b23fa0e1f698d31b01cdd1c3817a675805d8c6286cb66f9c231e6e2a42544d77`。下文地址均为 RVA；静态映像基址为 `0x140000000`，运行地址必须使用当前模块基址计算。没有把本项地址或实机结果继承到 1.37.5。

本地复用的 CWTools `triggers.cwt:3673–3675` 将 `province_trade_power` 声明为省份作用域的数值条件。这提供查询入口名称和作用域，不能独自证明原生内存位置或比例尺。

按实际二进制的条件描述符和已有工厂入口，token `0x32b7` 在 `0xb8b900` 工厂进入 `0xb9086b` 分支，调用构造器 `0xb9fb20`。普通有界反汇编显示，该对象的虚表为 `0x1d03ca8`，求值槽 `+0x30` 指向 `0xbce3c0`。这些工厂与构造器结论属于普通反汇编证据。

REA 成功归档的求值证据为 `ev_372f397e43cef666551917e9eae0ecb8200724728cc04a13f22f593369c41abf`。函数体范围为 `[0xbce3c0, 0xbce6e0)` 和 `[0xbce6e1, 0xbce6e8)`，合计 807 字节。伪代码有类型传播警告，关键读数和比较按汇编核对：省份作用域 `+0x28` 给出非零省份 ID，通过全局 `0x233feb8` 的管理器和 `0x9aa80` 查找记录，再将记录 `+0x890` 的有符号 32 位数与条件对象 `+0x68` 的阈值比较。零作用域走诊断路径，不表示一个有效省份的值为零。

查找函数只使用普通有界反汇编。其 `.pdata` 范围为 `[0x9aa80, 0x9ac92)`，已解码主体为 `[0x9aa80, 0x9ac91)`，两者末尾相差一个填充字节。管理器 `+0x6f0/+0x6f8` 给出连续记录数组的起止地址，记录步长为 `0x2e10`。原生越界分支会记录诊断后退回首记录；本项目不复制这个行为，越界必须返回未知。

同类虚拟格式化函数 `0xb98920` 的普通反汇编范围为 `[0xb98920, 0xb98a01)`。它以 1000 为比例尺格式化同一阈值，而求值器直接比较阈值与缓存，因此内部结果保留 `raw/scale=1000/unit=trade_power`。这没有验证实际界面的舍入或显示，也没有验证缓存何时刷新。

完整字节范围、哈希、24 段代码守卫和未决条件见 [原生读取合同](../../../work/runtime/information-territorial-trade-power-20261106-200-001/native-province-trade-power-contract-001.json)。新 profile 不改变既有 G02 v4 profile，也不扩大父级的 512 KiB 读取额度。

## 读取和身份检查

内部叶子 `province_trade_power_memory` 复用父级提供的规范省份记录，另外计算原生条件所用管理器中的记录地址。两个全局入口不同，只有算出的记录地址相同、记录 `+0x20` 的省份 ID 再次匹配时才读 `+0x890`。数组跨度必须非负且可被步长整除，记录数为 1 至 65536，省份 ID 为 1 至 65535 且小于记录数。读取后再次核对管理器指针和数组头。

叶子成功路径为 6 次、56 字节，设有 16 次、128 字节上限。它不打开进程或调用游戏函数。外层 capture 继续负责代码守卫、EXE/profile/会话身份、逻辑 FRA 非玩家角色、准入、发现、双遍稳定、原始读数严格回放和句柄关闭。实际完整 capture 的开销包含父级检查，不能用叶子 56 字节代替整个请求的开销。

成功值保留有符号原数。真实零、负数和读取失败分别表达；失败不会填成零。即使已读出数值，`complete=false` 仍表示缓存刷新、界面显示、国家分配和取得省份后的因果变化尚未全部证明。

## 当前测试范围

本批109个相关唯一用例有通过记录：叶子36、capture10、公开reader28、候选页相关35。叶子首测一个测试误要求完整错误前缀，只修该失败断言后补验该节点；候选页首条命令将既有测试文件的复数名误写为单数，未收集任何用例，改正文件名后35项通过。原失败记录保留，未为补件重跑成功用例。

按计划启动的单进程完整测试在约39%处触及资源上限，未生成完整计数。随后固定原599文件清单，分30个独立进程收齐，峰值875745280字节，所有进程终态，无分组超时或超限。JUnit总计10152项：8557通过、1351失败、243错误、1跳过；含子测试的JUnit计数与8232个顶层nodeid的phase计数不是同一口径。分组是资源限制下的替代观测，不等于单进程全套通过，且可能重复原中止运行中的部分成功项；没有把原残缺输出重构成不存在的完整报告。

前三组初筛发现临时目录权限、localhost连接权限和缺失历史工件等问题。三个已失败代表用例的独立环境探针表明：使用项目内 TMP/TEMP 后文件写入及HTTP状态连带失败通过；localhost代表在普通权限下仍失败，经授权的本机测试权限复核后12个子测试通过。这个小样本不能解释其余全部失败，也不改写原始基线。分组基线在本次公开接入修改之前完成；新模块及接入后的测试另有上述109项证据，`whole_suite_passed=false`。见 [基线汇总](../../../work/runtime/information-territorial-trade-power-20261106-200-001/full-suite-isolated-001/full-suite-isolated-summary-001.json)。

## 分析过程中的失败记录

构造器 REA 查询虽然产出内容，外层以 `read_only_database_changed` 判为失败，不能作为成功 REA 证据。检查发现新增临时数据库文件和两个项目锁；逐文件流式哈希表明只排除该临时文件即可复现原数据库承诺。在确认所属分析进程终态后，将这些本次残留移至隔离目录，原数据库内容未改写。

后续求值器查询成功且数据库承诺保持不变。查找函数的 REA 启动因所属进程树超出限制被终止，没有可用 REA 证据；没有重试，改用上述有界普通反汇编。对应失败、资源记录和恢复收据都保留在第200批目录，无关 MCP 服务未被终止。
