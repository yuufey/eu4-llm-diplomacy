# 节点贸易金额的刷新条件

第212批确认了两条静态刷新路径：普通日推进跨越月份时进入包含贸易刷新的流程，初始化流程也会调用该入口。信息查询仍只复制当前输入和缓存，不主动执行刷新。因此，同一个游戏日期下读取到的省份输入与节点缓存，不一定代表同一轮引擎计算。

这项发现帮助解释第211批的比较范围，但尚未证明香槟本地0.049差额的具体成因。该差额仍保留，不能直接称为缓存过期，也不能声称已经找到了遗漏的金额修正。

## 两个金额累加器

在保留的节点更新函数中，程序对每个成员省份调用两次同一金额函数。两次都将四个额外数值输入清零，并且不请求说明文本：第一次累加到节点 `+0xb0`，第二次独立累加到 `+0xb4`，随后分别除以12并向零截断。

第二个累加器不是第一个累加器的简单复制。两次调用参数相同也不能单独证明最终缓存必定相等：后续流程、被调函数副作用和刷新时间仍需分别核对。在当前函数体的两个换算写回点之后，没有发现直接写入这两个节点字段的指令；未跟进的被调函数保持未知。国家节点行的同偏移字段不能当成节点金额。

第211批留存数据仍为：香槟成员金额重算6.625，本地缓存6.674，流入6.946、流出4.399，总额缓存9.221。算术差异可分为0.049本地差额和2.547净流入。这些是原有实机观测，本批没有重新采集游戏状态。
