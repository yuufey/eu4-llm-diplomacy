| 条件 | 所需输入 | 当前证据 |
| --- | --- | --- |
| `tag = FRA` | 查询目标在该时点的国家 tag | 上下文与原生国家身份都绑定 `FRA`；这个身份字段不提供分支可见性 |
| `has_dlc = "Domination"` | 游戏同一时点实际加载的 DLC 集合 | 没有权威快照；`dlc_load.json` 是配置/模组栈，不能替代 DLC 加载状态 |

以后若定义出现 scripted trigger 引用，还需要以同一游戏版本解析该 trigger 的完整作用域和输入；本次 18 个根没有此项。任务自身的 `trigger`、完成状态和 effect 不属于本次根可见性清单，不能用 `country_missions` membership 或 `task_id` 反推。

## 可安全支持的三值边界

以下是拟采用的抽象三值逻辑，用于保留缺失输入。接入前还须核对相应 EU4 脚本操作与引擎求值语义；不能仅由这张真值表宣称等价实现。对每个原子条件只允许 `true`、`false`、`unknown`：

- `NOT`：子值为 `true` 时为 `false`，为 `false` 时为 `true`，为 `unknown` 时仍为 `unknown`。
- `AND`：任一子值为 `false` 即为 `false`；全部为 `true` 才为 `true`；其余为 `unknown`。
- `OR`：任一子值为 `true` 即为 `true`；全部为 `false` 才为 `false`；其余为 `unknown`。

当前手工上下文最多能绑定 `tag=FRA`；DLC、地图 setup 和旗标仍未知。因此即使静态公式完整，当前 18 个根也应保留为 `unknown`，不能输出“当前可见”。只有收到同一时点的权威 DLC、地图 setup、旗标和目标国家输入后，才可对根公式做三值合取。即使公式结果为 `true`，还需核对引擎如何使用 `potential` 决定显示或分支选择。当前国家容器的根集合已有独立实时证据，不必重新用静态候选推断。

## 缺口与下一步

1. 从同一游戏时点取得权威 DLC 加载集合、地图 setup 模式和 FRA 国家旗标快照，并保留其时间点与来源。
2. 复用已经确认的当前国家容器读取，进一步核对引擎的 `potential` 求值与显示/分支选择路径；根集合和完成 ID 没有提供可见性结果。
3. 在新的原生或实时证据出现 scripted trigger、任务 trigger 或 scope 依赖时，先扩展输入清单和三值规则，再决定是否支持求值；当前不应宣称求值已通过。
