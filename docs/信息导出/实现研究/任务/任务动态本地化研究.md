# 任务动态本地化的后续入口

2026-10-24，第七批有限动态派生已按合同 002 接入并完成 003 实采；第六批的102项普通文本、20项动态未知仍是派生前的历史基线。下述规则只处理已验证的两类任务方法，不能把研究中的候选中文推广为通用动态求值。

精确完整方法名、去掉Get后的名称和UTF-16LE名称在固定1.37.4 EXE中均未命中；GetName对照有15处。首次只检查common一级目录也没有目标目录。补查游戏和模组根后，在根下 `customizable_localization/00_customizable_localization.txt` 找到了两个方法定义：basegame与补充模组都将它们指向 `SELECTABLE_MISSION_TITLE`、`SELECTABLE_MISSION_DESCRIPTION`，没有条件。文件SHA、行号和AST见[根目录调查](../../../work/runtime/information-dynamic-text-20261024-001/custom-localization-source-002.json)。这些都是限定范围的文件结果。

## 第七批有限动态派生合同

合同文件为[dynamic-localization-contract-002.json](../../../work/runtime/information-dynamic-text-20261024-001/dynamic-localization-contract-002.json)，SHA-256 为 `ea13b783902b9a5410aa808ae7956e03732fe57376383cd0d4ea094ac9f1a5f7`。它把可派生范围固定为 `GetSelectableMissionTitle` 与 `GetSelectableMissionDescription`，并要求运行时记录证明：恰有一个候选、谓词数为零、权重修正向量为空、权重为正整数且小于 `0x80000000`、无内建同名项、Root promotion 为枚举 `3`。Root 只绑定到显式查询的 FRA 观察方；没有调用原生函数或选择器，`ui_root_scope_verified=false`，所以结果是查询上下文下的派生，不是对界面 Root 的证明。

模板规则由合同 002 扩展为“一个支持的 Root 标记加字面前缀和后缀”。`0xb78bc0` 的静态证据显示字面前缀会在标记结果前保留、后缀继续处理；这解释了实际说明模板的前导空格。匹配器不 `strip`，会保留空格与 `§` 格式控制；模板必须只有一次白名单标记，前后不能含其他 `[]` 或 `$` 标记。两种标记同时出现、重复、其他占位符、孤立或不平衡标记都不派生，缓存也必须是显式同 codec 的字面值。成功结果保留原模板与原始字节，并标记 `dynamic_substitution_evaluated=false`；未满足任一条件的条目仍为 `unknown`。模板规则的扩展不改变内存读取或引擎算法。

003 的实际 live 记录为 61 个任务、122 个键、14 项派生、116 个已知和 6 个未解析；名称字段为 `status=known`、60/1，说明字段为 `status=known`、56/5，两个容器均为 `complete=false`，顶层结果为 `partial`。主动逐项、单项和三次两秒周期均交付，POR 玩家槽189、FRA 观察方保持不变，详见[003报告](../../../work/runtime/information-dynamic-text-20261024-001/live-acceptance-003/report.json)和[003手工结果](../../../work/runtime/information-dynamic-text-20261024-001/live-acceptance-003/manual-result.json)。此次自定义方法捕获 SHA-256 为 `b0608f11ba54c174dcb742bfeddbcfd77ddbc671802d27be834d786cd28c1e8f`，原生缓存 SHA-256 为 `985d1b5b8bb839d6295f91e7b19f8ad369ca278a651164d4ed8f27b5b06ca3c1`。002 的报告保留为自动分项期望错误造成的失败记录，不能据此否定生产结果；003 已改用独立字段期望复核。

生产派生实现为 [`mission_custom_texts.py`](../../../bridge/information/mission_custom_texts.py)，当前文件 SHA-256 为 `f5eae66385211cfe69c8becfd05c2e86c71bb574f9e21e43185a00827b0cac02`；运行时使用的 [`custom-localization-memory-1374.json`](../../../bridge/information/profiles/custom-localization-memory-1374.json) SHA-256 为 `de62ff14b90effd34c5a882fdb6d586a85d7314dbf12d55169117b81d96849e6`。003 的 `custom-methods.json` 已用该 profile 和合同 002 做文件、代码与运行时守卫，本文不把静态 profile 或编译结果提升为 UI Root 证据。

首轮 001 的精确整模板策略曾因七个说明模板带有前导 ASCII 空格而拒绝；该失败报告保留。合同 002 的改动只是采用已证明的前后缀拼接规则，并没有修改内存布局、虚表或游戏代码。

独立纯RPM探针在原有身份、日期、代码与双遍检查之内扩展读取；只改变当前Python进程中的快照函数，没有游戏hook、调用、写入、线程操作、安装或保存。研究脚本与所有原始结果均保留：

旧研究仍保留 Root 转换表和内建优先顺序的静态限制；003 已在显式 FRA 观察方的有限 query scope 中闭合生产所需的 Root/枚举 `3` 守卫，但没有把它推广为实际 UI Root 绑定。生产适配器只接受已捕获的单项无条件正权重记录和一个支持的 Root 标记；不能以静态文件替代实际注册对象，也不能调用选择器获取文本。其余六个国家或省份相关占位符、一般条件求值、随机多候选和动态最终 UI 仍未实现。
