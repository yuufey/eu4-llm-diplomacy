# 停战截止日期来源研究

第124批找到了当前 B23 二进制中显示停战期限的取值路径。日期经过计算得到，不能直接读取关系记录中的某个整数就当作截止日期。`R03.truce_until` 仍未实现，本页不提供可调用接口。

## 对象与证据性质

本批只分析文件，没有访问游戏进程、存档、外交接口或游戏函数。普通 Capstone 反汇编、算术推导与运行时观测分别记录；本批没有运行时日期结果。

固定对象为本机 EU4 EXE，大小38,463,016字节，SHA-256：

```text
b23fa0e1f698d31b01cdd1c3817a675805d8c6286cb66f9c231e6e2a42544d77
```

下文均使用 RVA。文件首选 image base 为 `0x140000000`；文件分析中的 VA 等于该基址加 RVA，不能直接当作当前进程地址。旧 R23–R30 材料使用另一 EXE 哈希，本批没有沿用其地址作为 B23 证据。

REA 保留记录查询针对本 SHA 和 `0x140a30fd0` 返回0条匹配；该查询早于小函数入口地址的纠正，不能据此断言正确入口没有历史记录。本批后续结果来自普通文件分析，没有新增 REA 函数分析 Evidence，也没有启动其原生分析数据库。

## 已核对的路径

安装目录 `localisation/diplomacy_l_english.yml:118` 的 `TRUCE_WITH_COUNTRY` 文本包含 `SELECTED`、`COUNTRY` 与 `DATE` 占位符，明确表示选定国家与另一国家的停战期限。

纠正后的分块扫描找到唯一精确 `TRUCE_WITH_COUNTRY\0` 字符串：file offset `0x1cd6560`，RVA `0x1cd7360`。针对它的 RIP-relative LEA 原始候选为 `0x9e8ee8`、`0x9e9086`、`0xa3112d`。扫描只确认编码与位移算术；候选不能单独证明指令边界、可达性或实际 UI 绘制。

第三个引用位于 `0xa30fe0–0xa31178`，408字节已完整解码。该函数组装含 `DATE` 的三个替换项，日期文本由调用方传入，因此它本身不是原始日期读取器。

在另一引用所属大函数的两个限定代码窗口中，观察到以下相同路径：

1. 以国家对象 `+0x1510` 及另一国家的索引调用 `0xc9cc0`，得到关系记录候选。
2. 将记录送入 `0x99d20` 检查；其前7字节明确为读取 `[rcx+0x45]`、`and al,1`、`ret`。该小叶没有覆盖它的 `.pdata` 条目，故只保存了64字节窗口并展示至首个 RET。
3. `0xa6fb90–0xa6fbb3` 完整35字节：读取记录 `+0x24` 的有符号字节，把 `+0x34` 的地址及输出地址送给 `0xa6fbc0`。这里未证明该字节的业务名称；不能直接命名为战争分数。
4. `0xa6fbc0–0xa6fc89` 完整201字节：复制 `+0x34` 的4字节值，结合该字节及两个全局配置，计算一个整数，再依次调用 `0x14c7f30` 和 `0x14c7c10`。第二次调用的 EDX 为0。
5. 返回的本地4字节值送入 `0x6e5b70–0x6e5de9` 格式化，最终用于上述停战期限文本。

这证明静态取值路径包含 `+0x24` 和 `+0x34`，没有证明仅凭二者就能得到当前截止日期。大函数只读取了两个部分窗口，窗口起点指令边界与全函数控制流仍未完整验证。

## 中间整数计算

201字节计算函数读取两个 DWORD 全局：RVA `0x233dc88` 与 `0x233dd8c`。它们位于 `.data` 的虚拟尾部，超出文件 raw 范围；静态文件没有它们的值。本批没有读取运行时配置，也没有用游戏默认值代替它们。

设 `a` 为记录 `+0x24` 的有符号字节，`G1/G2` 为两个全局的有符号32位值，`i32` 表示32位有符号回绕，`trunc` 表示向零截断。实际整数指令可整理为：

```text
C = i32(i32(a * G1) * 1000)
F = i32(i32(G2 * 1000) + trunc(C / 100))
N = i32(12 * F + 1000)
EDX = ceil(N / 1000)
```

`integer-formula-001/report.json` 用67,140组确定性输入核对了字面指令序列与上述公式，覆盖窄整数路径、宽整数路径、负数、边界和溢出。它只证明中间整数的算术等价，不证明当前 G1/G2、日期结果或运行时引擎调用。假设 `G1=10/G2=5` 的例子只是算术用例。

日期格式化函数先读取 int32，减去43,800,000（5000×365×24），并进行24和365相关整数换算，支持小时日期编码的推断。它还含未跟进的可选调整分支，不能把这份推断当成完整 UI 日期格式验证。

`0x14c7f30` 最初只按一个20字节 `.pdata` 条目读取；后续控制流及 CHAININFO 证明这只是入口片段。现已保留 `0x14c7f30–0x14c8020` 的240字节，覆盖链式片段及 `0x14c801c` 的 RET。其整数除12、日期表和调用行为支持“按月调整”的推断，尚未完成所有被调用函数的语义核对。`0x14c7c10–0x14c7d9a` 的394字节已完整读取，但依赖其他日期辅助函数。
