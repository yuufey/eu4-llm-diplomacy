# 战报同事件的定义与文字上下文

第74批把战斗结束时的消息定义和本地化缓存文字接入逐场记录。此前独立读取只能证明“当前配置是什么”，不能说明旧战斗发生时的配置；新增来源在同一战斗的router scope结束、记录封存前读取，并将事件序号、日期和陆／海战类型一起保存。

玩家国家和LLM观察国继续分离：玩家为葡萄牙，LLM观察及操控的法国保持非玩家。定义和缓存由客户端共用，不能把它们称为法国专属消息队列。公开查询和订阅仍要求法国的完整国家引用确实出现在该场战斗的参战向量中；全局采集到其他国家的战斗不等于法国可以读取。

v33沿用v32的六处被动采集入口，使用wire7包住完整、未改动的v6记录，再追加`DCTX`扩展。新增部分只读复制内存，不调用查找fallback、setter或formatter，不增加游戏函数调用。原有标题helper的调用仍单独计数。构建排除切换玩家国家的功能。

| 字段 | 复制的来源 |
| --- | --- |
| `definition_key` | 陆战或海战消息定义中的精确键 |
| `language` | 本地化缓存的语言标识 |
| `body_template` | 定义键加`_1`对应的缓存文字 |
| `button1`、`button2`、`button3` | 定义键加`_BTN1`、`_BTN2`、`_BTN3`对应的缓存文字 |
| `compact_losses_template` | `COMPACT_BATTLE_RESULT_LOSSES`对应的缓存文字 |

定义还保留`popup_kind_raw`、`layout_raw`和`button_flag_raw`。popup类型可由构造函数初始化为0，战报形成时再写入陆／海类型，所以它与战斗类型分别记录；两者不同不会直接判定读取失败。布局和按钮标志说明定义的条件输入，不能单凭这些字段认定窗口或按钮已经显示。

采集要求两遍读取的地址、长度、原始字节和最终快照一致，并核对事件日期及前后玩家和代码状态。读取次数、总字节、单次读取、链长、表和字符串都有上界。两遍一致不等于原子快照。失败时清空新增扩展并保存原因，原有战斗记录继续保留；可选缓存条目缺失也不表示控件不可见。

公开投影位于`details.value.display_context`，来源标记为`IBOW.v7`、投影版本12。Python还会核对扩展身份与内嵌v6事件；序号、日期或类型不一致时，仅该部分变为unknown。文字逐字段使用`eu4_escape`解码，失败保留原字节。缓存查找只覆盖原生主表的hash lower-bound路径，未读取第二键表，不能把未命中说成本地化定义在所有来源中不存在。

`raw_text`继续表示原有v6捕获的Line1片段。新增模板、按钮缓存与定义参数不会被拼入它，也不会冒充实际渲染文字。旧v1—v6记录保持原有结构，不用今天的缓存补作旧事件证据。`full_display_complete`、`runtime_popup_verified`和`visibility_verified`继续为false；完整正文、各控件最终文字、实际布局及法国新正例仍须完成。
