# 玩家国家、LLM观察方与战报消息

本项目要求LLM操控非玩家国家。当前实际玩家是葡萄牙（POR），LLM的观察方和操控国是法国（FRA）。两者应保持分离，不能为取得法国的屏幕战报而把法国改成玩家国家。

第74批已进一步取得12陆1海共13场新战斗及同事件的定义/文字上下文，实际参战向量均不含法国或葡萄牙；因此法国新正例仍缺失，不据此泛称AI国家没有消息。本批与第72批是不同日期窗口，均只执行一次，当前已在raw56564448暂停。完整正文、实际显示与可知范围继续分别验证，见[同事件上下文](战报同事件定义与文字上下文.md)及HANDOFF最新状态。

## 已确认的实际情况

第64批的真实自然观察保持玩家POR、观察方FRA。数据库记录了11条完整战斗消息，其中第6条是一场法国直接参战、葡萄牙未参战的海战。服务为该场战斗生成事件并通过durable outbox交付；交付不表示LLM已阅读。

同一场海战还捕获到`formatter_container_before_cleanup`阶段的58项格式化输入。因此，非玩家法国的战斗数据和局部事件导出已有正例，不能说法国是AI国就没有战斗信息。

## 已确认的客户端条件

固定EU4 1.37.4程序的静态路径显示，陆战和海战消息都检查游戏当前国家是否在战斗双方名单中，并检查当前客户端是否正在查看该战斗。信息服务的`observer=FRA`不参与这项原生判断。

在已检查的路径中，当前国家不属于任一方、当前战斗UI覆盖条件也不成立时，程序跳过后续消息构造。这个条件说明客户端弹窗与世界战斗数据并非同一步；它不等于一条“所有非玩家国家都没有原生消息”的规则。

以上是静态条件。第6条历史事件没有保存逐场条件的全部值，不能用稍后暂停时的葡萄牙国家引用倒推出该场战斗究竟走了哪条分支。Line1未捕获还可能涉及后续消息消费条件或采集条件。

现有原始wire6记录已包含采样时的实际玩家完整引用和双方参战者完整引用；这些引用未公开到MCP对象，不表示原始记录没有它们。确实缺少的是同一战斗的当前战斗UI覆盖条件，以及原生消息入口是否到达。现有消息hook在过滤通过后才记录副本，零计数无法区分未到入口和入口后被过滤。

第72批已落实逐场被动采样，使用现有门槛通过路径中必经的原生调用位置观察其去向，并在消息副本过滤之前记录入口；不改变实际玩家，不主动构造或发送战报。

## 第72批实际观察

本轮仅推进一次35天，从raw56562768到56563608后暂停。当前玩家始终POR，LLM观察方始终FRA；独立读取在前后均确认Human数量1、POR控制器1、FRA控制器0。

取得10场陆战、1场海战，逐场有以下证据：

- 葡萄牙的完整国家引用和native slot189均不在双方参战名单中。
- 当前国家为葡萄牙，当前战斗UI槽为空，UI覆盖条件明确为false。
- 到达了同场战斗的格式化容器清理位置，门槛通过后的调用位置和消息入口均未到达。
- 作用域关联、前后代码校验均通过，没有采样丢失或过滤拒绝。

因此，这11场已经能区分原生流程未继续与副本捕获失败：在这些样本中，未进入所采样的同步客户端消息入口。该结论只覆盖这条客户端路径，不能扩大为“AI国家没有消息”或“所有非玩家战斗都不显示战报”。

**本轮没有法国直接参战事件。** 同服务订阅验收按正例要求保留`natural_fra_event_absent_no_vacuous_pass`失败，未用其他国家样本替代法国交付，也未把4条外交提案事件算作战斗。没有重跑窗口来等待法国样本。旧第64批法国海战的逐场UI条件仍不能事后补证。

逐场结果见[诊断与wire6只读关联](../../../work/runtime/information-battle-gate-trace-20261028-001/live-001/gate-trace-join-001.json)和[独立实机审计](../../../work/runtime/information-battle-gate-trace-20261028-001/independent-live-audit-001.json)。原始样本、三份只读数据库备份及日志截取边界见[快照收据](../../../work/runtime/information-battle-gate-trace-20261028-001/snapshot-receipt-001.json)。
