# 非玩家战报的派生文字候选

278批新增[独立名称行格式化](非玩家战报独立格式化.md)候选实现，复用这里的名称原料与字节模型请求原生格式器，独立保留输出和输入依据。v42已编译，部署与游戏内样本继续留项。本页各类纯派生候选的语义保持原约定。

第159批在现有 B04.details 中增加两类派生文字。它们使用同事件已经保存的原生输入，不调用游戏格式器，也不依赖客户端消息门槛通过。因此现有 v34 的 wire7 数据即可使用，无需为此安装 v35。

查询仍使用已有 B04 接口，指定事件订阅或历史查询实际返回的 `event_id`，选择 `details` 即可。结果位于：

- `details.value.display_context.body_candidate`：名称行候选。
- `details.value.display_context.compact_loss_candidates`：陆战紧凑损失文字候选，分别对应 OURLOST/OurLost 与 ENEMYLOST/EnemyLost。

第159批wire7/8公开投影为14；第160批加入[战报结果组合](../../02-使用与接口/战争与战报/战报结果组合接口.md)后为15，旧wire4–6仍为13。原生Line1继续单独放在 `raw_text`；派生文字不会使它升级。

## 名称行

要求模板、定义键、语言和底层战斗的序列、日期、陆海战类型一致。普通 `$NAME$` 使用同场捕获的 title helper 候选；若有经过验证的 wire8 NAME 交接值，则优先采用该值。两个已知来源字节不一致时，名称行候选返回未知。

`input_source` 区分 helper 候选、实际 NAME 交接与纯字面模板。仅实际交接来源把 `native_name_handoff_verified` 标为真。helper 来源仍保留“同 combat helper 的静态 NAME 来源”这一依据，不冒充本次原生构造函数已经使用的值。

## 紧凑损失文字

同事件的 `COMPACT_BATTLE_RESULT_LOSSES` 模板用原生容器中已复制的 OURLOST、ENEMYLOST 字符串替换普通 `$NUMBER$`。不从 B02 各兵种损失重新计算总和，不解析、改写输入中的小数或分组符，也不替换物理客户端 COUNTRY。

普通 PE 字节证明包装函数 RVA `[0x97fb0,0x9808a)` 构造 kind1/NUMBER 参数，将输入 String32 复制到参数 `+0x30` 后调用 `0x14b33a0`。既有已接受 REA 说明普通 kind1 与 kind2 均逐字节复制文字，不递归处理值中的美元符号。新增函数查询因缓存完整性变化被拒收；本结论使用独立的固定 EXE 字节与既有 REA，不把失败结果称为已接受证据。

`configured_layout_condition` 仅表示已捕获的定义 `layout_raw == 0`。即便能够计算候选，也不能据此说紧凑控件被选择或显示；布局非零时仍明确标为未满足配置条件的候选。

## 范围与缺项

当前仅实现普通单键文字替换。含管道修饰符、缺少所需输入、重复键、错误编码、NUL、事件错配或越界时，相关候选返回未知。两侧紧凑损失独立处理，保留原始记录和其他已知字段。

模板、单个值最多8192字节；结果与结尾 NUL 合计严格小于60 KiB。结果按显式 `eu4_escape` 解码，超过16 KiB时在完整转义序列边界分块，保持共享解码器原有上限。

所有候选都有 `not_raw_text=true`、`native_formatter_invoked=false`、`complete=false`、`full_display_complete=false` 和 `visibility_verified=false`。名称行另有 `native_line1_verified=false`；紧凑损失另有 `native_widget_text_verified=false`、`runtime_popup_verified=false`。

已保存第152批7场记录可派生7个名称行和12个陆战紧凑损失候选；它们无法国直接参战，只作为内部来源核对，不用于伪造法国战报正例。完整结果框、原生最终文字与可见性仍需继续开发，当前字段覆盖等级不变。

控件盘点以当前实现为准：OUR/ENEMY 的 combat-side 映射、观察方侧别、结构化胜负与新版海战 LOST/END 已有实现，不能再用旧 ledger 把这些结构数据列作未完成。尚待补齐的是相关控件的最终格式化、条件及显示状态；旧 v2 数据仍保留其实际缺项。
