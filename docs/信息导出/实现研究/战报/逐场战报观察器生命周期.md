# 逐场战报观察器生命周期

2026-10-25，第二十一批。已将自然入口、值复制和既有分片日志组件接入 v23 观察器的构建、帧循环和采集控制。当前交付的是**原始观察记录的研究实现**，还没有安装到游戏、产生新的自然战报或接入信息订阅。完整目标仍为 74 主题、397 字段；54 available、107 partial、236 planned，B01–B04 保持 planned。

## 这次实现了什么

[管理组件](../../../work/native/information-battle-observer.inc)在启动时核对固定 EXE、当前进程创建时间、DLL 文件和主模块 PE 身份。固定版本为 EU4 1.37.4，EXE SHA-256 为 `b23fa0e1f698d31b01cdd1c3817a675805d8c6286cb66f9c231e6e2a42544d77`。它检查候选入口 RVA `238620` 的完整 36 字节、原展开信息 RVA `1DE6C98` 的 32 字节，以及原 `RUNTIME_FUNCTION` 范围 `[238620,23A015)`。这些范围与前批静态证据一致，本批没有重新运行 REA。

启动后默认不采集。进程与 DLL 身份相符的 `enable` 请求还必须提供实际玩家的完整国家引用，才能在当前帧线程安装 21 字节入口补丁。它使用前批验证过的 41 字节跳板、观察 shim 和公共补丁事务，不调用游戏函数来制造战报。

成功初始化后保持 EXE/DLL 的只读文件句柄，拒绝其他句柄写入或删除这两个文件；校验在取得句柄之后进行。已经发布的 DLL、跳板、VEH 路由和展开表一直保留到进程退出。未发布的启动文件句柄在失败时关闭。发布阶段和失败阶段可在状态中查看。

## 捕获、排出与停止的关系

| 阶段 | 实际行为 |
| --- | --- |
| 自然入口回调 | 只接受启用时绑定的帧线程；使用尝试锁拒绝重入，复制到 8 槽自有存储；其他线程、满槽及复制失败分别计数 |
| 值复制 | 复制既有 result 原值、两侧完整国家引用、名称和指挥官字节，并补充 summary 的 11 个 raw int32 与 `+4C` 控制字节 |
| 帧循环 | 将自有记录编码、分片，交给既有队列、排出器和 checked 文件 writer；回调不做日志 I/O |
| `disable` | 等待正在复制的临界区结束，停止新增采集，继续排出已经取得的记录；保留入口补丁及已发布资源 |
| 异常状态 | 代码、上下文、线程或日期回退失效时停止采集；source_changed、fault、restart_required 不继续排出，保留待排内容用于诊断 |

状态切换、捕获提交及完整排出临界区共用同一把锁；回调只尝试取得锁。首个终止状态会保留，后续状态文件或线程错误不会把 restart_required 改写成其他状态。捕获序号不因停用和恢复而归零。日志代际使用当前进程的创建时间，首次启用拒绝既有原始日志，防止新进程追加重置后的序号。

[summary 复制器](../../../work/native/information-battle-owned-summary.h)每次实际读取 45 字节，总预算 256 字节；它不赋予原值单位、双方角色或可见性含义。[原始记录编码器](../../../work/native/information-battle-observation-wire.h)逐项写入固定版本、小端整数和实际字符串字节，不写入 C++ padding、容量或源地址。[Python 解码器](../../../work/information_battle_observation_wire.py)严格核验格式、长度、布尔值和尾随内容；输出明确保留 `complete=false`、`visibility_verified=false`，不生成公开战争或战斗身份。

## 构建和控制入口

```powershell
& work/native/build-diplomacy-observer.ps1 `
  -Experiment <新的实验目录名> -InformationBattle -ReasonMetadata
```

`-InformationBattle` 选择 v23，并把 11 个新增依赖加入构建来源，共 103 项。现有 v22 的已安装 DLL 与历史副本没有被替换。使用了与当前 v22 相同的 `-ReasonMetadata`；首次省略此项的构建触发了既有 `unused parameter id` 编译错误，失败目录保留。旧默认配置的这个编译问题没有在本批改写其他业务来源来掩盖。

[安装器](../../../tools/start_diplomacy_observer.py)现在识别 v23，但必须核对研究能力标志、所需源文件及 SHA 和 DLL 指纹。已有 bridge 的进程仍被拒绝，换版本需要新进程。本批没有调用安装器安装新 DLL。

[控制器](../../../tools/control_information_battle_observer.py)提供：

```text
--installation <新的 v23 目录>/installation.json --command status
--installation <新的 v23 目录>/installation.json --command enable --player-ref <已独立核对的16位小写hex完整玩家引用>
--installation <新的 v23 目录>/installation.json --command disable
```

`status` 只读取新鲜的原生状态，并核对当前真实进程、模块和文件身份。启停请求通过独占文件提交，客户端保存稳定绑定与请求记录。原生端先持久保存 started 收据，再执行配置，最后写独占响应；已有响应的 nonce 不再执行，只有 started 而没有响应时明确返回 `prior_outcome_unknown_no_retry`。客户端等待超时返回 `unknown_no_retry`，不会自动重新派发。保存请求、启用捕获和交付结果是不同状态。

启动状态采用两阶段发布：首份状态文件可以报告 `cold`，成功写入后才进入 `ready`，下一次心跳发布新状态。这两个状态都不会采集。`stats_consistent=false` 表示状态中的多个独立计数不是一个原子快照。

## 继续开发的条件

当前记录是自然入口前的原始值，尚未证明它等于最终展示内容。仍需补齐 kind、胜负及双方角色、后续数量变化、单位、完整展示原文、战争归属和稳定公开身份；没有接入 InformationService、事件持久化和 LLM 订阅，也没有取得新的自然陆战或海战验收结果。

本实现能发现指针、玩家、线程变化及日期回退，**不能识别所有同地址、同日期的读档**。自然对象在实际回调中的有效期、真实线程/重入、观察方可见性和源完整性仍须验证。状态保留 `same_address_reload_verified=false`；固定文件身份和自有程序组合测试不能替代这些证明。

下一步先完成新进程安装前的所有权与现场审计，再验证 v23 成功启动、采集启停和自然入口；继续取得完整陆海战内容并接入统一事件与订阅。历史成功、已派发、unknown、未闭合所有权、原 final-pass 请求和原 120 动作批仍禁止重放。静态来源与本批 fixture 不授予业务执行权限。
