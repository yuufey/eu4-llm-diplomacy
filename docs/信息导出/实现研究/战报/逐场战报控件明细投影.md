# 逐场战报控件明细投影

第三十五批已将本页的 projection8 升级为 projection9，主要控件的原生参战侧及实际参与国现可通过 `side_binding`、`side_identity` 读取，详见[控件参战侧](逐场战报控件参战侧.md)。下文保留第三十四批的原始范围与回执；其中侧身份统一为 unknown 的描述属于当时版本。

第三十四批新增 B04 projection 8。服务继续返回 formatter cleanup 前复制的 `details.message_template`，并在同一 `details` 下提供 `display`：它按照陆战、海战的静态控件绑定，把已有键值投影成可以直接阅读的控件输入。投影可以让威望、传统、厌战、将领和兵种/舰船数量等单一文本输入变得可读，同时保留原始字节和未绑定键值。

这是一层局部、可审计的显示投影。它不声明已经读取实际窗口，也不把控件输入拼成完整战报正文。`details.message_template`、`details.display` 与 B04 其他字段各自保留来源和缺口。

## 返回结构

`details.value.display` 的外层状态表示投影是否生成；`value.controls` 中的每一项再报告自己的文本状态。典型结构如下：

```json
{
  "details": {
    "status": "known",
    "value": {
      "display": {
        "status": "known",
        "value": {
          "battle_type": "land",
          "basis": "copied_native_values_with_static_gui_input_bindings",
          "controls": [
            {
              "template_key": "OURPRESTIGE",
              "widget": "our_prestige",
              "layout": "common",
              "value_kind": "text",
              "inputs": [
                {
                  "pair_index": 5,
                  "value_raw_hex": "a7472b302e3230",
                  "decoded": {"status": "known", "value": "§G+0.20"}
                }
              ],
              "display_text": {"status": "known", "value": "§G+0.20"}
            },
            {
              "template_key": "WINORLOSE",
              "widget": "winORLose",
              "layout": "common",
              "value_kind": "text",
              "inputs": [],
              "display_text": {"status": "unknown", "reason": "TEMPLATE_KEY_NOT_CAPTURED"}
            }
          ],
          "layout_candidates": ["land_compact", "land_detailed"],
          "selected_layout": {"status": "unknown", "reason": "RUNTIME_LAYOUT_NOT_CAPTURED"},
          "side_identity": {"status": "unknown", "reason": "TEMPLATE_OUR_ENEMY_ROLE_UNRESOLVED"},
          "order_basis": "binding_declaration_order_not_screen_order",
          "unbound_pair_indexes": [0, 1, 2, 3, 4],
          "missing_sections": ["title", "Line1", "button_text", "actual_layout_and_visibility"],
          "full_display_complete": false,
          "runtime_popup_verified": false
        }
      }
    }
  }
}
```

`controls[]` 还会带有对应的 `layout`、`value_kind` 和输入 pair 索引。`message_template` 仍是同一个 `details.value` 下的兄弟字段，重复键、顺序和原始字节不会因为生成 display 而丢失。

## 何时可以得到已知文本

静态绑定将模板键映射到控件。只有一个输入且它属于 direct text 时，投影才给出 `display_text.status="known"`。逐项 `eu4_escape` 解码保留 EU4 `§` 颜色码、数字逗号和空字符串；`inputs` 同时保留 `value_raw_hex`，因此消费端可以回到原始值。

缺少键值返回 `TEMPLATE_KEY_NOT_CAPTURED`。字节解码失败时保留 raw 输入并返回 unknown。重复键保留全部输入，最终显示效果为 unknown，避免把多个原生输入擅自合并。numeric、frame、icon、flag 只说明原生控件需要这类输入，不当作最终文本；compact 陆战的 `OURLOST`/`ENEMYLOST` 还依赖 `COMPACT_BATTLE_RESULT_LOSSES` 二次格式化，当前为 unsupported。海战 `CAPTURE` 已有静态 direct-text 绑定，但本次 KEL 记录没有该键，所以该控件返回 unknown。

陆战登记 41 个控件，候选布局为 `land_compact` 和 `land_detailed`；海战登记 42 个控件，候选布局为 `naval`。`selected_layout` 保持 unknown，因为本投影没有运行时 widget 选择或 visibility 证据。控件顺序是 binding declaration order，不是屏幕顺序。`OUR`、`ENEMY` 是原生模板标签，当前不能解释为观察方、胜者或具体国家；快照前五项中出现的 POR 国家/君主值也不能改写成战斗角色。

未绑定键值用 `unbound_pair_indexes` 留在结果中，并与原 `message_template` 一起返回。它们可以是标题、元数据或辅助输入的候选来源，但当前没有原生格式化结果证明其最终用途。已有 `display_text` 只描述单项控件输入，不表示 `Line1`、按钮或完整正文已经形成。

## 仍缺少的窗口内容

当前投影没有 `title`、`WINORLOSE` 的实际值、`CAPTURE` 缺失时的输入、`Line1` 最终正文、按钮文本、运行时布局/可见性、稳定控件 ID、完整 `raw_text` 或实际 popup 快照。静态 `_1` 与 `Line1` 字面值、陆战 `FUN_1408c75d0`、海战 `FUN_1408ca460` 和 formatter 路径只能说明键和控件的形成关系，不能替代运行时控件结果。

下一步需要补齐少量原生输入和最终 formatter 结果，再逐项闭合标题、胜负、俘获、`_1` 到 `Line1` 的关系。当前应继续保留 unknown/unsupported 状态，不用键值拼接完整战报或提高 `full_display_complete`、`runtime_popup_verified`、`business_complete`。完整 B04、歼灭、撤退及阶段二/三/四和 LLM 自主订阅目标继续 active。

## 证据边界

静态 REA、普通 PE 字面值、冻结副本和公开消费各自独立记录。display-binding 只证明有界的键到控件输入关系；公开消费证明 projection8 可以在报告、主动查询和订阅中稳定返回同一 payload；它们都没有证明当前游戏实际打开了哪个 popup，也没有证明 OUR/ENEMY 的观察角色归属。完整采集范围见[逐场战报格式化容器采集](逐场战报格式化容器采集.md)，最终文本关系见 `work/runtime/information-battle-display-20261026-001/final-text-contract-001.json`。
