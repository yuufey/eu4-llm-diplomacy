# 逐场战报控件参战侧

第三十五批为 B04 projection 9 增加 `details.value.display.value.side_identity` 和控件 `side_binding`，将已证明的控件键关联到原生参战侧及该侧的国家。`OUR` 对应 combat side 0，`ENEMY` 对应 combat side 1；服务再用实际参与者确定观察方位于哪一侧。当前 FRA 陆战中，OUR 属于 HSA，ENEMY 属于 FRA；KEL 海战中，OUR 属于 KEL，ENEMY 属于 PSA。标签本身不说明胜负或进攻、防守角色。

## 可调用行为

公开事件仍通过 `details.value.display` 返回控件投影；来源为 `IBOW.v4` 时，事件的 `source.projection_version` 为 9。控件项新增 `side_binding`，整体显示投影新增 `side_identity`。典型结构如下：

```json
{
  "source": {
    "name": "IBOW.v4",
    "projection_version": 9
  },
  "details": {
    "value": {
      "display": {
        "status": "known",
        "value": {
          "side_identity": {
            "status": "known",
            "value": {
              "basis": "native_formatter_combat_sides_with_copied_participants",
              "scope": "whole_combat_side",
              "sides": [
                {
                  "template_label": "OUR",
                  "combat_side_index": 0,
                  "participants": ["HSA"],
                  "participant_full_refs": ["0100029c00415348"],
                  "result_side_index": {"status": "known", "value": 1},
                  "observer_participated": false
                },
                {
                  "template_label": "ENEMY",
                  "combat_side_index": 1,
                  "participants": ["FRA"],
                  "participant_full_refs": ["0100007a00415246"],
                  "result_side_index": {"status": "known", "value": 0},
                  "observer_participated": true
                }
              ],
              "observer_template_label": {"status": "known", "value": "ENEMY"},
              "attack_defend_roles": {
                "status": "unknown",
                "reason": "ATTACKER_DEFENDER_UNRESOLVED"
              }
            }
          }
        }
      }
    }
  }
}
```

`side_identity` 为 known 表示上下文给出了两个完整且互不重叠的参战侧。观察方身份和 result 反排分别判断，不影响已取得的参战侧信息。`observer_participated` 表示观察方的完整国家引用是否位于该侧，`observer_template_label` 是由唯一命中得到的 `OUR` 或 `ENEMY`。若观察方没有唯一命中，信息服务不会把该记录作为本国可见战报发布；直接调用投影时，参战侧仍可保持已知，但 `observer_template_label` 返回 `TEMPLATE_OBSERVER_SIDE_UNRESOLVED`。

## 控件键的侧绑定

静态合同使用固定的 EU4 1.37.4 原生输入。只有已证明的键后缀才获得 `side_binding`：

| 模板键范围 | combat side | 侧标签 | 说明 |
| --- | ---: | --- | --- |
| `OURPRESTIGE`、`OURTRADITION`、`OUREXHAUSTION`、`OURLEADER`、`OURFIRE`、`OURSHOCK`、`OURMANEUVER`，以及陆战/海战的初始、损失、结束数量键 | 0 | `OUR` | 读取 formatter 的原始 combat side 0，作用域为整条参战侧 |
| 对应的 `ENEMY*` 键 | 1 | `ENEMY` | 读取 formatter 的原始 combat side 1，作用域为整条参战侧 |

陆战还包含 `SIEGE` 数值，海战还包含 `TRANS` 船只数量；它们沿用同一侧索引。`side_binding.basis` 为 `fixed1374_formatter_input`，不按 result 数组的当前位置猜测侧别。

图标、旗帜、`WINORLOSE`、`CAPTURE` 及其他没有固定侧输入证据的键保持 `CONTROL_SIDE_BINDING_UNRESOLVED`。numeric、frame、icon、flag 也不会因为已经知道 combat side 就变成最终可读文本。控件映射的顺序仍是静态 binding 声明顺序，不是运行时屏幕顺序。

## result 侧反排

原生结果窗口可以把结果侧重新排列，因此服务先把每个 result side 的代表国 full reference 与 formatter context 的参战 full reference 逐场匹配。只有每个 result representative 恰好匹配一个 combat side，且两个匹配构成双射时，才写入 `result_side_index` 和事件 `sides[].combat_side_index`。结果数组的 index 0 或 1 本身没有 `OUR`/`ENEMY` 含义。

如果调用方提供的 mapping 与 full reference 推导结果不一致，结果侧的 `result_side_index` 返回 `RESULT_SIDE_MAPPING_UNRESOLVED`，不会改写已确定的 combat side 绑定。参与侧 full reference 不完整、跨侧重叠或无法解码时，整体 `side_identity` 返回 `TEMPLATE_SIDE_CONTEXT_UNRESOLVED`；同侧的原始重复项保留。服务不会用国家短标签或观察方配置替代完整引用。

该规则同时解释了本批两个消费样本的反序结果：

- live FRA seq3 的 HSA/FRA 陆战中，combat side 0 是 HSA、模板标签 `OUR`，对应 result side 1；combat side 1 是 FRA、模板标签 `ENEMY`，对应 result side 0。FRA 观察方唯一命中 combat side 1，所以 `observer_template_label` 是 `ENEMY`。
- recorded KEL seq8 的 KEL/PSA 海战中，combat side 0 是 KEL、模板标签 `OUR`，对应 result side 1；combat side 1 是 PSA、模板标签 `ENEMY`，对应 result side 0。KEL 观察方唯一命中 combat side 0，所以 `observer_template_label` 是 `OUR`。

这两个样本只说明参战侧、结果侧和观察方标签之间的输入对应，不能推出 attack/defend、winner 或实际国家战果变化。

## 尚未确定的关系

`OUR`/`ENEMY` 标签通过参战侧关联到国家，不能单独决定 observer、winner、attacker 或 defender。`attack_defend_roles` 保持 unknown；国家实际 delta 和战争总分不由此推导。B01 已有的 `winner` 继续由原生结束方向及结果侧一致性独立判断，本批不改变该字段。

窗口标题、`WINORLOSE` 实际值、`CAPTURE` 未采集输入、`Line1` 最终正文、按钮文本、运行时布局与可见性、稳定控件 ID、完整 `raw_text`、实际 popup、歼灭和撤退仍缺少原生输入。`full_display_complete`、`runtime_popup_verified`、`native_visibility_verified` 和 `business_complete` 不因 side identity 已知而改变。

## 证据边界

侧绑定来自 [template-side-binding-002.json](../../../work/runtime/information-battle-title-20261026-001/template-side-binding-002.json) 记录的已有 REA、普通 PE 与 result full-reference 证据；formatter 生产代码位于 `bridge/information/battle_display_sides.py`，消费接入位于 `bridge/information/battles.py`。公开 acceptance 只证明 projection9 能在报告、主动查询和订阅中稳定返回同一侧身份字段，不证明当前游戏实际打开了哪个 popup。完整 B04、阶段二/三/四及 LLM 自主订阅目标继续 active。
