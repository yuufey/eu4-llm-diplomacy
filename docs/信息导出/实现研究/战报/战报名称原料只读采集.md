# 战报名称原料的只读采集

客户端消息门槛可能跳过战报 NAME 构造。因此，继续等待门槛后的 NAME 钩子，不能保证取得非玩家国家每场战斗的名称输入。第220批增加独立的原料复制组件 `work/native/information-battle-owned-name-sources.h`，供门槛前的战斗生命周期接入；组件不调用名称 helper，也不构造或发送原生消息。

## 复制哪些数据

固定 EU4 1.37.4，EXE SHA-256 为 `b23fa0e1f698d31b01cdd1c3817a675805d8c6286cb66f9c231e6e2a42544d77`。下列地址均为 RVA，运行时 VA 应另用实际模块基址计算。

已有 REA `ev_dda07501ba4e06feddf27307c6abb382f688162fc7ef0776bd755b43128fe6b1` 的 helper 范围为 `[0x23a930,0x23ab33)`；普通 PE 合同另保留该范围的字节。helper 对陆战、海战选择 `BATTLE_OF` 本地化前缀，再读取 `combat+0x30` 所指对象、该对象 `+0x28` 的名称所有者，以及所有者 `+0x10` 的 String32。它还读取全局 String32 `RVA 0x23266b8`。这些是静态数据流证据，不能表述为本批观察到 helper 执行。

新组件复用现有 title-query 的 String32 读取与对象图比较，复制后两项原始字符串。输出保留战斗序列、日期、陆海战类型、字节和长度，去掉指针。两遍共同使用 128 KiB／64 次读取上限；任何对象图、字符串或外层守卫变化都撤回输出。参数对象互不重叠时，复制成功或失败后都清除工作区中的对象图地址。

调用方必须在有效的同场战斗生命周期内调用组件，并通过 `Guard::guard()` 核对二进制、代码、线程、日期和战斗归属。传入序列与日期本身不构成这种证明。组件拒绝源读取与自有工作区、输出、结果记录重叠；参数对象互相重叠时拒绝操作并保持对象原值。
