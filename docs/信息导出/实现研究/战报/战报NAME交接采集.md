# 战报 NAME 输入采集

此组件读取陆战、海战格式器交给原生键值构造函数的 `NAME` 字符串。它补齐逐场战报的一项格式化输入；该值尚不能代表最终 Line1、完整结果框或玩家实际看见的文字。

## 采集时点与事件对应

固定 EU4 1.37.4，EXE SHA-256 为 `b23fa0e1f698d31b01cdd1c3817a675805d8c6286cb66f9c231e6e2a42544d77`。以下地址均为 RVA；运行时 VA 为模块基址加 RVA。

REA 证据 `ev_f04745edfd1a59c9c991fa1fcf7a117740f64f9dc1750d268dbd1ff019e9ed96` 说明 `[0x1af6a0,0x1af73b)` 构造函数会移动键和值，并清空源字符串。因此观察器在原函数执行前复制，不在移动后读取旧源对象。完整函数字节、调用点字节属于另存的普通 PE 静态证据；不将其称为运行观察。

仅允许陆战返回点 `0x235493`、海战返回点 `0x230c08`。还要核对原始 RSP/RBP、键和值的实际地址、`NAME` 键、格式器上级返回点与栈内 combat 归属。combat 来自格式器栈槽减 `0x20` 的位置，不能从代码返回地址减偏移后读取。外层必须已有同一同步 router scope、逐场序列、日期和陆海战类型。

字符串最多 8192 字节，容量最多 128 KiB；读取两遍头部与内容，拒绝指针重叠、变化、不完整读取和预算超限。输出只保留序列、日期、类型及文字字节，源地址在同步回调结束时清除。同一事件重复相同值可保留；出现冲突或观察失败后不再恢复该字段。scope 退出时再次核对状态与丢失计数，失败就撤回文字。

## 接入范围

本批采用 `-ReasonMetadata -BattleNameHandoff` 构建 v35，继承 v34 的能力。新增入口与其余入口放入同一补丁事务；代码与 unwind 资源一经发布便保留至进程退出。此文档中的构建能力不表示当前游戏已安装 v35。

IBOW v8 保留完整 v7 并增加 NAME 输入。它独立于原生消息 metadata、title helper 候选和最终 Line1。现有 NPC 观察国准入与直接参战范围保持原合同，不通过改物理玩家或改观察国来制造正例。

源码位于 `work/native/information-battle-owned-name-handoff.h`、`information-battle-name-handoff-entry-plan.h`、`information-battle-name-handoff-observer-stub.S` 和观察器接线。证据与测试回执保存在 `work/runtime/information-battle-text-20261104-158-001/`。

## 尚待验证

复查既有静态证据确认，两处 NAME 构造都受客户端消息门槛支配：陆战 `0x2353d0` 的条件跳转可直接到 `0x2354c9`，越过 pair call `0x23548e`；海战 `0x230b4e` 的条件跳转可到 `0x232a1f`，越过 pair call `0x230c03`。因此客户端门槛不满足时，新增钩子也不会命中。此结论来自原有 selected REA 与固定字节，不是本批运行观察，也不证明 NPC 没有其他消息来源。

不能只为等待这条受限路径而重启或延长自然窗口。后续优先使用门槛前已采到的战斗结果、同事件 title helper 输出及已有 owned formatter 输入组件，研究独立的 NPC 格式化路径；仍须分别证明输入对应、格式化输出和完整结果各部分，不将 helper 候选冒充实际 NAME/Line1。

还需 NPC 独立路径、真实直接参战正例，以及与最终 Line1/结果框各部分的对应。离线合成数据与构建成功不能替代这些运行证据；`B04.raw_text` 不因此升级为可用。
