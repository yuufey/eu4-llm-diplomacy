# 国家点数的原生来源

本接口只支持固定 EU4 1.37.4 EXE：SHA-256 `b23fa0e1f698d31b01cdd1c3817a675805d8c6286cb66f9c231e6e2a42544d77`。以下静态 VA 使用映像基址 `0x140000000`；运行读取必须使用当前进程实际模块基址加 RVA，不能复用历史 VA。

## 从标签到余额数组

此前的 R34 资料只明确证明 `country+0x264` 是外交点数；R55 的三项效果记录和保存文件都保留了未命名的有序向量。新接口没有按熟悉的顺序给它们命名，而是补充了同一 EXE 的原生代码证据。

| 原生入口 RVA | REA Evidence | 本次使用的结论 |
| --- | --- | --- |
| `0x37f860` | `ev_04a9f807ae277081377b3b0b81b73782251ba1e8545beae8662e5331c037eac0` | 参数类别 0、1、2 分别选择 `ADM_POWER`、`DIP_POWER`、`MIL_POWER`，并传给共同的点数变化计算函数 `0x384a90`。它本身输出增长说明，不是余额读取器。 |
| `0x2f36f0` | `ev_0845b02a4fc556291ab18a395a6086b512090c2cbdd612401387deb4877be09f` | 国家更新路径按相同类别调用 `0x384a90`；类别 0、1 的结果进入 `0x37f530`，类别 2 使用 `0x9a320` 余额参与计算。 |
| `0x37f530` | `ev_8d954e98e71c8b0eeab7a280ebf790fa20eb1e369ab2063504f4f9c321911b84` | 带有 `AddPower` 原生日志标签；对 `country+0x260+4×类别` 的有符号 32 位余额加上变化值，再执行上下限处理。仅静态分析，没有调用该函数。 |
| `0x9a320` | `ev_1afb5da9462760c5ec485c7146ac18c2d6e969136608c19adec5f2a0d5b49c7a` | 11 字节叶函数直接返回 `*(uint32*)(country+0x260+4×类别)`。调用方按有符号整数使用它；读取器保存原始 4 字节并解释为 int32。 |

上述调用关系与参数对应构成静态推断：行政、外交、军事余额分别位于 `+0x260`、`+0x264`、`+0x268`，尺度为 1 点。它不依赖当前三个数值的大小，也不把每月增长或外交费用当成余额。

完整 REA 记录及其原始限制保存在 `work/runtime/information-country-scalars-20261024-001/rea-*/evidence.json`。机器合同 [native-power-contract-001.json](../../../work/runtime/information-country-scalars-20261024-001/native-power-contract-001.json) 保留各文件 SHA、Evidence ID 和有界 RVA/VA 范围；研究索引同时保留未采用的候选。

## 读取与来源边界

[country_resources_memory.py](../../../bridge/information/country_resources_memory.py) 只使用 `OpenProcess` 的 QUERY/VM_READ 权限和 `ReadProcessMemory`。它验证安装记录、PID 创建时间、进程路径与 EXE SHA、实际模块身份、固定 profile、辅助源码指纹，以及文件和运行代码字节，再从有界国家表窗口匹配 FRA 标签及槽号。

读取器对完整地址范围、单次 64 KiB 和总计 512 KiB 设限。两遍采样比较代码守卫、全局指针、国家表窗口、国家 handle、日期及三个余额的原始读取记录。任何不一致、守卫失败或句柄关闭失败都撤回可发布值。负数、零和 int32 边界值不会被当作未知。

双遍相同只说明两次采样相同，不能证明主线程原子快照或 world generation。国家表只查固定 256 项窗口，不宣称遍历完整世界。接口支持 FRA；其他观察国必须保持不可用。

原生 REA 记录、普通字节调查、纯 RPM 运行样本和历史保存核对是不同证据类型。历史 R70 保存中的 `powers={471 389 152}` 保留为未命名向量；它可以与同日期的原生有序样本比较，不能作为实时接口的回填来源。点数标签来自以上原生合同。

宣战厌战候选 `0x506e90` 的新 REA 记录 `ev_3126e0733c9957a9aefebbb6f2c62aeef31f6d75b60c8e0cba9140a1e5461f61` 确认其使用稳定度惩罚成本并输出 `WAREX_FROM_STABHIT`。它不证明当前国家厌战余额，因此没有接入 N04。

## 对外字段

`N06.monarch_points` 是一个整体字段：

```json
{
  "status": "known",
  "value": {"administrative": 471, "diplomatic": 389, "military": 152},
  "unit": "monarch_points",
  "scale": 1
}
```

上例数值是本批暂停样本，不是固定返回值。查询只请求该字段时不需要参考国家；同时请求 `prestige` 时仍须给出 `reference_recipient`。点数来源是纯 RPM；威望来源会调用已有 DLL 的只读原生检查，混合查询必须分别记录这两种来源。

对外 provenance 保存紧凑的身份、守卫结果和原始字节的 SHA，而不重复携带整段代码及国家表。独立运行原始报告保存完整读取日志；结果中的完整 capture canonical JSON SHA 用于关联，不能冒充磁盘文件 SHA。主动查询、现实周期和 `change` 的采样比较共用同一来源，不代表已经获得完整事件流。
