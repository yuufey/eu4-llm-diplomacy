## 输入与调用

最小接口对应原生`0x86B6C0`：

```python
from bridge.information import loan_interest_quote_math as quote

result = quote.evaluate(
    principal_scaled_i32=100_000,
    stored_rate_i32=4_000,
    months_i32=12,
)
# 合成例子的amount_i32为3996，单位为1/1000杜卡特。
```

这里的本金已经乘1000并取signed32低位；`stored_rate_i32`直接对应贷款记录`+0x28`的原始整数。模型保持该原始值，不重新选择动态利率或破产模型中的利率分支。合成例子用于核对运算，本批没有读取游戏中的贷款数值。

`quote_loan`接受未缩放本金、存储利率、到期原始日期和报价原始日期，先复现调用者`0x86B4E0`的月份与本金缩放，再计算单笔利息和本金加利息项。`quote_total`最多接收64条这样的记录，按描述函数`0x7C2EB0`的signed32方式累加。输出中的`loan_count`只表示所提供的条数，`source_list_completeness_verified`始终为false。

所有标为`i32`的输入均严格要求signed32整数，bool、浮点数和越界整数会被拒绝。多笔输入的字段必须恰为`principal_i32`、`stored_rate_i32`、`expiry_raw_i32`，避免忽略未知字段后返回貌似完整的报价。

## 日期和计算顺序

日期复用现有`engine_dates.project_engine_date`及其固定B23来源合同：4字节原始hour tick、24 ticks/day、365天年、固定2月28天。传给利息helper的月份参数为：

```text
12 × (到期年索引 − 当前年索引) + 到期月索引 − 当前月索引
```

同一月份内不按天数比例分摊；跨月一天也会改变月份索引。负月份仍进入后续原生算式，不预先改成0。

核心计算按以下顺序保留位宽和舍入：

1. 月份先乘1000并保留signed32低位，然后由原生unsigned区间条件选择快速或宽整数路径；利率有独立的选择条件。两条路径最终得到向零截断的月份因子和利率因子。
2. 对本金及两个因子分别计算`Q(x)=trunc0((int64(x)<<30)/32768000)`。
3. 先将月份定点量与本金定点量相乘，只保留低64位，再作算术右移15位；之后乘利率定点量，再保留低64位并右移15位。保留这一先后顺序。
4. 按指令逐次执行int64到binary32转换、乘`2^-15`、乘1000、加0.5。第一次浮点缩放结果为负时，对加0.5后的值执行`floorf`。
5. `CVTTSS2SI`后只保留正数。模型按屏蔽异常的语义保留越界转换的INT_MIN及`conversion_invalid`，最终0与正常零值可以区分。

模型明确假设IEEE binary32就近偶数舍入和屏蔽浮点异常。当前游戏线程的MXCSR尚未观察。提供给`floorf`的值均有限：低64位乘积经SAR15后绝对值不超过`2^48`，后续两个缩放及偏置也不会产生NaN或无穷，因此实现只需要已核对的有限输入路径。

`trace`保留快速/宽路径选择、各固定宽度中间量、回绕标记和五个浮点阶段的位模式。上例的最终定点量为130926，经后续步骤得到raw3996；这正是需要保留定点截断的原因。

## 现有查询入口的具体缺口

本批另核对了当前48个注册动作ID、bridge校验器和R74原生dispatcher。它们没有债务或贷款动作族；`take_on_debt`及`take_on_foreign_debt`等候选名称会在native query之前被bridge以`UNKNOWN_ACTION_ID`拒绝。原生dispatcher的未知项返回`QUERY_ACTION_UNSUPPORTED`，当前响应也没有描述槽`+0x70`、代偿报价或MXCSR控制状态。

这是列明服务源码的能力盘点，游戏原生界面的披露条件仍须另行核对。后续应先补齐并验证只读查询入口及所需浮点上下文，再决定报价的公开准入。动作家族的识别依据是虚表`0x1CB3BC8`及已核对的描述方法；栈对象中的`0x165`是多家族共用标识。
