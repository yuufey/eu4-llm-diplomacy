## 如何确定语义

REA 对 `0x2DC6E0..0x2E125B` 的国家保存器给出完整函数体。在四个选定指令窗口中，它把国家对象对应偏移传给 `0x956F0`，再把复制结果和保存键 ID 传给 `0x1707A10`。REA 对 `0x956F0..0x956F8` 的结果证明这是四字节原样复制；`0x1707A10..0x1707A4A` 则调用键名解析器和固定点数格式器。

格式器 `0x246BF0..0x246C7C` 使用有符号除法和余数，将原始整数按 1000 分成整数、小数部分，并输出三位小数。由此确定存储宽度和尺度，而不是根据当前采样值猜测。

保存键的名称也有独立来源。初始化器 `0x170D180..0x170D332` 遍历 `0x1FD8660..0x2324620` 中步长为 `0x208` 的记录；每条记录头是整数 ID，随后是名称。对四条记录的有界 PE 字节读取确认了名称、ID 和记录边界。`0x170D980..0x170DC9C` 按 ID 把名称放入 String32 向量，`0x17091B0..0x1709288` 用同一 ID 解析输出键名。

向量构造器还读取运行时扩展记录。因此，文件里的编译记录只闭合静态默认映射；实时读取器必须再次读取全局 RVA `0x242B868` 指向的实际键名向量，核对本次请求涉及的 ID 当前对应的名称。键名不符时不能继续发布相应数值。

上述 REA Evidence、函数范围、伪代码锚点、普通 PE 字节记录与保存指令窗口保存在[修正后合同003](../work/runtime/information-domestic-pressure-20261025-001/native-domestic-pressure-contract-003.json)。初始合同001和profile快照保留为历史，不能继续据其发布宗教统一。普通字节记录不是 REA Evidence，也不是运行时采样。初始候选索引见 [research-index-001.json](../work/runtime/information-domestic-pressure-20261025-001/research-index-001.json)。

## 读取边界

[domestic_pressure_memory.py](../bridge/information/domestic_pressure_memory.py) 只使用 QUERY_INFORMATION、VM_READ 和 ReadProcessMemory，不调用游戏函数。它沿用当前安装记录，核对进程创建时间、会话、路径、模块和 EXE 指纹，限定观察国家 FRA，并检查固定 256 项国家表中的唯一身份匹配。

[profile](../bridge/information/profiles/domestic-pressure-memory-1374.json) 固定三个偏移、尺度、实际键名向量布局、来源依赖，以及 11 段文件和运行时字节守卫，共 21043 字节。保留的第四条编译键字节只作额外身份守卫，不再授权读取宗教统一。profile 上限 64 KiB，单次 RPM 上限 65536 字节，总量上限 512 KiB；每次读取还检查完整地址范围。两遍分别保留键名、日期、身份、字段及原始读取记录。全局守卫、身份、双遍或句柄关闭失败撤回结果；独立字段失败保留其他已验证字段。

两遍一致不等于主线程原子快照，也不证明 world generation。主动、周期和变化采样共用同一读取路径；变化采样不是无损事件捕获。
