# 双边战争赔款关系读取

`bridge/information/bilateral_reparations_memory.py`仍是私有的只读leaf：它从调用方提供的字节读取器取得FRA和目标国家这一对国家的赔款关系。当前F03 v2投影会在父层country-view/FRA观察方准入后调用它，再把安全字段作为`reparations.observer_involved_contracts`子项公开。该子项只覆盖FRA与所查询目标的国家对，不是独立的第六个F03字段，也不会枚举目标国与其他国家的全部关系。

赔款收入和关系对象走不同的准入条件。`received_previous_month`沿用`income_comparison`页面条件；pair关系使用`observer_economy_bilateral_reparations` own-fiscal scope。收入页面拒绝不会撤销已准入的关系子项，关系子项未知也不会抹掉已知的上月收入。若父层country-view或FRA观察方身份未通过，则不发布关系子项。

## 能取得什么

leaf分别检查两个方向的关系表，并要求双方都指向同一个关系对象。读取器核对FRA和目标国家的完整引用、关系对象虚表与类型标记，返回实际付款方、收款方和起止原始日期；父层将日期换算为安全的日历日期，并可计算`start <= observed_date < end`。

这个日期判断只描述观察日期是否在记录的起止区间内，不等同于原生“当前正在付款”或“当前存在支付义务”。关系对象`+0x28`字节的完整业务语义仍未闭合，实际支付义务、金额或比例仍为unknown。若FRA与目标这一对的两个方向都没有匹配关系，leaf只报告pair无匹配项，不推断目标国与第三国之间没有赔款关系。

输入、地址、计数、完整引用或双向对象不一致时，leaf返回unknown，不输出半个关系。每个向量最多4096项，单次读取不超过1024字节，整个调用最多256次、160 KiB。读取trace按请求顺序记录读取结果；国家引用在前后各核对一次，向量只读取一遍，因此它本身不是原子快照。

## F03公开投影与边界

父层通过准入后，公开contract对象只提供`payer.tag`、`claimant.tag`、起止日历日期和`date_window_contains_observed_date`。投影不包含完整国家引用、指针、内存地址、原始trace或私有来源路径。它把`complete_country_contracts`标为false，并让`current_payment_obligations`、目标完整`active_contracts`、支付金额或比例保持unknown。

本批MCP直接查询、报告查询及6条周期结果都读取ENG，观察方为FRA，日期保持1456.4.12（raw 56556984）。FRA–ENG两方向均没有匹配关系，公开结果把这一对报告为known absent；它不能外推到ENG和其他国家的关系。该关系字段由MCP实际查询、报告和周期结果交付，并与严格重放的capture相符；本次没有关系存在或反向付款的实机样本，也没有直接观察游戏UI实际渲染。

以上REA记录固定在同一B23 EXE上。leaf只解析读取器返回的向量字节，不调用创建、登记或修改向量的原生函数。付款方和收款方的业务命名还参考既有R49单次议和结果；该历史效果不是本模块的实时采集证据。

普通PE/Capstone复核显示，原生入口`0xeb7b20`选择客户端当前国家。采集器再按逻辑观察方FRA重绑定自身经济关系范围，因此本模块读取的是FRA–目标国pair；物理玩家仍可为POR。这是读取范围的映射，不表示实际打开或渲染了FRA界面。`0x289a40`和`0xa68d10`用于按关系行owner及对方引用查找关系对象；`0xa68d10`返回关系对象指针，UI随后在`0x2c5980`读取结束日期。profile v3固定相关代码窗口；普通复核报告记录了被复核字节、RVA和B23 hash。读取模块只解析采集器传入的字节，不调用这些UI函数。

REA结果、固定EXE字节复核和历史运行效果是不同证据类型。`work/runtime/information-foreign-economy-contracts-20261031-001/stage90/ordinary-reparations-001/`保存了三个关系函数的864字节普通PE/Capstone复核，其中`0x28d840`包含两条经核实的CHAININFO续行；文件范围、哈希和未跟随的调用也在该归档中。后续的UI/getter复核另存于stage91，不覆盖stage90原件。

## 当前验证范围

离线字节树测试覆盖两个付款方向、pair无匹配、日期端点、引用变化、错误对象、重复项、双向不一致、短读和资源上限。此外，batch91 MCP端到端验收已通过：FRA观察方对ENG运行F03直接查询、报告查询，以及2秒和5秒周期订阅。收据记录8份实际经济capture和8条公开引用（直接查询1、报告1、周期6；2秒4条、5秒2条），3份手动结果副本不计入；所有capture均严格重放且canonical hash与公开来源对应，source pins未变化。两个订阅取消后无active subscription，MCP server exit 0并完成清理。查询与报告交付的外层结果为partial，这是因为`bankruptcy_risk`仍unknown；赔款字段在本次ENG样本中为known absent。本批实机结果没有覆盖关系存在、反向付款或对象+0x28语义；这些分支目前只有离线测试或静态依据。

当前公开字段仍为partial。实际支付义务、金额/比例、目标国完整合同枚举和破产风险仍未完成；上月收入数值与关系对象是否存在分别报告，不能互相代替。
