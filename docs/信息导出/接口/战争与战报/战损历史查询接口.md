# 战损历史查询接口

W03.battle_losses返回已保留的本国直接参战记录及逐场战损。必须显式配置`--battle-stream`；没有该来源时，默认服务仍将W03视为未接入。当前验证使用真实历史库的recorded回放，不是当前运行会话的新战斗数据。

```json
{"queries":[{"topic":"W03","object":{"type":"country","country":"FRA"},"fields":["battle_losses"],"parameters":{"limit":64}},{"topic":"W03","object":{"type":"session","session_id":"15612-1dd64921da9212c"},"fields":["battle_losses"],"parameters":{"limit":64}}]}
```

value包含event_refs、next_cursor与coverage。每条引用保留event_id、战斗类型、地点、记录日期、参战国、war_id状态、losses状态与来源。外层unit=battle_loss_event_page、scale1、period=captured_history、complete=false；各条losses内另保留实际人数/舰船单位和缺项。海战净变化不能一概当正损失，整条参战侧的损失也不能分摊给其中单个国家。

limit范围1–256，默认64；after_event_id只使用接口返回的游标。最多扫描256条存储记录，未准入记录不会泄漏event_id。游标可能是事件引用，也可能是仅表示存储进度的opaque值；不应自行拼接或跨战争使用。page_complete仅表示当前保留库在该游标后没有更多可扫描行，不表示历史完整。空页不能解释为没有战损。

war对象只支持object.war_id，ID须来自同一观察会话/进程的已验证B01.war_id，不按国家对猜测。未知战争归属的记录跳过并保留缺口；匹配ID才返回。只给actor/recipient返回WAR_ID_UNRESOLVED；同时带pair与ID返回WAR_HISTORY_PAIR_SELECTION_UNSUPPORTED，避免悄悄忽略选择器。当前法国正向历史样本的war_id仍未知，因此上述示例使用country/session。正向战争匹配、未知行及跨战争游标由离线夹具验证；真实较新库的六战争查询均因无FRA直接参战而返回空partial页。

同一查询可用于报告、现实时间周期和change。change只比较选中的有界分页，分页以外新增记录可能不改变该页；这不是无损事件流。查询和周期订阅不会启用capture，也不保证未来战斗已被采集。occupations、blockades、current_forces、reinforcement_change及战争累计战损继续缺失。

可用以下命令启动本次历史回放。服务配置/结果DB与原始战斗DB分开；原库只读，不传--battle-ingest-installation或--battle-manage-capture：

```powershell
python tools/serve_information.py --recorded-manifest work/runtime/information-battle-history-reuse-20261104-149-001/fra-legacy/recorded-context.json --battle-stream work/runtime/information-battle-history-reuse-20261104-149-001/fra-legacy/recorded-battle-stream.json --database work/runtime/information-battle-history-reuse-20261104-149-001/user-history.sqlite3
```
