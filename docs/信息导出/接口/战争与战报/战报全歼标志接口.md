# 战报全歼标志接口

`B03.annihilation` 报告已采集陆海战中，原生战斗侧 `overrun` 路径确认的全歼正例。陆战使用wire9的EOST扩展；海战也可复用旧NAVL块。它使用同一战斗载荷里的标志，不根据剩余兵力为零、净损失或胜负自行推断全歼。

查询仍使用已有战报事件 ID：

```json
{
  "topic": "B03",
  "object": {"type": "battle"},
  "fields": ["annihilation"],
  "parameters": {"event_id": "实际查询或订阅返回的事件ID"}
}
```

已知结果始终为部分结果，`complete=false`。`value.sides` 按原始战斗侧排列，各侧包含：

| 字段 | 含义 |
|---|---|
| `combat_side_index` | 原始战斗侧编号，不直接代表进攻方或防守方 |
| `participants` | 该侧完整参与者列表中的国家标识 |
| `native_overrun` | 已复制原生标志的布尔值 |
| `annihilated` | 败方标志为1时为 `known/true`；标志为0时仍为 `unknown` |

`classification_scope=native_overrun_path_only` 表示当前只确认这一条全歼路径。程序的正常结束路径既可能安排撤退，也可能因无退路而移除单位，因此清零标志不能证明“未全歼”，接口当前不输出 `annihilated=false`。

旧陆战载荷没有EOST块、旧海战没有NAVL块、参与者不完整、侧映射不唯一、胜负冲突、标志不是0或1、或胜方被标记时，结果保持未知。EOST和NAVL同时存在但标志冲突时也不作判断。`B03.retreat` 仍未实现。本字段不证明后续单位清理已经完成，或原生弹窗实际显示过。

第177批复用了原始v3海战记录：ATJ侧标志为1，全歼正例已通过查询、报告、事件交付、去重和取消核对。验收使用明确的 `mode=recorded`、历史ATJ观察范围；没有建立实时ATJ权限，没有重新运行该游戏窗口。实时来源仍要求观察国的完整引用出现在同场完整参战列表中。

第178批安装v36后，在一个新的35天自然窗口中取得7条陆战记录，全部包含同场绑定的EOST标志，其中3条标志为1。克什米尔参战的一场已通过查询、报告、事件交付及去重核对；该验证仍明确使用历史KSH查看范围，不授予实时KSH权限。实时法国视角对该场非参战战斗的查询被拒绝。玩家始终为葡萄牙，实时逻辑观察国仍为法国NPC。
