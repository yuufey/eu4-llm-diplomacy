# 战争发现与议和信息接口

## 订阅宣战通知

`war_declared` 已接入 C04 报告与事件订阅。正式构建方法见[信息接口使用说明](../信息接口使用说明.md)。部署后，先通过 `information_discover` 确认 C04 的 `native_war_declaration.capture_available` 为 true，再创建报告。当前实现与实机证据见[宣战通知验收记录](../../../../logs/2026-11-13宣战真实通知与攻守角色导出.md)。

把以下查询放入 `information_manage_report` 的 `config.queries`，并将报告的 `detail` 设为 `full`。

```json
{
  "topic": "C04",
  "object": {"type": "session"},
  "fields": ["event_id", "event_type", "event_date", "event_objects", "event_payload", "complete"],
  "parameters": {"event_type": "war_declared"}
}
```

取得报告编号后，用 `information_manage_subscription` 创建事件订阅。下面的 `report_id` 需替换为实际编号，每次管理请求使用新 `request_id`。

```json
{
  "request_id": "war-declaration-subscription-example-unique",
  "operation": "create",
  "config": {
    "name": "宣战通知",
    "kind": "event",
    "enabled": true,
    "report_id": "替换为报告编号",
    "event": {"types": ["war_declared"]}
  }
}
```

事件范围为 FRA 实际位于新战争参战名单中，包括 FRA 作为第三方参战的情况。`event_payload.actor` 表示宣战命令发起国，`recipient` 表示该命令目标国。可在订阅的 `event` 中增加 `actors`、`recipients` 标签列表筛选这两个角色。`country` 固定为观察方 FRA，玩家国家无需与之相同。

`event_payload` 提供 `war_id`、`attackers`、`defenders` 和 `observer_role`。攻击方取本次宣战命令发起国所在的参战侧，防御方取目标国所在侧，`observer_role` 为 `attacker` 或 `defender`。这一推导适用于当前宣战回调的发生时快照。默认输出直接使用这些角色名称。

完整视图同时保留 `participants`、`observer_side` 和 `scope`。`participants.side_a`、`side_b` 是发生时完整参战国标签列表，`actor_side`、`recipient_side` 及 `observer_side` 指向其中一侧。来源的 `role_basis` 说明攻守角色依据。`event_objects` 包含会话战争对象及全部参战国家对象。持久事件中的原始采集payload继续保留发生时的原值，C04业务字段增加可读角色。

通知保留命令返回时的游戏日期、参战名单和战争编号。`information_get_result` 与持久重开读取这些已保存的值，经过数日仍可读取。后续召盟回应可能在同一游戏日期加入其它国家，查询当前名单应使用 W01。

当前原生采集要求原调用正常返回、双向国家关联出现唯一新战争引用，并确认 FRA 在完整参战名单中。绕过现有命令入口的直接宣战调用、已注册战争引用的复用仍有覆盖缺口。采集丢弃、日志错误和缓存淘汰会保留具体 gap，队列溢出不会生成虚构事件。

角色筛选、去重、完整读取、持久重开与溢出记录的历史证据见[第324批验证记录](../../../../work/runtime/information-war-delivery-20261109-324-001/summary.json)，当前实机与原始回调夹具见上述验收记录。

第67批增加了 W01 的两侧参战名单读取，调用和边界见[战争参战名单只读接口](战争参战名单只读接口.md)。新安装确认 `native_war_participants_query=true` 后，选定战争可返回国家标签及请求双方的侧别；领导人、加入日期和共同参战角色仍未知。下文第65批的实机样本属于当时只返回战争编号的版本。

W01 通过现有只读原生接口枚举一对国家当前关联的战争，返回会话内有效的编号。LLM 可以先发现编号，再把选定编号用于战争查询或议和预览。信息查询不会执行宣战或议和。

## 发现与选择战争

先调用 `information_discover`，查看 W01 的 `parameters`、`object_requirements` 和 `war_selection`。当前来源是 `ObserverSession.inspect_peace_contexts`，实际已验证范围为 1.37.4、观察方 FRA、`white_peace/initiate`；其他视角不能借此扩大读取权限。

```json
{
  "request_id": "war-discovery-example-unique",
  "queries": [{
    "topic": "W01",
    "object": {"type": "country_pair", "actor": "FRA", "recipient": "BUR"},
    "fields": ["war_id", "participants"],
    "parameters": {}
  }]
}
```

把这组参数传给 `information_query`。唯一候选的 `war_id` 返回 `known` 字符串；结果的 `objects` 同时提供可直接用于下一次查询的 `{type:war,war_id,actor,recipient}`。编号属于当前 observer session，不要照抄文档或历史存档中的编号。

| 实际读取状态 | 返回含义 |
| --- | --- |
| 完整枚举且只有一个候选 | `war_id=known`，自动选择该候选 |
| 完整枚举但有多个候选 | `WAR_SELECTION_REQUIRED`；从 `objects` 选择，不猜第一条 |
| 完整枚举且没有候选 | `not_applicable/NO_MATCHING_WAR`，不是读取失败 |
| 指定编号不在本次候选中 | `WAR_NOT_FOUND_IN_CURRENT_CONTEXT`，不替换成其他战争 |
| 枚举不完整 | `WAR_ENUMERATION_INCOMPLETE`；保留已观察到的公开候选，不声称集合完整 |
| 会话、日期、国家对或提交标记不符 | 撤回字段并报告具体原因，不重新发送查询 |

显式选择时，使用 `objects` 中的一项作为 `object`，`fields` 可只保留 `war_id`。也可用 `parameters.war_id` 选择；若两处编号不同，请求会失败。`action_id` 和 `phase` 仅兼容 `white_peace`、`initiate`，W01 不接受议和条款。当前仍需同时提供 actor 和 recipient。

`source.provenance.enumeration_complete` 表示国家对战争列表的枚举状态。它不表示战争参与者、领导人、加入日期或角色已齐全；这些字段仍返回 `WAR_CONTEXT_FIELD_UNVERIFIED`。两国标签不会冒作全部参战者。编号的同日期读档行为尚未专项验证，`same_date_reload_verified=false`。

## 查询选定议和方案的后果

先由 W01 获取当前编号，再对该战争查询 P04 或 P05。例如索取省份88的方案：

```json
{
  "topic": "P04",
  "object": {"type": "war", "war_id": "替换为当前编号", "actor": "FRA", "recipient": "BUR"},
  "fields": ["consequences", "territorial_changes"],
  "parameters": {
    "action_id": "cede_province",
    "phase": "initiate",
    "peace_context": {
      "war_id": "替换为当前编号",
      "direction": "demand",
      "terms": [{"action_id": "cede_province", "beneficiary": "FRA", "province_ids": [88]}]
    }
  }
}
```

将它放进 `information_query.queries`，并使用新的 request_id。P05 可用相同对象与方案，选择 `overextension` 或 `coalition`。预览对象中的 `complete`、`available`、`scope`、`requested_terms_applied` 和原始单位会保留；完整性须按对应层级解读。字段 `known` 只说明取得了这个对象，不代表对象内部的全部后果已经齐全。包围网候选的真实空集合与未知状态分别表达。

P03 和 A02 的 `acceptance_complete` 读取完整性标记。存在明细（`details_available=true`）并不保证明细完整；有未知因子时可以返回已知的 `false`。

报告和周期订阅使用同一组查询。第65批在暂停现场核对了 W01 的发现与显式选择、上述后果字段的主动查询和后台周期结果；查询原件与同次原生载荷逐项对照。多候选、空集合和身份异常来自明确标注的离线测试，未制造新的战争或推进日期。实机收据见 [第65批验收](../../../../work/runtime/information-war-discovery-20261027-001/live-acceptance-003/report.json)。完整战争状态、可见性和其他未实现字段仍按开发计划继续补齐。
