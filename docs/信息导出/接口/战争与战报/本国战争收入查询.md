# 本国战争收入分项

N01的`war_income`提供法国（FRA）上一月原生收入账本中的四类分项：战争赔款、战利品、封锁收入和劫掠收入。字段为`partial`，`complete=false`。完整战争收入总额、当前收款义务和具体战争归因仍为unknown；已取得的四项为0，也不能推出全部战争收入为0。

这项读取复用本国月度收支的同一份capture，不新增财务内存读取范围。它不使用第96批破产预测模型，也不授予F03查询外国账本的权限。观察方和对象均须为受支持的FRA本国范围，固定使用已验证的1.37.4 B23 EXE与原有资源、月度账本profile。

## 查询与单位

只请求战争收入或把它与月度三字段混合时，不需要参考国家：

```json
{
  "topic": "N01",
  "object": {"type": "country", "country": "FRA"},
  "fields": ["war_income", "monthly_income", "monthly_balance"],
  "parameters": {}
}
```

如果同时请求`treasury`，仍须提供不同于FRA的`reference_recipient`，沿用既有只读公共projection的参数规则。战争收入与月度字段共用一次月度capture；国库余额使用独立来源，不能代替缺失的收入分项。`loans`继续由独立的国家记录来源处理。

`war_income`外层的unit为`war_income_information`、scale为1。它的`value.components`分别包含以下项目；每个金额的原始值是signed32整数，单位为杜卡特、scale为1000，数值为raw/1000。

| 分项 | 原生收入类别 | 收入槽 |
| --- | --- | --- |
| `war_reparations` | `INCOME_WAR_REPARATION` | 8 |
| `spoils_of_war` | `SPOILS_OF_WAR_ECOVIEW` | 12 |
| `blockades` | `INC_BLOCKADES` | 17 |
| `looting` | `INC_LOOTING` | 18 |

这些金额的period为`month`、reference_period为`previous_month`，来源是所观察时刻的上一月收入账本缓存。它们不表示自查询以来新增的收入，也不保证属于同一场战争。赔款分项表示账本实收，不能据此推断当前赔款合同或付款义务。

`observed_components_subtotal`只对这四个原始整数作数学精确求和，不做不存在的“原生总额”32位回绕。它明确带有`native_total=false`和`four_components_only=true`。各分项仍保留负值；不把负值改为0，也不把未取得的值填成0。

赔款槽8已经包含在既有`monthly_income`经常性聚合中。因此，四项小计不能直接加到`monthly_income`上当作总收入。响应以`monthly_income_overlap`和分项的`overlaps_monthly_income`表达重叠；`total_war_income`仍为unknown。战争税带来的增收、其他战争相关款项、支出及逐场归因尚未完整分离。

## 校验与公开范围

父适配器沿用本国月度来源的live会话、版本、FRA观察方、对象、进程创建时间、ROM和日期检查，并比较两遍capture。投影再核对228字节账本、19个收入槽、profile pin、basis和period，并调用原有月度记录验证器。任何不一致都会撤回相应结果；两遍相同不等于原子快照。

`war_income`与月度字段混合查询时，三项经常性聚合仍使用原算式，战争收入只新增分项投影。一次查询不会为每个字段重复capture，也不会提交外交动作。该字段不调用游戏函数；只请求这些账本字段时也不发起只读外交inspection。

包含`war_income`的新查询会将这一路账本来源的公开`source.provenance`限制为会话校验摘要、profile、period及内容哈希。完整原始账本、收入/支出槽数组、模块基址、国家指针和ROM字节留在私有归档中。`capture_report_sha256`与`private_provenance_sha256`分别用于核对完整capture和经过选取的账本来源元数据；哈希表示内容，同样的观测内容可以得到相同哈希。旧月度三字段单独查询及其他独立来源的元数据合同暂时保持原样。
