# 任务信息查询

任务查询提供实际任务树、前置条件、完成记录、已支持的条件进度及奖励规则。C04提供任务可完成性变化、[最外层与省份持有条件变化](任务最外层条件变化订阅.md)和任务完成通知。当前实机与修复证据见[任务通知验收记录](../../../../logs/2026-11-13诺曼底任务通知与查询整合修复.md)。

运行中采样允许游戏日期单调向前，字段地址、国家和任务数据继续比较。完整视图保留采样时间区间，日期回退或采集中相关数据发生变化时撤回该次读数。读取按所选任务限定条件和省份范围。

任务适配器读取国家实际记录的任务槽位、子任务对象和完成记录，再与当前静态定义连接，提供 M01 的任务 ID、槽位根和部分本地化文本、M02 的前置规则与完成记录、M04 的奖励规则。它沿用信息服务的主动查询、现实或游戏周期及变化采样入口，不执行任务奖励，也不推进游戏。

任务槽位里可以同时保存用于不同分支的根。根已进入国家的任务容器，不等于其中所有任务都在界面中可见，也不等于分支条件已满足。返回的任务 ID 带有 `branch_visibility="unknown"`。M02可提供已支持原生条件的进度与部分可完成性，整体完整性仍为false，分支可见性继续未知。名称和说明可读取当前原生缓存，动态占位符保留未知，详见[本地化接口](任务本地化接口.md)。具体目标对象的作用域求值及奖励实际效果仍有缺口。

## 任务完成通知

原生任务完成采集已接入 C04 报告、订阅和持久快照。正式构建方法见[信息接口使用说明](../信息接口使用说明.md)。启用后，先通过 `information_discover` 检查 C04 的 `native_mission_completion.capture_available`，再建立报告和事件订阅。wire1覆盖命令返回时的完成记录变化，wire2覆盖已确认的任务命令和脚本效果插入位置，两种来源共用 `mission_completed`。

报告的 `detail` 设为 `full`，`config.queries` 使用下面的查询。取得报告编号后，创建 `kind="event"` 的订阅，填写该 `report_id`，并将 `event.types` 设为 `["mission_completed"]`。完整管理参数见[信息接口使用说明](../信息接口使用说明.md)。

```json
{
  "topic": "C04",
  "object": {"type": "session"},
  "fields": ["event_id", "event_type", "event_date", "event_objects", "event_payload", "complete"],
  "parameters": {"event_type": "mission_completed"}
}
```

`event_payload` 保存观察国 `country`、原生任务标识 `mission_id`、`completed_before=false`、`completed_after=true` 和来源范围 `scope`。v51/v52通知在任务命令返回后的实际状态从未完成变为已完成时产生。标识按现有 String32 合同保留最多256字节的可打印 ASCII，原生日志使用十六进制传输，公共结果恢复原字符串。它可作为既有任务查询的 `task_id` 参数，查询器继续核对任务是否在当前捕获树中。

wire2在完整视图中增加 `completion_path`。`command_handler` 表示任务命令中的完成记录插入，`script_effect` 表示已确认的脚本效果直接插入。原生必须正常返回并确认新定义键插入成功，重复写入已有完成记录不发通知。事件日期是这次原生插入返回时的游戏日期。脚本路径的通知描述完成记录变化，奖励的实际执行结果另按任务奖励接口的证据说明。

来源固定为 FRA。v51/v52读取命令中的任务标识及该国完成记录，原生处理中的奖励与完成记录更新在玩家专属消息分支之前执行。wire2读取已确认插入位置的定义标识、返回结果及该国完成记录。两者都按规范国家身份选择 FRA，物理玩家身份由会话另行记录，通知的 `event_objects` 包含 FRA 国家对象。

完整读取和持久重开使用已保存的发生时日期与完成状态，游戏继续推进后仍可读取。wire2在完成集合插入处采集，同一次插入交付一次通知。已识别的按阈值批量补录及其它未知调用未纳入此来源。任务条件的即时进展、完成记录撤销、其它脚本或 AI 写入位置仍有缺口，现有 M02 条件采样继续按下节合同使用。

来源证据、离线验证和游戏现场状态见[第326批记录](../../../../work/runtime/information-mission-source-20261109-326-001/summary.json)。

集合写入候选及新旧协议隔离的范围见[第330批记录](../../../../work/runtime/information-mission-set-20261109-330-001/summary.json)。

## 已知条件的变化订阅

### 原生可完成性变化

`mission_availability_changed`提供原生可完成性变化，可通过C04报告、订阅和持久快照读取。支持情况由当前安装的能力发现确认。

该来源观察游戏实际调用的任务可完成性谓词。首次成功求值为该任务建立基线，相同结果只更新观察日期，后续 `false→true` 或 `true→false` 才发通知。采集限定规范FRA身份，支持已核对的AI工作线程调用，物理玩家另行记录。采集发生在游戏自身的求值返回路径。

启用后，先发现 C04 的 `native_mission_availability.capture_available`。报告查询沿用上节 C04 结构，`parameters.event_type` 与订阅 `event.types` 使用 `mission_availability_changed`。

默认`event_payload`包含`country`、`mission_id`、`eligible_before`和`eligible_after`。完整视图还保留`previous_observed_date_raw`和`scope`。`event_date`是后一次求值的观察日期，`previous_observed_date_raw`是前值最近一次被成功观察的日期。两次求值之间世界状态实际改变的时刻仍未知。任务标识最长256字节，按现有可打印ASCII合同保存。

该谓词包含完成记录、前置和原生任务条件判断，分支可见性与条件树的详细进展继续由各自接口说明。游戏尚未求值的任务不会产生这项通知，两次求值之间改变又恢复的状态也可能遗漏。定义身份改变或日期倒退会重新建立基线并报告采集缺口。完整读取及持久重开保留发生时的两个观察日期与值。[329来源与离线交付记录](../../../../work/runtime/information-mission-events-20261109-329-001/summary.json)

### M02已知条件采样

M02的变化订阅可选择 `completion_status`、`currently_completable`、`condition_progress`。请求包含后两者时，来源仅在所选任务的条件、前置及完成记录均已知时建立比较基线。未知或读取失败保留原基线，定义或任务集合改变时重新建基线。字段的 `complete=false` 保留，比较不会将分支可见性判为已知。

使用原有 `kind="change"` 与现实或游戏周期调度。首次已知样本建基线，相同样本不交付，后续已知变化交付一次。完整条件的即时进展仍有来源缺口，两次采样之间发生后又恢复的状态无法由该方式交付。保存来源沿用主动查询限制。

314批134项受影响测试通过，覆盖实际调度、失败保留基线、定义变化及持久重开。当前FRA非玩家现场通过正常工具读取“解放诺曼底”、建立基线和抑制相同样本，订阅已取消，游戏日期未推进，未取得实机进度变化正例。[314验收](../../../../work/runtime/information-proposal-state-20261109-314-001/live-mission-change-acceptance/summary.json)

## 当前游戏

在已经安装并核对的 1.37.4 只读会话上启用：

```powershell
python tools/serve_information.py `
  --operator-session work/runtime/<installation>/installation.json `
  --observer FRA --mission-game-data `
  --database work/runtime/information-service/information.sqlite3 `
  --journal work/runtime/information-service/diplomacy.sqlite3 `
  --tick-seconds 2
```

原生读取器当前只核对了法国观察方。宿主的 `--observer` 必须与原生会话的控制范围一致；模型不能通过查询参数更换观察国。读取使用 Windows `QUERY_INFORMATION|VM_READ`，核对 EXE SHA-256、进程创建时间、安装会话、模块路径、关键指令和虚表调用关系。每次读取最多 512 KiB，并对日期、国家身份、槽位和字符串做前后两遍比较。它不是游戏主线程中的原子快照，也没有证明世界代际；重启后仍沿用公共合同的重新确认规则。

1.37.4 的布局与字节约束保存在 `bridge/information/profiles/mission-memory-1374.json`，不依赖本机研究目录存在。其他 EXE、缺少配置、字节不匹配、读取失败或两遍不一致时返回不可用，不尝试另一个偏移。

安装观察器后，M02读取器按已登记的DLL及构建清单散列核对任务可完成性、最外层条件和直接省份持有条件的补丁。对应资产保存各入口的实际主体、unwind、全局变量位置及原生继续执行模板，运行时逐项验证。构建变化后需要登记该工件的精确资产，原有任务查询和事件协议继续复用。当前v64资产及正常所选任务实读见[任务进展范围与v64准入核对](../../../../logs/2026-11-15任务进展范围与v64准入核对.md)。

## 查询对象与字段

任务主题要求明确的本国对象。参数可以选择槽位中的 `root_id` 或对应的 `task_id`；不在捕获树中的根或任务不会由国家标签推算出来。

```json
{
  "request_id": "mission-query-001",
  "queries": [
    {
      "topic": "M01",
      "object": {"type": "country", "country": "FRA"},
      "fields": ["task_id", "branches"]
    },
    {
      "topic": "M02",
      "object": {"type": "country", "country": "FRA"},
      "fields": ["completion_status", "prerequisites"],
      "parameters": {"task_id": "fra_liberate_norm"}
    },
    {
      "topic": "M04",
      "object": {"type": "country", "country": "FRA"},
      "fields": ["rewards"],
      "parameters": {"root_id": "french_missions_1"}
    }
  ]
}
```

| 字段 | 已提供的数据 | 限制 |
| --- | --- | --- |
| M01 `branches` | 按槽位顺序记录根 ID，说明来自实时容器还是保存字段 | 不判断分支可见性或条件真假 |
| M01 `task_id` | 实时源直接读取加载根中的子任务 ID；保存源对应当前静态定义，provenance 区分两者 | 不把脚本 ID 当作显示名称；分支可见性未知，不是当前可完成任务清单 |
| M01 `name`、`description` | 实时源按实际任务 ID 读取当前语言的原生缓存，按会话显式编码解码；逐项返回已知文本或未解析模板 | 含 `[]`、`$` 的动态文本保留 unknown，无 `text`；有缺项时字段 complete=false、报告 partial；保存来源不回填 |
| M02 `completion_status` | 捕获的已完成任务 ID；选定任务时可判断其是否在列表中 | 存档未写该字段时返回未知，不能当作空集合 |
| M02 `prerequisites` | 对应定义的 `required_missions` 原始规则，以及字面 ID 对捕获完成集合的核对 | 逐任务给出已满足、未满足或未知；不判断任务 trigger 或分支可见性 |
| M02 `unlock_conditions` | 根的 `potential`、`potential_on_load` 以及任务前置规则 | `evaluated=false`，没有引擎条件求值结果 |
| M04 `rewards` | 对应定义的 `effect` 原始规则，保留条件分支 | `evaluated=false`、`applied="unknown"`，不声称奖励执行或修正生效 |
| M04 `claims`、`casus_belli`、`trade_modifiers` | 将对应定义中的字面奖励命令按三类索引，保留原始节点、作用域、分支条件引用和文件行号 | 静态规则库存，三个字段均 partial/complete=false；不求值条件、解析实际对象或认定奖励已获得 |

静态规则来自当前安装和启用模组配置，按根 ID 与状态对应。来源说明保留文件 SHA、行号、编码及配置指纹；这个对应关系不能证明过去的存档使用过完全相同的定义文件。定义变化时，本次规则字段失效；已经确认的槽位和完成记录仍保留。解析细节见[任务定义接口](任务定义接口.md)。

三类奖励规则的查询、已知空库存与未知的区别见[任务奖励规则接口](任务奖励规则接口.md)。`unlocks` 和 `duration` 尚未实现；字面规则分类不能替代当前国家的条件奖励解释。

实时子任务与文件定义的差异会分别列出，文件读取失败不抹掉已经确认的原生任务 ID。任务专属读取失败不回退成静态任务列表，读取合同与实采见[实际子任务接口](任务实际子任务接口.md)。

字面前置列表的完成核对见[任务前置状态接口](任务前置状态接口.md)。它是当前文件规则与捕获完成记录的派生；`evaluated=true` 只限这个前置列表，不延伸到 `unlock_conditions`、任务 trigger 或整体可完成状态。

实时 `unlock_conditions.captured_inputs` 还会按需提供四个分支旗标、地图模式和 Domination 条件的有限结论。当前字节符合原生不经过 TLS 的短路返回真路径；其他组合保持未知，也不提供完整 DLC 清单。读取合同和当前证据见[任务分支输入接口](任务分支输入接口.md)；整体 `evaluated=false` 保持不变。

## 指定历史存档

也可以明确查询现有纯文本 `EU4txt` 存档：

```powershell
python tools/serve_information.py --mission-game-data `
  --mission-save 'C:/path/to/test.eu4' --observer FRA `
  --database work/runtime/information-service/saved-missions.sqlite3
```

这与 `--operator-session`、`--recorded-manifest` 互斥。存档数据始终标为 `recorded`，日期保留保存的日历日期；没有可靠的游戏会话、世界代际或单调游戏日时，这些字段保持未知。服务不会生成虚构的会话编号，也不会用文件时间代替游戏时间。因此这类存档任务来源只支持主动查询，不声明周期或变化订阅。

存档读取器流式扫描文件，保留文件 SHA-256、大小、mtime、目标国家块和原始任务结构。压缩存档、未知版本、目标缺失、结构歧义、超出读取上限或文件变化时失败关闭。`completed_missions={}` 与完全缺少 `completed_missions` 分别表示明确的空列表与未知。

## 已验证范围

2026-10-24 的 FRA/POR 暂停测试场景中，纯 RPM 读出了 5 个任务槽、18 个根 ID 和空的已完成列表。完整流式解析 R70 保存记录后，槽位和 18 个根 ID 与实时读取一致；存档没有写完成字段，因此存档查询对该列表保持未知。先前的来源清单漏列了 `fra_missions_5_continuation`，首次整体验收沿用该错误清单而在差异断言处失败，原始报告仍保留。当前数量来自重新读取的完整保存字段，不能再沿用旧清单的 17 个根。

第三批的18个实时根对应有效中文补充模组文件中的61个任务定义条目；第五批已直接读取这些根中的实际子任务，确认同样为61项。这个计数不表示61项都可见、可完成或已完成。最新任务 ID 的 MCP 主动查询、筛选与两次现实周期交付见[第五批验收](../../../../work/runtime/information-loaded-tasks-20261024-001/live-acceptance-001/report.json)。第三批根与完成记录验收仍保留在 [live-acceptance-003/report.json](../../../../work/runtime/information-missions-20261024-001/live-acceptance-003/report.json)。两批均核对前后玩家、暂停和日期未变。法国任务部分自包含为各自真实 fixture，离线回归时仍是历史记录。普通文件反汇编、REA、纯 RPM 观察和框架测试分别留存，见[原生读取合同](../../实现研究/任务/任务原生读取合同.md)与[实际子任务接口](任务实际子任务接口.md)。
