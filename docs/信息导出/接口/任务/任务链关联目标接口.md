# 任务链关联目标接口

`M05.linked_targets` 将所选任务的前置、后续任务与目标条件关联，`M05.basis` 提供这些关联的依据和缺项。两者复用已有 `M02.prerequisites` 和七个 `M03` 字段，不另写游戏脚本解析器。服务器启用 `--mission-game-data` 后注册这两个字段。

查询必须指定逻辑观察国、任务根和任务 ID；与已有 `reward_timing` 使用相同参数，可以一起查询：

```json
{
  "topic": "M05",
  "object": {"type": "country", "country": "FRA"},
  "fields": ["linked_targets", "basis", "reward_timing"],
  "parameters": {
    "root_id": "french_missions_1",
    "task_id": "fra_burg_succession"
  }
}
```

当前服务的一次 M03、M04 或 M05 读取使用独立的采集范围。M05 由 MissionAnalysisSource 统一路由，复用原投影器处理奖励期限、原生已加载前置和当前有效配置中的目标条件；各字段共用同一次经过身份和双次读取核对的任务状态。定义变化或任务成员关系未验证时，不生成替代的任务链。同次采集共享不代表主线程原子快照；不同查询、周期任务或会话之间不缓存这份状态，即使游戏日期相同也会重新采集。

这些规则查询仍采集任务身份、完成记录、原生前置和前置完成状态，跳过未被使用的完整任务触发树。M02 的条件进度及当前能否完成任务继续使用原有完整读取，不因本次优化减少条件输入。原有身份、代码校验、双次读取和句柄关闭检查保持。

依赖关系按已加载任务组织，可以跨任务根。缺失或同名歧义的依赖、循环、未知目标及未解析的作用域分别保留，不能把它们当作空集合。目标规则保留条件、作用域和文件来源，供调用者追溯；静态引用的省份或国家不一定是当前实际生效的目标。

例如所选任务 A 的后续任务 C 同时要求 A 和 B，接口也收录 B 及其前置，并将其与 A 本身的前置区分。结果中的 `dependency_edges` 按“任务要求某前置任务”的方向记录，不能反向解释为已经解锁或已经完成。

两个字段均为 `partial`、`complete=false`。任务链表示依赖与目标条件的关联，不证明这些任务当前可完成，也不证明一次扩张能同时完成多个任务。完整条件求值、外交与贸易冲突、完整扩张代价及方案可行性仍需后续分析。第189批新增[候选成本接口](任务链候选成本接口.md)，提供显式候选行动在当前局势下的部分成本，不代表本任务链图已求值成本或连带完成目标。磁盘配置与当前已加载任务相互关联，也不证明配置内容与引擎启动时加载的规则完全一致。

这两个字段支持主动查询、报告和现实时间周期订阅，不声明原生事件通知或变化订阅能力。周期读取复用同一来源，不会推进游戏日期。可调用观察国、版本、参数和触发方式以 `information_discover` 返回的字段能力为准。

第179批实机查询中，`fra_burg_succession` 关联11个任务：所选1个、前置1个、后续5个及后续的其他前置4个，共13条依赖。七字段的规则行数分别为省份7、区域7、国家1、所有权8、控制2、核心0、属国11；同一条件可以投影到多个字段，这36行不代表36个不同目标。核心字段保持未知，行数0不解释为“没有核心目标”。已加载的后续任务也不一定是当前可见或可选的任务分支。

第179批的混合采集约28秒，较长周期的一次结果合并了6个到期点；首次客户端等待超时后，从原输出库经MCP取回成功结果。原记录保存在 `work/runtime/information-mission-chain-targets-20261105-179-001/summary.json`。

第180批改为按需采集并共享同次状态后，单次混合查询实测4.93秒，原生规则输入采集约0.16秒；所有字段与完整读取结果逐项相同。实际两个周期采集分别约5.02和5.19秒，较长周期仍合并了2个到期点，因此配置间隔仍不是交付延迟保证。周期验收没有发生客户端超时，并实际验证了取消短订阅后长订阅保持运行、最终两个订阅均取消。不同请求之间没有共享状态缓存。
