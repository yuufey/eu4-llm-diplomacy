# 静态任务定义接口

`bridge.information.mission_definitions.MissionDefinitionIndex` 是一个只读的、
有界的 EU4 任务脚本索引。它读取安装目录的 `missions/*.txt`，按版本和启用模组
解析有效文件集合，并保留任务树的原始规则结构。它描述的是静态候选定义，不代表
游戏进程当前已经加载了哪个任务树，也不读取任务完成状态或本地化名称。

## 构造

```python
from bridge.information.mission_definitions import MissionDefinitionIndex

index = MissionDefinitionIndex(
    game_root=None,
    user_data=None,
    enabled_mods=None,
)
```

- `game_root`：EU4 安装目录。省略时读取 `work.local_config.game_root()`。
- `user_data`：EU4 用户数据目录。省略时读取 `work.local_config.user_data()`。
- `enabled_mods`：模组描述文件、模组目录或带 `descriptor`/`root` 的对象列表。
  `None` 表示必须读取 `user_data/dlc_load.json`；显式传入 `[]` 表示只读基础游戏，
  即使用户数据目录没有 `dlc_load.json` 也不会补猜模组栈。
- 默认单文件上限为 8 MiB、所有候选输入上限为 32 MiB、文件数上限为 4096，
  可以通过 `max_file_bytes`、`max_total_bytes` 和 `max_files` 调小。超过上限时来源
  进入 `unready`，不会返回部分旧索引。

目前只把从 `launcher-settings.json` 验证出的 `1.37.4` 宣称为支持版本。版本文件
缺失、格式无效、版本未知或模组描述文件无法解析时，索引失败关闭。

## CWTools解析

正常服务的`--mission-game-data`入口使用`CwtoolsScriptParser`读取任务脚本。
适配清单的`max_batch_files`声明每个解析器进程的文件上限，当前清单为64，
省略该字段的旧清单使用16。每批输入总量上限为4 MiB，结果按输入文件顺序返回。
同一文件的任务规则原文共用一次按行拆分，完成该文件的定义投影后释放行索引。

## `context()`

`context()` 每次调用都会重新检查输入。结果是 JSON 可序列化对象，主要字段如下：

```json
{
  "status": "ready",
  "complete": true,
  "mode": "static",
  "context_scope": "static_rules",
  "game_version": "1.37.4",
  "supported_versions": ["1.37.4"],
  "configuration_sha256": "...",
  "definitions_sha256": "...",
  "configuration_files": [],
  "definition_files": [],
  "input_files": [],
  "mission_directory_members": [],
  "enabled_mods": [],
  "reasons": []
}
```

`configuration_files` 至少包含版本文件；自动读取模组栈时还包含
`dlc_load.json` 和每个模组描述文件。`definition_files` 是覆盖解析后的有效文件，
`input_files` 则包含基础游戏和启用模组的全部候选文件，包含被同路径覆盖的文件。
每项带路径、来源、大小和 SHA-256。`mission_directory_members` 记录基础游戏及每个
启用模组的任务目录成员；目录在构造时不存在也会记录为不存在。

构造后出现文件新增、删除、内容变化、目录变化或配置变化时，`status` 变为
`unready`，`complete` 变为 `false`，原因写入 `reasons`。上层可以把这个上下文作为
`static_rules` 来源的范围证明；它不能改变实时会话上下文的 `unready` 状态。

## 模组覆盖

每个启用模组描述文件必须能解析出本地目录。`archive` 模组不支持；目录未知、描述
文件缺失或 `replace_path` 无法建立时直接失败关闭。模组按 `enabled_mods` 顺序应用：

1. 先加入基础游戏 `missions/` 文件。
2. 同一相对路径的模组文件覆盖之前的文件，并在 `definition_files` 中保留模组来源。
3. `replace_path="missions"` 或其 `missions/` 子路径先移除被替换范围内的基础定义，
   再加入模组文件；模组没有提供替换范围内文件时失败关闭，不回退到基础游戏。

解析器保留重复顶层任务根的证据，但不会无证据选择其中一个；同一有效文件集合中
重复 `root_id` 会产生 `DUPLICATE_MISSION_ROOT` 并使来源不可用。

## `roots(ids=None)` 和 `root(root_id)`

索引就绪时，`roots()` 返回按有效文件路径和脚本顺序排列的任务根列表。传入字符串
或字符串列表只返回指定根，且保留调用者请求顺序。`root(root_id)` 是单根便捷接口。
未知根不会静默忽略，而是抛出 `MissionDefinitionError`，其 `code` 为
`UNKNOWN_ROOT_ID`；索引不可用时则抛出首个范围错误。

每个根的结构为：

```json
{
  "root_id": "french_missions_1",
  "slot": 1,
  "generic": false,
  "potential_on_load": null,
  "potential": {"key": "potential", "children": []},
  "tasks": [
    {
      "task_id": "fra_liberate_norm",
      "position": 1,
      "required_missions": {"key": "required_missions", "children": []},
      "trigger": {"key": "trigger", "children": []},
      "effect": {"key": "effect", "children": []},
      "provinces_to_highlight": {"key": "provinces_to_highlight", "children": []},
      "source": {
        "path": "missions/DOM_French_Missions.txt",
        "source_kind": "enabled_mod",
        "line": 1,
        "end_line": 2,
        "encoding": {"name": "utf-8-sig", "structural_only": false}
      }
    }
  ],
  "source": {}
}
```

示例中的规则节点是简写。实际节点总是保留 `key`、`value`、`children`、`line`、
`end_line` 和 `ast_semantics="structural"`；`children` 的顺序与脚本一致。`kind` 区分 `bare`、`scalar` 和 `block`，因此裸任务标记与空条件块不会混同；`assignment` 保留等号、比较符或 `null`，`raw_key/raw_value` 保留引号与转义写法。单个字段返回一个节点对象，重复字段返回
按原顺序排列的节点列表。因此重复的 `required_missions`、`has_dlc`、`NOT` 等不会被
字典覆盖。比较运算会在对应节点上保留 `operator`（例如 `>=`、`!=`），规则字段节点
还带有从原文件截取的 `raw_script`。`required_missions` 没有出现时为空列表，其他规则字段没有出现时为 `null`。

`slot`、`position` 和 `generic` 提供便于调用的标量值；规则树中的 `yes`、`no` 和
数字仍保留原始 `value` 字符串。索引不求值 `potential_on_load`、`potential`、
`trigger` 或 `effect`，也不把 `tag` 匹配当作当前国家身份。

索引不读取 `localisation/`，所以没有 `name` 字段，任务根和任务的 ID 只是脚本稳定
键，不是显示名称。脚本不是 UTF-8 时使用一对一的 `latin-1` 结构解码，并在每个来源
位置写入 `encoding.structural_only=true` 和 `reason=UTF8_DECODE_FAILED`；这不会把
解码结果冒充本地化文本。

## 与 M01–M04 的边界

该接口可提供静态候选根、槽位、任务 ID、前置任务和原始规则树，可用于定位
`potential_on_load`、`potential`、`required_missions`、`trigger`、`effect` 和
`provinces_to_highlight`。它不能单独证明任务已经进入当前国家的任务界面，不能求出
当前分支、完成状态、条件进度或奖励实际生效。要实现这些字段，需要另有存档或实时
会话来源，并把其身份和版本与静态上下文绑定。

本机 1.37.4 只读验收使用安装目录和 `dlc_load.json`，启用的中文补充模组覆盖
`DOM_French_Missions.txt`，能够返回 `french_missions_1` 等根并标出模组文件来源。
验收不启动游戏，也不修改任何文件。
