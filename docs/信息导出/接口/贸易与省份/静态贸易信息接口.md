# 静态贸易与节点名称接口

`bridge.information.static_data.StaticTradeSource` 从本机 EU4 安装目录读取
`common/tradenodes/*.txt`，将节点、省份归属和文件中声明的出口路线提供给
信息服务。默认构造只读取静态规则。与运行中的观察会话组合时，来源还可以按
节点 ID 读取游戏当前本地化缓存中的显示名称。节点名称与节点图共用 T01 查询，
并可加入同一份周期报告。实时贸易价值、竞争力、收入、国家主节点和收集方向
仍需各自的实时来源。

## 构造与来源上下文

```python
from bridge.information.static_data import StaticTradeSource

source = StaticTradeSource(
    game_root=None,          # 缺省由 work.local_config.game_root() 提供
    user_data=None,          # 缺省由 work.local_config.user_data() 提供
    enabled_mods=None,       # 缺省读取 user_data/dlc_load.json
    context_provider=None,   # 可选；只核对版本并附加采集上下文
    localization_reader=None,  # 可选；读取当前会话的字面本地化文本
)
```

`context()` 返回 `mode="static"` 和 `context_scope="static_rules"`。上下文保存
`game_version`、启动器和启用模组描述文件的 SHA-256、解析到的贸易定义文件
及其 SHA-256、`replace_path` 和覆盖来源。上下文还记录 basegame 与每个启用模组
的 `common/tradenodes` 目录成员，即使该目录在构造时不存在。若配置文件、模组
描述、目录成员或贸易定义在构造后发生变化，来源将变为 `unready`，并返回
`STATIC_INPUT_CHANGED` 或 `STATIC_TRADE_DIRECTORY_CHANGED`；它不再使用旧图，
也不静默退回原版文件。

当前以启动器中的 `rawVersion` 核对 `1.37.4`。缺少版本文件、无法解析版本或
使用未验证版本时，来源会返回 `GAME_VERSION_UNAVAILABLE` 或
`UNSUPPORTED_GAME_VERSION` 并停止读取。版本号只说明静态文件的适用版本，不能
代替某个运行中游戏会话的身份。

如果没有显式传入 `enabled_mods`，来源必须读取 `user_data/dlc_load.json`；该文件
缺失或无法解析时，来源返回 `ENABLED_MOD_CONFIG_UNAVAILABLE` 或
`ENABLED_MOD_CONFIG_INVALID`。显式传入 `enabled_mods=[]` 才表示调用方确认本次
只读取 basegame。

启用模组来自 `dlc_load.json` 的 `enabled_mods` 顺序。相同相对路径由后加载的
模组覆盖；模组声明 `replace_path` 覆盖 `common/tradenodes` 时，程序先移除
此前所有该目录候选，再加入模组文件。若描述文件使用 `archive`，缺少目录，或
声明了无法处理的条件，来源会失败关闭。这样不会在模组规则无法解释时误读
basegame 定义。

如果同一文件或不同贸易定义文件重复声明顶层节点键，来源返回 `DUPLICATE_TRADE_NODE` 并
停止读取。单个文件内的重复键仍由解析器保留；跨文件的合并需要明确的游戏加载
证据，适配器不会自行选择一个定义。

## 查询方法

来源实现统一信息合同的五个方法：

| 方法 | 作用 |
| --- | --- |
| `context()` | 返回静态输入、版本、哈希、启用模组和来源状态。 |
| `catalog()` | 返回本来源覆盖的 T01、G04、T02 字段；条目声明 `context_scope=static_rules`。 |
| `validate_query(query, context=None)` | 复用公共对象和字段 schema；本来源只接受 T01、G04、T02。 |
| `read(query, context=None)` | 返回字段级 `known`、`unknown`、`unsupported` 或 `unavailable` 状态。 |
| `poll_events(context, cursor)` | 返回空事件批次。静态文件来源没有原生事件流。 |

## 字段覆盖

T01 的对象必须是 `{"type": "trade_node", "node_id": "..."}`。`node_id` 使用
脚本中的稳定节点键。`provinces` 来自节点的 `members`，`downstream` 来自
每个 `outgoing.name`，`upstream` 是根据这些出口边反向建立的节点列表。
`routes` 保存每条单跳静态出口边，包含 `source`、`target`、`path` 和 `control`。
它只对应节点定义中的一个 `outgoing` 块，不表示多跳候选路线、当前流量或
本局当前是否存在对应路线。

请求 `name` 时，程序先确认节点存在且静态文件检查通过，再以完整的 `node_id`
查询当前游戏缓存。例如 `english_channel` 直接对应“英吉利海峡”，请求键不加
`_name` 或 YAML 版本后缀 `:0`。名称字段保持普通字符串，原始字节、语言、编码和
缓存读取来源另存于 `source.name_localization`。

没有注入实时读取器、离线运行或读取历史记录时，名称返回 `unknown`，原因为
`LOCALISATION_NOT_READ`。缺失缓存键、动态模板和解码错误也保留明确缺项。
程序不会用节点 ID 代替显示名称。会话、日期或静态定义变化时，来源拒绝返回
先前名称；同一查询中仍有效的静态字段保留各自结果。

## 实时名称查询与周期报告

启动信息服务时，同时提供现有观察会话和静态规则选项：

```powershell
python tools/serve_information.py --operator-session <installation.json> `
  --observer FRA --static-game-data --database <information.sqlite3>
```

随后调用现有 `information_query`：

```json
{
  "request_id": "trade-node-name-001",
  "queries": [{
    "topic": "T01",
    "object": {"type": "trade_node", "node_id": "english_channel"},
    "fields": ["node_id", "name", "upstream", "downstream"]
  }]
}
```

同一查询可以保存为报告，再创建不同现实时间周期的订阅。注入实时名称读取器后，
T01 声明 `query` 和 `periodic`；纯静态构造仍只声明 `query`。G04、T02 的触发方式
保持原状。名称读取复用有界只读缓存工具，不读取任务状态，也不执行任务自定义
文本方法。服务不会为了周期导出推进游戏日期。

G04 只对省份对象实现 `trade_node`：只有省份在恰好一个节点的 `members` 中时
才返回 `known`；省份没有归属或同时属于多个节点时分别返回明确的 `unknown`
原因。节点的 `location` 只是地图展示位置，不能证明节点存在港口；节点之间的
`outgoing` 边也不是国家贸易权转移关系，因此 `ports` 和 `transfer_relations`
返回 `unsupported`。

T02 只提供节点对象的 `upstream` 和 `routes` 静态部分。`home_node`、
`collect_node` 和 `leak_direction` 未实现；对于国家对象，来源不会把任意
节点当作该国的 home node，相关字段返回 `unknown` 或 `unsupported`。
T03–T06 的实时价值、竞争力、收入和扩张收益不属于本适配器。

## 验证边界

测试用小型 Clausewitz fixture 覆盖注释、引号、嵌套列表、重复 `outgoing`、
覆盖目录、条件拒绝、输入 SHA 变化、目录新增/删除、缺少模组栈、未知版本和
跨文件重复节点键。另有只读验收读取配置安装中的
`00_tradenodes.txt` 和 `english_channel` 节点；该验收不启动游戏、不推进日期，
也不执行任何外交动作。静态结果的 `game_date` 只有在组合来源明确提供采集上下文
时才会附带，静态文件本身不会制造游戏日期。
