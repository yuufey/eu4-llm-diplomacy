# 省份核心与宣称快照接口

G01 主题已可查询；`cores` 和 `claims` 为 `partial`、`complete=false`。默认 factory 现在使用 schema v2 reader：`cores.value` 仍是原来的国家 tag 列表，并附加 `territorial_core_membership` 分类详情。schema v1 的显式 parser manifest 仍可用于旧快照，但不会为 v1 补造这项新证据。两种版本都读取操作者指定的 EU4 存档快照，不把保存内容当作当前游戏状态，也不从物理玩家身份推导观察方。

## 第105批：核心列表附加显式领地核心标记

`territorial_core_membership` 是现有 `cores` 字段内的详情，不新增 G01 字段，也不改变原有 `cores.value` 或 `claims.value` 列表。schema v2 只在保存数据显式给出非空 `territorial_core` 列表、列表中的国家 tag 均属于该省份的 `cores`，并且同一快照的 `discovered_by` 明确包含查询观察方时，才将这项详情标为 known。详情的基础为 `saved_province.territorial_core`，时期为 `saved_snapshot`，完整性仍为 false。

标记缺失、`null` 或空列表时，详情为 unknown；格式非法或 tag 不属于原有 `cores` 列表时，也只撤回这项详情，不撤回已知的 `cores`、`claims` 成员列表。旧 schema v1 快照的详情固定为 unknown，即使文档额外带有 `territorial_core` 键也不会回填。`full_core_classification` 始终是 unknown；未标记核心不能因此被判定为某个核心类别。

国家反向查询只枚举同时满足“观察方已发现”和“存在有效显式标记”的省份，返回的详情带有 `collection_scope="explicit_markers_on_observer_discovered_provinces_in_snapshot"`，并保持 `complete=false`。有可见标记子集但目标国家不在其中时，结果是该子集内的已知空列表；没有任何可见显式标记时，详情为 unknown。该分项不代表永久宣称，也不提供宣称到期日。

第105批的 v2 MCP 场景 A/B/C 已完成。FRS 视角验证了省份 2234 的显式标记，FRA 视角验证了同省份不可知及省份 186 的无标记详情，v1 manifest 视角验证旧格式不会回填新详情。A 场景初始收据因检查器错误假设 raw 列表顺序而失败；后续只对已保存结果按公开列表顺序做离线 reconciliation，没有重发查询。B、C 原收据通过。完整结果和边界见下文第105批验收段。14 项定向测试也已通过，其中包括旧 factory 互斥测试；首轮排序断言失败原件保留在 v2 leaf verification attempt-001。

## 选择保存快照

服务启动时同时指定存档、逻辑观察方和信息数据库：

```powershell
python tools/serve_information.py `
  --database work/runtime/information-service/saved-interests.sqlite3 `
  --province-interest-save 'C:/path/to/allowed-save.eu4' `
  --province-interest-parser-manifest tools/rust/eu4-save-provinces-v2/adapter-manifest.json `
  --observer FRA
```

`--province-interest-save` 必须与 `--observer` 一起使用。若显式提供 `--province-interest-parser-manifest`，它也必须与存档一起提供；省略时，服务使用 v2 manifest。操作者若显式选择旧 v1 manifest，基础核心/宣称列表仍按旧格式读取，但 v2 详情保持 unknown。这个保存快照来源不能与 `--operator-session`、`--recorded-manifest`、`--mission-save` 或 `--mission-game-data` 混用。

观察方是本次查询所依据的逻辑国家。存档中的 `saved_player` 单独保存在 `context.archive.player`。例如，存档玩家是 POR 时仍可显式以 FRA 为观察方；服务不会将 FRA 改写成物理玩家，也不会把快照包装成实时会话。

解析器 manifest 固定 Jomini commit、二进制和源文件的相对路径、长度与 SHA-256。快照和这些依赖在加载后会继续核对；输入文件或解析器依赖发生变化时，source 转为不可用，不用另一个文件重新解析来替换已建立的快照。实现对保存文件、解析器清单及解析输出均设置了大小上限，解析进程也有超时边界。

默认解析输出采用 `eu4.save_provinces_snapshot.v2`，并保留 `territorial_core` 显式标记；reader 同时接受旧 `eu4.save_provinces_snapshot.v1`。当前上游 Jomini EU4 存档模型没有 `discovered_by` 字段；本地小型 serde 投影从存档数据保留该字段，供快照查询执行正向发现门。v2 中的本地投影字段是解析输出合同，不是上游模型字段，也不证明保存内容与当前 UI 可见性相同。

## 查询 G01

省份查询返回该省份记录中的核心国和宣称国：

```json
{
  "request_id": "saved-province-cores-001",
  "queries": [{
    "topic": "G01",
    "object": {"type": "province", "province_id": 186},
    "fields": ["cores", "claims"],
    "parameters": {}
  }]
}
```

国家查询反向列出快照中观察方已发现省份里的核心或宣称省份：

```json
{
  "request_id": "saved-country-cores-001",
  "queries": [{
    "topic": "G01",
    "object": {"type": "country", "country": "FRA"},
    "fields": ["cores", "claims"],
    "parameters": {}
  }]
}
```

`parameters` 必须为空。省份对象使用 `province_id`，国家对象使用三字符 `country` tag。`cores` 和 `claims` 的单位随对象类型变化：省份查询返回国家 tag；国家查询返回省份 ID。两字段都以 `scale=1`、`period="saved_snapshot"` 和 `complete=false` 返回，字段及整体查询因此保持 `partial`。

省份查询的 `cores` 仍返回原来的 tag 列表，并可能附带以下详情结构：

```json
{
  "status": "known",
  "value": ["FRS", "KRM", "TIM"],
  "unit": "country_tag",
  "territorial_core_membership": {
    "status": "known",
    "value": ["FRS"],
    "unit": "country_tag",
    "basis": "saved_province.territorial_core",
    "period": "saved_snapshot",
    "complete": false
  },
  "full_core_classification": {
    "status": "unknown",
    "reason": "FULL_CORE_CLASSIFICATION_NOT_EVALUATED"
  }
}
```

这是字段形状示例，不表示任意省份都有已知分类。标记缺失、`null` 或空列表时，详情返回 unknown；格式错误或标记国家不属于该省份的原始核心列表时，也只撤回详情，原 `cores` 和 `claims` 成员值仍可独立为 known。旧 v1 文档始终不能给出这项新详情，即使含有未受信的额外键。

## 可知范围与空值

省份查询只有在快照记录中存在该省份，且其 `discovered_by` 列表包含逻辑观察方时，才返回已知成员列表。满足发现条件但没有核心或宣称的省份返回已知空列表。省份不在快照中，或没有正向发现记录时，结果为 `unknown`；系统不把 unknown 解释成“没有核心或宣称”。

国家反向查询的原 `cores`/`claims` 列表只遍历 `discovered_by` 明确包含观察方的省份，带有 `collection_scope="observer_discovered_provinces_in_snapshot"` 和 `unobserved_provinces_omitted=true`，并保持 `complete=false`。核心分类详情使用更窄的 `explicit_markers_on_observer_discovered_provinces_in_snapshot` 范围，只检查同一发现子集内带有效显式标记的省份。未发现省份不会进入任一列表。请求国家不在快照的 `country_tags` 中时，结果为 unknown；若快照中没有正向发现记录，原成员列表也为 unknown，而不是全局空集。对核心详情而言，若至少有一个可见显式标记子集，目标国家未命中时结果为该子集内的已知空列表；若没有可见显式标记，详情为 unknown。

`claims` 表示快照记录的当前宣称成员关系，字段明确标记 `claim_expiry_evaluated=false`。已核对的允许存档投影没有独立的永久宣称或宣称到期字段；修正上的 `permanent` 标记不是宣称信息。这个存档缺少对应键时仍是 unknown，不能据此返回已知空集。接口不解析宣称到期日期，也不区分永久宣称；因此 `permanent_claims` 仍是 planned。`task_targets` 与 `strategic_targets` 同样保留为 planned，不能从核心或宣称集合推导。H02 的 `claim_expiry` 仍属于 DurableJournal 生命周期记录，本快照 source 不生成或改写 H02 事件；任何日期都只按存档显式保存值处理，不按固定年限推算。核对记录见 [claim-key-research-001.json](../../../../work/runtime/information-claim-details-20261102-001/claim-key-research-001.json)。

## 快照上下文和触发方式

上下文标记为 `mode="recorded"`，日期来自 `saved_date`，版本来自保存文件的版本字段，归档同时记录物理玩家、文件长度、修改时间及 SHA-256。`game_day`、`session_id` 和 `world_id` 保持 null；`status="ready"` 只表示存档及解析器依赖仍与已记录的输入一致，不表示游戏进程在线或快照仍是实时状态。

来源目录声明 `query`。直接查询和手动配置/执行的报告可使用同一查询合同；来源不声明 `periodic` 或 `change`，也没有事件类型，不提供周期或事件订阅。服务不会为历史存档创建伪造的游戏会话、心跳或日期推进。
