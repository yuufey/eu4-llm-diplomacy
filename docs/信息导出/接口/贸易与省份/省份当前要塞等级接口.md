# 省份当前要塞等级接口

G03 的 `fort` 字段读取指定省份当前的要塞等级整数。观察方仍是逻辑上的法国非玩家国家；物理玩家为葡萄牙。省份须先通过原有准入、发现范围和规范 ID 检查。这个字段提供引擎 `fort_level` 触发器比较时使用的当前值，不代表完整要塞状态。

查询示例：

```json
{
  "topic": "G03",
  "object": {"type": "province", "province_id": 183},
  "fields": ["fort", "straits"],
  "parameters": {}
}
```

`fort` 已知时，`value` 包含 `province_id` 和整数 `fort_level`，单位为要塞等级、scale 为 1。公开结果不包含进程指针。`straits` 继续由既有静态海峡来源提供；同一主题的两个字段分别路由，互不替代。国家对国家的 `fort` 查询保留原对象合同，明确返回 `unknown / FORT_COUNTRY_PAIR_NOT_IMPLEMENTED`。

## 原生依据与复用范围

本机目标是 EU4 1.37.4，EXE SHA-256 为 `b23fa0e1f698d31b01cdd1c3817a675805d8c6286cb66f9c231e6e2a42544d77`，首选映像基址 `0x140000000`。下列地址均为 RVA，不是运行时 VA。

复用仓库中已有的 cwtools-eu4-config 元数据，确认原生名字为省份作用域的整数触发器 `fort_level`。配置提供名字和作用域说明，不提供本机内存布局，也不能替代原生证据。原生 `.data` 有界流式搜索找到 `fort_level` 与 token `0x2963`；`base_fort_level` 的子串命中已排除。

已有工厂入口的指令在 `0xb8b945` 比较该 token，分支到 `0xb8c014`，调用构造器 `0xba1140`。构造器写入虚表 `0x1d01f28`；其 `+0x30` 槽指向 `0xbe63a0`。该函数先从作用域省份 ID 解析规范记录，再在 `0xbe66b5–0xbe66c3` 按有符号整数比较记录 `+0x2de0` 的四字节值和所要求的等级。叶子读取原整数，不调用此函数，也不增加未经证明的非负截断。

这些是原始 PE 字节和有界 Capstone 指令证据。REA 的 `has_fort` 搜索成功但没有命中；后续字符串查询触发资源监测终止，函数查询又分别因 Node 堆耗尽和 provider 失败而没有取得有效函数 Evidence ID。失败记录保留，普通指令没有被标成 REA 结果。缓存变化另按原始文件和本次临时文件分别审计，不以失败查询证明数据库未变。

读取复用 `province_state_memory.read_two_pass` 和既有只读采集 owner，保留进程创建身份、会话、法国 NPC 身份、每遍准入和发现检查、前后上下文、运行时代码守卫及严格原始日志回放。新增独立要塞 profile，继承省份 v4 守卫，再增加 1,047 字节的工厂、构造器、比较函数及 token 守卫；重定位表检查确认这些守卫不含 ASLR 修正位置。原港口 profile 和读取保持不变。

原生合同与有界证据位于 `work/runtime/information-province-fort-20261107-214-001/native-fort-level-contract-001.json`，独立 profile 为 `bridge/information/profiles/province-fort-memory-1374-v1.json`。
