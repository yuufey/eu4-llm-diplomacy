# 本埠贸易节点只读接口

`T02.home_node` 返回指定国家当前原生缓存中唯一的本埠贸易节点。当前合同固定
支持 EU4 1.37.4 的 FRA 查询，字段覆盖为 `partial`，结果的 `complete` 始终为
`false`。适配器读取已有原生缓存，不主动刷新缓存，也不重新计算贸易路线。

## 查询

国家查询示例：

```json
{
  "request_id": "trade-home-node-001",
  "queries": [{
    "topic": "T02",
    "object": {"type": "country", "country": "FRA"},
    "fields": ["home_node"],
    "parameters": {}
  }]
}
```

本次实机查询的 `value` 为 `champagne`，表示 FRA 的本埠位于香槟节点。
结果以 `basis=native_trade_node_home_flag` 标明来源，以
`value_origin=derived_from_copied_native_flags` 说明节点标识由原生标志筛选得到。
`native_home_flag_raw=1` 和 `native_home_flag_raw_hex="01"` 保留该标志的原始字节。
节点标识是字符串，无需数值换算；协议中的单位为 `trade_node`、scale 为1。

若没有非零标志，返回 `unknown` 和
`no_node_with_flag_ad`；若有多个非零标志，返回 `unknown` 和
`multiple_nodes_with_flag_ad`，不会任意选择一个节点。

得到 `champagne` 后，可以查询同一主题的静态拓扑字段：

```json
{
  "request_id": "trade-home-routes-001",
  "queries": [{
    "topic": "T02",
    "object": {"type": "trade_node", "node_id": "champagne"},
    "fields": ["upstream", "routes"],
    "parameters": {}
  }]
}
```

第二个查询需要使用 `--static-game-data` 启用静态来源。`home_node` 属于实时
原生来源，支持 `query` 和 `periodic`；`upstream`、`routes` 属于静态来源，
只支持 `query`。来源按字段分别选择，同一主题的字段不会因为另一字段支持周期
读取而自动获得该触发方式。所有这些查询的 `parameters` 都必须为空。

## 报告和周期读取

可以把第一个查询放入现有 `information_manage_report` 的报告配置，再用
`information_manage_subscription` 创建 `periodic` 订阅；例如每 2 秒读取一次，
调度器复用同一报告和会话绑定。周期读取不会推进日期，也不会执行游戏或外交
动作。实机验收已交付 3 条两秒结果，订阅随后取消；静态拓扑报告若单独创建
周期订阅，会因字段触发能力为 query-only 返回 `unsupported_trigger`。

本接口只读固定版本和 FRA 观察者的原生缓存。若会话、日期、身份或守卫检查不通过，
字段保留具体的 `unknown` 或 `unavailable` 状态，不沿用旧值。当前未证明
`merchant_task`、`collection`、`transfer` 或引导方向的语义，不能从 flags
推断这些字段。
