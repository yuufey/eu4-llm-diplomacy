# 宣称自然到期事件接口

`H02.claim_expiry` 提供已观察并持久化的宣称自然到期事件。观察国 FRA 可以是宣称国，也可以是到期时的省份所有国。这些记录用于重新评估本国扩张依据，以及外国对本国领土的主张。

## 查询与交付

正常查询沿用 `information_query`。下面的查询返回涉及 FRA 的已观察宣称到期记录。

```json
{
  "request_id": "claim-expiry-history-fra",
  "queries": [
    {
      "topic": "H02",
      "object": {"type": "country", "country": "FRA"},
      "fields": ["claim_expiry"],
      "parameters": {"limit": 50}
    }
  ]
}
```

`session` 对象返回当前观察会话已保存的全部相关记录。`country_pair` 对象中的 `actor` 指宣称国，`recipient` 指当时的省份所有国。国家对按这一方向筛选。每行提供以下字段。

| 字段 | 含义 |
| --- | --- |
| `event_id` | 当前会话内稳定的公开事件编号 |
| `event_type` | 固定为 `claim_expired` |
| `claimant` | 失去该宣称的国家 |
| `owner` | 到期移除时的省份所有国，原生 `---` 表示的无所有国状态显示为 `null` |
| `province_id` | 经当前游戏省份数组核对的省份编号 |
| `event_date` | 原生自然到期移除调用返回时的游戏日期 |

完整视图保留日期的 `game_date_raw` 单位，简洁视图显示可读的游戏日期。宣称国与省份所有国相同时，事件保留相同的两个业务角色。

查询支持既有 `limit` 和 `cursor`。持久账本先按事件类型分页，再按对象筛选，因此空结果页也可能带有 `next_cursor`。`complete` 和 `gaps` 继承事件采集的连续性。

事件订阅将类型设置为 `claim_expired`，报告可以联合选择其它 H02 生命周期字段。宣称国和当前所有国由报告中的国家或国家对对象筛选。订阅的 `actors` 和 `recipients` 描述外交动作角色，该事件使用 `claimant` 和 `owner`，相应动作角色过滤会返回 `unsupported_event_filter`。

显式带 `request_id` 或 `case` 的 H02 查询继续委托已有 journal 查询，以读取既有请求关联记录。

## 原生自然到期来源

固定 B23 EXE 为 38,463,016 字节，SHA-256 为 `b23fa0e1f698d31b01cdd1c3817a675805d8c6286cb66f9c231e6e2a42544d77`。以下地址均为 RVA，文件首选 image base 为 `0x140000000`。实际进程 VA 根据其载入基址换算。

国家宣称维护函数位于 `[0x303b70, 0x3041dc)`。该函数遍历国家的当前宣称省份，沿既有有序历史查找器 `0x9f9f00` 取得相应宣称记录。它跳过 `0x029c77f8` 标记，读取历史记录 `+0x10` 的日期，并将国家期限读取器 `0x3f9410` 的返回值乘以 8760 后加到该日期。原生计算的截止值小于等于当前日期时，执行到 `0x30415c` 的移除调用。

观察器挂接 `[0xa06cc0, 0xa070ff)` 的省份宣称移除函数，并精确要求调用方返回地址为 `0x304161`。原生维护函数已经完成期限及其它适用条件的判断，捕获沿这个已确认的自然到期分支产生事件。

入口采集需要同时确认以下条件。

- 调用发生在已绑定的游戏 frame 线程，当前游戏日期与上下文一致。
- FRA 是宣称国或当前省份所有国。双方完整国家引用均从原生国家表精确重查。
- 省份在当前省份数组范围内，地址符合 `records + province_id * 0x2e10`，记录 `+0x20` 回显同一编号。
- 省份对 FRA 的发现位为 true。
- 省份 `+0x4c0` 的当前宣称链中，指定完整引用恰好出现一次。链长、指针、循环、重叠和同槽不同完整引用均受到有界检查。

原调用正常返回后，观察器重查世界、省份、所有国、国家完整引用、发现位和游戏日期，并要求指定宣称已经消失，其余成员及其顺序保持一致。每次调用单独保存短期状态。成员采集读取节点 `+0` 的完整引用和 `+0x10` 的后继地址，具体边界与既有成员读器一致。

事件中的 `event_date` 记录实际完成移除的日期。摘要的日期语义由已确认的原生移除分支提供。

## 顺序、断档与恢复

原生队列容量为 64，捕获回调只保存自有值。读取或队列失败累计丢失数量，传输失败保留健康状态。用户态复用共享原生日志游标、载入确认门槛、单调事件序号和容量 1024 的缓存。

公开编号由会话编号和宣称事件序号生成。重复记录、序号冲突、序号断档、缓存淘汰和传输失败沿既有采集器报告。C04 保存宣称国、所有国、省份编号、来源范围和实际发生日期。H02、订阅与冷重开使用已经保存的快照及 `info_events` 账本。

v63、v64 的能力 ACK 需要同时声明 `native_claim_expiry_observation=true`、`native_claim_expiry_wire=1` 和精确 scope `FRA_claimant_or_current_owner_at_native_claim_expiry_remove_return`。构建开关为 `-ClaimExpiryObservation`。

验收应保留固定 EXE 和候选 DLL 身份、实际自然到期前后的同一省份宣称状态、原生事件、C04/H02 正常交付、去重与恢复结果。普通文件反汇编、REA 留存证据、自有进程夹具和游戏实机观测分别记入执行日志。
