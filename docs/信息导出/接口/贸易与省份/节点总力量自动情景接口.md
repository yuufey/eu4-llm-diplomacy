# 节点总力量自动情景

第208批为 `T06.expected_trade` 与 `T06.assumptions` 增加 `total_power_input_model="fixed_other_country_power"`。调用者明确选择“其它国家贡献固定”，接口核对法国在原生求和列表中恰好出现一次后，从法国力量变化推导节点总量变化，再使用现有条件收入模型。

原有手工国家变化、显式总量变化和候选省份分页继续可用。自动模式仍以调用者明确给定的省份来源变化为输入，不证明取得某省、战争或外交行动会产生该变化，也不模拟其它节点或国家随之作出的反应。

## 请求形式

```json
{
  "topic": "T06",
  "object": {"type": "trade_node", "node_id": "champagne"},
  "fields": ["expected_trade", "assumptions"],
  "parameters": {
    "scenarios": [
      {
        "id": "province-source",
        "power_input_model": "province_source_fixed_other_inputs",
        "province_power_delta_raw": 50000,
        "total_power_input_model": "fixed_other_country_power"
      }
    ]
  }
}
```

自动模式使用 `total_power_input_model` 替代 `total_power_delta_raw`，两者不可同时提供。此模式只接受省份来源情景；手工 `country_power_delta_raw` 情景仍须显式提供总量变化。一个请求可混合三种形式，最多8条，编号、说明与输入大小限制沿用[原有接口](贸易竞争力条件情景接口.md)。

| 情景形式 | 国家力量输入 | 总量输入 |
| --- | --- | --- |
| 手工国家变化 | `country_power_delta_raw` | `total_power_delta_raw` |
| 省份来源、显式总量 | 固定 `power_input_model` 与 `province_power_delta_raw` | `total_power_delta_raw` |
| 省份来源、自动总量 | 固定 `power_input_model` 与 `province_power_delta_raw` | 固定 `total_power_input_model` |

选择 `costs` 时继续提供当前行动选择，不执行行动。只选择 `targets` 时仍不读取贸易基线，即使附带有效情景。查询、报告和周期订阅共用同一实现。

## 新模式实际核对的条件

可选父采集子项 `trade_power_sum` 与收入、国家力量、总力量使用同一个只读进程句柄和两遍采集。默认旧模式不启用它，读取量和原有调用方式保持。

子项复用父采集已确认的法国身份，重新核对规范国家表的指针、法国slot对应单元及fullref；没有再次扫描完整国家表。它另读[第207批确认的全局求和列表](../../实现研究/贸易与省份/节点总贸易力量更新依据.md)，检查成员指针与fullref，并分别确认：规范法国指针、完整法国引用、法国slot都恰好出现一次，且指向同一个成员。仅比较标签字符串不足以满足这个条件。

同时复制当前控制数组，要求人类玩家数为1、法国对应控制类型为0。逻辑观察国仍是非玩家法国，物理玩家不会切换。这是对既有T04本国范围增加的身份与角色核对；子项只读取结构性成员标识，不读取各外国的力量、外交或经济详情，也不冒称执行了外国信息可见性谓词。现有完整国家扫描准入接口未被修改或伪造。

每遍内部复核规范绑定、列表、控制状态等锚点，父层再比较两遍结果。新子项带有固定profile、1066字节原生守卫和原始读取轨迹；消费时从轨迹严格重放，并逐项对应父进程句柄实际记录的读取，不能只凭一份自洽的子项报告交付。父会话、日期、身份、守卫、两遍或句柄关闭失败仍撤回结果。

子项自身未知时，自动总量情景保持未知，不填零，也不影响仍有有效基线的手工或显式总量情景；若父层确认两遍发生变化，则按原有整体一致性规则撤回本次读取。

## 算法与结果

国家力量变化继续使用[已有原生整数模型](../../实现研究/贸易与省份/省份来源与国家贸易力量情景.md)。自动总量计算为：

```text
country_delta = country_after - country_before
total_after = wrap_i32(total_before + country_delta)
total_delta = total_after - total_before
```

两个差值使用数学整数求差，若不能用signed i32表示，对应情景为未知，不把超范围差值静默回绕。总量缓存加法本身保留原生32位回绕；收入有效域检查独立进行。新总量为负或其它收入前提不满足时，收入仍未知，符合条件的力量转换可继续保留。

这个计算要求列表及其它国家贡献保持不变，并把当前总量解释为原生求和阶段的基线；它没有证明当前缓存恰好处于该阶段，也未排除引擎后续调用、沿节点传播或其它世界变化。因此 `game_fact=false`、`complete=false` 和未来收入未知的边界保持。

原始情景仍放在 `inputs`。自动情景的 `power_transition.value` 另含 `total_power_input_model`、`total_power_before_raw`、`total_power_after_raw`，以及推导出的 `total_power_delta_raw`。`expected_trade.native_power_scenarios[]` 在收入不能校准时仍保留力量转换。

`assumptions.value.native_power_sum_membership` 提供本次法国slot、成员数、三种唯一性计数、规范身份与非玩家角色标志。来源中的 `trade_power_sum` 保留新profile与验证记录摘要，不公开完整外国成员列表。

## 本轮验证

本轮沿用v37、PID37508／创建身份134384086783026355，实读前后1456.7.26、暂停，物理玩家POR、逻辑观察国FRA。新联合采集确认求和成员590个，法国slot122、列表位置45；指针、fullref、slot计数均为1，人类数1、法国控制类型0。子项每遍612次读取、14296字节，另有1066字节守卫；共同父采集512 KiB上限没有提高。

| 省份来源变化 | 国家力量变化 | 自动总量变化 | 条件月收入 |
| ---: | ---: | ---: | ---: |
| 0 | 0 | 0 | 4.589000 |
| +1 | 0 | 0 | 4.589000 |
| +50 | +58.900 | +58.900 | 5.496133 |
| -1 | -1.178 | -1.178 | 4.569343 |

其中来源+1仍受既有限额限制。若明确给出总量+1，原显式模式仍得出4.582645；两种结果不同，是因为假设不同。波尔多当前不收取收入，接口保留未知收入和已核对的力量转换。

新增或受影响的定向测试、初始断言错误及受影响节点修正均保留。父读取器源文件更新所影响的domestic-pressure来源校验已升为独立v8，原v7与修改前源文件留存；其原生布局和守卫没有变化，不冒称重新完成内政字段的实机验收。完整测试集仍采用第200批失败基线，`whole_suite_passed=false`。
