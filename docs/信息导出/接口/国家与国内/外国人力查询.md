# 外国人力查询

F02 的 `manpower` 提供目标国家的人力储备原值、三项原生贡献及合计，覆盖为 **partial**。逻辑观察方仍为非玩家法国（FRA）；请求中的国家是被查询方。[外国陆海军统计](外国陆海军统计查询.md)按同一原生统计条件读取；[军力质量](外国军力质量查询.md)采用独立的页面与发现条件，不能从人力准入推断质量可见。

```json
{
  "request_id": "foreign-manpower-query-example",
  "queries": [{
    "topic": "F02",
    "object": {"type": "country", "country": "ENG"},
    "fields": ["manpower", "visibility"]
  }]
}
```

主动查询、保存报告和周期订阅使用相同查询结构。也可以同时请求 `military_technology`；科技和人力使用各自经过校验的采集报告，来源中分别保留报告散列。

`manpower.value` 的含义如下：

| 项目 | 含义 |
| --- | --- |
| `reserve_raw` | 目标国家的人力储备原生整数 |
| `components` | 按原生顺序排列的三项贡献，每项提供计数、定义中的数值和乘积 |
| `recruited_total_raw` | 三项贡献的原生合计；字段名不表示已确认的兵种或在外作战人数 |
| `total_raw` | 储备加三项贡献，供原生外交面板后续格式化使用 |

计数为零时，`definition_cost.status` 为 `not_applicable`，读取器不访问对应定义指针。乘法及加法保留原生32位回绕行为。当前单位明确写为 `native_manpower_statistic`、scale 1；组件类别、物理人数单位及最终显示文字尚未全部确认，因此不把合计直接解释为剩余可征兵人数。

读取有两层条件。父层在完整国家表中解析观察方和目标，核对完整引用，并确认 FRA 由 AI 控制，再计算国家查看条件。人力字段还单独计算外交面板的军事统计条件：两个原生设置都为零时允许；否则沿目标的限时记录表查找观察方，使用首个匹配项，并要求当前日期严格早于到期日期。记录的业务名称尚未确认，不据此推断联盟或间谍关系。

`visibility.value.manpower` 分别提供国家查看条件、军事统计条件及有效准入结果。准入明确拒绝时，人力为 `invisible` 且没有人力资源读取；条件不足、读取失败或两遍不一致时为 `unknown`。零值保留为零。公开结果不包含进程地址、国家指针或私有读取记录。

当前私有实采中，英国的储备及合计均为2239，勃艮第为20395，奥尔良为20623；三项贡献计数均为零，军事统计条件走 `public_options`。三份保存后的原始报告均已严格重放。原件见[私有读取收据](../../../../work/runtime/information-foreign-military-resources-20261029-001/manpower-private-live-001/receipt.json)。

真实MCP已完成查询、报告及两个周期订阅：2秒任务交付2次，5秒任务交付2次；另有科技与人力的组合查询，共归档20份原始采集。每份均从保存后的JSON重放，并与公开来源散列关联。结果列表中的3份手动查询副本不计新采集。订阅已取消，服务正常退出。首次验收脚本误读结果ID字段，原失败记录保留；[最终核对](../../../../work/runtime/information-foreign-military-resources-20261029-001/mcp-live-001/offline-reconciliation-001.json)只使用既有原件完成，没有重采。
