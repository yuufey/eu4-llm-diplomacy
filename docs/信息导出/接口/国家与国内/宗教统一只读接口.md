# 宗教统一只读接口

第三十六批起，`N04.religious_unity` 可以在明确请求该字段时通过国内压力只读接口返回。它当前是 `partial`：固定 1.37.4 的非 `CALCULATING` 缓存、且相关修正处理器为空时可计算；处理器非空或缓存正在计算时保守返回 `unknown`。默认的三字段读取仍沿用原有 reader，不会因为普通请求而调用这条新路径。

## 当前可调用行为

请求对象仍是国家范围，例如：

```json
{
  "topic": "N04",
  "object": {"type": "country", "country": "FRA"},
  "fields": ["religious_unity"]
}
```

已知结果保留原始整数和编码，不先转成浮点数：

```json
{
  "status": "known",
  "value": 1000,
  "raw": 1000,
  "raw_hex": "e8030000",
  "unit": "fraction",
  "scale": 1000,
  "upper_clamp": false,
  "basis": "native_getter_equivalent_from_copied_inputs",
  "value_origin": "derived_from_copied_native_inputs",
  "components": {
    "province_component_raw": 1000,
    "modifier_raw": 0,
    "special_rule_forced": false
  }
}
```

本例的比例是 `1000/1000=1`，即100%。`raw_hex` 是计算结果按 little-endian 编码后的四字节表示，不是把国家对象 `+0xEE0` 直接改名为最终值。`unit=fraction`、`scale=1000` 与界面的百分比约定一致；`upper_clamp=false` 表示结果可以超过 1000。

## 计算边界

读取器复用已经绑定的国家内存 reader 和生命周期，只读复制计算所需输入，不调用游戏函数。支持路径如下：

1. 缓存状态不是 `CALCULATING`，且 `E7` 特殊修正的处理器指针为空；进入普通叠加分支时，还要求 `A8` 数值修正的处理器为空。
2. 数值修正表按原生布局读取：密集表按 ID 取值，稀疏表按顺序取第一个匹配项，缺项初值为零。
3. `E7` 的布尔标志有效且其基础值非零时，getter 直接得到 1000；否则把省份分量与 `A8` 基础值做有符号 32 位加法，再执行原生的下限 0。

国家对象 `+0xEE0` 只是 `RELIG_UNITY_FROM_PROVINCES` 省份分量。最终值还要经过缓存选择、`E7` 特殊规则和 `A8` 修正，因此不能用存档字段或单独的 `+0xEE0` 代替接口结果。原生界面调用 getter 时不启用上限截断，接口保留同一约定。

遇到 `CALCULATING` 缓存返回 `RELIGIOUS_UNITY_CACHE_CALCULATING`；特殊规则或数值修正的处理器非空分别返回 `RELIGIOUS_UNITY_SPECIAL_PROCESSOR_UNSUPPORTED` 或 `RELIGIOUS_UNITY_VALUE_PROCESSOR_UNSUPPORTED`。这些路径不借用相邻字段，也不把未解析的处理器结果发布成零。

## reader 与版本守卫

新 reader 使用独立 profile `religious-unity-memory-1374.json`，profile SHA-256 为 `281c45c5dfee98a366858e212eefc52c26c907d8695b3802538fcd2bde4caef7`。它只适用于 EU4 1.37.4、EXE SHA-256 `b23fa0e1f698d31b01cdd1c3817a675805d8c6286cb66f9c231e6e2a42544d77`，并保留有界代码守卫、最大稀疏条目数和最大修正类型 ID。原三字段 `domestic-pressure-memory-1374.json` profile SHA-256 `b727bcd112ace025fcbc0fce78e6194cbb5055642ff12fd85280356e8347d9fd` 不变；默认的稳定度、厌战和腐败读取生命周期也不变。

每次发布仍须核对进程安装身份、会话、版本、国家和日期。reader 使用 `QUERY_INFORMATION|VM_READ` 与 `ReadProcessMemory`，不写目标进程、不推进日期、不保存或重载存档。双遍一致不等于主线程原子快照，也不等于完整事件捕获。
