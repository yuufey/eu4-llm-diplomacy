# 治理容量只读接口

第165批新增 `N06.governance_capacity`，读取逻辑观察国 FRA 的当前治理用量与原生上限，并提供原生使用比例和明确标注的派生容量差值。支持主动查询、报告及周期订阅；只使用已有只读采集，不调用游戏函数。

```json
{
  "topic": "N06",
  "object": {"type": "country", "country": "FRA"},
  "fields": ["governance_capacity"],
  "parameters": {}
}
```

实机非玩家法国的结果如下：

| 子项 | raw | scale | 数量及含义 |
| --- | ---: | ---: | --- |
| used | 204540 | 1000 | 当前用量204.540 |
| limit | 500000 | 1000 | 原生上限500.000 |
| used_fraction | 409 | 1000 | 原生截断比例0.409，即40.9% |
| headroom | 295460 | 1000 | 派生有符号差值295.460 |

外层为 `unit=governing_capacity_summary`、`scale=1` 的汇总，`value` 含这四项。每项分别保留 `status/value/raw/raw_hex/unit/scale/period/partial/complete/basis/value_origin`。容量单位为 `governing_capacity`，比例单位为 `ratio`；不能将四项直接相加。前三项 raw_hex 为4字节，headroom为8字节。整体和已知子项均保留 `partial=true/complete=false`。

headroom 定义为数学上的 `limit-used`，可为负数，明确属于派生结果；不声称已读取原生 UI 的“剩余容量”字段。原生使用比例按千分定点截断，因此本例的0.409与精确除法0.40908有区别。上限为零时不把原生比例函数的-1哨兵解释为负比例，而返回 `not_applicable/GOVERNANCE_CAPACITY_LIMIT_ZERO`。

单独查询无需参数。为兼容N06其他字段，可选 `reference_recipient` 仍接受合法的其他国家标签，但它不参与本国容量计算。只支持逻辑观察国FRA，物理玩家身份不替换该观察国。

## 原生依据

固定EU4 1.37.4、B23 SHA-256 `b23fa0e1f698d31b01cdd1c3817a675805d8c6286cb66f9c231e6e2a42544d77`。CWTools的国家修正声明提供候选入口；普通流式PE字符串/RIP搜索仅定位种子，不能单独证明字段。

两次新接受的缓存REA证据确认：

- RVA `0x3f2e40` 读取 `u64[country+0x2440]+0x1c` 的基数和编号409、410的修正；其数值路径为 `i32(trunc_zero(i32(base+modifier409)*max(0,i32(1000+modifier410))/1000))`。不将基数对象按猜测命名为政府等级；原生说明使用 `FROM_TECH_NON_PERC`。
- RVA `0xf53080` 的治理容量控件分支调用上述上限函数，并取 `country+0xe2c` 的当前用量构造治理容量提示。Ghidra遗漏提示帮助函数的额外参数，当前PE窄窗另行确认R9传上限、栈上传用量，不能将缺失的反编译参数当作不存在。

普通固定PE还确认 RVA `0xf671e0` 的提示参数键为 `CAPACITY`、`USED`、`MOD`，前两者使用type7描述符。千分单位复用已经接受的定点数字格式器证据，没有重查该帮助函数。RVA `0x9a1f0` 的普通完整小函数确认使用比例为 `i32(trunc_zero(used*1000/limit))`，零分母返回原生哨兵。普通字节、接受的REA、离线算术与实机取值分别记录；RVA加实际模块基址才是运行地址。

## 读取与未知状态

读器先复核完整FRA绑定，再复制当前用量、非计算态的修正缓存、基数和两个修正。稠密存储按编号读取，稀疏存储取首个匹配，无匹配为已知零；仅支持两个修正处理器均为空的路径。不能伪造空处理器或执行游戏函数来补值。

本例原始操作数为基数0、修正409为400000、修正410为250，故上限为 `(0+400000)*1250/1000=500000`。这些是聚合操作数，不是已完成的具名来源分解。

用量与上限保留各自状态：计算态、基数指针或修正读取失败可使上限未知，而独立读取成功的用量仍可保留。比例和差值依赖两者，缺一则未知；共享读取预算失败会撤回整项。正式采集还要求两遍结果一致、进程/会话/代码和国家查看准入有效。公共DTO严格校验各子项位置、单位、比例、原始字节及派生算术，拒绝额外私有字段和指针。

35段ROM守卫均在读取前后匹配，当前profile为 `governance-capacity-memory-1374-v1.json`，SHA-256 `9b29637ecf3c4b8a58da57471cca5f2e056dd3d945ee1e17148cac6bd9cd0c65`。
