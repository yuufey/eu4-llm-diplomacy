## 数值与可见条件

收入来自目标国上一月的原生账本缓存。公开金额以杜卡特表示，原始整数除以1000。返回的14个展示类别对应 0 `INCOMETAX`, 1 `INCOMEPROD`, 2 `INCOMETRADE`, 3 `INCOMEGOLD`, 4 `INCOMETARRIFFS`, 5 `INCOMEVASSAL`, 6 `INCOMEHARBORFEES`, 7 `INCOMESUBS`, 8 `INCOME_WAR_REPARATION`, 12 `SPOILS_OF_WAR_ECOVIEW`, 15 `CONDOTTIERI`, 16 `KNOWLEDGE_SHARING`, 17 `INC_BLOCKADES`, 18 `INC_LOOTING`。原生总额还按原生公式纳入索引14，但接口不单独输出该索引；总额不保证等于已列展示类别之和。

`reparations`把两种范围不同的数据放在一个partial结果中：

- `received_previous_month`报告目标国上月收到的赔款收入，单位为杜卡特，scale为1000。它沿用`income_comparison`页面条件。
- `observer_involved_contracts`报告当前观察日期下，FRA与本次目标国这一对国家参与的关系对象。其scope为`observer_target_pair_only`，单位为`bilateral_reparations_relation`，scale为1，period为`current`。公开的关系对象只包含付款方和收款方标签、起止日历日期，以及日期是否落在`start <= observed_date < end`范围内。

赔款关系子项只查询FRA与目标国这一对国家，不枚举目标国和第三国之间的关系。`complete_country_contracts`固定为false；pair中没有关系只说明这对国家未找到匹配项，不能推出目标国没有其他赔款关系。日期区间判断也不代表原生支付正在进行。实际支付义务、活动合同全集、金额或比例目前都保持`unknown`；上月收入为0也不能填补这些未知值。

`subsidies`也是mixed结果。`received_previous_month`报告目标国上一月收到的补贴收入，沿用`income_comparison`准入，单位为杜卡特、scale为1000、period为`month`、reference为`previous_month`。`observer_involved_contracts`报告当前FRA财政关系中，FRA与本次目标国这一对是否存在补贴关系；scope为`observer_target_pair_only`，unit为`bilateral_subsidies_relation`，scale为1，period为`current`。pair未匹配只表示这对国家没有已观察到的关系。

这两个子项分别通过自己的准入检查。父层country-view和FRA非玩家角色检查不通过时，整个F03目标结果都被阻挡。父层通过后，上一月补贴收入使用`income_comparison`权限，关系子项使用`observer_fiscal_bilateral_subsidies`权限；一项权限失败或对应数据漂移，只撤回该子项，不会清除另一项。关系权限将FRA与目标国的完整引用、双方财政行owner和当前capture日期重新绑定；这证明指定pair的财政关系范围，不证明FRA界面实际渲染。若关系日期与capture context日期不一致，只将关系子项改为unknown，不撤回已通过自身检查的上一月收入。

补贴关系的公开`contracts`列表只保留付款方和收款方标签、观察方角色、月度名义金额的signed原值与杜卡特值、起始日历日期、signed年数，以及由年数推导的显示截止日和公式。日期原始整数、完整国家引用、内存指针、私有读取trace和source路径不会进入公开对象。月度名义金额不是上一月实收金额；截止日期也不能证明关系处于活动期或正在付款。`current_payment_obligations`、`active_contracts`、`term_legality`、`relation_flag`（源对象`+0x28`字节）和生命周期语义继续为`unknown`。

F03父层先检查FRA对目标国的country-view准入和FRA非玩家观察方身份。任一条件拒绝或未知，整个目标结果都不发布可用字段。父层通过后，收入、贷款、赔款关系和补贴关系分别检查自己的来源条件。`income_comparison`权限只控制`income`、上一月补贴收入和上一月赔款收入；`observer_lent_loans`控制贷款子集；`observer_economy_bilateral_reparations`和`observer_fiscal_bilateral_subsidies`分别控制各自的当前pair关系。某个子项的来源拒绝、读取漂移或日期不匹配，只会撤回该子项，不会抹掉通过独立检查的其他子项。

结果中的`visibility`只给出安全的准入状态与scope，不包含完整国家引用、内存地址或私有trace。原生入口`0xeb7b20`先选择客户端当前国家；采集器随后把自身经济关系读取重绑定到逻辑观察方FRA。`private_native_fra_own_economy_pair_relation`描述的是这项国家范围映射，不表示物理客户端已经切到FRA，也不表示实际渲染了FRA界面。

`debt`有两个互相独立的分量。`loans_to_observer`只列FRA借给目标国的已观察贷款子集，原始本金scale为1，利率原始值除以1000；子集记录数或本金为0，不表示目标国没有其他贷款。`total_debt`通过独立的原生披露scope报告目标贷款列表中本金的外交理由缩放和，单位为杜卡特、scale为1000；它不包含剩余利息，也不公开目标贷款总笔数、逐笔记录、未缩放替代和、内存地址或私有读取trace。两个分量分别准入，任一来源失败或变化只影响该分量。

目标本金总额只有在父层country-view、FRA非玩家身份、EXE/DLL与当前session、目标国家绑定和日期检查通过后才可读取。目标不能是宿主控制国家或物理玩家POR。对每个实际进入`total_debt`读取路径的目标，程序调用一次只读`trade_favors_for_gold` / `initiate`选择器检查；它不提交动作。native执行是否合法、FRA拥有人情数、外交官数量或冷却时间都不作为读取门槛。映射必须在两遍观察中保持一致，并且只能匹配原生`0x8F440`谓词或经过审核的v33 GUI转发函数；任何映射、身份或日期不确定都会让`total_debt`返回unknown。

REA与普通B23代码证据显示，AI accept提示路径经`+0xB8`进入`0x4EA210`，再从动作对象`+0x120`取`DIPLO_LOANS`理由；按钮启用状态另走`+0x90`。已安装v33 hook只对一个特定AI返回地址进入待处理动作抑制分支；GUI调用`0xEF2B00`不匹配该返回地址，因此走保存的原生谓词。运行时映射检查只验证hook函数体`[0x56850,0x56cdf)`、PE头子集、游戏基址全局值和保存的原生指针，不验证整个已装载DLL的hash。REA/反汇编和映射检查都不证明本次实际绘制了UI；结果继续标记`actual_UI_observed=false`。因此，bridge查询中“当前动作不合法、native_value为0”不能用来否定UI提示路径中的债务理由。

## 报告与周期查询

先保存一份可复用报告：

```json
{
  "request_id": "F03-report-create",
  "operation": "create",
  "config": {
    "name": "FRA观察方的外国经济",
    "detail": "raw",
    "queries": [{
      "topic": "F03",
      "object": {"type": "country", "country": "ENG"},
      "fields": ["income", "debt", "reparations", "subsidies"],
      "parameters": {}
    }]
  }
}
```

使用创建报告返回的`report_id`，可以按真实时间每2秒或每5秒创建周期订阅。配置中将`schedule.every`设为2或5、`schedule.unit`设为`seconds`、`schedule.basis`设为`real`，并明确选择`schedule.missed`为`skip`或`coalesce`。读取结果时使用信息服务返回的`result_id`；停止订阅时通过`information_manage_subscription`的`cancel`操作提交`subscription_id`。
