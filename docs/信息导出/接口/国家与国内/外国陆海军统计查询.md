# 外国陆海军统计查询

F02 的 `visible_army` 提供原生外交面板的士兵统计值，`visible_navy` 提供船只数，两字段均为 **partial**。观察方是非玩家法国（FRA），请求中的国家是被查询方；物理客户端保持葡萄牙。

```json
{
  "request_id": "foreign-forces-query-example",
  "queries": [{
    "topic": "F02",
    "object": {"type": "country", "country": "ENG"},
    "fields": ["visible_army", "visible_navy", "visibility"]
  }]
}
```

本次实际读取并从保存后的JSON严格重放的结果如下：

| 目标 | `visible_army.value`，士兵 | `record_count`，陆军记录 | `visible_navy.value`，船只 |
| --- | ---: | ---: | ---: |
| ENG | 50970 | 51 | 30 |
| BUR | 27224 | 28 | 11 |
| ORL | 5052 | 6 | 0 |

陆军记录数与士兵数分开报告。例如英国有51条记录，本次记录中的原生强度合计为50970；不能把51直接当成士兵数。海军按相应对象的记录向量计数。两字段 `scale=1`，公开保留 `value`、`raw` 和单位；陆军另附 `record_count`。

士兵与船只的含义来自同一原生显示链：数值写入对应外交控件，提示分别使用 `DIP_LAND_FORCE`、`DIP_NAVAL_FORCE`，说明文字将它们称为士兵和船只总量。读取器核对了这条路径的对象判断、累加方式和格式化编码。报告提供格式化前的整数，界面可能缩写显示；`actual_UI_observed=false`，不提供实际渲染文字。

读取先核对进程、会话、代码、国家完整引用和 FRA 非玩家角色。国家查看条件是保守导出前提，军力字段还需满足独立的军事统计条件。`visibility.value.army` 和 `navy` 分别说明国家查看条件、军事统计条件及有效准入。

条件明确拒绝时为 `invisible`，不读取部队数据。条件未知、未支持的对象类型、坏指针、循环或两遍不一致时为 `unknown`，不以0代替未知。奥尔良的海军0来自完整遍历后的实际结果。两遍读取不能证明主线程原子性或缓存刷新时机。

实现只读取已有数据，不调用对象的原生判断方法。当前已核实两种对象虚表，超出该映射时保持未知；不按旧 `type_kind` 标签猜测类别，也不导出进程地址、单位指针或私有读取记录。计算保留原生32位有符号回绕；格式化所需的乘1000编码留在私有记录中。字段不包含部队位置或完整战场视野。

主动查询、报告和周期订阅使用相同来源。可以组合请求 `military_technology`、`manpower`、`visible_army`、`visible_navy` 与 `visibility`；来源中分别记录科技、人力、军力报告的散列。仅请求军力及可见条件时，复用同一份军力采集。
