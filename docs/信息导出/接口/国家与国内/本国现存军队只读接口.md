# 本国现存军队只读接口

N02 的 `army_size`、`navy_size`、`army_composition`、`navy_composition` 读取本国当前单位记录，支持主动查询和周期报告。当前来源限定已核对的 EU4 1.37.4 二进制及 FRA 观察方，四个字段均为 partial。人力仍由原有 `manpower` 路径提供；`sailors`、`force_limits` 现由[水手与军队上限接口](本国水手与军队上限只读接口.md)提供。

## 查询与单位

```json
{
  "request_id": "forces-query-unique-id",
  "queries": [{
    "topic": "N02",
    "object": {"type": "country", "country": "FRA"},
    "fields": ["army_size", "navy_size", "army_composition", "navy_composition"],
    "parameters": {}
  }]
}
```

将此参数传给 `information_query`。四个单位字段可省略 `reference_recipient`；同时请求 `manpower` 时仍须提供该参数。

| 字段 | value 的含义 | 单位 |
| --- | --- | --- |
| army_size | 本国现存陆军团记录数量 | regiments，scale=1 |
| navy_size | 本国现存舰船记录数量 | ships，scale=1 |
| army_composition | 各原生陆军类别的数量、strength总和及逐条分布 | count_unit=regiments |
| navy_composition | 各原生海军类别的数量、strength总和及逐条分布 | count_unit=ships |

数量字段附带 `strength` 对象，类别列表每行也带该对象：`raw` 为整数，`scale=1000`。陆军单位为 `serialized_regiment_strength`，舰船单位为 `serialized_ship_strength`，与保存数据中的 strength 对应。舰船数量由记录条数取得；舰船 strength 的合计表达各船强度，不换算成船数。陆军 strength 到实际人数的换算仍缺独立证据。

来源的 `projection_version=4`。每个类别行的 `record_strengths` 返回该次采集中逐条记录的strength，格式如下。

```json
{
  "raw_values": [0, 500, 500, 1000],
  "scale": 1000,
  "unit": "serialized_regiment_strength",
  "ordering": "ascending_strength",
  "identity_scope": "anonymous_records_current_capture"
}
```

示例数字用于说明结构。`raw_values` 按数值升序排列，重复值和零值均保留，空类别返回空列表。列表长度对应该类别的 `count`，各值之和对应 `strength.raw`。海军行使用 `serialized_ship_strength`。这些匿名记录可表示同一总强度下不同的分布，排序顺序只在本次采集中有意义，跨次查询无法据此识别同一单位。各类别数量和原有聚合strength的含义延续。

已核对类别名依次为 infantry、cavalry、artillery、heavy_ship、light_ship、galley、transport，原生编号为0至6，`category_name_status=known`。同一类型对象的成员函数读取其 `+0x10` 编号，再由原生格式器选择对应类别键。具体兵种由 `unit_types` 返回。[完整类别证据](../../../../work/runtime/information-galley-category-20261107-243-001/native-galley-contract-001.json)

类型5按桨帆船记录参与海军数量、strength及具体兵种分组。范围外类型、布尔值等畸形类型和重复身份仍使本次字段返回unknown。

## 具体兵种与本地化名称

每个类别行新增 `unit_types`，按原生类型对象中的定义key分组。`value` 按key排序，各项包含 `key`、`count`、`strength`、`record_strengths` 和 `name`。其中 `count` 是该key对应的记录数，`strength` 与匿名逐条分布沿用上面的单位和scale。

`unit_types.status` 和 `complete` 表示该类别现存记录的key读取情况。全部key已取得时为known和true，取得部分时为partial和false，现有记录均缺key时为unknown和false。没有记录的空类别返回known、true和空列表。`unresolved_records` 说明缺key的条数，`unresolved_record_strengths` 保留这些记录的匿名strength分布。旧采集记录缺key时，原类别数量和strength继续返回，并标记 `UNIT_TYPE_KEY_NOT_CAPTURED`。

每个具体兵种的 `name` 独立报告本地化状态。读取成功时包含 `status=known`、`value`、`key`、`language`、`source=native_literal_localization_cache` 及读取来源。名称来自现有本地化缓存，实际widget赋值仍待核对，结果保留 `native_widget_text_verified=false`。动态参数、缺失键、字节解码失败及本地化读取错误使对应名称保持unknown，已取得的key和数值继续返回。`unit_types.complete` 只覆盖key读取，名称状态由各项 `name.status` 说明。

生产服务把共享的 `NativeLocalizationReader` 传给本来源，主动查询与周期报告使用同一读取路径。仅查询 `army_size` 或 `navy_size` 时，跳过新增类型key与名称读取。查询组成时，类型key和名称各自接受身份、日期与读取边界核对。来源上下文在名称读取后改变时，本次结果撤回。

## 来源范围与失败

读取只沿本国单位组及单位向量遍历，不递归汇总属国或盟国，也不把排队建造和雇佣兵公司定义计作单位。现存记录尚未区分战斗就绪、撤退、运输中等状态，因此字段 `complete=false`，整体结果也保持 partial。公开结果不含进程地址、原始内存或内部单位编号。

读取前后核对进程创建时间、会话、EXE/DLL 身份、原生短代码片段、观察方和游戏日期，并比较两遍单位组、向量、编号、类型与 strength。循环、重复编号、坏指针、读取超限或两遍不一致会撤回本次结果。真正的完整空集合可返回数量0；读取失败保持 unknown。

## 周期订阅

通过 `information_manage_report` 创建报告，`config.queries` 使用上述同一查询、设置 `name` 和 `detail`。随后用 `information_manage_subscription` 创建周期订阅：

```json
{
  "request_id": "forces-subscribe-unique-id",
  "operation": "create",
  "config": {
    "name": "法国现存军队",
    "kind": "periodic",
    "report_id": "替换为已创建的报告编号",
    "enabled": true,
    "schedule": {"basis": "real", "every": 30, "unit": "seconds", "missed": "coalesce"}
  }
}
```

后台调度复用主动查询的同一读取实现。创建订阅与交付报告分别记录，已交付表示输出适配器接收了结果。目录为本来源及四个字段声明 `query` 和 `periodic`，变化订阅会返回 `unsupported_trigger`。

来源原件位于 `work/runtime/information-country-forces-20261027-001/`：既有 checkpoint 与独立 RPM 的60个单位按编号逐条对应，显式 strength 全部一致，省略 strength 的16条对应原生 raw1000。主动查询及后台周期的实机验收以该目录中的正式报告为准。

第240批对旧60条样本重新投影，双遍记录一致，匿名分布、原聚合及排序稳定性通过。旧样本中的44条显式保存strength可独立比较数值，另16条省略该字段，只能由编号对应和原生读数说明其值。[历史回放收据](../../../../work/runtime/information-country-force-distributions-20261107-240-001/historical-replay-001.json)

第240批实机为1457.6.21暂停，法国NPC的41团、13艘，对应strength总和raw39056、raw12080。真实MCP主动查询、保存报告查询、2秒周期两次及5秒周期一次返回相同字段，均带projection_version2。两项订阅取消并确认状态后，服务正常退出。前后日期、速度、暂停和物理玩家槽一致。[第240批实机收据](../../../../work/runtime/information-country-force-distributions-20261107-240-001/live-003/receipt.json)

国家发现的双遍读取进一步确认FRA槽122由原生控制器数组判定为非玩家，POR槽189为物理玩家。当前输出绑定FRA观察方。[当前视角核对](../../../../work/runtime/information-country-force-distributions-20261107-240-001/npc-binding-001/receipt.json)

历史及当前法国实机均无类别2或类别5记录，两类正数实采仍待补。当前功能覆盖仍为partial，实际人数和战斗就绪状态继续待补。

## 第242批实机验收

原生类型对象的有界读取已接入生产来源。`country_forces_memory.capture` 默认使用原始记录接口，组成查询显式启用 `include_type_keys=True`。独立类型profile固定原生vptr、成员函数和字符串分支，并记录来源pin、文件及运行代码守卫。新增读取复用原有1 MiB预算，同一类型每遍读取一次。类型key失效或两遍变化时，相关key返回unknown，原始记录数量和strength继续返回。私有proof保存在原始采集工件中。

## 第243批桨帆船准入

原生任务阈值函数以类型参数5和国家 `+0xd18` 链地址调用公共计数器。计数器沿相同的组和记录向量读取类型对象，筛选其 `+0x10` 编号，并分别保留逐条计数和 `record+0x28` 求和分支。本接口沿用现存记录数量与strength汇总语义，结果中的 `count` 统计记录条数。

当前法国实机的galley行返回known和0艘，projection4下的主动查询、保存报告查询及2秒/5秒周期一致。正数路径由合成内存采集、公开投影及订阅回归覆盖，真实正数桨帆船记录仍待取得。[第243批实机收据](../../../../work/runtime/information-galley-category-20261107-243-001/live-001/receipt.json)
