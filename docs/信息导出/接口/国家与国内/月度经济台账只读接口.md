# 月度经济台账只读接口

N01 的三个经常性月度字段读取本国上一个游戏月的原生经常性台账：
`lastmonthincometable`、`lastmonthexpensetable`。它们返回台账中保留的经常性项目，
不把一次性项目加进来，也不把当前界面的动态月度预算预测当成历史值。

同一月度采集中还可请求 `war_income`。它只投影上月收入台账中的赔款、战利品、
封锁和劫掠四个命名分项；它不是完整战争收入、当前收款或某场战争的归因。

## 可直接使用的查询

月度字段和 `war_income` 都是本国字段。只请求其中一个或多个字段时，`parameters`
可以是空对象，不需要 `reference_recipient`：

```json
{
  "queries": [{
    "topic": "N01",
    "object": {"type": "country", "country": "FRA"},
    "fields": ["monthly_income", "monthly_expenses", "monthly_balance"],
    "parameters": {}
  }]
}
```

三个经常性字段的含义如下：

| 字段 | 读取内容 | 派生关系 |
| --- | --- | --- |
| `monthly_income` | 上月经常性收入台账合计 | 从 `lastmonthincometable` 的已审计经常性槽位求和 |
| `monthly_expenses` | 上月经常性支出台账合计 | 从 `lastmonthexpensetable` 的已审计经常性槽位求和 |
| `monthly_balance` | 上月经常性台账结余 | `monthly_income - monthly_expenses`，按有符号 32 位整数规则保存 |

`war_income` 返回四项独立的上一月收入槽位：`war_reparations`、`spoils_of_war`、
`blockades` 和 `looting`。每项保留原始有符号整数，并以 `raw / 1000` 表示 ducats。
其中 `war_reparations` 使用的收入槽位也包含在 `monthly_income` 中，因此四项小计
不能再加到月度收入上。`war_income` 为 `partial`、`complete=false`；四项小计不是
游戏的完整战争收入总额，字段也不说明当前应付义务或各笔款项属于哪场战争。

收入和支出是独立读取的台账合计。`monthly_balance` 不是国库余额，也不是当前
UI 的“预计月度收入”或“预计月度支出”。它只表示同一上月经常性口径下的收入减
支出结果。

## 结果如何解释

已读到的字段返回 `status="known"`。接口保留有符号整数的 `value` 和 `raw`，两者
在本端点相同；`scale=1000` 表示以 ducats 解释时计算 `raw / 1000`。消费方可以
直接保留三位小数，不必先转成二进制浮点数。负值和零值都是合法的已知值，不做
绝对值、下限截断或百分比换算。

单个字段的公共形状如下：

```json
{
  "status": "known",
  "value": 21104,
  "raw": 21104,
  "raw_hex": "70520000",
  "unit": "ducats",
  "scale": 1000,
  "basis": "native_recurring_monthly_ledger",
  "period": "month",
  "reference_period": "previous_month",
  "value_semantics": "previous_month_recurring_ledger",
  "value_origin": "derived_from_copied_native_ledger",
  "complete": false
}
```

`raw_hex` 是派生合计的四字节小端有符号 32 位编码，不是从游戏中另找的“合计
缓存”。例如，独立 RPM 参考样本中的三个原始值和可读 ducats 值为：

| 字段 | `raw` | `scale=1000` 的 ducats 表示 | 派生 `raw_hex` |
| --- | ---: | ---: | --- |
| `monthly_income` | `21104` | `21.104` | `70520000` |
| `monthly_expenses` | `26240` | `26.240` | `80660000` |
| `monthly_balance` | `-5136` | `−5.136` | `f0ebffff` |

该样本的负结余是正常结果：支出合计大于收入合计。示例来自
[expected-ledger-raw-001.json](../../../../work/runtime/information-economy-20261027-001/expected-ledger-raw-001.json)
记录的独立原始 RPM 观察和已审计槽位集合；该记录的 `reference_sha256` 为
`e931ad4a5a8a69bc0f3374376918bb09f45e337b022ebe414e362ca0184cfa4e`，文件自身
的 SHA-256 为
`4915d11e4f1be9bfd953dac3f617e0c65360e0861ea50974a5c08e8f89df32fe`。
它是单位和算术的独立参考样本。本批实机公开 MCP 的三项值已与该参考一致；独立
RPM 原始记录与公开 MCP 结果仍分别保留，不能互相替代。

## `partial` 与 `complete=false`

在 InformationService 结果中，三个经常性字段即使全部返回 `status="known"`，查询项仍会
带 `complete=false`，总体状态通常是 `status="partial"`。这里的 `partial` 有明确
范围：本端点只承诺“上月原生经常性台账的已审计子集”，而当前 UI 动态预算预测与
一次性台账行尚未纳入这个合同。它不表示 228 字节的原始月度范围只读了一部分，
也不表示三个字段缺少值。

三个经常性字段的 `complete=false` 同时出现在字段、查询项和来源合同中，表示这个语义范围
仍是有边界的部分合同。只要相应台账范围和身份守卫通过，字段仍可以是 `known`；若实际
读取失败或会话身份变化，字段会单独返回 `unknown`、`unavailable` 或 `stale`，并
带具体 `reason`。不要因为 `complete=false` 把一个有 `status="known"` 的数值改成
缺失，也不要因为 `status="partial"` 用 UI 预测值补齐它。若一次结果没有任何已知
字段，服务会按自身公共合同返回 `failed`，而不是伪造月度数值。

## 与 treasury 混合查询

`reference_recipient` 只服务于 N01 的公共 treasury projection。月度字段和 `war_income`
本身不需要参考国家；但请求 `treasury`，或把 `treasury` 与任一其它 N01 字段放在同一个
查询中时，仍必须提供不同于观察国的参考国家：

```json
{
  "queries": [{
    "topic": "N01",
    "object": {"type": "country", "country": "FRA"},
    "fields": [
      "treasury", "monthly_income", "monthly_expenses", "monthly_balance",
      "loans", "war_income"
    ],
    "parameters": {"reference_recipient": "PAP"}
  }]
}
```

在混合结果中，`treasury` 仍走原有公共 projection，三个 `monthly_*` 字段和
`war_income` 共享月度经济采集；`loans` 由独立的 `NativeCountryRecordsSource` 读取，
其记录与月度收入、支出无关。`war_income` 按其部分合同返回四个上月收入分项，不把
余额或其他字段用作替代值。不能用参考国家的国库或台账替代 FRA 的本国数值。混合查询的整体
`complete` 会同时受各字段状态和月度合同的 `complete=false` 约束。

## 使用边界

当前源码合同只支持已核验的 `1.37.4` 可执行文件和 FRA 观察范围。月度 reader 本身不
调用游戏函数，不重算 UI 预算，不读取历史存档，也不把上月所有交易流水当成经常性
台账。`war_income` 复用同一份上月月度采集，不另开一次合同读取。混合查询的 `treasury`
字段仍通过既有只读 native inspection，该路径包含游戏函数调用；这不改变月度字段的来源。
静态来源、profile 守卫和运行时会话身份必须通过；会话变化、日期或身份守卫失败时，本次读取保留明确的未知/不可
用原因，不沿用旧会话的数值。双层 provenance 会把原始台账快照和派生合计的关系保
留下来，但它不等于同一时刻的主线程原子世界快照。

## 来源、单位和派生规则

本接口的来源索引是
[monthly-ledger-source-001.json](../../../../work/runtime/information-economy-20261027-001/monthly-ledger-source-001.json)，
其 SHA-256 为
`7fd7af774a6c75731b3f54874ef179444c19b28ddf58845e867cac32462468ac`。固定 profile
是
[monthly-economy-memory-1374.json](../../../../bridge/information/profiles/monthly-economy-memory-1374.json)，
其 SHA-256 为
`bd5e3ee39b02e4b5f183790d4550f394c6248eaa4dc4c68e9c17d9ec3254d831`。两者均绑定
EU4 `1.37.4`，EXE SHA-256 为
`b23fa0e1f698d31b01cdd1c3817a675805d8c6286cb66f9c231e6e2a42544d77`。

profile 规定从当前国家对象复制一个连续的 228 字节范围：

* `country+0x770` 的 19 个有符号 `int32` 是 `lastmonthincometable`；
* `country+0x7bc` 的 38 个有符号 `int32` 是 `lastmonthexpensetable`；
* 收入保留槽位 `0..8、15、16`，支出保留槽位 `0..10、15、21..27、30、31、33、34`；
* 每次加法及最终收入减支出都按 32 位模运算，再以有符号 `int32` 对外表示。

`war_income` 从同一复制范围的收入槽位 `8、12、17、18` 生成四个分项，分别对应
`INCOME_WAR_REPARATION`、`SPOILS_OF_WAR_ECOVIEW`、`INC_BLOCKADES` 和 `INC_LOOTING`。
金额缩放为 `1000`。字段及其查询项保持 `partial`、`complete=false`：完整战争收入、
当前支付义务和具体战争归因均未由这些槽位确定。当前目录中的实现和离线合同不应被
误读为本字段已经通过新的实机验收。

这些槽位是原生经常性口径；未列槽位的一次性项目不会被偷偷加回总额。原生月度
表序列化器把每个 `int32` 交给带 `/1000` 固定小数写出器，因此 `scale=1000` 的
单位证据来自表序列化路径，而不是只依据旧报告中的小数样本。更完整的有界静态
单位证据见
[ledger-unit-source-001.json](../../../../work/runtime/information-economy-20261027-001/ledger-unit-source-001.json)。
