# 停战自然到期事件接口

`H02.truce_expiry` 提供已观察并持久化的直接停战自然到期事件。外交决策者可据此重新评估指定方向的宣战窗口。每条记录描述一个 `actor` 对 `recipient` 的停战记录，观察国 FRA 须参与该国家对。

## 查询与事件订阅

正常查询使用既有 `information_query`。国家对选择具有方向，下面的查询返回 FRA 对 SAV 的已观察到期记录。

```json
{
  "request_id": "truce-history-fra-sav",
  "queries": [
    {
      "topic": "H02",
      "object": {"type": "country_pair", "actor": "FRA", "recipient": "SAV"},
      "fields": ["truce_expiry"],
      "parameters": {"limit": 50}
    }
  ]
}
```

使用 `country` 对象时，结果包含涉及该国家的两个方向。`session` 对象包含当前观察会话已经保存的全部停战到期记录。两个方向各有自己的日期和事件编号。

每行包含 `event_id`、`event_type`、`actor`、`recipient`、`end_date` 和 `event_date`。`event_type` 为 `truce_expired`。完整视图保留日期的 `game_date_raw` 单位，简洁视图将日期显示为可读的游戏日历日期。

`end_date` 使用已核对的 B23 直接停战日历规则，从关系记录输入和运行时配置计算。`event_date` 为原生维护调用返回时的游戏日期。游戏可以在截止日期当天清除标志，也可以在稍后的维护调用中清除，因此两个日期分别保留。

查询支持既有 `limit` 和 `cursor`。持久事件先按事件类型分页，再按对象筛选。某页的结果可以为空，调用方应继续使用该页给出的 `next_cursor`。字段中的 `complete` 和 `gaps` 继承事件账本的采集连续性。

事件订阅使用现有报告与订阅工具，事件类型设置为 `truce_expired`。`actors` 筛选停战方向的记录所有国，`recipients` 筛选另一端国家。一个事件触发的报告可联合读取 `truce_expiry`、修正生命周期和提议到期字段。订阅重放直接使用保存的事件快照。

显式提供 `request_id` 或 `case` 的 H02 查询继续委托既有 journal 查询，以便读取已有请求关联记录。

## 原生捕获合同

固定 EXE 的 SHA-256 为 `b23fa0e1f698d31b01cdd1c3817a675805d8c6286cb66f9c231e6e2a42544d77`。下文地址均为 RVA。文件首选 image base 为 `0x140000000`，实际进程 VA 需加上该进程的载入基址。

捕获入口是 `[0xa67420, 0xa68447)` 的关系维护函数。入口参数指向一个 `0x48` 字节的方向性关系记录。原生函数读取 `+0x45` 的 bit0，并在 `[0xa674ad, 0xa674f5)` 调用已有日期计算器、比较截止日期和当前日期、写入 `+0x44=2`，随后清除 bit0。

观察器在原调用前后分别读取同一记录。进入自然到期候选需要同时满足下列条件。

- 调用发生在已绑定的游戏 frame 线程，当前日期与会话上下文相符。
- 原记录的直接停战 bit0 为 true，双方完整国家引用可从原生国家表精确重查，并且该记录位于所有国的 `+0x1510` 关系数组中。
- 记录输入日期晚于游戏对象 `+0x1dd4`，并且不晚于当前日期。当前日期与 RVA `0x1fd13c4` 的特殊值不同。
- 原生记录根对象的 `+0x50/+0x5c` 向量不含目标国家槽。读取上限为 4096 项。
- 使用既有日历模型得到的截止日期不晚于当前日期。

返回后，观察器再次核对记录归属、双方完整引用、日期输入、调整量、两项配置与游戏日期，并要求 `+0x44=2` 和原 bit0 从 true 变为 false。短期状态由每次调用的局部变量保存。重复维护已清除标志的记录时，入口检查会结束该次采集。

`+0x1dd4` 和 RVA `0x1fd13c4` 的业务名称继续按未解析条件记录。捕获使用其已确认的原生比较条件。直接停战的来源范围与现有 `R03.truce_until` 一致，关联国家继承停战继续沿该字段已有覆盖范围。

日期输入早于 raw `43800000` 或计算结果超出有符号 32 位范围时，采集按不可读候选处理，并报告断档。日历规则复用 `bridge/information/truce_date_math.py`，原生观察器的等价整数实现保留相同的 32 位回绕、向零除法和月份起始日规则。

## 顺序、断档与持久化

原生回调只保存自有值。事件进入容量 64 的队列，队列满或读取失败时累积丢失数量。刷新与日志写入失败会保留可追查的健康状态。每次排队尝试使用单调序号，用户态复用共享日志游标和容量 1024 的事件缓存。

公开事件编号由会话编号和停战事件序号生成。重复日志、序号冲突、序号断档、缓存淘汰和传输失败分别沿现有采集器报告。载入确认门槛控制当前世界的采集起点。持久化、分页、订阅投递、恢复和去重沿用 `info_events` 账本。

`C04.event_payload` 保存双方国家、日期输入、调整量、两项配置、派生截止日期和来源范围。重放时重新执行既有日历投影，并验证事件日期已经到期。原生地址与完整引用留在原始采集材料中。

## 构建与准入

构建开关为 `-TruceExpiryObservation`，它继承已有 v61 功能。v62 可以独立选择停战自然到期、补贴自然到期，或同时选择两项。每项需要对应的编译开关、四个源码文件、wire 与来源范围，且完整继承 v61 的准入合同。

停战能力由安装 ACK 的 `native_truce_expiry_observation=true`、`native_truce_expiry_wire=1` 和精确 scope `FRA_actor_or_recipient_directional_direct_truce_expiry_returns` 共同声明。正常安装器、战报控制器和探针共用源码及散列验证。

Python读取支持v62及继承该能力的v63、v64。v63包含停战、补贴两项父能力，并增加宣称自然到期生产方。v64继续继承这些能力。

验收应同时保留目标 EXE 身份、原生候选 DLL 与清单身份、真实自然到期前后的方向性状态、原生事件、正常 C04/H02 交付、恢复重放和去重结果。普通文件反汇编、静态条件推论、自有进程夹具及游戏实机观测分别记入执行日志。
