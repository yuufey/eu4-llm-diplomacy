# 外交官总量只读接口

第162批新增 `N05.diplomats_total`，读取逻辑观察国 FRA 的原生外交官总容量。支持主动查询、报告及周期订阅，复用现有只读采集和标量公开接口。

```json
{
  "topic": "N05",
  "object": {"type": "country", "country": "FRA"},
  "fields": ["diplomats_total"],
  "parameters": {}
}
```

实机结果为 `value=raw=4000`、`raw_hex="a00f0000"`、`unit="diplomats"`、`scale=1000`，即总容量 **4**。数值保留原生有符号定点精度，不按任务列表长度或空闲外交官数量推算，不增加假定的基础值。该字段保持 `partial=true`、`complete=false`；总容量不证明当前任务实例的数量。

为了兼容 N05 其他字段，可选 `reference_recipient` 接受合法的其他国家标签，但不参与本字段的本国容量计算。单独查询无需提供它。公开结果不会返回进程地址或私有读取轨迹。

## 原生依据与当前支持路径

目标固定为 EU4 1.37.4、B23 可执行文件 SHA-256 `b23fa0e1f698d31b01cdd1c3817a675805d8c6286cb66f9c231e6e2a42544d77`。CWTools 的 `num_of_diplomats` 条件声明提供语义入口；接受的缓存 REA 证据分别确认条件说明函数 RVA `0xc6ca70` 和求值函数 RVA `0xc6c6a0`。后者读取修正编号 34，将整数阈值乘 1000 后与原生处理结果比较。读取沿用既有 RVA `0x93d5c0` 缓存访问器的证据，没有重查它。

实机表明编号 34 存在处理器，最初仅支持空处理器的 v1 因而返回未知。只读绑定探针进一步确认虚表 RVA `0x1cc9238`、计算方法 RVA `0x8f9d20`。对该方法的 REA 查询因内存达到上限被停止，没有可接受证据；没有把 exit137 或空 evidence 文件当作成功。

后续使用固定 EXE 的独立普通 PE 字节，核对范围 `[0x8f9d20, 0x8f9e28)`，共 264 字节。该范围包含局部各返回路径，外部 TLS 初始化调用仍未闭合。这类普通文件分析与此前接受的 REA 证据分开记录。RVA 必须加实际模块基址才是运行地址。

当前支持非计算态缓存的两种路径：

- 编号 34 的处理器为空时，复用既有有界稠密/稀疏读取器。
- 处理器的虚表和方法与上述地址精确一致，且模块 RVA `0x233ff0c` 的字节非零、`0x233feb6` 的字节为零时，原生方法直接返回输入修正值。读器复制同一编号 34 的原始存储，不执行处理器，并在读取后再次核对处理器槽、虚表、方法及两个标志。

新 `modifier_storage.py` 提取既有 quality 读器的原始字典读取方式，供已单独确认的处理器使用。它只读取原始存储，不解释处理器或自动发布字段。稠密编号按 `id*8+4` 取值；稀疏按首匹配取值，合法空表或无匹配为已知零。绑定、指针、数量及读取预算继续有界。旧 quality 读器和旧 profile 没有改写。

其他标志组合涉及线程状态，此时返回 `DIPLOMATS_TOTAL_THREAD_CONTEXT_UNAVAILABLE`。未知处理器、计算态、绑定失败、读取失败或前后变化均不会用零或历史值补齐。编号 220 的附加值和相关 TLS 分支不在当前支持范围；没有按修正名称猜测它们的实际效果。
