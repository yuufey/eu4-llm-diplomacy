# 外交官派遣冷却到期通知

`H02.cooldown_expiry` 提供已经观察到的外交官派遣等待期限到期提醒。A01原生预览显示“最近已经派遣过外交官，所以直到某日才能再次派遣”后，服务记录该方向国家对的截止日期。游戏日期到达该日时，现有事件轮询生成 `cooldown_expired`，供LLM重新评估这一国家对的外交行动。

## 查询与简洁输出

```json
{
  "request_id": "read-contact-expiry",
  "queries": [{
    "topic": "H02",
    "object": {"type": "country_pair", "actor": "FRA", "recipient": "BUR"},
    "fields": ["cooldown_expiry"]
  }]
}
```

默认字段值形如以下列表。

```json
[
  {
    "event_id": "cooldown-expired:...",
    "event_type": "cooldown_expired",
    "actor": "FRA",
    "recipient": "BUR",
    "cooldown": "diplomatic_contact",
    "available_on": "1455.11.12"
  }
]
```

`actor` 是派遣外交官的国家，`recipient` 是接收国。国家对查询具有方向，`country` 查询返回涉及该国的记录，`session` 查询返回当前观察会话的已记录事件。`limit` 默认50，`cursor` 用于读取后页。

`available_on` 是原生提示给出的可再次派遣日期，事件日期使用同一日期。行动的当前合法性继续由A01预览给出。完整视图保留日期原始刻度、采集来源和连续性信息，简洁输出直接给出可读日期。

## 自动记录与订阅

通过正常查询或报告读取 `A01.cooldown`，已知的原生派遣等待期限会随查询结果保存。服务每轮调度通过共享事件来源读取这些结果，维护待到期国家对并记录到期事件。随后运行的H02定时和变更报告可读取同轮新记录。事件订阅控制主动交付，历史采集独立运行。服务须保持启用，并持续调用 `information_tick` 或配置后台调度。

同一方向国家对重复查询同一截止日期只产生一次提醒。后续明确观察到更晚的等待期限时更新截止日期，后续原生通用动作条件通过时取消尚未到期的提醒。其它未知字段继续保留已有等待记录。

订阅沿用已有事件配置。

```json
{
  "kind": "event",
  "report_id": "contact-expiry-report",
  "event": {
    "types": ["cooldown_expired"],
    "actors": ["FRA"],
    "recipients": ["BUR"]
  }
}
```

轮询只增量读取本地已保存查询，每页128份结果。积压页全部处理后再判断到期，以便使用后续已经观察到的延期。它复用原有游戏日志轮询，已有截止日的提醒不增加原生行动预览调用。

## 来源范围

当前自动来源覆盖A01原生 `ENROUTE` 提示所说明的再次派遣等待时间，支持中文、英文及结构化日期的既有日历格式。提示可位于一般行动诊断或议和预览的 `diagnostics.common_action_gate` 中，均使用同一完整句式提取日期。

其它行动专属冷却继续按各自来源处理。显式提供 `request_id` 或 `case` 时，H02继续使用已有journal关联查询入口。

A01查询允许游戏时钟在采集期间继续前进，完整视图记录采样窗口。等待国家对、已交付截止日和结果读取游标随现有事件游标保存，事件与游标在同一事务中提交。
