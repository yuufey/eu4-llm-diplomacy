## 读取与订阅

使用已有报告和订阅工具创建下列配置。报告编号使用创建报告时实际返回的`id`。

```json
{
  "name": "收到的外交请求",
  "detail": "brief",
  "queries": [{
    "topic": "A04",
    "object": {"type": "session"},
    "fields": ["proposal_id", "action_id", "actor", "recipient", "proposal_status", "parameters"],
    "parameters": {}
  }]
}
```

```json
{
  "name": "法国收到的外交请求",
  "kind": "event",
  "report_id": "替换为实际报告编号",
  "enabled": true,
  "event": {"types": ["diplomatic_proposal"], "recipients": ["FRA"]}
}
```

该订阅也交付其它已接入的外交提议，`action_id=call_to_arms`标识参战召唤。每条事件按自己的载荷投影报告，省略`proposal_id`时也能分别交付多条请求。正常A04查询仍可通过`parameters.proposal_id`选择留存的观察记录。

## 载荷含义

- `actor`和`recipient`对应请求双方，捕获时核对完整国家引用及接收国FRA。
- `parameters.versus`和`specific_enemies`提供召唤针对的国家。无法解析的引用返回未知，保留已复制的数量。
- `defensive_war_with`、`replace`、`autojoin`、`full_ally`、`union`、`promised_land`、`ignore`沿用固定版本原生写出字段的布尔含义，并保留原始字节。除`replace`外，其余六项按原生的`raw_byte == 0`解释。
- `call_type`保留原始枚举整数，其业务枚举含义仍未知。所属战争编号也保留缺项。
- 事件`game_date`来自复制时读取的游戏日期。`native_date_fields`保留两个原生日期字段，其创建或到期含义尚未解释。

`proposal_id`为会话内观察记录的公开标识，`identity_scope=captured_observation`。原生多次执行入口观察可能对应同一业务请求，读取器按观察序号去重。两个内容相同的独立观察仍分别留存。

队列最多保留64条尚未排出的记录，敌国向量最多复制128项。已核对为本国请求后，扩展载荷复制失败或队列丢失进入`CALL_TO_ARMS_CAPTURE_DROPPED`，订阅采集状态保留缺口。当前记录整体为partial。
