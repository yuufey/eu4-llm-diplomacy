# 双向好感年度变化接口

第188批另行接通[双向好感计划结束日期接口](双向好感计划到期接口.md)。它只投射固定期限记录保存的计划日期，不改变本接口对年度贡献的解释，也不表示实际年度结算或修正已经到期。

第187批将 `R04.decay` 接入实时查询、报告和周期订阅，状态为 `partial`。接口读取当前具名修正及其已加载的计算输入，按原生提示路径推导每条修正的年度好感变化。正数表示恢复好感，负数表示降低好感；结果不表示已经执行了年度结算，也不用于推算到期日。

## 查询与结果

通过 `information_query` 查询逻辑观察国 FRA 参与的国家对：

```json
{
  "queries": [{
    "topic": "R04",
    "object": {"type": "country_pair", "actor": "FRA", "recipient": "ENG"},
    "fields": ["decay"],
    "parameters": {}
  }]
}
```

可在同一次查询中选取 `opinion`、`opinion_modifiers`、`decay`、`end_date`。返回两个方向，顺序与请求一致；每个方向保留原记录顺序和重复修正键。物理玩家可以是 POR，不要求将玩家切换为 FRA。

已知记录包含 `modifier_id`、`yearly_change_raw`、`yearly_change_decimal`、`unit`、`scale` 和计算依据。单位为好感点/年，比例为1000；例如原始整数10320对应 `"10.320"` 点/年。这里的整数是推导结果，并非声称从内存直接复制了最终年度变化值。无法计算的记录单独返回 `unknown` 及原因，不撤回同方向的其他已知记录。

报告和现实时间周期订阅使用同一读取器。支持 `query`、`periodic`，尚不声明 `change` 或逐条原生事件。每次请求重新采集；报告频率不会推进游戏日期。

## 计算范围与未知条件

实现复用现有国家身份与准入、双向修正容器、原始属性存储、双遍一致性和严格读取记录回放。原生提示中的基础年度量来自已加载 definition，负面记录另结合被评价国家的属性和国家对附加量。

当前处理器已按 vtable 和方法地址识别。其两个分支分别返回原值、原值加两倍附加属性；仅在附加属性为零时，才能不执行处理器或依赖 TLS 而取得两分支相同的数值。其他处理器类型或非零附加属性保持未知。

国家对附加量同样只处理已证明为零的路径：没有适用候选、缓存未启用、选中记录为空，或选中记录的已处理属性为零。需要继续判断国家关系且结果可能非零的候选保留未知，不能按零处理。

此外，属性正在计算、字段读取失败、容器或记录变化、超出读取预算、未知记录类型等均保留缺项。第188批已补足调用门：当前原始值除以1000并向零截断后为零时，不进入年度累计路径。因此绝对值不足1点的当前修正返回已知零贡献，也无需读取负面因子。记录标志可以使其不计入这段提示的年度贡献，但这不等于证明整个游戏永远不会改变该记录。

第187批完成时，完整提示中的其他好感因素、实际提示绘制、缓存新鲜度、年度结算及实际到期日仍未完成；当时 `R04.end_date` 仍为 `planned`。第188批随后将 `R04.end_date` 接入 partial 实时查询，但它提供的是记录保存的计划日期，而不是实际失效或移除状态。不能用当前好感值除以年度变化推算该计划日期或实际到期状态。
