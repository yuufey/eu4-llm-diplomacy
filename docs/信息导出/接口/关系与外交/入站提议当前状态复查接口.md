# 入站提议当前状态复查接口

A04默认返回曾观察到的提议。proposal_status.value=observed_pending只说明观察时状态；period=observed、currently_pending=unknown，不能解释为现在仍在等待回应。以下查询先获取本会话实际观察到的公开ID：

```json
{
  "request_id": "query-inbound-001",
  "queries": [{
    "topic": "A04",
    "object": {"type": "session"},
    "fields": ["proposal_id", "action_id", "actor", "recipient", "proposal_status"],
    "parameters": {}
  }]
}
```

只有proposal_id已知时，使用该返回值再请求proposal_status，并将parameters设为`{"proposal_id":实际返回的公开ID,"fresh_pending":true}`。这是参数形状说明，其中“实际返回的公开ID”应使用上一结果的字符串；不要使用原生数字编号、旧实验ID或自行构造ID。fresh_pending必须为bool，必须有明确ID；phase只能省略或为观察阶段initiate。参数缺失/错误会明确拒绝，查询其他字段不会额外触发状态检查。

复查复用现有只读inspect接口。其内部使用accept阶段检查响应规则，但不会发送接受或拒绝，不创建执行授权。已知结果为pending或inactive，period=current，并给出currently_pending的已知bool、观察游戏日期和observed_status。inactive只说明该提议不再active，不说明已接受、拒绝、撤回还是过期。active的native_validity仍可能false，不能把“仍pending”视作合法响应或执行许可。

会话/国家/日期、公开ID绑定、typed native flags或决策国证明不满足时返回unknown/unavailable，不用缓存的observed_pending冒充新结果。inactive的已证原生格式可以含decision_country_verified=false；这不是“响应资格已验证”。只查本会话明确提议，不枚举全部当前pending集合，所有当前状态结果complete=false/partial=true。原生编号、token和完整检查对象不导出。

报告、现实时间周期和采样变化均共用查询路径；显式fresh_pending查询会在每次采样尝试复查这个ID。它不保证捕获采样间全部生命周期事件，也不会自动改为其他提议。默认观察查询的周期结果仍是观察缓存；无可用观察ID时不发原生复查，不能因此推断游戏无待回应事项。C03.pending_matters内的native_inbound_pending继续未知。

## 待处理状态变化订阅

254批新增独立字段`A04.currently_pending`，当前支持实时FRA观察方。在`fresh_pending=true`且明确选择公开提议编号时，返回已校验的布尔值。它与`proposal_status`共用一次原生只读复查，查询结果保留`partial=true`和`complete=false`。默认观察查询及捕获事件的重放保留当前状态未知。

变化订阅使用该布尔字段作为比较值。有效样本建立基线，后续值改变时生成`trigger=change`结果。采集日期和检查凭据另行记录，日期变化本身不触发通知。读取失败保留已有基线，恢复后继续比较。

先将下面配置作为`information_manage_report`的`config`，用`operation=create`保存。`proposal_id`使用当前会话实际返回的公开编号。

```json
{
  "name": "所选外交提议的待处理状态",
  "detail": "brief",
  "queries": [{
    "topic": "A04",
    "object": {"type": "session"},
    "fields": ["currently_pending"],
    "parameters": {
      "proposal_id": "替换为当前会话返回的公开提议编号",
      "phase": "initiate",
      "fresh_pending": true
    }
  }]
}
```

再将返回的报告编号填入下列配置，通过`information_manage_subscription`创建变化订阅。

```json
{
  "name": "所选外交提议状态变化",
  "kind": "change",
  "report_id": "替换为实际报告编号",
  "enabled": true,
  "schedule": {
    "basis": "real",
    "every": 5,
    "unit": "seconds",
    "missed": "coalesce"
  }
}
```

服务启用`--tick-seconds`后台调度，或由调用方使用`information_tick`驱动采样。配置操作沿既有版本化接口执行。取消订阅后该订阅停止复查；其它订阅继续按自身配置运行。状态字段和结果对象均保留公开提议编号，便于关联原始提议。

该变化范围只接纳`currently_pending`且要求`fresh_pending=true`，配置不符时明确拒绝。其它字段可继续用于一次性查询或周期报告。当前复查支持已观察为`observed_pending`的既有行动族，参战召唤的被动观察仍保留当前状态未知。

`false`表示本次复查发现提议已不活跃。原生接受、拒绝、撤回和过期的原因及发生时点各自保留缺项。采样时间在结果上下文中记录，轮询间隔内的瞬时变化可能缺失。

## 254批验证

使用两份独立的R32历史检查，分别验证已知true与false的公开投影。变化订阅的true→false序列是明确构造的离线测试情境，两份不同会话和提议的历史检查分别保留身份。正常信息工具覆盖基线、日期变化、读取失败、单次通知、配置原子拒绝及取消，既有来源组合与战报包装器的比较转发也有检查。

当前静态目录为74主题、398字段。默认工厂另外包含244批的`N01.loan_summary`，合并目录为399字段。历史397字段的覆盖统计继续作为对应批次记录使用。当前游戏会话上的待处理状态变化尚缺新实采正例，原撤回和过期通知来源继续按P2推进。收据见[254批摘要](../../../../work/runtime/information-inbound-change-20261107-254-001/summary.json)。

第151批125项受影响测试通过；历史R32 true/false记录经真实验证器和公开转换回放通过。当前运行会话没有可用观察ID，所以实机仅核观察缺项、缺ID拒绝、报告/2秒5秒和独立取消，未取得当前pending/inactive原生正例。字段覆盖由available纠为partial，完整计划范围和原120禁重试政策保持。原始记录见work/runtime/information-inbound-current-state-20261104-151-001/。
