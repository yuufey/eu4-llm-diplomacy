# 外交声誉只读接口

第161批新增 `N06.diplomatic_reputation`，读取逻辑观察国FRA的外交声誉原生聚合缓存。支持主动查询、报告和周期订阅，复用当前operator session；读取不会推进日期、提交外交动作或操作窗口。

```json
{
  "topic": "N06",
  "object": {"type": "country", "country": "FRA"},
  "fields": ["diplomatic_reputation"],
  "parameters": {}
}
```

已验证结果如下：

```json
{
  "status": "known",
  "value": 3000,
  "raw": 3000,
  "raw_hex": "b80b0000",
  "unit": "diplomatic_reputation",
  "scale": 1000,
  "period": "current",
  "partial": true,
  "complete": false
}
```

实际外交声誉为 `raw / scale = 3.000`。`value`保留有符号原始整数，与raw相同；已知零值与未知分别表达。为了兼容N06已有字段混查，可选 `reference_recipient` 仍接受合法的其他国家标签，但它不参与本地声誉计算；单独查询本字段无需提供该参数。范围之外的国家和未声明参数会被拒绝。

## 原生依据与支持路径

固定EU4 1.37.4、B23可执行文件。既有CWTools配置提供 `diplomatic_reputation` 的country修正和浮点条件声明。新接受的REA证据确认：原生面板在 `DIPLOMATIC_REPUTATION` 分支向帮助函数传入属性编号 `0x85`（133）及缩放1000；帮助函数按同一编号读取稠密数组或稀疏首匹配值，并在处理器存在时执行额外路径。

读器复用已有有界修正缓存实现，重新核对FRA完整引用，再复制非计算态缓存及编号133的数据。稀疏列表首匹配优先，合法空表或无匹配返回已知零；负值不钳制。不执行原生帮助函数。计算态、非空处理器、绑定或代码变化、读取失败和预算超限均返回未知或不可用，不能用已有值补齐。

读取由共同的只读所有者管理：核对进程、创建时间、会话、B23代码守卫、NPC角色和国家查看准入；两遍结果一致后才发布，并用保存的原始读取严格重放。公开层再次核对前后上下文与会话，保留raw/hex/unit/scale一致性，拒绝额外地址字段。上下文过期与读取失败分开返回。

新 `ScalarCaptureSource` 供这类有符号标量复用公开边界；新字段的语义、版本profile和取值读器仍分别指定，没有把所有修正编号自动开放给LLM。

## 验证与限制

87个当前唯一相关测试经单项夹具修正后通过，覆盖稠密/稀疏、负值与零、首匹配、处理器/计算态、坏引用/指针/预算以及公开层篡改、过期、报告和周期行为。原失败结果保留；没有重跑完整bridge，完整回归仍有126个既有坏ID。

实机FRA是非玩家国家，物理玩家为POR。一次有效私采5656次只读调用、62504字节，句柄关闭、严格重放和摘要篡改拒绝通过；独立从两遍原始字节重算编号133、空处理器及raw3000。实际MCP查询、报告、2秒/5秒结果与私采一致，两个订阅取消，服务exit0、读取线程退出，日期保持raw56558664。本批未重新核对暂停标志；沿用上一轮已暂停的证据。

v1 profile因新ROM守卫使用了错误的 `bytes_hex` 键而被共同所有者拒绝，未取得字段结果；保留v1及失败记录，v2改用合同要求的 `bytes` 键后完成验收。当前使用 `diplomatic-reputation-memory-1374-v2.json`，SHA-256为 `9449d3f449d472e081976aae29666b4dbd7156687f47027e5876a25cf2cb29b4`。

字段保持partial：非空处理器、计算态、具名贡献分解、缓存新鲜度及主线程原子快照仍有缺口。静态REA、普通PE字节、离线测试和实机读取分别记录；没有原生游戏函数调用、业务派发、保存/重载、重启注入、日期推进或Computer Use。
