# 外交关系数量与容量接口

`N05.relations_count`提供原生外交关系数量条件和upkeep界面采用的当前关系数，`N05.relations_limit`提供该界面`ALLOW`容量值。当前仅支持EU4 1.37.4固定B23构建、逻辑非玩家FRA。两字段支持查询、报告和periodic，均为partial、complete=false、period=current、unit=diplomatic_relation、scale=1。

```json
{"queries":[{"topic":"N05","object":{"type":"country","country":"FRA"},"fields":["relations_count","relations_limit"],"parameters":{}}]}
```

本批法国结果为数量7、上限7；已知字段保留整数value/raw和4字节little-endian raw_hex。可与diplomat_tasks、diplomats_available共同查询。请求diplomats_available时仍须提供reference_recipient；只查这两个本地字段可用空参数，可选reference_recipient仅为共享查询选择器，不改变本地计算或观察国。

计算为`L=trunc_zero(M/1000)`、`C=i32(L+i32(A-F))`：M是原生修正159，A为+0x98c4原始加项，F为+0x98c8空闲缓存。上限L直接对应原生UPKEEP_EXPLANATION的ALLOW；不能把C+F当上限，A也不能直接解释为基础容量。有符号除法向零截断，数量算术保持32位回绕，不把超限状态强制截断成零。

只在正常缓存状态且修正处理器为空时输出已知计算；未知处理器和计算中的缓存保持unknown。count的独立缓存读失败时仍可保留已知limit；身份、共同预算、日期或两遍证据失败会撤回相应结果。公开结果不含原始地址或内存trace。完整关系成员、具名来源贡献、缓存刷新时机和主线程原子性尚未证明。

最终149项相关测试通过。实机A=0/F=0/M=7000，查询、报告和2秒/5秒均为7/7；A非零的通用公式由原生UI静态证据和离线反例验证，尚无非零A的实机样本。本批未观察实际界面绘制、调用游戏函数、推进日期或保存重载。
