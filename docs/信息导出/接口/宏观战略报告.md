# 宏观战略报告

本页提供可以直接交给`information_manage_report`的[报告配置](宏观战略报告配置.json)。配置复用已有查询、报告保存和订阅接口，默认返回国家、日期及宏观战略业务值。

配置使用`detail="brief"`。默认输出采用直接数值、必要范围和可读日期，来源及诊断信息可按结果编号以`view="full"`读取。具体规则见[简报与完整结果](信息简报与完整结果.md)。

## 示例范围

当前示例以FRA为观察国、ENG为一个比较对象，沿已有1.37.4来源的适用范围。启动时的观察方仍由服务实际连接决定，配置中的国家需要与所接来源匹配。`reference_recipient`供部分既有本国资源读取路径使用，宏观视角仍为FRA。

| 内容 | 选取方式 |
| --- | --- |
| 国家背景与待办 | 日期、观察方、日志复核事项及FRA原生收件队列摘要 |
| 风险承受能力 | 国库、收支、贷款数量与本金总额、军团与舰船数量、人力、水手、上限、主要军事质量及国内压力 |
| 外交资源 | 可用外交官、关系容量、点数、外交声誉和威望 |
| 关系与比较对象 | 本国关系网、战争与宿敌、包围网成员及目标、对ENG的停战和好感、ENG可见实力及财政 |
| 持续承诺 | 与ENG相关的当前土地标记、备战约定、补贴、战争赔款及期限 |
| 贸易背景 | 本埠、收集节点、收入与收集状态，具体贸易转移关系按节点展开 |

军力保持现有团数和船数语义。具体型号和逐记录分布归详情。财政和外国信息沿来源的可见性和已知限制，计划字段返回的缺项继续保留。

N01的`loan_summary`复用已有贷款记录，默认呈现为`loans.count`与`loans.principal`。存在未知或非标准本金时，完整视图保留已知小计及未知数量。原`loans`明细仍可单独查询，国库和贷款摘要直接读取FRA本国数据。

C03的`pending_matters`在默认实时工厂中同时提供日志分页和FRA原生待处理链表摘要。两部分分别标记状态，队列条目提供行动类型、国家对和可知期限。来源元数据中的`proposal_lookup.links`提供唯一匹配的A04提议编号，可继续查询提议详情。284–285批已取得当前BOU→FRA联姻待办及查询衔接正例，其它通道仍有缺项，具体范围见[待处理事项接口](国家与国内/决策输入与待处理事项接口.md)。

## 创建与查询

1. 调用`information_discover`确认当前对象和来源范围。
2. 读取配置文件，将其内容作为`information_manage_report`的`config`，操作为`create`，为本次创建提供唯一`request_id`。
3. 保存返回的`report.id`。后续调用`information_query`时传入该`report_id`和新的`request_id`。
4. 修改比较对象或字段时，使用`update`及当前`expected_version`更新同一报告。

配置和结果保存在服务的数据库中。重复读取使用已保存的报告编号，恢复服务时沿用同一数据库和owner。

也可以通过现有JSONL入口离线保存配置。从项目根目录运行以下命令，启动参数见[接口使用说明](信息接口使用说明.md)。

```powershell
$reportConfig = Get-Content -LiteralPath 'docs/信息导出/接口/宏观战略报告配置.json' -Raw | ConvertFrom-Json
$request = @{
    tool = 'information_manage_report'
    arguments = @{
        request_id = 'macro-create-' + [guid]::NewGuid().ToString('N')
        operation = 'create'
        config = $reportConfig
    }
}
$request | ConvertTo-Json -Depth 32 -Compress |
    python tools/serve_information.py --database work/runtime/information-service/information.sqlite3 --observer FRA --jsonl
```

该命令保存配置，随后退出。实时读取沿用相同数据库、owner和实际游戏来源的启动参数。未连接来源时，查询会保留未就绪状态。

## 订阅与情境展开

通过`information_manage_subscription`创建`periodic`订阅，引用同一报告。周期按当前决策需要选择，运行时启用已有调度器。配置的字段和周期可以独立修改，操作合同沿[接口使用说明](信息接口使用说明.md)。

基础报告用于定位当前可用信息和缺口。选定相关国家、任务、贸易节点、领土和外交方案后，再使用既有接口展开。

已有可保存的[任务、贸易与具体行动情境报告](宏观战略情境报告.md)，包含明确的任务、节点和宣战方案参数。

- 任务树在启用任务数据来源后查询相关M01–M04信息，使用实际加载结果和关键目标。
- 贸易节点由基础报告取得，再查询相关T01、T03和T04的线路、价值与竞争份额。
- 宣战、召盟及议和沿D/P/A类具体行动预览，提供实际对象和参数。
- B01–B04和外交事件沿独立事件订阅，保留明确要求的完整记录。

逐场战斗可直接采用[宏观战报配置](战争与战报/宏观战报简报配置.json)，将已采到的国家、胜负、规模、损失和结果量组织为同场简报。参数与状态见[战报接口](战争与战报/战报结果组合接口.md)。

## 当前验证

### 连续运行时的采集日期

财政、军力和国内压力用于宏观决策，最近一次有效读数可继续参考。`information_get_result`按结果编号返回原采集值及日期，数值不会因过了几个游戏日自动清空。更新报告时可以让游戏继续运行，各字段附带采集时间范围。

本国N01–N04主动查询或周期刷新失败时，字段可通过`last_known.field`附上最近有效数值及原单位/尺度，`last_known.context`和`observation_window`标明其原采集日期，`last_known.result_id`指向原完整结果。本次读取的状态和失败原因同时保留。匹配限于相同owner、会话、观察方、世界和构建、报告版本及查询，读取新值成功时直接提供新值。没有世界身份的来源仅自动复用本次服务实例取得的读数，服务重开后仍可用原编号查看已有报告。外交资源、外国情报、行动检查和事件沿原读取合同。[历史值交付合同](../开发与验收/信息服务合同.md)

实时宏观查询允许游戏日期正常前进，已读数值保留并附带 `observation_window`。其中 `start_game_date` 和 `end_game_date` 是原生游戏日期范围，`collection_end_game_date` 是报告结束时取得的心跳日期。心跳可能滞后于内存读取，所以采集范围的结束值可以更晚。`atomic_snapshot=false` 说明各项在这个时间范围内取得。

正常跨日不会使整份宏观报告自动过期。国家、会话或世界身份改变、日期倒退、字段自身读取失败仍分别报告。原始读取证据及日期继续保存，完整结果和数据库重开也保留采集范围。具体行动预览及执行仍按各自当前状态检查。
