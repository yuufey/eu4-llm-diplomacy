# 神罗当前改革记录接口

实时服务默认提供 S01 的 `reforms` 字段，返回当前全局神罗记录中存储的已通过改革标识。单位为 `reform_id`，`period=current`，`complete=false`。它不计算改革效果、按钮可执行条件或帝国成员身份。

## 查询与来源选择

以经过核对的实时安装身份启动服务：

```powershell
python tools/serve_information.py --operator-session '<installation.json>' --observer FRA --database work/runtime/current-reforms/information.sqlite3
```

使用 `information_query`：

```json
{
  "queries": [{
    "topic": "S01",
    "object": {"type": "country", "country": "FRA"},
    "fields": ["reforms"],
    "parameters": {}
  }]
}
```

`country` 或 `session` 选择的都是同一全局记录，不表示所选国家存在、属于神罗或拥有改革权限。显式 `session_id` 必须匹配当前会话。逻辑观察方保持 FRA 非玩家，物理客户端仍可为 POR；不为读取而将玩家切换成 FRA。

三个来源必须按时间与含义区分：

| 启动方式 | `reforms` 内容 | 时间与单位 |
| --- | --- | --- |
| 默认实时安装来源 | 当前全局记录中的通过标识 | `current` / `reform_id` |
| 显式 `--empire-game-data` | 配置中的神罗改革声明，包括未求值脚本 | `static_definition` / `imperial_reform_definition` |
| 显式 `--empire-save` | 历史保存时的通过标识；缺失保持 unknown | `saved_snapshot` / `reform_id` |

静态开关启用时，不同时注册当前改革字段的 owner，避免两种语义争用同一字段。旧皇帝、选侯仍由独立来源负责；新改革 GUI/profile 校验失败时，不借此撤回其它来源已经核实的字段。历史来源的隔离要求保持不变。

## 读取和公开范围

v3 profile 固定 B23 EXE、读取布局及命名控件的静态绑定。`reform_selected_frame` 是独立 `iconType`，与 `reform_button`、`reform_checkbox` 两个按钮不同；条目构造路径按全局通过表的精确对象指针匹配更新状态图标。按钮条件不直接支配该匹配路径。

准入范围仅为全局存储记录的标识投影。配置文件及 GUI 指纹不证明引擎实际载入或绘制了对应控件，也不证明任意观察方的完整知识。因此 `actual_ui_observed`、`visibility_evaluated`、效果和条件求值标记保持 false；字段不能用来承诺改革当前实际生效、可执行或可撤销。静态研究的证据和限制见[改革采集研究](../../实现研究/机制与宗教/神罗改革实时采集研究.md)。

捕获复用既有只读句柄、角色与国家完整引用绑定、两遍比较及顺序 trace 重放。改革项自身失败或变化时返回 unknown；会话、进程根目录、世界或全局身份不一致时撤回该来源结果。计数明确为 0 才能返回已知 `[]`，不能把缺失或读取失败改写为空。配置、模组选择、有效 GUI 或依赖变化后拒绝旧绑定。没有调用游戏函数、写内存、推进日期或操作 UI。

v1/v2 模块及 profile 保持独立不改。v3 有 15 个代码/字符串 guard，共 2018 字节，profile SHA-256 为 `dd884cf7b234811429dccd0ba33e5b4710914f3d6413c8b69eec55ada3913d39`。GUI 指纹、游戏根目录与实际进程路径一并核对；只把原始 v3 报告用于验证，本地格式化副本不成为 v2 验证或准入证据。
