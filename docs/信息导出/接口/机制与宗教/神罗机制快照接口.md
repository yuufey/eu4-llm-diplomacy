# 神罗机制快照接口

本接口从操作者明确指定的历史存档读取全局神圣罗马帝国（HRE）记录。接口合同包含四个 `partial` 字段：`emperor`、`electors`、`reforms` 和 `empire_status`。第112批 v2 已完成一次真实 MCP 验收；第111批结果仍是独立的 v1 历史记录。快照只包含存档记录，不计算规则效果，也不代表当前游戏界面或实时状态。

S01 原有 6 个字段和全目录 74 个主题、397 个字段的统计保持不变；`empire_status` 是原有字段的补充信息，不拆成额外目录字段。皇帝介入条件和宗教联盟仍为 planned；目前没有 HRE 已通过改革的正例存档样本。

## 指定历史存档

启动信息服务时，显式指定存档并提供逻辑观察方：

```powershell
python tools/serve_information.py `
  --empire-save 'C:/path/to/allowed.eu4' `
  --observer FRA `
  --database work/runtime/information-service/information.sqlite3
```

`--empire-parser-manifest` 可显式选择受信解析器清单；新默认使用 v2 清单 `tools/rust/eu4-save-empire-v2/adapter-manifest.json`：

```powershell
python tools/serve_information.py `
  --empire-save 'C:/path/to/allowed.eu4' `
  --observer FRA `
  --empire-parser-manifest tools/rust/eu4-save-empire-v2/adapter-manifest.json `
  --database work/runtime/information-service/information.sqlite3
```

清单采用既有通用解析器 pin 容器格式 `eu4.save_provinces.parser.v1`，用于校验 Jomini 提交、解析器源文件和二进制；v2 解析器输出使用 `eu4.save_empire_snapshot.v2`，v1 输出仍为 `eu4.save_empire_snapshot.v1`。这两个 payload schema 与通用清单 schema 用途不同。新 v2 CLI 位于 `tools/rust/eu4-save-empire-v2`；旧 `tools/rust/eu4-save-empire` 的源码、二进制、manifest 和 pin 保持不变。要显式使用 v1，应把 `--empire-parser-manifest` 指向旧清单：

```powershell
python tools/serve_information.py `
  --empire-save 'C:/path/to/allowed.eu4' `
  --observer FRA `
  --empire-parser-manifest tools/rust/eu4-save-empire/adapter-manifest.json `
  --database work/runtime/information-service/information.sqlite3
```

固定 Jomini 提交为 `8fbd6861f453c719da59daac6970babd9ddc19ac`。

`--empire-parser-manifest` 必须与 `--empire-save` 一起使用；`--empire-save` 必须提供 `--observer`，并且不能与实时 operator session 或其他状态来源组合。解析器只接受其合同支持的文本格式；二进制存档会返回解析错误。文件与展开数据均受解析器大小上限约束。

解析器把存档日期、版本、玩家、国家标签以及 HRE 记录写成独立的快照对象。下面只列出已核对存档中的相关片段：`passed_reforms: null` 表示该字段未出现在 HRE 记录中；显式空数组 `[]` 与它不同。v1 payload 保留这三个原字段，不包含新增的七项全局状态。

```json
{
  "schema": "eu4.save_empire_snapshot.v2",
  "saved_date": "1456.4.12",
  "saved_player": "POR",
  "empire": {
    "emperor": "HAB",
    "electors": ["BOH", "BRA", "KOL", "MAI", "PAL", "SAX", "TRI"],
    "passed_reforms": null,
    "imperial_influence": "17.869",
    "imperial_ban_allowed": false,
    "internal_hre_cb": true,
    "hre_inheritable": false,
    "allows_female_emperor": true,
    "emperor_has_revoked": false,
    "imperial_realm_war": false
  }
}
```

`--observer FRA` 是操作者指定的逻辑观察方，并要求 FRA 标签存在于存档国家目录中。它不会改写存档记录中的玩家身份。例如，已核对的快照日期为 `1456.4.12`，玩家为 POR，而观察方为 FRA。`session` 对象必须恰好是 `{"type":"session"}`，不携带 live session 标识；查询 `session` 时，HRE 全局字段仍可读取，country roles 为 `not_applicable`。查询某个国家时，字段仍表示全局 HRE 记录，不表示该国自己的国家状态。如果指定国家不在存档中，字段返回 `unknown`，不会用其他来源补值。

## 查询与报告

主动查询可一次请求三个已接入字段：

```json
{
  "request_id": "hre-snapshot-001",
  "queries": [
    {
      "topic": "S01",
      "object": {"type": "session"},
      "fields": ["emperor", "electors", "reforms", "empire_status"],
      "parameters": {}
    }
  ]
}
```

也可以查询明确存在于快照中的国家对象。国家对象只用于指定和校验快照中的国家标签，返回值仍是全局 HRE 记录：

```json
{
  "request_id": "hre-country-view-001",
  "queries": [
    {
      "topic": "S01",
      "object": {"type": "country", "country": "FRA"},
      "fields": ["emperor", "electors", "reforms", "empire_status"],
      "parameters": {}
    }
  ]
}
```

报告可以复用同一查询配置：

```json
{
  "request_id": "hre-report-create-001",
  "operation": "create",
  "config": {
    "name": "神罗机制快照",
    "queries": [
      {
        "topic": "S01",
        "object": {"type": "session"},
        "fields": ["emperor", "electors", "reforms", "empire_status"],
        "parameters": {}
      }
    ],
    "detail": "brief"
  }
}
```

服务返回 `report_id` 后，可用 `information_query` 的 `report_id` 再次生成报告结果。报告仍读取同一指定存档，不会变成实时报告。历史存档没有可验证的 `session_id`、`world_id` 或单调 `game_day`，因此该来源只支持主动查询和手动报告，不支持周期或变化订阅。

## 字段含义与缺失值

| 字段 | 已知值 | 缺少记录时 | 不表达的含义 |
| --- | --- | --- | --- |
| `emperor` | 存档 HRE 记录中的国家标签 | `unknown`；不推断皇位空缺或帝国解散 | 当前 UI 可见性、皇位合法性或继承结果 |
| `electors` | 存档中显式保存的选帝侯标签列表；显式空列表可返回已知空列表 | `unknown`；缺少列表不当作没有选帝侯 | 选举权计算、选举意向或实际投票 |
| `reforms` | 存档中逐项保存的改革标识；显式空列表可返回已知空列表 | `unknown`；缺少改革键不当作改革列表已知为空 | 改革效果、改革是否适用于当前国家，或未保存改革的推断 |
| `empire_status` | 分组给出可读取的保存时全局标记及国家角色比较 | 每个子项独立返回 `unknown`；缺失或非法值不影响其他子项 | 完整帝国成员名单、规则效果、实时状态或完整 UI |

### `empire_status` 的分组值

`empire_status` 把全局 HRE 记录和查询对象的角色比较分开。`global_state` 的七项包括保存时的 `imperial_influence` 原始十进制文本，以及六个布尔标记。影响力保留字符串，例如 `"17.869"`；接口不将它转成浮点数、百分比，也不为它指定权威性单位。布尔值 `false` 是已读取的值，不是缺失。某一项为 `null`、缺失或无法解析时，只将该项标为 `unknown`，其余有效子项仍可返回。

下面的角色结果以已核对存档中的 FRA 国家查询为例；它把 FRA 标签与存档皇帝 HAB 及 7 名选帝侯比较。其他国家应按各自标签比较，不沿用示例中的布尔值。

```json
{
  "global_state": {
    "imperial_influence": {"status": "known", "value": "17.869"},
    "imperial_ban_allowed": {"status": "known", "value": false},
    "internal_hre_cb": {"status": "known", "value": true},
    "hre_inheritable": {"status": "known", "value": false},
    "allows_female_emperor": {"status": "known", "value": true},
    "emperor_has_revoked": {"status": "known", "value": false},
    "imperial_realm_war": {"status": "known", "value": false}
  },
  "country_roles": {
    "is_emperor": {"status": "known", "value": false},
    "is_elector": {"status": "known", "value": false},
    "member_of_empire": {"status": "unknown"}
  }
}
```

上面七个全局值取自已保存的 338B HRE 原始记录摘录；本轮没有重新扫描存档。MCP 验收核对了同一组值在 direct、country 和 report 结果中的一致性；示例省略了外层请求和来源元数据。

`country_roles.is_emperor` 将所查国家标签与同一快照的 `emperor` 比较；`is_elector` 将它与显式选帝侯列表比较。只有比较双方都已知时，结果才是已知的 `true` 或 `false`。没有国家对象可比较的 `session` 查询，将这两个角色标为 `not_applicable`，但仍可读取全局状态。`member_of_empire` 一直是 `unknown`：皇帝或选帝侯身份、省份的 `hre` 标记和其他角色都不构成完整的帝国成员名单。若国家标签不在快照国家目录中，对该国家的查询返回 `unknown`，不把它标为非皇帝或非选帝侯。

明确选择旧 v1 manifest 时，v1 source 仍提供原来的 `emperor`、`electors` 和 `reforms` 字段。`empire_status.global_state` 的七项在 v1 下全部为 `unknown`；即使输入对象额外带有 v2 状态键，v1 也不会据此升级为已知。若 v1 快照确实包含皇帝和选帝侯标签，国家角色比较仍可使用这两个旧字段；`member_of_empire` 仍是 `unknown`。v1 的新组合字段和 v2 的新状态值须通过各自版本化的 adapter 读取，不能混用 payload。

字段级结果会附带 `scale: 1`、`period: "saved_snapshot"`、`basis: "saved_global_empire_record"` 和 `complete: false`。已知值示例：

```json
{
  "status": "known",
  "value": "HAB",
  "unit": "country_tag",
  "scale": 1,
  "period": "saved_snapshot",
  "basis": "saved_global_empire_record",
  "complete": false,
  "runtime_effect_evaluated": false,
  "current_ui_visibility_verified": false
}
```

当快照中没有整个 `empire` 记录时，四个字段均为 `unknown`。记录存在但某个字段没有保存时，只有该字段或子项为 `unknown`，其他已读值仍可返回。改革字段保留标识，不会按标识名称猜测效果；`celestial_empire` 是另一个存档对象，其中的中国皇帝或改革不会合并进 HRE。已核对的 1456.4.12 快照记录皇帝 HAB、7 名选帝侯，HRE 对象没有 `passed_reform` 键；该存档邻近的 `celestial_empire` 改革不属于 HRE 结果。

上下文明确标记 `mode: "recorded"`，并记录存档日期、存档玩家 POR 和逻辑观察方 FRA。`game_day`、`session_id`、`world_id` 为空；这不是游戏当前状态，也不证明游戏仍载入该存档。`complete: false` 同样表示本接口只覆盖 HRE 快照子集，不表示 S01 的其他机制为空。

## 来源与验收边界

Jomini 的固定 EU4 模型包含 `empire: Option<HRE>`、皇帝 `Option<CountryTag>`、选帝侯列表和重复的 `passed_reform` 标识。HRE 快照解析器额外保留列表字段是否出现：缺失的选帝侯或改革字段为 `unknown`，显式空列表才是已知空值。这个存在性区别很重要，因为通用 Jomini `Vec` 模型会把重复字段缺失折叠为空列表。

本次核对没有验证游戏实时界面、当前会话中的 HRE 记录、皇帝介入条件、宗教联盟或改革效果。字段来源盘点见[神罗快照盘点报告](../../../../work/runtime/information-empire-snapshot-20261102-001/inventory-002/report.json)。

### 本批验证记录

第111批的 v1 解析器对这份允许使用的存档完成了一次实际读取并以 exit 0 结束，结果为皇帝 HAB、7 名选帝侯、改革字段 `null` 和 1379 个国家标签；77 项来源 pin 在读取前后保持稳定。构建成功，Cargo 五项测试通过。初次编译缺少 trait 实现、第一次 CLI 在进入解析器前因路径检查失败的原件均保留；它们不是本次成功解析的输入。这些结果只验证 v1 payload，不验证本节新增的 `empire_status`。

组件测试初次运行有 15 项中的 4 项失败。修复 `passed_reforms` 映射并调整 C01 边界后，受影响的 4 项在 [attempt-003](../../../../work/runtime/information-saved-empire-20261102-001/empire-tests-001/attempt-003/receipt.json) 全部通过；独立 factory 的 11 项也通过，见 [run-002](../../../../work/runtime/information-empire-snapshot-20261102-001/factory-tests-001/run-002/receipt.json)。这些定向结果不代表完整 bridge 回归通过。

第111批 MCP 首次运行的收据仍为失败：检查器预期 `unsupported_trigger`，实际 JSON-RPC 响应是 `-32602`，原因是历史存档没有 `session_id`。client exit 1，server exit 0，reader 已停止；聚合峰值为 102,113,280 字节。随后只用同一批原始结果做了离线重核，没有重发查询。重核确认 direct 六字段结果、country 三字段结果和报告结果相符；`emperor`、`electors` 来自快照，`reforms` 为 `unknown`，S01 其余三个原有字段仍为第111批时的 planned/unsupported。周期请求按无会话边界被拒绝，数据库只有一份报告、没有订阅。由于 final discovery/public list 没有完成，这次不标记为完整 MCP 通过。离线重核记录及原始 MCP 收据分别见[重核报告](../../../../work/runtime/information-empire-snapshot-20261102-001/mcp-reconciliation-001/report.json)和[初次 MCP 收据](../../../../work/runtime/information-empire-snapshot-20261102-001/mcp-001/receipt.json)；重核报告 SHA-256 为 `fba0c79607e0e7b7564ec46617ff6eee066ff082ea26a8837f01ccbc129b6a94`。

第111批没有读取或修改 live 游戏状态。MCP 启动的 Rust 子进程没有单独采样内存，因此聚合峰值不能解释为该子进程的独立峰值；完整 bridge 回归也未通过，最后一次完整回归仍有 141 项既有失败。第111批配置记录为 62 available、212 partial、123 planned、53 callable，共 74 个主题和 397 个字段。
