# 宗属关系信息接口

`NativeSubjectRelationSource` 为信息服务提供 R02「宗主与属国关系」的选定国家对查询。它包装现有 `DiplomacySource`，通过 `DiplomacyTools.inspect_diplomatic_action` 读取 `offer_vassalization` 的公共关系投影。当前实现只证明请求中明确给出的一个 country pair；它不声称返回完整属国列表、全部属国类型，也不把一个选定国家对的无关系结果推广为全局无关系。

R02 的目录项本身可路由，三个字段的 coverage 为 `partial`：`overlord`、`subject` 和 `subject_type`。字段值只在公共投影完成方向、关系状态和类型检查后产生。

## 查询合同

R02 使用成对对象，actor 是本次观察方，recipient 是显式指定的另一个国家：

```json
{
  "topic": "R02",
  "object": {
    "type": "country_pair",
    "actor": "FRA",
    "recipient": "ORL"
  },
  "fields": ["overlord", "subject", "subject_type"],
  "parameters": {}
}
```

当前已核对的实时上下文限定 `actor=FRA`。actor 必须等于基础 context 的 observer，recipient 必须是不同的三字母国家标签；`parameters` 必须为空对象。这个限制说明数据的观察方和关系方向，不能通过把 actor 改成其他国家来查询另一观察方的关系。

inspection 的原生身份固定为：

| 项目 | 要求 |
| --- | --- |
| `action_id` | `offer_vassalization` |
| `family` | `vassalization` |
| `phase` | `initiate` |
| pair 方向 | `actor` 与 `recipient` 必须和查询对象相同 |
| 关系状态 | `relationship_state.complete=true`，且嵌套与顶层 `vassal_active` 相同 |

适配器还要求 `vassal_state_verified=true`，并要求 `actor_is_overlord`、`actor_is_subject` 是严格的布尔值。激活关系时两个角色必须恰好有一个为真，`subject_type` 必须是受限 ASCII 标识；否则三个字段均为 `unknown`。

## 返回值与无关联状态

当 FRA→ORL 的投影显示关系激活、FRA 为宗主方时，结果为：

```json
{
  "fields": {
    "overlord": {"status": "known", "value": "FRA"},
    "subject": {"status": "known", "value": "ORL"},
    "subject_type": {"status": "known", "value": "appanage"}
  },
  "complete": true
}
```

当 FRA→PAP 的同一原生投影确认该选定 pair 没有宗属关系时，三个字段分别返回：

```json
{
  "status": "not_applicable",
  "reason": "SELECTED_PAIR_HAS_NO_VASSAL_RELATION"
}
```

这里的 `not_applicable` 表示“该明确选定的国家对没有可适用的宗主、属国或属国类型字段”。它不是 `unknown`，也不是“世界中不存在任何宗属关系”的断言。若关系角色冲突、类型缺失、公共 projection 身份不一致，适配器返回 `unknown`；基础会话未就绪、inspection 不可用或调用失败时返回 `unavailable`。

## 上下文保护与采样范围

读取前和原生 inspection 返回后，适配器重新取得基础 context。context 必须满足 `status=ready`、`mode=live`、`complete=true`、`observer=FRA`、游戏版本 `1.37.4`、EXE SHA-256 `b23fa0e1f698d31b01cdd1c3817a675805d8c6286cb66f9c231e6e2a42544d77`、有效 DLL SHA-256、非空 `session_id`，并且 `game_date` 与 `game_date_raw` 都是相同整数。调用前提供的 context 也必须与刚取得的基础 context 相同；调用前后任一身份字段变化，结果就标为不可用或未知，不沿用旧关系。

R02 目录声明 `query`、`periodic` 和 `change` 三种触发方式。它们表示对这个明确 pair 重新采样并比较状态；`poll_events` 返回空列表，不能被解释为完整、无丢失的外交关系事件流。R02 仍是选定 pair 的 partial 字段来源，不提供全世界属国枚举、关系历史、权限集合或世界代际。

查询调用已加载 DLL 中的只读 native predicates，所以这条路径不是纯 RPM。它没有外交提交、执行、日期推进、保存重载或游戏启动分支；业务动作不会因为读取 R02 而发送给游戏。

## 证据与限制

真实记录 [information_country_relations_live_1374.json](../../../../bridge/tests/fixtures/information_country_relations_live_1374.json) 保存了 native-public-001 的两个 selected pair：FRA→PAP 为 inactive，FRA→ORL 为 active appanage；两者均使用 `offer_vassalization`，并保留公共与 native capture 的来源 SHA。`live-acceptance-001/report.json` 通过了 pair 投影、字段合并、3 次 periodic 交付以及暂停/玩家/日期不变检查。

独立存档核对 [save-crosscheck-002.json](../../../../work/runtime/information-country-relations-20261024-001/save-crosscheck-002.json) 在固定 R70 存档中找到 FRA/ORL 的 `appanage` dependency，并核对 FRA prestige raw `-11643`。它是 recorded 存档证据，不是 live fallback；`world_generation_verified=false`，所以不能据此补充未实现的全局关系或代际字段。早期 `save-crosscheck-001` 的字段名错误仍保留为失败历史，不作为当前接口依据。

更完整的国家资源合同、N06 raw/1000 语义和上下文核对 见[国家资源信息接口](../国家与国内/国家资源信息接口.md)。
