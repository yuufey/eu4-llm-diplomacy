# 宗教身份与机制声明接口

第167批把原生宗教配置 key 接入 `S02.faith`、`S02.religion_group`，并新增 `S02.mechanics` 的配置声明查询。逻辑观察方仍为非玩家法国，物理玩家为葡萄牙；法国、英国的实际 key 都是 `catholic / christian`。显示名仍为“天主教 / 基督教”，不参与 key 的推断。

三个字段均为 `partial=true`、`complete=false`，支持查询、手动报告和周期订阅。机制字段当前提供准确原生身份和配置文件中的声明；动态机制状态、条件求值和实际应用效果没有因此变成已知。

## 请求与结果

```json
{
  "topic": "S02",
  "object": {"type": "country", "country": "FRA"},
  "fields": ["faith", "religion_group", "mechanics"],
  "parameters": {}
}
```

`faith` 原有的 `primary_religion_name`、`icon_frame_request` 和 `religion_group` 原有的 `religion_group_name` 保留。已确认身份时，两者的 `value.identity` 为：

```json
{
  "status": "known",
  "religion_key": "catholic",
  "religion_group_key": "christian"
}
```

`mechanics.value` 还包含：

| 成员 | 含义 |
| --- | --- |
| `identity` | 本次只读采集的准确宗教和宗教组 key |
| `religion_rules` | 对应宗教的配置 AST、相对文件/行号、文件 SHA 和来源 pins |
| `group_rules` | 对应组的组级声明；排除该组下的其他宗教定义，保留宗教学校等组级声明 |
| `runtime_state` | 当前为 `unknown / RELIGION_MECHANIC_STATE_NOT_READ` |
| `conditions_evaluated`、`effects_executed` | 均为 `false` |

每份已知规则另带 `static_semantics`，明确条件、效果和运行时机制状态都未执行或观察。规则值保留脚本原始语法，不把声明中的修正数值解释成国家当前已应用数值。

实际天主教声明包括 `country`、`country_as_secondary`、`on_convert`、`papacy` 等；基督教组声明包括 `defender_of_faith`、`can_form_personal_unions`、`center_of_religion` 等。它们说明配置文件声明了什么，不证明当前国家是信仰守护者、当前教廷状态或当前可以联姻。

## 名称与身份的关联校验

名称和 key 使用各自已验证的只读采集。仅有相同的国家、会话和日期不足以把两份结果拼在一起，因为暂停时也可能改宗。

组合来源因此比较采集中的国家完整引用、模块、国家对象和主宗教对象的绑定摘要；宗教组名称还要比较组对象的摘要。摘要只包含 SHA-256，不公开内存地址。只有摘要相同，名称值才附加已知 identity；摘要缺失时返回 `RELIGION_NAME_IDENTITY_UNVERIFIED`，有效摘要不同则返回 `RELIGION_NAME_IDENTITY_CHANGED`，该名称字段不发布值。独立的机制身份与规则字段仍可保留其已验证结果。

如果原生 identity 本身未知，旧名称投影仍可独立返回名称，并把其 identity 标为未知。多个采集和绑定摘要比较仍不构成主线程原子快照；读取新鲜度限于采集时点。

## CWTools 复用

`ReligionDefinitionIndex` 继续复用固定 CWTools 解析器和既有有效游戏/MOD 文件解析器。本批在 `lookup()`、`lookup_group()` 之上新增：

```python
index.definition("catholic")
index.group_definition("christian")
```

它们返回完整静态声明 AST、相对来源及配置/定义/解析器/CWT pins。声明序列化复用现有改革定义 AST 实现，限制 32,768 节点、64 层和 2 MiB JSON；重复、坏节点、坏运算符、输入变化和超限都拒绝为未知。公开投影再次检查 key 精确相等、来源路径和 pins，以及非执行标志。

实际配置目录解析出 28 个宗教、7 个宗教组。文件仍为 `common/religions/00_religion.txt`，SHA-256 `609e2d235f3441c64b895d9faf3927bbf1399149cffa955137ab2d070b9645a6`。组合来源只在需要 `mechanics` 时建立定义索引，并缓存输入未变化的规则；索引失效后不会继续使用旧规则。如果配置定义中的组与原生组不同，规则保持未知，不修改原生 key。

这些是当前配置文件及 MOD 覆盖后的声明。配置文件是否与游戏已载入的全部定义完全一致尚未另行证明，因此机制字段保留相应缺口。
