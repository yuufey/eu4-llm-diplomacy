# 路径配置与换电脑迁移

本机路径统一放在项目根目录的`local.env`。Python入口使用`work/local_config.py`，PowerShell入口使用`work/native/import-local-env.ps1`。两者优先采用进程环境变量，随后读取本地文件。Git忽略实际的`local.env`。

## 获取源码与依赖

新电脑使用递归克隆取得固定提交的第三方源码。已有克隆执行第二条命令。

```powershell
git clone --recurse-submodules https://github.com/yuufey/----4.git
git submodule update --init --recursive
```

使用64位Python 3.11或更新版本，安装测试依赖并创建本地配置。

```powershell
python -m pip install -r requirements-dev.txt
Copy-Item local.env.example local.env
```

编辑local.env填写实际路径。路径可包含空格和中文，相对路径以仓库根目录为基准，可使用`%USERPROFILE%`等环境变量。命令行显式提供的路径参数优先于配置默认值。

## 配置项

| 配置项 | 用途 |
| --- | --- |
| EU4_GAME_ROOT | 包含eu4.exe的游戏安装目录 |
| EU4_USER_DATA | 包含mod、dlc_load.json、logs和save games的用户目录，可填写实际Documents或OneDrive目录 |
| EU4_PYTHON | PowerShell启动脚本调用的64位Python可执行文件 |
| EU4_CXX | MinGW-w64的g++.exe，供现有原生构建脚本使用 |
| EU4_OBJDUMP | 静态分析使用的objdump.exe |
| EU4_DOTNET | .NET 8 SDK的dotnet.exe或所在目录，已加入PATH时可省略 |
| EU4_NUGET_PACKAGES | 可选的NuGet包缓存目录，供离线构建使用；显式NUGET_PACKAGES环境变量优先 |
| EU4_VCVARS64 | Visual Studio的vcvars64.bat，MSVC测试入口也支持vswhere发现 |
| EU4_NATIVE_TEXT_CODEC | 支持的EU4dll文本补丁使用eu4_escape，原始UTF-8环境使用utf8 |
| EU4_CRASH_DUMP | 可选的崩溃转储默认路径 |

PowerShell也可只通过进程环境变量配置。需要某个工具时，由对应入口报告缺少的配置项。

## CWTools解析器

安装.NET 8 SDK并配置EU4_DOTNET后执行以下构建命令。

```powershell
python tools/build_cwtools_parser.py
```

构建沿用packages.lock.json中的包版本。产物和本地清单写入被忽略的work/deps目录，正常信息入口随后使用本地产物。首次构建需要NuGet访问或相应包缓存。版本化清单记录源码与依赖合同，本机SDK位置由local.env提供。

## 迁移兼容问题

| 问题 | 处理方式 |
| --- | --- |
| 用户名、盘符、仓库位置变化 | local.env配置游戏、用户数据和工具路径，入口从自身位置定位仓库 |
| Documents被OneDrive重定向 | EU4_USER_DATA填写实际目录，模组安装器使用该配置 |
| Python与PowerShell覆盖顺序不一致 | 统一采用进程环境优先，并按仓库根目录解释配置中的相对路径 |
| Visual Studio版本、版本类型和安装位置不同 | 使用EU4_VCVARS64或vswhere定位构建环境，并安装C++ x64工具和Windows SDK的UCRT头文件及库 |
| 新克隆的第三方目录为空 | .gitmodules提供来源，递归克隆或submodule update取得固定提交 |
| CWTools私有SDK和编译产物缺失 | 使用本机.NET SDK及锁定依赖重新构建 |
| 自动换行改变受散列检查的文件 | .gitattributes保留检出字节，CWTools规则按相同文本接纳LF和CRLF |
| 旧PID、进程创建时间及安装记录失效 | 新电脑启动游戏后生成新的安装记录，信息服务显式接收新的operator-session |
| 编译器变化导致DLL布局及散列不同 | 使用release/diplomacy-observer-v64-1374.zip中的已验证构建，或为新构建提供相应布局支持 |
| 游戏版本及启用模组不同 | 使用对应版本的构建与读取布局。信息模块实机交付依据为1.37.4，远端V32交付依据为1.37.5 |
| 原生文本补丁不同 | 按实际安装配置EU4_NATIVE_TEXT_CODEC，再生成安装记录 |
| 旧存档或历史实验文件缺失 | 当前运行选择新电脑的存档，重现实验时按历史记录提供输入文件 |
| 远端V32执行依赖未随提交提供 | 保留接口合同和原始记录，重建完整宿主需要原交付提供运行时模块及构建 |

原生注入、游戏控制和构建需要Windows x64及对应工具链。游戏可执行文件的版本校验按具体后端执行。V32依赖范围见[统一接口合同](../外交操作/接口/关系与外交/unified-diplomacy-operations-1375.md)。

## 当前观察器便携构建

`release/diplomacy-observer-v64-1374.zip`包含当前已验证的v64 DLL、206项构建源码和可迁移清单，旁附SHA-256文件。解压后可将该清单交给现有安装入口，在新电脑的游戏进程中生成新安装记录。

```powershell
Expand-Archive release/diplomacy-observer-v64-1374.zip work/runtime
python tools/start_diplomacy_observer.py --pid <当前游戏PID> --manifest work/runtime/diplomacy-observer-portable-v64/build-manifest.json
```

该构建对应EU4 1.37.4的既有FRA非玩家观察场景。清单使用相对文件名，DLL和源码保持原构建字节。ZIP按已有打包器的`--observer-manifest`与`--output`参数生成。

## 验证配置

运行pytest前创建临时目录并设置保留策略入口。

```powershell
New-Item -ItemType Directory -Force work/tmp
$env:PYTEST_DEBUG_TEMPROOT = (Resolve-Path work/tmp).Path
python -m pytest tests/test_local_config.py tests/test_diplomacy_operations.py bridge/tests/test_information_cwtools_rules.py bridge/tests/test_information_cwtools_script.py -q
python tools/serve_information.py --help
python tools/diplomacy.py --help
```

当前运行现场统一见logs/CURRENT.md。历史日志中的绝对路径用于追溯当时证据，重新运行时使用当前配置和新安装记录。
