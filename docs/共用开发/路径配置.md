# 路径配置与换电脑迁移

以下命令在 Windows x64 的 PowerShell 中运行。准备 64 位 Python 3.11 或更新版本，以及 EU4 1.37.4。本项目按 `eu4.exe` 的 SHA-256 校验兼容性。同为 1.37.4 的不同可执行文件也需确认与所用构建匹配。首次安装时，在游戏中创建一个本地测试存档。

## 获取仓库

```powershell
git clone --recurse-submodules https://github.com/yuufey/eu4-llm-diplomacy.git
Set-Location eu4-llm-diplomacy
Copy-Item local.env.example local.env
```

已有本地克隆时，从仓库根目录运行 `git submodule update --init --recursive` 补齐第三方源码。有 `local.env` 时，直接编辑已有文件。

## 设置本机路径

编辑仓库根目录的 `local.env`，将下表中的值改为本机路径。

| 配置项 | 填写内容 |
| --- | --- |
| `EU4_GAME_ROOT` | 包含 `eu4.exe` 的游戏安装目录。 |
| `EU4_USER_DATA` | 游戏实际使用的用户数据目录，里面有 `save games` 和 `logs`。通常在 `Documents\Paradox Interactive\Europa Universalis IV`，使用 OneDrive 重定向时填写重定向后的目录。 |
| `EU4_PYTHON` | 64 位 `python.exe` 的完整路径，供 PowerShell 辅助脚本调用。可用 `python -c "import sys; print(sys.executable)"` 查看。 |

路径可以含空格和中文。相对路径以仓库根目录为准，也可使用 `%USERPROFILE%`。同名进程环境变量优先于 `local.env`。`local.env` 只保存在本机。

在仓库根目录运行下列命令，确认配置能找到游戏程序和存档目录。输出应为 `True True`。

```powershell
python -c "from work.local_config import game_exe, user_data; print(game_exe().is_file(), (user_data() / 'save games').is_dir())"
```

配置结束后，用测试存档安装观察器并读取一次实时局势。[连接游戏与复现流程](人工实验与日志读取流程.md)

## 按需配置的工具

| 用途 | 配置或命令 |
| --- | --- |
| 从当前源码构建观察器 | 将 `EU4_CXX` 指向 64 位 MinGW-w64 的 `g++.exe`。构建命令见[连接游戏与复现流程](人工实验与日志读取流程.md)。 |
| 渲染或导出政治地图 | `python -m pip install -r requirements-map.txt` |
| 运行项目测试 | `python -m pip install -r requirements-dev.txt`。该文件也会安装地图依赖。 |
| 构建 CWTools 解析器，读取任务定义等静态资料 | 安装 .NET 8 SDK，运行 `python tools/build_cwtools_parser.py`。SDK 未加入 `PATH` 时，将 `EU4_DOTNET` 指向 `dotnet.exe` 或其目录。构建使用锁定的 NuGet 依赖，产物写入 `work/deps/`。可用 `EU4_NUGET_PACKAGES` 指定已有缓存。 |
| 使用原生分析或 MSVC 测试工具 | `EU4_OBJDUMP` 指向 `objdump.exe`，`EU4_VCVARS64` 可指向 `vcvars64.bat`，`EU4_CRASH_DUMP` 可指定待分析的崩溃转储。 |

观察器默认按 UTF-8 解读游戏文本。使用受支持的 EU4dll 文本补丁时，可按实际环境设置 `EU4_NATIVE_TEXT_CODEC=eu4_escape`。
