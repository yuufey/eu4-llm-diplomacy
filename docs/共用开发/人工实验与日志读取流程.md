# 连接游戏与复现流程

这套流程用本地测试存档启动 EU4，随后通过统一游戏服务读取一次当前游戏日期。读到的日期与游戏界面一致，就可以继续在 MCP 客户端中查询局势和预览外交操作。先完成[路径配置](路径配置.md)，以下命令均从仓库根目录在同一个 PowerShell 窗口运行。

## 选择观察器构建

观察器是统一游戏服务读取游戏和提交外交操作时使用的 DLL。安装器根据 `build-manifest.json` 核对 DLL、构建材料和游戏程序。请保留构建清单和同目录的文件。

**使用仓库自带的便携包。** 这是较早交付的 EU4 1.37.4 v65 构建，适合复现该版本已有的信息读取和外交能力。近期增加的原生功能以当前源码构建为准。[便携包验收范围](../../logs/2026-11-16信息导出与统一接口GitHub交付.md)

```powershell
$portableRoot = 'work/runtime/portable-' + [guid]::NewGuid().ToString('N')
Expand-Archive -LiteralPath release/diplomacy-observer-v65-1374.zip -DestinationPath $portableRoot
$manifest = Join-Path $portableRoot 'diplomacy-observer-portable-v65/build-manifest.json'
```

**从当前源码构建。** 如需复现当前源码中的功能，先在 `local.env` 配好 `EU4_CXX`。构建脚本会把 DLL 和清单写入新的运行目录。

```powershell
New-Item -ItemType Directory -Force work/runtime | Out-Null
$experiment = 'observer-' + [guid]::NewGuid().ToString('N')
& .\work\native\build-diplomacy-observer.ps1 -NativeCountryControl -Experiment $experiment
$manifest = "work/runtime/$experiment/build-manifest.json"
```

两种方式均要求受支持的 EU4 1.37.4 可执行文件。安装前可以对照本机 `eu4.exe` 的 SHA-256 与清单中的 `game_sha256`。如果游戏文件与便携包不匹配，请先确认所用的游戏构建。用当前机器重新编译也仍然要求游戏与源码使用的地址布局兼容。

## 载入测试存档并安装

### 使用便携包

启动 EU4，在游戏界面载入本地测试存档，确认成就提示，并暂停游戏。保持只有一个 EU4 进程，然后安装观察器。

```powershell
$gameProcess = Get-Process -Name eu4 -ErrorAction Stop
python tools/start_diplomacy_observer.py --pid $gameProcess.Id --manifest $manifest
$installation = Join-Path (Split-Path -Parent $manifest) 'installation.json'
```

安装成功时，安装器会返回 `installed: true`。再次使用便携包时，重启游戏并解压到新的运行目录，因为安装器会保留已经生成的安装记录。

### 使用源码构建

先正常退出已打开的 EU4，然后把下面的路径改成自己的本地测试存档。载入工具会启动游戏、处理成就提示、安装观察器，并核对当前玩家、日期和暂停状态。

```powershell
$save = 'C:\path\to\test-save.eu4'
python tools/load_observer_save.py --save $save --manifest $manifest
```

成功时，最后一行 JSON 会给出 `date`、`player`、`paused` 和 `installation`。将 `installation` 的值填到下一步。这个路径指向本次进程的 `installation.json`。每次重开游戏都会生成一份新记录。

如果测试局已在游戏中载入并暂停，也可以沿用便携包一节的安装命令，将所用清单换成源码构建的清单。

## 读取一次实时游戏日期

如果使用了自动载入工具，把输出中的 `installation` 路径保存到 `$installation`，例如 `$installation = 'work/runtime/load-observer-.../installation.json'`。如果用的是手动安装命令，沿用已设置的 `$installation`。

`$country` 填测试局中实际存在的三位国家标签，例如奥斯曼 `TUR` 或英国 `ENG`。即使存档以观察者席位打开，也可以选择局内一个实际国家。下面的查询只读，但服务会将观察国作为该连接的默认外交控制国，观察器可能暂停该国的原生自动外交。

```powershell
$country = 'TUR'
$database = 'work/runtime/getting-started/information.sqlite3'
$journal = 'work/runtime/getting-started/diplomacy.sqlite3'
$request = @{
  tool = 'information_query'
  arguments = @{
    request_id = 'quickstart-' + [guid]::NewGuid().ToString('N')
    queries = @(@{
      topic = 'C01'
      object = @{ type = 'session' }
      fields = @('game_date', 'observer', 'session_id')
    })
  }
} | ConvertTo-Json -Depth 8 -Compress

$request | python tools/serve_information.py --jsonl `
  --operator-session $installation --observer $country `
  --database $database --journal $journal
```

检查返回结果中的 `game_date` 与游戏界面相符，`observer` 与所填国家一致。如果查询返回来源不可用，先确认游戏仍停在已载入的测试局，并核对 `--operator-session` 指向本次进程的安装记录。安装失败时，可在对应运行目录中查看 `control-probe.jsonl`（若已生成）及命令行报错。

## 在 MCP 客户端中使用

让客户端从仓库根目录启动 `python tools/serve_information.py`，沿用上面的安装记录、观察国、信息数据库和外交账本参数。用于命令行查询的 `--jsonl` 参数在 MCP 模式下省略。调用外交工具前，可先在工具列表中查看当前构建开放了哪些能力，并预览目标操作的条件。提交操作后，可用原请求编号和同一份外交账本回查结果。[统一游戏服务使用说明](统一游戏服务使用说明.md) · [功能概览](../功能概览.md)
