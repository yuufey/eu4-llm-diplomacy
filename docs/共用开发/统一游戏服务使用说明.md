# 统一游戏服务使用说明

本服务为LLM提供信息查询、报告、订阅和外交操作。启动入口为`tools/serve_information.py`，示例命令从项目根目录运行。

## 工具注册与调用

服务默认注册 13 个工具，并根据当前会话注册可用的召回、时钟和地图工具。默认通过 MCP 标准输入输出通信，添加 `--jsonl` 可接收逐行的 `{"tool": ..., "arguments": ...}` 请求。9 个信息工具的参数见[信息接口使用说明](../信息导出/接口/信息接口使用说明.md)。政治地图的渲染、点选和定期导出见[地图导出接口使用说明](../地图功能/地图导出接口使用说明.md)。以下是默认的外交工具。

| 工具 | 用途 |
| --- | --- |
| `list_diplomatic_actions` | 查询外交行动目录、参数和当前会话的能力 |
| `inspect_diplomatic_action` | 查询具体方案的条件、接受因素和可执行状态 |
| `execute_diplomatic_action` | 向游戏提交一次外交操作 |
| `get_diplomatic_result` | 按原请求编号读取执行状态和结果 |

支持按 ID 召回的 DLL 会为已绑定控制国的连接额外注册 `recall_diplomat`。从 `N05.diplomat_tasks` 取得 `diplomat_id` 后，提交该 ID 和唯一的 `request_id`。服务只在本轮控制国的外交官中查找。引擎确认任务结束后，结果会标明该外交官正在返回或已经空闲。用 `get_diplomatic_result` 和原编号复查结果。

### 游戏时钟控制

`set_game_speed` 默认关闭。操作者绑定安装会话并传入 `--allow-time-control` 后，服务核验当前玩家席位和原生桥的时钟能力。核验通过时，工具会出现在 `tools/list` 中。传整数 `speed`，用 `0` 暂停全局时间，用 `1` 至 `5` 恢复并设为游戏界面对应的档位。游戏确认后，工具返回 `status="applied"`、有效 `speed`、布尔值 `paused` 和原始游戏日期 `game_date_raw`。

每次调用都核对当前帧心跳是否仍报告安装记录中核验过的玩家席位。随后，DLL 在游戏线程上重新验证当前席位和服务器状态。若游戏未确认所请求的状态，工具返回 `game_time_unconfirmed`，操作者需核对游戏状态。关闭服务并在游戏暂停时去掉 `--allow-time-control` 重连，即可撤销该工具的权限。运行配置和 DLL 请求目录由操作者写入。要把模型的游戏操作限制在 MCP 内，客户端也需限制 Shell、桌面和运行目录访问。

通过下文的`--operator-session`和`--journal`连接时，信息读取与外交操作复用同一个`ObserverSession`、`DiplomacyTools`及外交请求账本。游戏采集与外交调用共用采集锁，后台订阅轮询在操作期间让出，操作返回后可继续查询受影响的状态。游戏动作的适用版本、国家和原生执行条件由既有外交组件检查。

例如，通过JSONL查询法国对萨伏依获取人情的当前条件。

```json
{"tool":"inspect_diplomatic_action","arguments":{"action_id":"curry_favors","actor":"FRA","recipient":"SAV"}}
```

执行工具另需`request_id`，支持`phase`和`parameters`，其默认值和行动参数沿用外交接口。执行会改变真实游戏状态。查询结果使用`get_diplomatic_result`并传入原请求编号，随后可调用`information_query`复查外交官、任务或相关关系。相同请求编号的重复调用、参数冲突和会话冲突由共享账本按原规则处理。

MCP 的 `tools/list` 在初始化后返回当前连接的工具定义。离线、历史记录和 `--battle-only` 模式保留 13 个默认定义，外交调用返回 `source_unavailable`。指定时钟权限但无法核验安装记录或 DLL 能力时，服务继续启动，时钟工具从目录中省略。原生接管国集合未获确认时，服务继续提供信息查询、外交预览及账本回读，并从目录中省略执行和召回工具。外交目录与预览会报告执行权限不可用。服务退出时先结束后台轮询，再关闭信息服务及共享账本。

## 启动与连接

### 调用方与控制国

操作者通过启动参数为LLM指定身份和控制国。`--owner`同时作为信息存储命名空间和外交请求调用方身份，`--controlled-country`指定该连接允许作出外交决定的国家。省略控制国时沿用`--observer`，两个参数都省略时，外交操作保持只读连接的权限范围。

直接从 Python 使用 `ObserverSession` 和 `DiplomacyTools` 时，也需要由操作者显式指定控制国，例如以 `ObserverSession(installation, game_exe, controlled_country="ENG")` 创建会话。没有控制国时，外交预览、执行和受保护的账本记录读取会抛出权限错误；安装记录中的物理玩家不会自动成为控制国。对于指定了调用方身份的记录，应使用对应的 `DiplomacyControl` 读取，不能仅靠国家相同取得其他调用方的记录。

`--observer` 指定信息查询的观察视角。各来源按该视角和自身的可见性范围提供数据。运行时心跳中的实际玩家席位用于确认当前游戏世界已载入且稳定。通用会话健康检查要求连续两条有效心跳报告相同席位，时钟控制和存档确认另行核对安装或存档声明的席位。

例如，英国模型使用`--owner england-agent --controlled-country ENG --observer ENG`。主动发起和撤回按发起国检查权限，接受或拒绝入站提议按实际回应国检查权限。发起者是法国、接收者是英国的提议，可以由英国模型代表英国回应。提议编号、双方和原生决策国仍需匹配。

`--managed-countries`配置同一游戏进程中由服务接管的完整国家集合。集合最多包含32个实际存在的国家，支持字母数字组成的三位国家标签。它决定原生自动外交行为的拦截范围，每个LLM连接的操作范围仍由各自的`--controlled-country`决定。单国服务省略集合参数即可，默认集合包含该控制国。多个连接共享游戏时，应由操作者提供相同的完整集合，并为每个模型设置各自的身份和控制国。

```powershell
python tools/serve_information.py `
  --operator-session work/runtime/<installation>/installation.json `
  --database work/runtime/information-service/information.sqlite3 `
  --journal work/runtime/information-service/diplomacy.sqlite3 `
  --owner england-agent --observer ENG --controlled-country ENG `
  --managed-countries ENG FRA
```

受控国家配置通过`EU4CONTROL1`协议绑定游戏会话及递增版本号，DLL确认完整国家集合后，服务才开放相应操作。配置保存在原生会话内，短暂脚本退出后继续生效。新版国家配置需要具备`native_country_control_configuration`能力的DLL，旧DLL的既有法国单国范围可继续连接。信息字段的版本、观察方和可知范围由各来源的能力发现结果提供。

新外交请求同时保存调用方身份和实际决策国，回读及重复执行校验这些归属。旧账本记录保留原编号、状态和证据，按原动作双方及阶段推导决策国，允许相符国家回读。旧记录没有调用方证据时，字段继续保留为空。

这些启动参数由操作者设置。模型工具的公开参数只描述行动与对象，服务根据已配置身份检查请求。

在不绑定游戏观察会话时，服务仍可用于发现接口和管理离线配置。此时能力目录会明确标记来源尚未就绪。

```powershell
python tools/serve_information.py --database work/runtime/information-service/information.sqlite3
```

需要使用已经核对过的观察会话时，同时提供安装记录和外交日志数据库。继续查询已有操作结果时，`--journal`使用原动作账本的路径，示例中的路径按实际替换。

```powershell
python tools/serve_information.py `
  --database work/runtime/information-service/information.sqlite3 `
  --operator-session work/runtime/<installation>/installation.json `
  --observer FRA `
  --journal work/runtime/information-service/diplomacy.sqlite3 `
  --tick-seconds 2
```

如果只需要读取已经保存的历史记录，可以显式指定记录清单或归档文件。

```powershell
python tools/serve_information.py `
  --database work/runtime/information-service/information.sqlite3 `
  --recorded-manifest work/runtime/<recorded>/manifest.json
```

`--recorded-manifest`与`--operator-session`互斥。省略这两个参数时，实时来源保持未就绪，仍可发现目录、管理配置，并使用另外启用的静态规则来源。各信息来源的额外配置见[信息来源配置](../信息导出/接口/信息接口使用说明.md#信息来源配置)，原生组件的安装见[DLL安装与更新](DLL安装与更新.md)。
