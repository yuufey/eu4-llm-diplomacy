# HTTP 拒绝请求时的连接处理

2026-10-25，第十四批修复了只读观察服务和 TAG 命令服务在拒绝未授权请求时的请求体清理。鉴权、路由、状态码和业务 JSON 保持原有含义。未授权请求仍被拒绝，清理过程不会解析命令，也不会调用 observe、publish 或写出请求文件。

## 问题与修复

第十三批完整回归两次出现 `ConnectionAbortedError [WinError 10053]`，客户端在读取 HTTP 状态行时失败。旧 Observer 的 `refuse_write()` 只在授权成功时读取小请求体；旧 TAG 服务在鉴权失败后直接返回403。两个客户端测试都会先发送带 `Content-Length` 的 body，因此拒绝分支关闭连接时可能仍有未读取的入站数据。源码与失败位置支持这个时序解释；本批没有抓包，不能把异常本身称为已直接观察到 TCP RST。

新 [http_rejection.py](../../bridge/http_rejection.py) 只清理能够明确界定的小请求体，然后让调用方返回原来的拒绝。Observer 对授权与未授权的 POST、PUT、PATCH、DELETE 都使用该函数，状态分别仍为405或403。TAG 服务只在鉴权失败分支使用它，仍返回403。原有正常请求处理没有改用此函数。

## 固定读取边界

| 条件 | 处理 |
| --- | --- |
| 恰好一个ASCII十进制 `Content-Length`，数值不超过65536 | 最多读取所声明的字节数 |
| 缺失、重复、非法、超长或超过上限的长度 | 跳过清理 |
| 存在任意 `Transfer-Encoding` 或 `Expect` 头，包括空值 | 跳过清理，不尝试解释分块或继续发送协议 |
| 合法长度为0 | 不读取 body |
| 分片或缓慢发送 | 每次 `read1()` 最多8192字节，共用开始时确定的0.2秒截止时间 |
| 读取超时、失败或提前EOF | 停止清理，仍由调用方尝试返回原拒绝 |

读取前保存 socket timeout，结束时恢复。上限和截止时间是代码常量，函数不接受能够放大它们的参数。它既不解析JSON，也不将清理成功视为鉴权成功。对于未知 framing、超限或未及时发完的 body，不承诺已经全部消费。

## 验证范围

[helper 测试](../../bridge/tests/test_http_rejection.py)覆盖不透明分片数据、单次和总字节预算、读取异常、绝对截止及超时恢复。截止测试在第一片成功后推进时钟，确认后续不再读取，而不只是用第一次读取就抛异常来代替截止检查。非法长度和未知 framing 验证不读取请求体。

两个服务的实际 HTTP 测试重复发送小 body，检查完整403 JSON，并核对没有 observe 调用或请求文件。HTTP 专项为36 passed、113 subtests，见[最终专项报告](../../work/runtime/information-http-rejection-20261025-001/report-002.json)。完整回归及归档状态以本批最终测试摘要和来源审计为准；专项通过不能替代整套回归。

本修复没有访问游戏或重放外交请求。第十三批的失败日志、定向诊断和未通过归档记录继续保留；新的结果不覆盖旧证据。
