首次整理于2026-11-07，2026-11-08补充执行约束。用户要求整理本次复盘并恢复开发。后续按[当前开发计划](../信息导出与订阅开发计划.md)推进，以“信息支持宏观战略决策”为取舍原则。

## 本次结论与执行约束

原始需求、实现所需工作和自行扩展的研究需要分别登记。计划中的历史条目也要经过用途判断，不能仅凭曾列入目录就持续提高其实现精度。每项新增工作先说明它影响哪个可执行的宏观或外交选择，再确定需要取得的信息。

要塞等级归具体目标的按需详情，精确待补员人数及逐团编制归扩展，荒废度与逐项产出归因归扩展研究。已有实现及验收继续保留，这些细项不作为当前核心交付的完成条件。逐场完整战报是明确需求，继续处理真实内容与交付缺口。

批量填写“待重核实际配置、字段语义、可知范围与端到端证据”混淆了已验收部分和真正缺项，应删除这种笼统状态。已有证据按适用版本、观察方和场景继承。相关实现或依赖变化、出现具体矛盾时才复查受影响部分。保存用于实际恢复需要，目录整理与字段新增本身不触发保存或重载验收。

已发生过委派重叠、短任务进入等待关键路径及跨模块合同授权过宽的问题。主代理负责范围、优先级、语义、架构和交付判定。子代理只承担输入与产物明确的独立工作，其事实、推断和建议分别呈现。模型较弱增加了核对关键结论的必要性，但现有记录不足以把全部进度缓慢归因于模型能力。

恢复开发后按交付缺项合并同类改动。定向验证用于当前变化，共享入口和完整回归沿整合里程碑安排。开发记录说明本次取得的结果、尚缺的结果和下一步依据，避免把检查数量或批次数量作为完成度。

### 部分委派重叠或范围过宽

子代理曾两次全量读取约350MB反汇编，各占用约9–10GB内存，触发换页风暴。资源限制已经写入项目指令，委派时仍需限定输入和读取范围。[资源限制](../../work/AGENTS.md)

### 子代理的事实与建议需要分开处理

最近验收审查把较早阶段“公开来源只有荒废度单分量”的状态误归到219批。219批接口文档已记载23个缓存项和4个直接来源。主代理核对后采用了正确状态。这类长历史中的时间错置会把已有能力重新列为缺项。

较弱子代理适合边界清楚的提取、比对和实现。需求解释、优先级、架构合同和完成判定需要主代理负责。多个同模型代理赞同同一建议，仍需核对决定范围的原始证据。

## 开发与验证的执行规则

1. 先写清缺少哪项结果会影响哪个可执行决策，复用已有接口和配置取得当前可用结果。
2. 继承已有验收收据与适用条件，相关代码、配置、协议、语义变化或出现具体矛盾时，检查受影响部分。
3. 原生读取的进程、观察方、地址、单位和可知范围守卫继续执行，来源证明按依赖变化复用。
4. 查询、报告、调度、取消和恢复按共享功能组验收。单个叶字段变化选择受影响入口，完整回归集中到交付整合里程碑。
5. 批次以交付结果组织，合并同类定向检查和归档。已有证据可链接复用，缺失历史工件与当前功能故障分别登记。

## 子代理的执行边界

| 主代理负责 | 子代理可以承担 |
| --- | --- |
| 需求解释、当前范围与优先级 | 固定文件中的事实、行号和证据提取 |
| 架构、跨模块协议与兼容边界 | 合同确定后的独立文件或模块实现 |
| 证据是否足够及交付判定 | 固定规则的比对、检查与结果归纳 |
| 采纳建议及处理冲突 | 将额外建议单列，说明依据和未确定条件 |

委派前比较直接完成与说明任务、等待、审查、返工的总成本。短任务由主代理直接完成，有明确独立产物的耗时工作按净收益委派。每项任务给定输入范围、文件所有权、预期输出和停止条件。

主代理集中核对改变范围与实现方向的关键结论，其余机械结果抽查。等待依赖中的子代理时遵守项目分工约束，同一事实提取避免双方重复执行。子代理发现相邻工作时先记录建议，主代理决定是否另立任务。

子代理的结论分为事实、推断和建议。主代理核对会改变范围或架构的原始依据后作决定，额外建议单独登记。主代理和子代理共同查同一批文件、让子代理重新统计已有台账、把短查询委派到关键路径，都会增加交付成本。后续以独立产物和节省的总工时决定是否委派。
