## 当前接口及实际阅读成本

bridge/information/tools.py定义9个工具：information_discover、information_query、information_get_result、information_manage_report、information_manage_subscription、information_configure、information_status、information_list_results、information_tick。工具定义紧凑JSON共5608字符。已有批量查询、报告复用、事件订阅和完整结果回读，不需要为每个字段再新建一个工具。

360实机information_discover收据原文件346562字节，紧凑JSON仍215188字节。工具定义数量不是主要体积来源；无筛选的全量发现结果比一份宏观简报大得多，应先支持按类别发现和字段按需展开。

直接查询示例，使用现有参数形状：

```json
{
  "request_id": "finance-001",
  "queries": [{
    "topic": "N01",
    "object": {"type": "country", "country": "FRA"},
    "fields": ["treasury", "monthly_income", "monthly_expenses", "monthly_balance", "loan_summary"],
    "parameters": {"reference_recipient": "ENG"}
  }]
}
```

此对象传给information_query。也可使用request_id和report_id查询已保存报告。2026-11-12起直接查询默认简洁，view=full读取完整记录。发现接口支持topics主题筛选。

355批实际brief结果中，treasury返回status=known、value=84730、raw=84730、raw_hex=fa4a0100、unit=ducats、scale=1000。模型需自行换算为84.730杜卡特。月度收入、支出、结余分别为29.198、31.253、-2.055杜卡特，语义是上一月经常账目；贷款4笔，本金合计512杜卡特。此为历史样本，不是当前游戏即时值。

按紧凑JSON序列化测量，355基础报告brief为34334字节，完整结果为250036字节；任务贸易情境brief为68932字节。财政单个条目仍有2685字节。这里报告字节数，未测模型token数，也未测压缩后的决策质量。

brief实现主要删除source.provenance与fields.*.provenance，仍保留query、objects、来源树、原始整数、十六进制、重复状态及窗口信息。任务、战报简报还在原字段之外追加摘要，容易同时出现摘要与大块详情。完整追溯有价值，但不必每次都进入模型上下文。

## 面向LLM的默认输出

默认输出已换算的业务数值。金币单位统一为ducats，在接口定义中说明。previous_month_recurring表示上一月经常收支，口径同样在接口定义中说明。不同采集日期和来源的差异留在完整结果中。

查询、结果回读、结果列表及订阅交付默认使用简洁格式。对象身份和业务值直接返回，未知值使用null。内部来源、诊断、十六进制、缩放参数、完整性研究备注和重复上下文留在完整存储记录中。调用information_get_result并指定view=full可读取完整结果。

财政条目形如以下内容。

```json
{
  "country": "FRA",
  "treasury": 84.730,
  "previous_month_recurring": {"income": 29.198, "expenses": 31.253, "balance": -2.055},
  "loans": {"count": 4, "principal": 512}
}
```

结果外层包含result_id和items。能力发现默认仅返回主题、标题、接入状态及字段名，支持topics筛选。需要对象参数定义时使用view=full。

宏观报告模板和按需展开继续复用现有入口。服务负责周期采集，LLM围绕关键事件或实际决策读取。后续以真实LLM方案比较效果评估进一步调整。
