# 按外交官 ID 召回

新版 v65 通过统一服务开放 `recall_diplomat`。输入是 `request_id` 和 `diplomat_id`，服务从连接的控制国配置取得所属国。DLL 再核对接管集合、国家完整句柄、外交官 ID 及游戏原生取消条件。请求和结果由既有外交账本按调用方归属保存。DLL 分别回报派发和状态复查；只有同一外交官从执行任务变为返回或空闲后，服务才记录 `executed`。

`N05.diplomat_tasks` 支持已配置观察国，简洁视图包含 `diplomat_id`。信息读取继续按观察国限制查询范围。模型测试轮次的观察国和控制国均为 `TUR`。[测试 API 目录](../../eu4-testing/prompts/mcp-catalog.md)

## 实机验收

最终使用 EU4 1.37.4 和 v65 DLL，在 PID 29752、会话 `29752-1dd79c727f2a13d` 验证。从观察者开局出发，短暂让原生 AI 运转并确认其派出 `TUR` 的 0 号外交官，在 `BYZ` 建立间谍网。重新绑定模型控制国为 `TUR`，通过 MCP 按 ID 召回。结束状态为 `returning`，原始日期为 `56457096`，其余三个外交官的查询结果一致。同一请求编号再次调用得到原结果。MCP 拒绝额外的国家参数，DLL 拒绝不存在的 ID 和未接管的 `FRA` 请求。[MCP 收据](../work/runtime/diplomat-recall-mcp-20261121/mcp.jsonl) [DLL 权限收据](../work/runtime/diplomat-recall-mcp-20261121/native-scope.json)
