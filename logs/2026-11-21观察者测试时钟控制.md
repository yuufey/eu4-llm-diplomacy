# 观察者测试时钟控制

统一 MCP 服务默认提供 13 个工具。操作者在测试轮次设置 `allow_time_control=true`，包装器才向服务传入 `--allow-time-control`。服务核对安装记录中的 `O00` 玩家和 DLL 能力，每次调用再核对当前会话。DLL 在游戏帧线程检查完整的 `O00` 句柄、单人测试的运行结构、请求所属会话、有效期和序号。请求只含整数速度。模型若要只通过 MCP 操作游戏，客户端还需限制 Shell、桌面和 DLL 请求目录的访问。

`set_game_speed` 的 `0` 表示暂停，`1–5` 对应游戏界面档位。接口返回游戏确认的档位、暂停状态和原始日期。[统一服务用法](../docs/共用开发/统一游戏服务使用说明.md)

## 构建与验收

实测游戏为 EU4 1.37.4，EXE SHA-256 为 `b23fa0e1f698d31b01cdd1c3817a675805d8c6286cb66f9c231e6e2a42544d77`。REA 核对了目标文件身份，读取字节时未返回结果。普通 objdump 的有界反汇编与实机证据分别保留。调速注册槽 RVA `0x1fce998` 在运行进程指向 `base+0xe91210`。普通反汇编显示 RVA `0xe9134e` 调用内部速度设置函数 RVA `0x757a20`，将索引限制在 `0–4`（RVA `0x757a27–0x757a42`），显示值为索引加一（RVA `0x757a43`）。暂停状态另行读取。一次早期实机验证读到原生调速输入 `5` 的实际索引为 `4`，随后修正了接口到界面档位的映射。载入提示确认后也补齐了 `O00` 的一次性暂停收尾，避免观察者局的时钟请求一直等待。

最终 v65 构建包含 207 个源文件收据，通过安装器清单校验。DLL SHA-256 为 `b3e8cf3eae2f2e93ccb59bc5ad0c3442884aeb33d4b0e7f9206086baf0f6cb61`。101 项定向 pytest 和 35 个子测试通过。

测试轮次 `baseline-tur-001` 以 `TUR` 为模型控制国。实机验收在 PID 38668、会话 `38668-1dd79bf4f0c119d` 进行。通过测试项目的 MCP 启动脚本验证了 14 个工具、无效参数拒绝、暂停、依次切换 1–5 档、再次暂停。最高速测试将原始日期从 `56456976` 推进到 `56457000`，只读探针确认最终已暂停。关闭权限的独立服务连接列出 13 个工具，直接调用返回 `permission_denied`。原始存档和测试副本的 SHA-256 均为 `853d7582d7e30f3f88e6bd160cd8a9917cdc9b3ad0baa413189374f940c5cb13`。[开启收据](../work/runtime/test-observer-game-speed-20261121/enabled.mcp.jsonl) [关闭收据](../work/runtime/test-observer-game-speed-20261121/disabled.mcp.jsonl)

用户要求关闭游戏后，已关闭重载命令先行启动的 PID 39976，并确认本轮 MCP 和安装进程已退出。测试项目使用最终构建，`baseline-tur-001` 保留已开启的开关及最近验收的安装记录。下次启动需绑定新的游戏进程。新建轮次默认关闭。
